# Ch24: 调用帧与函数调用

## 学习目标
- 理解 CallFrame 的结构及其在函数调用中的作用
- 掌握函数调用时压帧、执行、返回时弹帧的完整流程
- 能够追踪递归调用时调用帧栈的变化过程

## 核心概念

单纯的操作数栈无法支持函数调用，因为每次调用都需要保存**调用者的执行状态**（指令指针、栈基位置）。解决方案是引入 **CallFrame（调用帧）**。

每个 CallFrame 记录三件事：
- `ip`：当前函数执行到哪条指令
- `stackBase`：本次调用在操作数栈中的起始位置（用于访问局部变量）
- `chunk`：本次调用对应的字节码块

VM 维护一个 **CallFrame 栈**。调用函数时压入新帧，函数返回时弹出当前帧，恢复到调用者的帧继续执行。

#### CallFrame 栈变化图

```text
  frames = [Frame(fib, ip=0, base=1)]

  ]

fib(2) 调 fib(1):
  frames = [
    Frame(fib(1), ip=0, base=3),
    Frame(fib(2), ip=..., base=2),
    Frame(fib(3), ip=..., base=1)
  ]

RETURN 时:
  当前 Frame 弹出
  返回值压回上一层操作数栈

核心作用:
  frame 保存“执行到哪 + 局部变量起点 + 当前 chunk”
```

```
调用 fib(5)
  → 创建 CallFrame { ip=0, stackBase=当前栈顶, chunk=fib的Chunk }
  → 压入 CallFrame 栈
  → 执行 fib 的字节码
  → 遇到 RETURN 指令
  → 弹出 CallFrame，恢复调用者状态
  → 将返回值压入调用者的操作数栈
```

局部变量通过 `stackBase + 偏移量` 访问，这样每次调用都有独立的局部变量空间，递归也能正确工作。

## 为什么“只有一个操作数栈”仍然能支持递归

这一章最容易卡住的点，是很多人会直觉上认为：递归调用这么多层，难道不应该每次都新建一整套独立栈吗？

其实不需要。真正需要隔离的不是整条栈，而是：

1. 当前函数从哪里开始
2. 它的局部变量位于哪些槽位
3. 返回后应该回到哪条指令继续执行

CallFrame 正是在保存这三件事。操作数栈本身仍然可以复用，因为每个函数只要记住自己的 `stackBase`，就能把同一条大栈切成互不干扰的多个逻辑片段。

## stackBase 本质上是在给当前函数划地盘

可以把操作数栈想象成一长条工作台，而 `stackBase` 是当前函数被分配到的起始工位。

| 信息 | 作用 |
|------|------|
| `stackBase` | 当前函数局部变量区从哪里开始 |
| `slot` | 相对于当前函数起点的偏移 |
| `ip` | 当前函数下一条要执行的指令 |

所以 `GET_LOCAL 0` 不是“拿整台 VM 的第 0 个槽位”，而是“拿当前帧起点之后的第 0 个槽位”。这正是递归能成立的根本原因。

## 关键代码

```java
public class CallFrame {
    public int ip;
    public final int stackBase;
    public final Chunk chunk;

    public CallFrame(Chunk chunk, int stackBase) {
        this.ip = 0;
        this.stackBase = stackBase;
        this.chunk = chunk;
    }
}

public class VM {
    private final Object[] stack = new Object[256];
    private int stackTop = 0;
    private final Deque<CallFrame> frames = new ArrayDeque<>();

    public void call(Chunk chunk, int argCount) {
        // stackBase 指向参数开始的位置
        int stackBase = stackTop - argCount;
        frames.push(new CallFrame(chunk, stackBase));
    }

    public void execute() {
        while (!frames.isEmpty()) {
            CallFrame frame = frames.peek();
            byte[] code = frame.chunk.getCode();

            OpCode op = OpCode.values()[code[frame.ip++]];
            switch (op) {
                case GET_LOCAL -> {
                    int slot = code[frame.ip++];
                    stack[stackTop++] = stack[frame.stackBase + slot];
                }
                case SET_LOCAL -> {
                    int slot = code[frame.ip++];
                    stack[frame.stackBase + slot] = stack[stackTop - 1];
                }
                case CALL -> {
                    int argCount = code[frame.ip++];
                    // 栈顶往下 argCount+1 处是被调用的函数对象
                    FunctionObject fn = (FunctionObject) stack[stackTop - argCount - 1];
                    call(fn.getChunk(), argCount);
                }
                case RETURN -> {
                    Object result = stack[--stackTop];
                    frames.pop();
                    // 清理本次调用的栈帧
                    stackTop = frame.stackBase - 1;
                    stack[stackTop++] = result;
                }
                // ... 其他指令
            }
        }
    }
}
```

### fib(3) 调用追踪

```
fun fib(n) { if (n <= 1) return n; return fib(n-1) + fib(n-2); }
fib(3)

CallFrame 栈变化：

Step 1: fib(3) 入栈
  frames: [fib(3, ip=0, stackBase=0)]
  stack:  [3]

Step 2: fib(3) 调用 fib(2)
  frames: [fib(3, ip=5, stackBase=0), fib(2, ip=0, stackBase=1)]
  stack:  [3, 2]

Step 3: fib(2) 调用 fib(1)
  frames: [..., fib(2, ip=5, stackBase=1), fib(1, ip=0, stackBase=2)]
  stack:  [3, 2, 1]

Step 4: fib(1) return 1，弹帧
  frames: [..., fib(2, ip=5, stackBase=1)]
  stack:  [3, 2, 1]  ← 返回值 1

Step 5: fib(2) 调用 fib(0)
  ...继续递归

最终: fib(3) = fib(2) + fib(1) = 1 + 1 = 2
```

## 常见问题 Q&A

**Q1: 为什么 CallFrame 用栈而不是堆？**

A: 函数调用遵循 LIFO（后进先出），栈是天然的数据结构。而且栈上分配内存比堆快（只需移动指针）。Java 的 Deque 实际上是堆上的数据结构，但逻辑上是栈操作。

**Q2: 操作数栈大小 256 够吗？**

A: 对于教学语言足够。递归深度主要受 CallFrame 栈限制，不在操作数栈。如果真的溢出，可以改为动态扩容数组。

**Q3: CALL 指令怎么知道参数数量？**

A: 编译器在编译函数调用时，将参数数量写入 CALL 指令的操作数。VM 执行时读取这个操作数，就知道要弹出多少个参数。

## 小结

| 要点 | 说明 |
|------|------|
| CallFrame | 保存 ip、stackBase、chunk 三个关键信息 |
| 调用流程 | 压帧 → 执行 → 遇到 RETURN → 弹帧 |
| stackBase | 局部变量通过偏移量访问，支持递归 |
| 递归 | 每次调用独立 CallFrame，互不干扰 |
| 栈深度 | 最大 256 帧，超出则栈溢出 |
