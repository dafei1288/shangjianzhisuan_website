## 核心概念

### 整体架构

JimLang 的架构分为两条执行路径，共享前端（Lexer/Parser/Resolver），后端分叉为**解释器路径**和**字节码 VM 路径**。

```
                        ┌──────────┐
                        │  源码文件  │
                        └────┬─────┘
                             │
                        ┌────▼─────┐
                        │  Lexer   │ ← Ch03-04
                        └────┬─────┘
                             │ Token 流
                        ┌────▼─────┐
                        │  Parser  │ ← Ch05-07
                        └────┬─────┘
                             │ AST
                        ┌────▼─────┐
                        │ Resolver │ ← Ch11-12
                        └────┬─────┘
                             │ 带绑定信息的 AST
                    ┌────────┴────────┐
                    │                 │
              ┌─────▼──────┐   ┌──────▼──────┐
              │ Interpreter│   │  Compiler   │ ← Ch20-22
              │ (树遍历)    │   │ (字节码编译)  │
              └─────┬──────┘   └──────┬──────┘
                    │                 │ Chunk
                    │           ┌─────▼──────┐
                    │           │    VM      │ ← Ch23-24
                    │           └─────┬──────┘
                    │                 │
              ┌─────▼─────────────────▼──────┐
              │         执行结果               │
              └──────────────────────────────┘
```

### 模块职责

| 模块 | 职责 | 输入 | 输出 | 章节 |
|------|------|------|------|------|
| Lexer | 词法分析 | 源码字符串 | Token 列表 | Ch03-04 |
| Parser | 语法分析 | Token 列表 | AST | Ch05-07 |
| Resolver | 语义分析 | AST | 带作用域信息 AST | Ch11-12 |
| Interpreter | 树遍历执行 | AST | 执行结果 | Ch08-18 |
| Compiler | 编译字节码 | AST | Chunk | Ch20-22 |
| VM | 执行字节码 | Chunk | 执行结果 | Ch23-24 |
| GC | 垃圾回收 | 运行时堆 | 释放无用对象 | Ch25 |
| REPL | 交互式环境 | 用户输入 | 即时输出 | Ch26 |

### ANTLR4 的角色

```
ANTLR4 生成的是 CST（具体语法树），包含所有语法细节（括号、分号等）。
我们通过 ASTBuilder（Visitor）将其转换为自定义 AST，只保留语义信息。

ANTLR4 CST:                    自定义 AST:
  ProgramContext                Program
  ├── VarDeclContext            ├── VarDecl("x", Binary(+))
  │   ├── VAR()                 │
  │   ├── IDENTIFIER("x")      └── Print(Call(fib, [10]))
  │   ├── EQUAL()
  │   └── ExprContext
  └── PrintContext
      ...

CST 问题：节点太多、与语法规则耦合、难以操作
AST 优势：简洁、与语法无关、便于遍历和变换
```

### 主入口

```java
public class JimLang {
    public static void run(String source, boolean useVM) {
        // 前端（共享）
        var lexer = new JimLangLexer(CharStreams.fromString(source));
        var parser = new JimLangParser(new CommonTokenStream(lexer));
        var tree = parser.program();
        var ast = new ASTBuilder().visit(tree);
        new Resolver().resolve(ast);

        // 后端（二选一）
        if (useVM) {
            var chunk = new Compiler().compile(ast);
            new VM(chunk).run();
        } else {
            new Interpreter().interpret(ast);
        }
    }
}
```

### 核心数据结构

```java
// Token
public record Token(TokenType type, String lexeme,
                    Object literal, int line) {}

// AST 节点（sealed interface）
public sealed interface Expr permits
    Expr.Literal, Expr.Binary, Expr.Unary,
    Expr.Variable, Expr.Assign, Expr.Call {
    record Literal(Object value) implements Expr {}
    record Binary(Expr left, Token op, Expr right) implements Expr {}
    record Variable(Token name) implements Expr {}
}
```

## 两种执行路径对比

| 维度 | 解释器（Tree-walk） | 字节码 VM |
|------|-------------------|----------|
| 执行方式 | 递归遍历 AST 节点 | 顺序执行字节码指令 |
| 启动速度 | 快（无需编译） | 稍慢（需编译步骤） |
| 运行速度 | 慢（5-10 倍差距） | 快 |
| 实现难度 | 简单 | 较复杂 |
| 调试 | 容易（AST 直观） | 需反汇编工具 |
| 代表语言 | 早期 Ruby | JVM、Lua |

## 小结

| 要点 | 说明 |
|------|------|
| 前端共享 | Lexer → Parser → Resolver 两条路径共用 |
| 后端分叉 | Interpreter（简单）或 Compiler+VM（高效）|
| ANTLR4 | 生成 CST → ASTBuilder 转为自定义 AST |
| sealed interface | Java 17 的密封接口定义 AST 节点 |
| record | 不可变数据类，适合 Token 和 AST |

## 常见问题 Q&A

**Q1: 为什么要同时实现解释器和 VM？**

A: 解释器简单，适合教学和理解语义。VM 高效，展示工业级实现。同一门课学两种方案，对比理解更深入。

**Q2: ANTLR4 生成代码的性能可以接受吗？**

A: 前端（Lexer+Parser）只在启动时运行一次，耗时通常 < 100ms。运行时性能取决于后端（解释器/VM），与 ANTLR4 无关。

**Q3: 为什么要把 CST 转成自定义 AST？**

A: 解耦。ANTLR4 的 CST 和语法规则强耦合，改语法就要改所有下游代码。自定义 AST 一旦稳定，前端可以随意替换。
