# Ch16: this 与方法绑定

## 学习目标
- 理解 `this` 关键字在方法调用中的语义
- 掌握 `bind(instance)` 的实现：将 `this` 注入闭包环境
- 实现构造函数 `init()`：实例化时自动调用并返回实例
- 理解方法绑定与闭包环境的交互关系

---

## 1. 为什么需要 this

方法与普通函数的本质区别在于：方法调用时需要知道"当前对象是谁"。`this` 就是这个答案。

考虑以下 JimLang 代码：

```
class Dog {
    init(name) {
        this.name = name;       // this 指向新创建的实例
    }

    bark() {
        print this.name + " says woof!";
    }
}

var d = Dog("Rex");
d.bark();  // Rex says woof!
```

如果方法体内不能访问 `this`，就无法获取实例的属性——面向对象就无从谈起。

## 2. 方法绑定的核心思路

### 2.1 两种取值场景

```
// 场景1：通过实例调用方法 → this 正确绑定
d.bark();        // this = d ✅

// 场景2：将方法赋值给变量后调用 → this 仍需正确
var f = d.bark;
f();             // this 仍然 = d ✅
```

### 2.2 bind 方案

当从实例上取出一个方法时，不直接返回原始 `JimFunction`，而是返回一个**新的函数对象**——它的闭包环境中预先注入了 `this = 当前实例`。

```
原始 JimFunction (closure = 全局环境)
      ↓ bind(instance)
新 JimFunction (closure = { this: instance } → 全局环境)

调用新函数时，方法体内的 this 在环境链中自然找到
```

**关键**：`bind` 创建新的闭包环境，**不修改**原始函数对象。这保证了同一方法可以被多个实例安全绑定。

## 3. 关键代码

### 3.1 JimFunction 支持 bind

```java
public class JimFunction implements Value.Callable {
    private final Stmt.Function declaration;
    private final Environment closure;
    private final boolean isInitializer;

    public JimFunction(Stmt.Function declaration, Environment closure,
                       boolean isInitializer) {
        this.declaration = declaration;
        this.closure = closure;
        this.isInitializer = isInitializer;
    }

    // 创建绑定了 this 的新函数对象
    public JimFunction bind(JimInstance instance) {
        Environment env = new Environment(closure);
        env.define("this", instance);
        return new JimFunction(declaration, env, isInitializer);
    }
```

### 3.2 构造函数 init()

```java
    @Override
    public Value call(Interpreter interpreter, List<Value> args) {
        Environment env = new Environment(closure); // closure 已含 this
        for (int i = 0; i < declaration.params.size(); i++) {
            env.define(declaration.params.get(i).lexeme, args.get(i));
        }
        try {
            interpreter.executeBlock(declaration.body, env);
        } catch (Return returnValue) {
            // init() 始终返回 this，忽略显式 return
            if (isInitializer) return closure.getAt(0, "this");
            return returnValue.value;
        }
        // 无显式 return 时
        if (isInitializer) return closure.getAt(0, "this");
        return Value.NIL;
    }
```

### 3.3 解释器处理 this 表达式

```java
// 在 evaluate 中
case Expr.This e -> environment.get("this");

// 在类的属性取值时绑定 this
case Expr.Get get -> {
    Value obj = evaluate(get.object);
    if (obj instanceof JimInstance instance) {
        Value value = instance.get(get.name.lexeme);
        if (value instanceof JimFunction method) {
            yield method.bind(instance);  // 取方法时自动绑定
        }
        yield value;
    }
    throw new RuntimeError("只有实例有属性");
}
```

## 4. 执行追踪

```
class Counter {
    init() { this.count = 0; }
    inc()  { this.count = this.count + 1; }
}

var c = Counter();  // 1. 创建实例，调用 init()
c.inc();            // 2. 方法调用
c.inc();
print c.count;      // 3. 输出 2
```

详细追踪 `c.inc()` 的第一次调用：

```
1. 解析 c.inc
   → Expr.Get(Expr.Variable("c"), "inc")
   → evaluate(Variable("c")) → JimInstance(count=0)
   → instance.get("inc") → JimFunction(inc)
   → method.bind(instance) → 新 JimFunction(closure 含 this=instance)

2. 调用绑定后的函数（参数为空）
   → env = new Environment(closure 含 this)
   → executeBlock([this.count = this.count + 1], env)

3. 执行 this.count = this.count + 1
   → evaluate(this) → 在 env 中查找 → JimInstance(count=0)
   → evaluate(this.count) → instance.get("count") → 0
   → evaluate(0 + 1) → 1
   → instance.set("count", 1)

结果：c.count 从 0 变为 1
```

## 5. 构造函数的特殊语义

```
class Foo {
    init() {
        this.x = 10;
        return 42;     // 显式 return 会被忽略
    }
}

var f = Foo();
print f.x;    // 10
print f;      // <Foo instance>（而非 42）
```

设计理由：
- 构造函数的职责是**初始化实例**，不应改变实例化表达式的值
- 如果允许 `init()` 返回其他值，会破坏 `new` 的语义一致性
- `isInitializer` 标志在函数创建时设置，保证 `init()` 始终返回 `this`

## 8. 常见问题 Q&A

**Q1: 为什么 init 必须返回 this？**

A: 用户期望 `var c = Counter()` 得到的是实例。如果 init 返回其他值，语义会混乱。强制返回 this 保证了一致性。

**Q2: this 和 super 有什么区别？**

A: this 指向当前实例（运行时），super 指向父类方法表（定义时）。this 是动态绑定，super 是静态绑定。

**Q3: 为什么 bind 不修改原函数？**

A: 多个实例共享同一个方法定义。如果 bind 修改原函数，绑定到实例 A 后，实例 B 就无法正确绑定。

## 9. 小结

| 要点 | 说明 |
|------|------|
| bind(instance) | 创建新闭包环境，定义 this |
| 不修改原函数 | 多实例安全共享方法定义 |
| init 返回 this | 强制返回实例，忽略 return 值 |
| this 查找 | 沿环境链查找，与变量机制一致 |
