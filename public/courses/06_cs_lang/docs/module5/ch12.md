# Ch12: Resolver — 静态作用域分析

## 学习目标
- 理解为什么需要 Resolver：闭包中变量绑定的运行时 bug
- 掌握两遍处理流程：先 Resolve，再 Interpret
- 理解作用域栈的数据结构与变量状态标记
- 掌握 `getAt(distance)` / `assignAt(distance)` 的精确定位机制

## 核心概念

**问题根源**：没有 Resolver 时，变量查找在运行时沿 Environment 链进行。当闭包函数被调用时，调用栈的环境可能与定义时不同，导致变量被绑定到错误的 Environment 层。

经典 bug 示例：

```java
// 源码
var a = "global";
{
    fun showA() { print a; }
    var a = "block";
    showA(); // 期望输出 "global"，但可能输出 "block"
}
```

**Resolver 的解决方案**：在解释执行之前，对 AST 做一次静态遍历，计算每个变量引用距离其定义所在 Environment 的**层数（distance）**，存入 `Map<Expr, Integer> locals`。解释时直接用 `getAt(distance)` 跳到正确的层，不再逐层查找。

**作用域栈**：Resolver 维护一个 `Deque<Map<String, Boolean>>` 作为作用域栈。进入块时压栈，退出时弹栈。`Boolean` 值表示变量是否已完成初始化（防止 `var a = a;` 这类自引用）。

**两遍处理**：
1. **Resolve 遍**：遍历 AST，记录每个变量引用的 distance
2. **Interpret 遍**：执行时用 distance 精确定位变量

## 关键代码

```java
class Resolver {
    private final Interpreter interpreter;
    // 作用域栈：每层是 变量名 -> 是否已初始化
    private final Deque<Map<String, Boolean>> scopes = new ArrayDeque<>();

    void resolve(Expr expr) {
        switch (expr) {
            case Expr.Var(var name) -> resolveLocal(expr, name);
            case Expr.Assign(var name, var value) -> {
                resolve(value);
                resolveLocal(expr, name);
            }
            case Expr.Binary(var l, var op, var r) -> { resolve(l); resolve(r); }
            // ... 其他表达式类型
        }
    }

    void resolve(Stmt stmt) {
        switch (stmt) {
            case Stmt.Block(var stmts) -> {
                beginScope();
                for (Stmt s : stmts) resolve(s);
                endScope();
            }
            case Stmt.Var(var name, var init) -> {
                declare(name);
                if (init != null) resolve(init);
                define(name);
            }
            case Stmt.Function(var name, var params, var body) -> {
                declare(name); define(name);
                resolveFunction(params, body);
            }
            // ... 其他语句类型
        }
    }

    private void resolveLocal(Expr expr, String name) {
        // 从栈顶向下查找，计算距离
        int i = 0;
        for (var scope : scopes) {
            if (scope.containsKey(name)) {
                interpreter.resolve(expr, i); // 记录 distance
                return;
            }
            i++;
        }
        // 未找到 -> 全局变量，不记录（运行时动态查找）
    }

    private void beginScope() { scopes.push(new HashMap<>()); }
    private void endScope()   { scopes.pop(); }
    private void declare(String name) { if (!scopes.isEmpty()) scopes.peek().put(name, false); }
    private void define(String name)  { if (!scopes.isEmpty()) scopes.peek().put(name, true); }
}

// Environment 中精确定位
Value getAt(int distance, String name) {
    return ancestor(distance).values.get(name);
}

Environment ancestor(int distance) {
    Environment env = this;
    for (int i = 0; i < distance; i++) env = env.parent;
    return env;
}
```

## Resolver 如何解决闭包问题

```
问题场景：
  var a = "global";
  {
    fun showA() { print a; }
    var a = "local";  // 在 showA 定义之后
    showA();
  }

没有 Resolver: 运行时 showA() 的 Environment 链包含 a="local"
有 Resolver: 静态分析知道 showA 中的 a 在外层第几步，直接定位
```

### 变量"距离"机制

Resolver 遍历 AST 时，为每个变量引用记录一个 `distance` 数字（向上穿越多少层 Environment）。

```java
// Resolver 输出：在每个 Expr.Variable 上标注 distance
case Expr.Variable var_expr -> {
    int distance = resolveLocal(var_expr, var_expr.name);
    // 存入 Map<Expr, Integer> locals
}

// Interpreter 用 getAt(distance, name) 直接跳到正确层级
Value getAt(int distance, String name) {
    Environment env = this.environment;
    for (int i = 0; i < distance; i++) env = env.enclosing;
    return env.get(name);
}
```

将变量查找从 O(n) 链式遍历变为 O(1) 直接跳转，同时保证正确性。

## 常见问题 Q&A

**Q1: Resolve 遍不增加启动时间吗？**

A: 会增加，但只遍历一次 AST，时间复杂度与程序大小成正比。对于大多数程序，Resolve 阶段耗时 < 1ms，远小于运行时间。

**Q2: 为什么不用符号表而用 distance？**

A: distance 更简单、更直接。符号表需要维护复杂的映射关系，distance 只需一个整数。这在 Lox/Python 等语言中被广泛使用。

**Q3: 所有语言都需要 Resolver 吗？**

A: 不。动态语言如 JavaScript 不做静态 resolve，变量查找完全在运行时进行。缺点是闭包可能有意外行为（ES6 的 let/const 修复了大部分问题）。

## 小结

| 要点 | 说明 |
|------|------|
| 两遍处理 | 先 Resolve 遍，再 Interpret 遍 |
| 作用域栈 | Deque<Map<String, Boolean>> 跟踪变量状态 |
| distance | 变量引用到定义的层数，O(1) 查找 |
| 正确性 | 解决闭包中变量绑定的运行时 bug |
| 性能提升 | 变量查找从 O(n) 链式遍历变为 O(1) 跳转 |
