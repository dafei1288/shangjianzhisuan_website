## 1. Environment 数据结构

### 1.1 链式结构

```
Environment 链 = 单向链表，每个节点代表一个作用域

全局 Environment                  块级 Environment
┌──────────────────┐             ┌──────────────────┐
│ values:          │             │ values:          │
│   x → 10        │ ← parent ── │   y → 20         │
│   name → "Jim"  │             │   x → "local"    │  ← 遮蔽外层 x
│ parent: null     │             │ parent: ─────────→│
└──────────────────┘             └──────────────────┘
```

每个 Environment 包含：
- `Map<String, Value> values`：当前作用域的变量绑定
- `Environment parent`：指向外层作用域（全局为 null）

### 1.2 生命周期

```
进入块时：创建新 Environment，parent = 当前环境
执行块内语句：使用新环境
退出块时：恢复为 parent 环境（finally 保证）

case Stmt.Block(var stmts) -> {
    Environment previous = this.env;
    this.env = new Environment(previous);  // 进入
    try {
        for (Stmt s : stmts) execute(s);
    } finally {
        this.env = previous;  // 退出（无论是否异常）
    }
}
```

## 2. 三个核心操作

### 2.1 define（定义变量）

```java
void define(String name, Value value) {
    values.put(name, value);
}
```

只在**当前层**创建绑定。允许重复定义（后定义覆盖前定义）。

### 2.2 get（查找变量）

```java
Value get(String name) {
    if (values.containsKey(name)) return values.get(name);
    if (parent != null) return parent.get(name);  // 递归向上
    throw new RuntimeError("未定义变量: " + name);
}
```

从当前层开始，逐层向上查找。最先找到的定义生效。

### 2.3 assign（赋值变量）

```java
void assign(String name, Value value) {
    if (values.containsKey(name)) {
        values.put(name, value);
        return;
    }
    if (parent != null) {
        parent.assign(name, value);  // 递归向上
        return;
    }
    throw new RuntimeError("未定义变量: " + name);
}
```

赋值修改的是**定义处的变量**，而非在当前层创建新绑定。

## 3. 变量遮蔽（Variable Shadowing）

```
var x = "global";       // 全局 env: {x: "global"}
{
    var x = "local";     // 块 env: {x: "local"}, parent → 全局
    print x;             // 查找 x → 命中块层 → "local"
}
print x;                 // 查找 x → 全局层 → "global"
```

**遮蔽不等于修改**：内层的 `x` 是一个全新的变量，与外层的 `x` 是不同的 Map entry。退出块后，内层变量随 Environment 一起被 GC 回收。

## 4. 词法作用域 vs 动态作用域

### 4.1 核心区别

```
var x = "global";

fun foo() {
    print x;      // 词法作用域：x = "global"（定义时确定）
                  // 动态作用域：x = ??? （取决于调用时谁定义了 x）
}

{
    var x = "local";
    foo();         // 词法作用域：仍然输出 "global"
                   // 动态作用域：输出 "local"
}
```

| 维度 | 词法作用域 | 动态作用域 |
|------|-----------|-----------|
| 绑定时机 | 定义时（编译期可确定） | 运行时（沿调用栈查找） |
| 可预测性 | 高 | 低 |
| 代表语言 | Java, Python, JS, C | Bash, Emacs Lisp |
| Environment 链 | 基于嵌套结构（定义位置） | 基于调用栈（调用位置） |

### 4.2 JimLang 采用词法作用域

我们的 Environment 链基于代码的**嵌套结构**，而非**调用栈**。这意味着函数内访问的外层变量，始终是函数**定义位置**的外层变量，与函数**在哪里被调用**无关。

这也是后续引入 **Resolver** 的根本原因：纯运行时的 Environment 链在某些场景下会"误绑"到调用栈的环境，而非定义时的环境。

## 5. 执行追踪示例

```
var a = 1;
var b = 2;
{
    var c = a + b;    // c = 3，跨层查找 a 和 b
    {
        var d = c * 2; // d = 6，跨层查找 c
        print d;       // 6
        a = 100;       // 赋值修改全局层的 a
    }
    print a;           // 100（被内层修改了）
}
print a;               // 100
print b;               // 2
// print c;            // 错误：c 不存在（块作用域已退出）
```

Environment 链变化：

```
全局: {a:1, b:2}
  → 块1: {c:3}          parent → 全局
    → 块2: {d:6}        parent → 块1
      赋值 a=100: 递归找到全局层，修改
    ← 块2退出
  ← 块1退出
全局: {a:100, b:2}
```

## 7. 常见问题 Q&A

**Q1: Environment 链的性能问题？**

A: 每次变量查找需要沿链遍历，最坏 O(n)（n = 嵌套深度）。大多数程序嵌套不超过 10 层，实际可接受。Resolver（下一章）会预计算 distance，将查找优化为 O(1)。

**Q2: 为什么用 Map 而不用数组？**

A: 动态语言中变量在运行时才能确定，Map 提供灵活的字符串键查找。在字节码 VM 中，编译期已知变量位置，会改用数组索引（slot）。

**Q3: 词法作用域 vs 动态作用域？**

A: 词法作用域：变量在"定义处"查找（大多数语言）。动态作用域：变量在"调用处"查找（Emacs Lisp、Bash）。词法作用域更可预测、更易推理。

## 8. 小结

| 要点 | 说明 |
|------|------|
| 数据结构 | Map + parent 指针 |
| define | 只在当前层操作 |
| get/assign | 沿 parent 链递归查找 |
| 变量遮蔽 | 内层同名变量覆盖外层 |
| 块作用域 | 进入创建新 Env，退出恢复 |
| finally | 保证 Environment 正确恢复 |
