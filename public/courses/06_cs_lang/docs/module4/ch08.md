## 1. 为什么需要 Visitor 模式

### 1.1 问题：操作与数据结构耦合

AST 节点本质上是纯数据容器。如果我们把求值、打印、类型检查等操作都写在节点类里：

```java
// ❌ 糟糕的设计：操作散落在各个节点类中
class Num implements Expr {
    double value;
    Value evaluate() { return new Value.Num(value); }     // 求值
    String prettyPrint() { return String.valueOf(value); } // 打印
    Type typeCheck(TypeEnv env) { return Type.NUMBER; }    // 类型检查
}
// Binary、Unary 等每个类都要重复实现三套逻辑
```

这违反了**开放-封闭原则**：每新增一种操作，就要修改所有节点类。

### 1.2 解决：将操作抽离到 Visitor

Visitor 模式将操作逻辑从数据结构中抽离出来，集中在一个独立的类中：

```
AST 节点（数据）          Visitor（操作）
┌──────────┐            ┌──────────────┐
│ Num      │            │ Interpreter  │ 求值
│ Binary   │ ──访问──→  │ Printer      │ 打印
│ Unary    │            │ TypeChecker  │ 类型检查
└──────────┘            └──────────────┘

新增操作 → 新增 Visitor 类，不修改 AST 节点
新增节点 → 在每个 Visitor 中新增一个方法
```

### 1.3 传统 vs 现代实现

| 维度 | 传统 Visitor | Java 21 pattern matching |
|------|-------------|------------------------|
| 节点类修改 | 每个 permit 加 `accept` 方法 | 无需修改 |
| 分派方式 | 双重分派（节点调 Visitor） | 单一分派（switch 按类型匹配） |
| 穷举检查 | 运行时可能遗漏 | 编译期 sealed interface 保证 |
| 代码集中度 | 分散在各 Visitor 接口 | 集中在一个 switch 表达式 |

## 2. 核心概念

**双重分派（Double Dispatch）** 是传统 Visitor 的精髓：

```
第一次分派：客户端调用 node.accept(visitor)
第二次分派：节点的 accept 方法回调 visitor.visitXxx(this)
→ 最终执行到正确的 visit 方法，同时确定了节点类型和操作类型
```

Java 21 的 **pattern matching switch** 让我们跳过这种迂回：

```java
// 传统 Visitor：每个节点类都需要 accept 方法
sealed interface Expr permits Expr.Num, Expr.Binary {
    <R> R accept(Visitor<R> visitor);  // ← 每个permit都要实现
}

// 现代 Visitor：一个 switch 搞定
Value evaluate(Expr expr) {
    return switch (expr) {
        case Expr.Num(var v)    -> ...;
        case Expr.Binary(var l, var op, var r) -> ...;
        // 编译器保证穷举 sealed interface 的所有 permits
    };
}
```

配合 **sealed interface**，编译器能保证所有子类型都被处理（穷举检查），漏掉一个分支就报错。

**运行时值**统一用 `sealed interface Value` 表示：

```
           Value (sealed interface)
          /      |      \       \
       Num     Str     Bool    Nil
    (double)  (String) (boolean)  ()
```

求值时若类型不匹配（如对字符串做减法），抛出 `RuntimeError`。

## 3. 关键代码

### 3.1 AST 节点定义

```java
// sealed interface 保证穷举
sealed interface Expr permits Expr.Num, Expr.Str, Expr.Bool,
                           Expr.Nil, Expr.Binary, Expr.Unary, Expr.Grouping {}

record Expr.Num(double value) implements Expr {}
record Expr.Str(String value) implements Expr {}
record Expr.Bool(boolean value) implements Expr {}
record Expr.Nil() implements Expr {}
record Expr.Binary(Expr left, String op, Expr right) implements Expr {}
record Expr.Unary(String op, Expr right) implements Expr {}
record Expr.Grouping(Expr expression) implements Expr {}
```

### 3.2 求值器实现

```java
class Interpreter {
    Value evaluate(Expr expr) {
        return switch (expr) {
            case Expr.Num(var v)   -> new Value.Num(v);
            case Expr.Str(var v)   -> new Value.Str(v);
            case Expr.Bool(var v)  -> new Value.Bool(v);
            case Expr.Nil()        -> Value.NIL;
            case Expr.Grouping(var e) -> evaluate(e); // 递归求值
            case Expr.Unary(var op, var right) -> evalUnary(op, evaluate(right));
            case Expr.Binary(var l, var op, var r) ->
                evalBinary(evaluate(l), op, evaluate(r));
        };
    }
```

### 3.3 二元运算处理

```java
    private Value evalBinary(Value left, String op, Value right) {
        // 数值运算
        if (left instanceof Value.Num(var a) && right instanceof Value.Num(var b)) {
            return switch (op) {
                case "+" -> new Value.Num(a + b);
                case "-" -> new Value.Num(a - b);
                case "*" -> new Value.Num(a * b);
                case "/" -> {
                    if (b == 0) throw new RuntimeError("除以零");
                    yield new Value.Num(a / b);
                }
                case ">"  -> new Value.Bool(a > b);
                case "<"  -> new Value.Bool(a < b);
                case ">=" -> new Value.Bool(a >= b);
                case "<=" -> new Value.Bool(a <= b);
                case "==" -> new Value.Bool(a == b);
                case "!=" -> new Value.Bool(a != b);
                default   -> throw new RuntimeError("未知运算符: " + op);
            };
        }
        // 字符串拼接：+ 支持任意类型拼接
        if ("+".equals(op)) return new Value.Str(stringify(left) + stringify(right));
        // 字符串比较
        if (left instanceof Value.Str(var a) && right instanceof Value.Str(var b)) {
            return switch (op) {
                case "==" -> new Value.Bool(a.equals(b));
                case "!=" -> new Value.Bool(!a.equals(b));
                default   -> throw new RuntimeError("字符串不支持运算符: " + op);
            };
        }
        // 相等性比较（跨类型：1 == "1" → false）
        if ("==".equals(op)) return new Value.Bool(left.equals(right));
        if ("!=".equals(op)) return new Value.Bool(!left.equals(right));

        throw new RuntimeError("类型不匹配: " + stringify(left) + " " + op + " " + stringify(right));
    }
```

### 3.4 一元运算处理

```java
    private Value evalUnary(String op, Value right) {
        return switch (op) {
            case "-" -> {
                if (right instanceof Value.Num(var v))
                    yield new Value.Num(-v);
                throw new RuntimeError("只能对数字取负: " + stringify(right));
            }
            case "!" -> {
                // 对任意值取布尔反（truthy/falsy 语义）
                yield new Value.Bool(!isTruthy(right));
            }
            default -> throw new RuntimeError("未知一元运算符: " + op);
        };
    }

    private boolean isTruthy(Value value) {
        return switch (value) {
            case Value.Nil()    -> false;
            case Value.Bool(var b) -> b;
            default             -> true; // 数值和字符串都是 truthy
        };
    }
```

## 4. 执行追踪示例

给定表达式 `-(3 + 4) * 2`，其 AST 结构：

```
        Binary(*)
       /         \
    Unary(-)    Num(2)
      |
   Binary(+)
   /       \
 Num(3)   Num(4)
```

求值过程：

```
evaluate(Binary(Unary(Binary(Num(3), +, Num(4))), *, Num(2)))
  → evalBinary(evaluate(Unary(-, Binary(+))), "*", evaluate(Num(2)))
    → evaluate(Unary(-, Binary(+)))
      → evalUnary("-", evaluate(Binary(Num(3), +, Num(4))))
        → evaluate(Binary(Num(3), +, Num(4)))
          → evalBinary(Num(3), "+", Num(4))
          ← Value.Num(7.0)
        → evalUnary("-", Num(7.0))
        ← Value.Num(-7.0)
    → evalBinary(Num(-7.0), "*", Num(2.0))
    ← Value.Num(-14.0)
```

## 7. 常见问题 Q&A

**Q1: 为什么 Value 用 sealed interface 而不是 Object？**

A: Object 需要到处 instanceof，容易遗漏。sealed interface + pattern matching 让编译器帮你检查所有情况。

**Q2: 动态类型语言怎么做类型检查？**

A: 运行时检查。每次运算前检查操作数类型，不匹配就抛 RuntimeError。这就是动态类型"灵活但不安全"的原因。

**Q3: RuntimeError 和 NullPointerException 有什么区别？**

A: RuntimeError 是 JimLang 的语义错误（如对字符串做除法）。NullPointerException 是 Java 层的 bug，说明解释器代码有问题。

## 8. 小结

| 要点 | 说明 |
|------|------|
| Visitor 模式 | 求值逻辑集中，AST 保持纯数据 |
| pattern matching | sealed interface + switch，编译期安全 |
| Value | sealed interface + record，不可变 |
| 动态类型 | 运行时检查，不匹配抛 RuntimeError |
| binaryOp | 通用二元运算封装，减少重复代码 |
