## 1. 四层安全策略

### 1.1 安全分层模型

```
┌────────────────────────────────────────┐
│ Layer 4: Git 保护                       │
│   protected branches + PR review + CI  │
├────────────────────────────────────────┤
│ Layer 3: AGENTS.md 约束                │
│   不可修改文件 + 危险操作清单 + 安全规则 │
├────────────────────────────────────────┤
│ Layer 2: 沙箱配置                       │
│   可写目录白名单 + 网络控制 + 命令超时   │
├────────────────────────────────────────┤
│ Layer 1: 审批模式                       │
│   Suggest / Auto-Edit / Full-Auto      │
└────────────────────────────────────────┘
```

### 1.2 按场景选择安全级别

| 场景 | 审批模式 | 沙箱 | 额外措施 |
|------|---------|------|---------|
| 生产代码 | Suggest | 严格 | PR 审查 + CI 门禁 |
| 开发分支 | Auto-Edit | 标准 | 定期 commit |
| 个人项目 | Auto-Edit | 宽松 | — |
| CI/CD | Full-Auto | 严格 | 超时保护 |
| 实验原型 | Full-Auto | 关闭 | 隔离环境 |

### 1.3 AGENTS.md 安全模板

```markdown
## 安全约束
- ❌ 不要修改 .env 文件
- ❌ 不要执行 DROP TABLE 或 TRUNCATE
- ❌ 不要安装新的 npm 包（先问我）
- ❌ 不要修改 CI/CD 配置（.github/workflows/）
- ❌ 不要在生产代码中使用 console.log
- ✅ 所有数据库操作使用参数化查询
- ✅ 所有用户输入使用 Zod 校验
- ✅ 新增 API 必须包含错误处理
```

## 2. Context Window 管理

### 2.1 Token 消耗意识

| 操作 | 大约 Token 消耗 | 成本 |
|------|----------------|------|
| 读取一个 100 行文件 | ~500 tokens | $0.002 |
| 修改一个文件 | ~2,000 tokens | $0.01 |
| 一次完整对话轮 | ~3,000-5,000 tokens | $0.02 |
| 10 轮对话 | ~30,000-50,000 tokens | $0.20 |
| 典型开发日（50 次） | ~150,000 tokens | $1-3 |

### 2.2 省 Token 技巧

```
技巧 1：精准描述，避免全项目搜索
  ❌ "找到处理用户认证的文件"
  ✅ "修改 src/server/routers/auth.ts 的 login 函数"

技巧 2：及时 /compact
  上下文超过 100K tokens 时质量开始下降
  每 10-15 轮对话压缩一次

技巧 3：分批处理
  大任务拆成多个小对话，每段 /clear
  避免"一锅炖"式需求

技巧 4：善用 AGENTS.md
  项目信息写在 AGENTS.md 中，避免每次重复描述
  AGENTS.md 的内容自动加载，不占对话 Token

技巧 5：选择合适的模型
  简单任务 → codex-1（便宜）
  复杂任务 → gpt-5.2-codex（贵但质量高）
```

### 2.3 成本估算

```
典型开发者的月度成本：

轻度使用（每天 10 次交互）：
  ~30K tokens/天 × 22 天 = 660K tokens/月
  ≈ $5-10/月

中度使用（每天 30 次交互）：
  ~100K tokens/天 × 22 天 = 2.2M tokens/月
  ≈ $20-40/月

重度使用（每天 80 次交互）：
  ~250K tokens/天 × 22 天 = 5.5M tokens/月
  ≈ $50-100/月

建议：设置 API 月度预算告警，在 $50 时通知
```

## 3. 常见陷阱与解决方案

### 3.1 Codex 修改了不该改的文件

```
原因：AGENTS.md 没有明确约束

解决：在 AGENTS.md 中列出不可修改的文件
  ## 不要修改的文件
  - prisma/schema.prisma
  - .github/workflows/*
  - docker-compose.yml
  - package-lock.json
  - .env
  
  如果需要修改这些文件，先问我确认
```

### 3.2 Codex 陷入循环

```
现象：反复尝试同一个修改，每次都失败

根因：可能是需求描述有歧义，或代码中有隐藏的约束

解决步骤：
  1. Ctrl+C 中断当前操作
  2. /clear 清除上下文
  3. 用更精确的语言重新描述需求
  4. 提供具体的代码示例或错误信息
  5. 如果仍失败，手动修改一部分，让 Codex 处理剩余部分
```

### 3.3 上下文过长导致质量下降

```
现象：长对话后 Codex 开始"忘记"前面的内容

原因：Context Window 有限，旧内容被压缩或截断

解决：
  1. /compact 压缩上下文（保留关键信息）
  2. /clear 开始新对话（完全重置）
  3. 将关键约定写入 AGENTS.md（不会丢失）
  4. 将重要信息写入文件（让 Codex 重新读取）
```

### 3.4 生成的代码风格不一致

```
解决：在 AGENTS.md 中提供具体的代码示例

  ## 代码风格示例
  
  ```typescript
  // ✅ 好的写法（使用函数式 + 类型注解 + 错误处理）
  const getUser = async (id: string): Promise<User> => {
    const user = await db.user.findUnique({ where: { id } });
    if (!user) throw new NotFoundError('User not found');
    return user;
  };
  
  // ❌ 不要这样写
  async function getUser(id) {
    return await db.user.findUnique({ where: { id } });
  }
  ```
```

### 3.5 Codex 删除了太多代码

```
预防：
  1. 使用 Suggest 模式（必须手动确认）
  2. 频繁 git commit（容易回滚）
  3. 要求 Codex 解释每次删除的原因

恢复：
  git diff HEAD~1           # 查看被删除的内容
  git checkout HEAD~1 -- file.ts  # 恢复文件
  git stash                 # 暂存当前修改
```

## 4. 个人方法论

### 4.1 日常开发流程

```
1. 启动 Codex（在项目目录下，cd my-project && codex）
2. 第一个任务："解释这个项目的结构"（建立上下文）
3. 开始实际任务，先用 Suggest 模式（观察质量）
4. 确认 Codex 理解正确后切到 Auto-Edit
5. 每 10-15 轮 /compact 一次
6. 完成小功能后 git commit
7. 完成大功能后让 Codex 审查 + 生成 PR 描述
```

### 4.2 渐进信任策略

```
第一周：全程 Suggest 模式
  → 观察输出质量，理解 Codex 的能力边界
  → 完善 AGENTS.md

第二周：日常任务切 Auto-Edit
  → 关键代码（认证、支付、权限）保持 Suggest
  → 开始建立个人快捷命令

第三周：尝试 Goal 模式
  → 给 Codex 明确的目标，观察自主规划能力
  → 对比不同模式下的效率差异

第四周：建立最佳实践文档
  → 记录常用的提示词模板
  → 记录常见的陷阱和解法
  → 形成个人化的工作流
```

### 4.3 效率提升清单

```
□ AGENTS.md 写好了吗？（项目规范 + 约束 + 示例）
□ config.toml 配好了吗？（模型 + 审批 + 沙箱）
□ 常用 MCP Server 配好了吗？（数据库、文档等）
□ git 仓库干净吗？（方便 undo 和回滚）
□ 分支策略设好了吗？（feature branch + PR）
```
