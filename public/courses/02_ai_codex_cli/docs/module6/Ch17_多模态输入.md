# Ch17：多模态输入

## 学习目标

- 理解多模态输入的概念及其在编程场景中的价值
- 掌握图片输入的使用方法（截图、架构图、手绘草图）
- 学会利用多模态能力加速 Bug 定位和 UI 开发
- 了解多模态输入的局限性和最佳实践
- 掌握多模态提示词的编写技巧

## 1. 为什么需要多模态输入

### 1.1 纯文本描述的局限

很多编程场景用文字描述既低效又不准确：

| 场景 | 文字描述 | 图片输入 |
|------|----------|----------|
| UI Bug | "按钮偏右了，大概 5 像素" | 截图直接标注问题 |
| 布局需求 | "左边一个侧边栏，右边主内容区..." | 手绘草图 3 秒搞定 |
| 报错排查 | 复制粘贴大段堆栈信息 | 截图包含完整错误信息 |
| 架构设计 | "A 模块调用 B，B 调用 C..." | 一张架构图胜千言 |

### 1.2 多模态的工作原理

Codex CLI 的多模态能力来自底层模型（GPT-5-Codex）的视觉理解能力：

```
用户输入              Codex 处理
┌──────────┐        ┌──────────────────┐
│ 文本指令  │───────→│ 文本编码器       │
│          │        │         ↘        │
│ + 图片   │───────→│ 视觉编码器 → 融合 │──→ 推理 → 工具调用
│          │        │         ↗        │
└──────────┘        └──────────────────┘
```

模型同时理解文本和图片内容，将两者融合后进行推理。

## 2. 使用方法

### 2.1 基本用法

```bash
# 方法 1：直接粘贴图片路径
> 截图里这个报错帮我看看 @screenshot.png

# 方法 2：使用管道输入
> cat error.png | codex "分析这个错误截图"

# 方法 3：在 REPL 中拖拽图片文件
> （拖入文件或粘贴截图）
  [图片已附加]
> 这个 UI 有什么问题？帮我修复
```

### 2.2 图片 + 文本组合提示

多模态的关键是**图片和文本的配合**：

```bash
# 好的组合：图片提供视觉信息，文本提供上下文和目标
> 这是我当前的 UI 截图 @current-ui.png，
  请把导航栏改为深色主题，按钮改为圆角，保持现有的间距

# 差的组合：只有图片没有文本说明
> @screenshot.png
  → Codex 不知道你想做什么
```

**模板：图片 + 当前状态描述 + 目标 + 约束**

```bash
> [图片：当前状态] @current.png
  当前：这是一个登录页面，使用了默认样式
  目标：改为暗色主题，添加品牌 Logo
  约束：保持响应式布局，不改变表单验证逻辑
```

## 3. 典型应用场景

### 3.1 UI Bug 修复

```bash
# 截取 UI Bug 截图
> 这个按钮的位置不对 @bug-screenshot.png，
  应该在导航栏右侧垂直居中，和搜索框对齐

# Codex 会：
# 1. 分析截图，识别按钮当前位置
# 2. 找到对应的 CSS/组件文件
# 3. 计算正确的定位参数
# 4. 应用修改
```

### 3.2 从设计稿生成代码

```bash
# 输入设计稿截图
> 根据这个设计稿生成 React 组件 @design-mockup.png，
  使用 Tailwind CSS，要求响应式

# Codex 会：
# 1. 识别设计稿中的布局结构
# 2. 分析颜色、字体、间距
# 3. 生成对应的 JSX + Tailwind 代码
```

### 3.3 手绘草图 → 代码

```bash
# 输入手绘草图（甚至拍照白板上的草图）
> 把这个手绘架构图变成 Python 代码 @whiteboard.jpg
  使用 Flask 框架，每个方框代表一个模块

# Codex 会：
# 1. 识别手绘中的方框和箭头
# 2. 理解模块关系和数据流
# 3. 生成对应的代码结构
```

### 3.4 错误截图排查

```bash
# 直接截图终端中的报错信息
> 帮我分析这个报错并修复 @error-terminal.png

# Codex 会：
# 1. OCR 识别截图中的文字
# 2. 定位报错文件和行号
# 3. 分析根本原因
# 4. 提供修复方案
```

## 4. 支持的图片格式与限制

### 4.1 支持格式

| 格式 | 支持情况 | 推荐场景 |
|------|----------|----------|
| PNG | ✅ 最佳 | 截图、设计稿 |
| JPEG/JPG | ✅ 良好 | 照片、白板 |
| WebP | ✅ 良好 | 网页截图 |
| GIF | ⚠️ 仅首帧 | 动画（只取第一帧） |
| SVG | ⚠️ 需栅格化 | 图标、矢量图 |

### 4.2 大小限制

- 单张图片最大：**20MB**
- 单次最多图片数：**4 张**
- 推荐分辨率：**宽高不超过 2048px**（超过会自动压缩）

### 4.3 模型对图片的理解能力

| 能力 | 水平 | 说明 |
|------|------|------|
| 文字识别 (OCR) | 优秀 | 能识别截图中的代码和错误信息 |
| UI 布局理解 | 良好 | 能分析组件位置、间距、对齐 |
| 颜色识别 | 良好 | 能提取颜色值，但可能有色差 |
| 手绘识别 | 一般 | 简单草图可以，复杂细节会丢失 |
| 小文字识别 | 一般 | 字号过小的文字可能识别不准 |

## 5. 多模态最佳实践

### 5.1 图片质量要求

```
✅ 好的图片：清晰、完整、重点突出
  - 截图包含完整的错误信息
  - 设计稿分辨率足够高
  - 手绘线条清晰、标注完整

❌ 差的图片：模糊、截断、信息过载
  - 模糊的手机拍照
  - 只截了一半的错误信息
  - 一张图里挤了太多内容
```

### 5.2 多图对比

```bash
# 用两张图展示"当前"和"期望"
> 当前状态 @current.png，期望效果 @expected.png，
  把当前改成期望的样子
```

### 5.3 结合 AGENTS.md 提供上下文

```bash
# AGENTS.md 中写明项目信息
## 项目信息
- 技术栈：React 18 + Tailwind CSS
- 设计系统：使用 design-tokens.css 中的变量
- 组件库：shadcn/ui

# 然后直接用图片输入
> 根据设计稿生成组件 @design.png
# Codex 会自动遵循项目的设计系统
```

## 常见问题 Q&A

**Q1：图片中的代码文字识别准确吗？**

A：对截图中的代码识别效果很好（>95% 准确率），尤其是 IDE 截图和终端截图。但注意：如果文字很小或模糊，识别率会下降。建议截图时确保文字清晰可读。

**Q2：可以直接粘贴剪贴板中的截图吗？**

A：可以。在支持的终端中，`Ctrl+V` 直接粘贴截图。如果终端不支持，先保存为文件再通过路径引用。

**Q3：多模态会消耗更多 Token 吗？**

A：会。图片会被编码为 Token 消耗，一张图片大约消耗 85-170 Token（取决于分辨率和细节）。整体成本比纯文本高 10-30%，但节省了人工描述的时间。

**Q4：可以用视频作为输入吗？**

A：目前不支持视频输入。如果需要展示动态效果，可以截取关键帧（多张图片），或用文字描述动态行为。

## 小结

| 要点 | 说明 |
|------|------|
| 核心价值 | 用图片替代文字描述，更直观高效 |
| 最佳用法 | 图片 + 文本组合：图片提供视觉，文本提供上下文 |
| 适用场景 | UI Bug、设计稿、手绘草图、错误截图 |
| 限制 | 单张 20MB，单次 4 张，不支持视频 |
| 关键技巧 | 清晰图片 + 明确目标 + 项目上下文 |
