## 1. 斜杠命令总览

在 REPL 中输入 `/` 开头的命令可以控制 Codex 的行为，类似于终端的内置命令。

### 1.1 完整命令列表

| 命令 | 功能 | 常用度 |
|------|------|--------|
| `/help` | 显示帮助信息 | ⭐ |
| `/model` | 查看/切换模型 | ⭐⭐⭐ |
| `/approval` | 查看/切换审批模式 | ⭐⭐⭐ |
| `/clear` | 清除对话上下文 | ⭐⭐⭐ |
| `/compact` | 压缩上下文（节省 Token） | ⭐⭐⭐ |
| `/history` | 查看对话历史 | ⭐⭐ |
| `/undo` | 撤销上一次修改 | ⭐⭐⭐ |
| `/diff` | 查看当前所有未提交修改 | ⭐⭐ |
| `/status` | 查看当前状态（模型/模式/Token） | ⭐⭐ |
| `/exit` | 退出 REPL | ⭐⭐ |

## 2. 核心命令详解

### 2.1 /model — 模型管理

```
# 查看当前模型
> /model
当前模型: codex-1 (GPT-5-Codex)
上下文窗口: 128K tokens

# 切换模型（会话内即时生效）
> /model gpt-5.2-codex
模型已切换为: gpt-5.2-codex

# 列出可用模型
> /model list
  codex-1         GPT-5-Codex（默认，推荐，快）
  gpt-5.2-codex   GPT-5.2-Codex（更强，适合复杂任务）
  o3-codex        推理模型（适合算法和架构设计）
```

**何时切换模型？**

| 场景 | 推荐模型 | 原因 |
|------|---------|------|
| 日常开发 | codex-1 | 快速响应，成本低 |
| 复杂重构 | gpt-5.2-codex | 理解力强，重构更准确 |
| 调试疑难 Bug | gpt-5.2-codex | 需要深度分析 |
| 算法实现 | o3-codex | 推理能力强 |
| 快速小修改 | codex-1 | 不需要复杂推理 |

### 2.2 /compact — 上下文压缩

当对话越来越长时，Token 消耗会持续增长。`/compact` 可以压缩上下文：

```
> /compact
📊 上下文压缩报告：
  压缩前: 45,231 tokens
  压缩后: 12,456 tokens
  压缩率: 72%
  保留内容: 最近 5 轮对话 + 系统提示 + 工具定义
  丢弃内容: 早期对话的详细代码 + 重复的工具结果
```

**何时需要手动压缩？**

```
# 场景 1：长时间对话后
> 帮我重构整个认证模块
[10 轮对话后，上下文已经很长]
> /compact          ← 压缩旧对话，保留关键信息

# 场景 2：切换任务
> /clear            ← 清除所有上下文
> 现在帮我分析另一个模块的性能

# compact vs clear：
#   /compact  — 保留关键信息，压缩冗余（推荐）
#   /clear    — 完全清除，从零开始（切换话题时用）
```

### 2.3 /undo — 撤销修改

```
> 给 auth.ts 添加日志

📝 修改 src/auth.ts:
  + console.log('[auth] login attempt', email);
  + console.log('[auth] token refreshed', userId);

应用此修改？[y] > y
✅ 已修改 src/auth.ts

> /undo
✅ 已撤销对 src/auth.ts 的修改（恢复到修改前状态）

# /undo 可以连续使用
> /undo
✅ 已撤销上一次修改（如果有的话）

# 查看修改前的对比
> /diff
显示当前所有未提交的修改（包括尚未 undo 的）
```

### 2.4 /diff — 查看修改

```
> /diff

📝 未提交的修改：

src/api/users.ts:
  -  const users = await db.query('SELECT * FROM users');
  +  const users = await db.query('SELECT id, name, email FROM users');

src/api/auth.ts:
  +  console.log('[auth] login attempt', email);

tests/api/users.test.ts:
  +  it('should return user list with selected fields', async () => { ... });

共 3 个文件被修改
> 审查这些修改是否正确
```

### 2.5 /approval — 切换审批模式

```
# 查看当前模式
> /approval
当前审批模式: suggest（所有修改需手动确认）

# 切换模式
> /approval auto-edit
审批模式已切换为: auto-edit（自动编辑文件，命令需确认）

# 三种模式快速参考：
#   suggest    — 最安全：只显示建议，不做任何修改
#   auto-edit  — 平衡：自动修改文件，执行命令前确认
#   full-auto  — 最快：全自动，不做确认（谨慎使用）
```

## 3. 键盘快捷键

### 3.1 完整快捷键表

| 快捷键 | 功能 | 使用场景 |
|--------|------|---------|
| `Enter` | 发送消息 | 正常发送 |
| `Shift+Enter` | 换行（多行输入） | 粘贴代码或多行需求 |
| `Ctrl+C` | 取消当前操作 | 停止生成、取消等待 |
| `Ctrl+C` (两次) | 退出 REPL | 结束会话 |
| `Ctrl+D` | 退出 REPL | 结束会话 |
| `↑` / `↓` | 浏览历史输入 | 重复之前的命令 |
| `Tab` | 自动补全 | 补全文件名/命令 |
| `Ctrl+L` | 清屏 | 屏幕太乱时 |
| `Ctrl+R` | 搜索历史命令 | 找之前的命令 |
| `Esc` | 取消当前输入 | 重新开始输入 |

### 3.2 实用快捷键组合

```
场景 1：重复执行类似命令
  > 分析 src/api/users.ts 的安全性
  [修改完成]
  ↑ ↑ [找到之前的命令]
  修改为：分析 src/api/products.ts 的安全性
  Enter

场景 2：中断长时间生成
  > 重构整个项目结构...
  [生成时间太长]
  Ctrl+C  ← 中断，然后细化需求

场景 3：多行需求描述
  Shift+Enter → 第一行需求
  Shift+Enter → 第二行需求
  Shift+Enter → 第三行需求
  Enter → 发送
```

## 4. 高效工作流技巧

### 4.1 批量确认

```
> 重构所有 API 路由的错误处理

📝 修改 users.ts
  应用？[y/N/a(全部)/q(退出)] > a  ← 输入 a 全部应用
✅ users.ts 已修改
✅ auth.ts 已修改
✅ products.ts 已修改
✅ orders.ts 已修改

# 也可以用 q 退出批量操作
📝 修改 config.ts
  应用？[y/N/a(全部)/q(退出)] > q  ← 停止后续修改
⏹️ 已停止（已修改 3/4 个文件）
```

### 4.2 上下文管理策略

```
# 策略：一个会话一个主题
# 避免在一个会话中处理多个不相关的任务

会话 1：认证模块重构
> /clear
> 重构 auth 模块，将 session 改为 JWT
[完成]

会话 2：性能优化
> /clear
> 分析首页加载性能
[完成]

# 而不是：
> 重构 auth 模块
> 顺便帮我优化一下首页
> 还有个 Bug 要修
→ 上下文混乱，Codex 可能搞混不同任务
```

### 4.3 模型切换策略

```
# 开会话时用强模型，执行时切回标准模型

> /model gpt-5.2-codex      ← 用强模型做架构分析
> 分析这个项目的整体架构，给出重构建议

[获得详细的架构分析]

> /model codex-1             ← 切回标准模型执行
> 按照刚才的建议，先重构 users 模块

[快速执行具体重构任务]
```

## 5. 实践练习

### ⭐ 基础：命令熟悉

1. 启动 REPL，依次执行 `/help`、`/model`、`/approval`、`/status`
2. 使用 `/model list` 查看可用模型
3. 用 `Shift+Enter` 输入多行需求

### ⭐⭐ 进阶：高效工作流

1. 在一个会话中完成一个小功能（如添加日志）
2. 用 `/undo` 撤销，然后重新实现
3. 用 `/diff` 查看修改，用 `/compact` 压缩上下文
4. 测试批量确认（`a`）和退出（`q`）

## 小结

| 要点 | 说明 |
|------|------|
| 核心命令 | /model、/approval、/clear、/compact、/undo、/diff |
| 上下文管理 | /compact 压缩旧内容，/clear 完全重置 |
| 快捷键 | ↑↓历史、Tab补全、Shift+Enter多行 |
| 批量操作 | `a` 全部应用，`q` 停止 |
| 模型切换 | 分析用强模型，执行用标准模型 |
