## 1. REPL 是什么

### 1.1 REPL 的定义

REPL = **R**ead-**E**val-**P**rint **L**oop（读取-执行-打印-循环）

```
┌──────────────────────────────────────────────┐
│                  REPL 循环                     │
│                                               │
│   读取用户输入 ──→ LLM 推理 ──→ 工具调用       │
│        ↑                          ↓           │
│   打印结果 ←─── 格式化输出 ←─── 获取结果       │
│                                               │
│   直到用户退出或任务完成                        │
└──────────────────────────────────────────────┘
```

### 1.2 REPL vs 单次命令

```
# 单次命令模式（非交互）
$ codex "解释这个项目的技术栈"
# 输出结果后立即退出

# REPL 模式（交互式，推荐）
$ codex
# 进入交互界面，持续对话直到主动退出
# 优势：上下文保持、多轮对话、动态调整方向
```

## 2. 启动与退出

### 2.1 启动 REPL

```bash
# 在项目目录下启动（推荐，Codex 能看到项目代码）
cd my-project
codex

# 启动后显示欢迎信息
# ╭──────────────────────────────────╮
# │  Codex CLI v1.0.0                │
# │  Model: codex-1                  │
# │  Approval: suggest               │
# │  Sandbox: enabled                │
# │  Project: /path/to/my-project    │
# ╰──────────────────────────────────╯
# >
```

### 2.2 启动参数

```bash
# 指定模型
codex --model gpt-5.2-codex

# 指定审批模式
codex --suggest         # 建议模式（默认）
codex --auto-edit       # 自动编辑模式
codex --full-auto       # 全自动模式

# 指定初始提示
codex "帮我分析这个项目的安全性"
# 会自动进入 REPL，预填第一条消息

# 组合使用
codex --model gpt-5.2-codex --auto-edit
```

### 2.3 退出 REPL

```
# 方式一：斜杠命令
> /exit

# 方式二：快捷键
Ctrl + C（按两次）
Ctrl + D

# 退出前会显示本次会话统计：
# 📊 会话统计：
#   对话轮次：12
#   文件修改：3
#   命令执行：5
#   Token 消耗：45,231
```

## 3. 第一次交互：完整循环

### 3.1 简单提问

```
> 这个项目用的是什么技术栈？

🔍 正在分析项目结构...
   📖 读取 package.json
   📖 读取 tsconfig.json
   📖 读取 next.config.js

这个项目使用以下技术栈：
- 语言：TypeScript 5.3
- 框架：Next.js 14（App Router）
- 样式：Tailwind CSS 3.4
- 数据库：Prisma + PostgreSQL
- 测试：Vitest + Playwright
- 包管理：pnpm
```

### 3.2 代码修改请求

```
> 给 auth.ts 添加 JWT 过期检查

📖 读取 src/auth.ts...
📝 分析代码结构，定位认证逻辑...

建议修改 src/auth.ts：

--- a/src/auth.ts
+++ b/src/auth.ts
@@ -40,6 +40,12 @@
   const token = headers.get('Authorization');
+  if (!token) return unauthorized();
+
+  const decoded = jwt.verify(token, SECRET);
+  if (decoded.exp < Date.now() / 1000) {
+    return Response.json({ error: 'Token expired' }, { status: 401 });
+  }

是否应用此修改？[y/N] > y
✅ 已应用修改到 src/auth.ts
```

### 3.3 Agent Loop 内部过程

```
用户输入："给 auth.ts 添加 JWT 过期检查"

Codex 内部循环：
  第 1 轮：LLM 推理
    → 决定：需要先读取 auth.ts 的内容
    → 调用工具：read_file("src/auth.ts")

  第 2 轮：LLM 推理
    → 分析：当前代码没有过期检查
    → 决定：在第 40 行后添加过期检查逻辑
    → 输出：diff 补丁 + 解释

  第 3 轮：用户确认
    → 用户输入 y
    → 应用修改

  循环结束（stop_reason = "end_turn"）
```

## 4. 多轮对话

### 4.1 上下文保持

REPL 模式下，Codex 会保持完整对话历史，后续指令可以引用前面的内容：

```
> 给 auth.ts 添加 JWT 过期检查           # 第 1 轮
[修改完成]

> 现在给对应的测试文件也补上测试          # 第 2 轮
# Codex 知道"对应的"是 auth.test.ts
# 因为上下文记住了第 1 轮操作的文件

> 顺便看看还有没有其他安全漏洞            # 第 3 轮
# Codex 记得前面做了什么，能检查整体安全性
```

### 4.2 上下文管理

```
# 场景 1：对话太长，Token 消耗增长
> /compact
📊 上下文已压缩：45,231 → 12,456 tokens

# 场景 2：完全切换话题
> /clear
📊 上下文已清除

# 场景 3：撤销错误的修改
> /undo
✅ 已撤销上次修改

# 最佳实践：
#   - 一个会话处理一个主题
#   - 话题切换时用 /clear
#   - 长对话定期 /compact
```

## 5. 工具调用观察

### 5.1 图标含义

| 图标 | 含义 | 说明 |
|------|------|------|
| 📖 | 读取文件 | Codex 在查看代码 |
| 📝 | 修改文件 | Codex 准备修改代码 |
| 🔧 | 执行命令 | Codex 在运行命令 |
| 🔍 | 搜索代码 | Codex 在搜索项目 |
| ✅ | 操作完成 | 工具调用成功 |
| ❌ | 操作失败 | 工具调用失败或被拒绝 |
| ⏳ | 等待确认 | 等待用户确认操作 |

### 5.2 观察工具调用的意义

```
为什么要观察？

1. 了解 Codex 在做什么
   📖 读取 5 个文件 → 可能要做大规模修改
   🔧 执行 rm -rf → 危险！应该拒绝

2. 判断推理质量
   📖 只读了 1 个文件就修改 → 可能不够全面
   📖 读了 5 个相关文件 → 分析更全面

3. 学习项目结构
   Codex 读取的文件路径就是项目的关键文件
   你可以从中了解项目架构
```

## 6. 高效使用 REPL 的技巧

### 6.1 输入技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| 具体描述 | 告诉 Codex 文件名、行号、函数名 | "修改 src/auth.ts 的 verify 函数" |
| 提供上下文 | 说明为什么需要这个修改 | "因为 JWT 可能过期，需要添加检查" |
| 分步执行 | 复杂任务拆成多步 | "先分析，再修改，最后测试" |
| 引用前面 | 多轮对话利用上下文 | "按照刚才的分析，开始修改" |

### 6.2 常见交互模式

```
模式 1：探索式
> 这个文件做什么的？
> 这个函数的参数是什么意思？
> 数据库表之间什么关系？

模式 2：指令式
> 给 X 添加 Y 功能
> 修复这个 Bug：[描述]
> 重构 X 使用 Y 模式

模式 3：迭代式
> 先写一个简单版本
> 现在加上错误处理
> 再添加单元测试
> 最后优化性能
```

## 7. 实践练习

### ⭐ 基础：REPL 入门

1. 启动 REPL，输入 "分析这个项目的结构"
2. 观察工具调用过程（📖📖📝）
3. 使用 `/status` 查看当前状态

### ⭐⭐ 进阶：多轮对话

1. 让 Codex 分析一个文件的代码质量
2. 在第 2 轮要求修复发现的问题
3. 在第 3 轮运行测试验证修复
4. 用 `/compact` 压缩上下文

## 小结

| 要点 | 说明 |
|------|------|
| REPL 循环 | 读取→推理→工具调用→确认→循环 |
| 启动 | `codex`，可带 `--model`、`--suggest` 等参数 |
| 多轮对话 | 上下文保持，后续可引用前面的结果 |
| 上下文管理 | `/compact` 压缩，`/clear` 重置 |
| 观察工具调用 | 理解 Codex 的推理过程和行为 |
