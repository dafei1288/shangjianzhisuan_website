# Ch02：安装与认证

## 学习目标

- 准备 Node.js 22+ 运行环境
- 完成 Codex CLI 的安装
- 掌握两种认证方式（ChatGPT 账号 vs API Key）
- 解决 Windows/macOS/Linux 下的常见安装问题

---

## 1. 环境准备

### 1.1 Node.js 安装

Codex CLI 需要 Node.js 22 或更高版本：

```bash
# 检查 Node.js 版本
node --version
# 需要 v22.0.0+

# macOS（推荐使用 nvm）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.0/install.sh | bash
nvm install 22
nvm use 22

# Linux（同 nvm）
nvm install 22

# Windows（推荐使用 nvm-windows）
# 下载 https://github.com/coreybutler/nvm-windows/releases
nvm install 22
nvm use 22

# 或使用 fnm（跨平台，更快）
fnm install 22
fnm use 22
```

### 1.2 npm 全局目录确认

```bash
# 确认 npm 全局路径
npm config get prefix

# 如果权限问题，可以设置用户级全局目录
mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
export PATH=~/.npm-global/bin:$PATH
```

## 2. 安装 Codex CLI

```bash
# 全局安装
npm i -g @openai/codex

# 验证安装
codex --version
# 输出类似：codex/1.0.0

# 查看帮助
codex --help
```

安装完成后，`codex` 命令即可在终端中使用。

## 3. 认证方式

Codex CLI 支持两种认证方式：

### 3.1 ChatGPT 账号认证（推荐新手）

```bash
# 登录 ChatGPT 账号
codex login

# 浏览器会自动打开 OpenAI 登录页面
# 登录成功后终端显示：
# ✅ Logged in as your-email@example.com
```

**优点**：
- 无需付费 API Key
- 使用 ChatGPT Plus/Pro 订阅额度
- 最简单的入门方式

**限制**：
- 有速率限制（与 ChatGPT 网页版共享）
- 不适合 CI/CD 自动化场景

### 3.2 API Key 认证（推荐开发者）

```bash
# 设置环境变量
export OPENAI_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"

# 或写入 shell 配置文件（持久化）
echo 'export OPENAI_API_KEY="sk-xxxxxxxx"' >> ~/.bashrc
source ~/.bashrc
```

**获取 API Key**：
1. 访问 https://platform.openai.com/api-keys
2. 点击「Create new secret key」
3. 复制 Key（仅显示一次）

**优点**：
- 无速率限制（按用量付费）
- 适合 CI/CD 自动化
- 可精确控制成本

### 3.3 两种认证方式怎么选

很多初学者会把“能登录”理解成“配置完成”，但在真实使用里，认证方式其实直接决定了后续工作流能不能稳定运行。

可以用下面这个判断方式：

| 场景 | 更适合的认证方式 | 原因 |
|------|------|------|
| 个人学习、课堂演示 | ChatGPT 账号认证 | 上手最快，不需要单独管理 Key |
| 本地日常开发 | ChatGPT 账号认证 或 API Key | 取决于你更重视省事还是额度控制 |
| 团队共享环境 | API Key | 便于统一配置和权限隔离 |
| CI/CD、脚本自动化 | API Key | 无法依赖浏览器登录态 |
| 成本审计要求明确 | API Key | 更容易按项目或环境拆分计费 |

要点不是“哪种更高级”，而是哪种更匹配你的运行环境。对新手来说，先用 ChatGPT 账号走通流程；一旦进入自动化、多人协作或成本管理场景，就应该切到 API Key。

## 4. 首次运行

```bash
# 启动交互式 REPL
codex

# 首次启动会显示：
# ╭──────────────────────────────────╮
# │  Codex CLI v1.0.0                │
# │  Model: codex-1 (GPT-5-Codex)    │
# │  Approval: suggest               │
# ╰──────────────────────────────────╯
# 
# ❯ 输入你的第一个问题...

# 试试看
> 你好，请介绍一下你自己
```

### 4.1 非交互式执行

```bash
# 单次任务执行
codex exec "在当前目录创建一个 hello.py，输出 Hello World"

# 查看执行结果
cat hello.py
```

### 4.2 安装是否真的成功：验收清单

很多同学执行完 `npm i -g @openai/codex` 就以为结束了，但真正的“安装完成”至少要满足下面 4 项：

1. `node --version` 能稳定返回 `v22+`
2. `codex --version` 能返回版本号，而不是“command not found”
3. `codex` 启动后能进入交互界面，而不是认证或权限报错
4. `codex exec "..."` 能成功执行一次最小任务

如果只满足前两项，说明只是“命令装上了”；只有四项都通过，才说明你的运行环境、认证状态和执行链路都打通了。

## 5. 平台差异与常见问题

### 5.1 macOS

```bash
# 如果遇到权限问题
sudo chown -R $(whoami) ~/.npm

# 如果遇到沙箱问题（Seatbelt）
# 确保 macOS 版本 >= 12.0（Monterey）
sw_vers
```

### 5.2 Linux

```bash
# 安装沙箱依赖（Bubblewrap）
# Ubuntu/Debian
sudo apt install bubblewrap

# Fedora
sudo dnf install bubblewrap

# Arch
sudo pacman -S bubblewrap
```

### 5.3 Windows

```bash
# 推荐使用 WSL2
wsl --install

# 进入 WSL
wsl

# 在 WSL 中正常安装
npm i -g @openai/codex
```

### 5.4 常见错误排查

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `node: command not found` | Node.js 未安装或不在 PATH | 安装 Node.js 22+ |
| `EACCES permission denied` | npm 全局目录权限不足 | `sudo chown -R $(whoami) ~/.npm` |
| `Authentication failed` | API Key 无效或过期 | 重新生成 Key |
| `Model not found` | 模型名称错误 | 检查 config.toml 中的 model 字段 |
| `Sandbox error` | 沙箱依赖缺失 | Linux 安装 bubblewrap |

## 7. 动手练习

### ⭐ 基础：完成最小可运行环境

1. 安装 Node.js 22+
2. 安装 `@openai/codex`
3. 选择一种认证方式完成登录
4. 运行 `codex --version`、`codex`、`codex exec "创建 hello.txt"` 三个命令

验收标准：
- 三个命令都能成功执行
- 当前目录中成功生成目标文件
- 你能说清楚自己使用的是哪种认证方式

### ⭐⭐ 进阶：对比两种认证方式

1. 分别记录 ChatGPT 账号认证和 API Key 认证的配置步骤
2. 写出两者在“适用场景、成本控制、自动化支持”上的差异
3. 判断你当前项目后续更适合哪一种

验收标准：
- 至少给出 3 项对比结论
- 结论能对应你的真实使用场景，而不是只抄优缺点

### ⭐⭐⭐ 挑战：做一次安装排障演练

1. 故意制造一个安装问题，例如切换错误 Node 版本或移除 PATH
2. 记录错误现象
3. 按本章排查思路恢复环境
4. 写出“问题原因 - 排查步骤 - 修复结果”

验收标准：
- 不是只写“重装成功”，而是能复盘问题链路
- 最终重新通过本章 4 项安装验收清单

## 常见问题 Q&A

**Q1：为什么课程一开始就强调 Node.js 版本，而不是先讲 Codex 命令？**

A：因为 Codex CLI 本质上是跑在 Node 运行时上的。只要运行时不稳定，后面所有“命令不会用”“认证失败”“包安装报错”都可能只是表象，所以先把底座打稳更专业。

**Q2：我本地能 `codex login`，是不是就说明以后 CI/CD 也能直接用？**

A：不是。浏览器登录态适合人交互，不适合无人值守环境。只要场景里没有人能手动登录，通常就应该改用 API Key。

**Q3：Windows 为什么推荐 WSL，而不是直接在原生 PowerShell 里完成全部操作？**

A：不是因为原生 Windows 一定不能用，而是很多开发链路、路径习惯和沙箱相关行为在类 Unix 环境里更稳定。课程里推荐 WSL，本质是在降低环境差异带来的教学噪音。

**Q4：安装成功但第一次执行很慢，是不是哪里配置错了？**

A：不一定。首次执行可能会遇到登录态初始化、包缓存、网络请求或环境检查，通常会比后续慢。先看是否能稳定完成一次任务，再判断是不是性能问题。

## 小结

- Node.js 22+ 是唯一前置依赖
- `npm i -g @openai/codex` 一行命令安装
- 两种认证：ChatGPT 账号（简单）和 API Key（灵活）
- Windows 用户推荐 WSL2
- 遇到问题先检查 Node.js 版本和权限
