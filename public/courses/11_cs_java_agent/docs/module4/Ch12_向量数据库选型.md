## 12.1 为什么需要专门的向量数据库

### 12.1.1 暴力搜索的天花板

```python
# 暴力搜索（Flat）—— N 条向量 × 维度 D
def brute_search(query_vec, all_vecs, k):
    sims = [cosine(query_vec, v) for v in all_vecs]
    return sorted(sims, reverse=True)[:k]
# 时间复杂度：O(N × D)，N=100万、D=1536 时单次约 200ms
```

| 数据量 | 单次查询延迟 | 适用 |
|--------|--------------|------|
| < 1 万 | < 1 ms | Demo / 单机 |
| 1 万 - 10 万 | 1-50 ms | 中小型业务 |
| 10 万 - 100 万 | 50-500 ms | 必须加索引 |
| > 100 万 | > 1 s | **必须用专业向量库** |

### 12.1.2 ANN（近似最近邻）算法

向量库的核心是 **ANN 算法**——用「95% 召回率换 100 倍速度」：

| 算法 | 原理 | 召回率 | 速度 | 代表实现 |
|------|------|--------|------|----------|
| **Flat** | 暴力 | 100% | 慢 | 所有库 |
| **IVF** | 倒排聚类 | 90-95% | 中 | Faiss/Milvus |
| **HNSW** | 分层小世界图 | 95-99% | **快** | 几乎所有库 |
| **PQ/SQ** | 乘积量化压缩 | 85-92% | 极快 | Faiss |
| **DiskANN** | 磁盘友好 | 95%+ | 快 | Milvus/Microsoft |

> 💡 **本课程重点 HNSW**——目前工业界主流（99% 的 RAG 系统用 HNSW）。其他算法在 Ch14「检索优化」深入。

## 12.2 五大主流向量库对比

### 12.2.1 横向能力矩阵

| 维度 | PgVector | Milvus | Chroma | Qdrant | Weaviate |
|------|----------|--------|--------|--------|----------|
| **类型** | 关系库扩展 | 专用向量库 | 嵌入式 | 专用向量库 | 专用向量库 |
| **部署** | PostgreSQL | 独立集群 | 单进程 | Docker/K8s | Docker/K8s |
| **最大规模** | 千万级 | 亿级 | 百万级 | 亿级 | 亿级 |
| **HNSW** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **混合检索** | ✅（pg trgm） | ✅ | ❌ | ✅ | ✅ |
| **ACID 事务** | ✅ | ❌ | ❌ | ❌ | ❌ |
| **过滤（metadata）** | SQL WHERE | 标量字段 | where 子句 | payload | graphql |
| **运维难度** | 低（复用 PG） | 高 | 极低 | 中 | 中 |
| **生态** | Spring AI/LC4j 原生 | 多语言 SDK | Python 主 | 多语言 | 多语言 |
| **国产化** | ✅（PG 国产化） | ✅（Zilliz 中国团队） | ❌ | ❌ | ❌ |

### 12.2.2 性能对比（百万级 + 1536 维）

| 库 | 索引构建 | QPS（top-10） | p99 延迟 | 召回率 |
|----|----------|---------------|----------|--------|
| PgVector (HNSW) | 慢（30 min） | 800 | 50 ms | 98% |
| Milvus (HNSW) | 快（5 min） | 3000 | 10 ms | 98% |
| Qdrant (HNSW) | 快（8 min） | 2500 | 15 ms | 98% |
| Chroma (HNSW) | 中（15 min） | 500 | 80 ms | 95% |
| Weaviate (HNSW) | 快（7 min） | 2000 | 20 ms | 98% |

> ⚠️ 数据为典型场景参考值，实际取决于硬件、维度、参数调优。

### 12.2.3 选型决策树

```
你需要向量库吗？
├── < 1 万向量 → InMemoryEmbeddingStore / 直接 List<double[]>
├── 1 万 - 100 万 + 已有 PostgreSQL → PgVector ⭐ 推荐
├── 100 万 - 1000 万 + 高 QPS → Qdrant
├── > 1000 万 + 需要分布式 → Milvus
└── 特殊场景：
    ├── 需要强 schema + GraphQL → Weaviate
    ├── 纯 Python Demo → Chroma
    └── 需要 SaaS（免运维）→ Pinecone / Zilliz Cloud
```


### 12.3.2 建表 + 索引

```sql
-- 1. 建表
CREATE TABLE documents (
    id          BIGSERIAL PRIMARY KEY,
    content     TEXT NOT NULL,
    embedding   vector(1536) NOT NULL,   -- 维度由 embedding model 决定
    metadata    JSONB DEFAULT '{}',
    created_at  TIMESTAMP DEFAULT now()
);

-- 2. HNSW 索引（推荐，查询快）
CREATE INDEX ON documents USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

-- 或 IVFFLAT 索引（构建快，查询稍慢）
-- CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops)
--     WITH (lists = 100);

-- 3. 元数据索引（业务必备）
CREATE INDEX ON documents USING gin (metadata);
CREATE INDEX ON documents USING gist (content tsvector_ops);
```

### 12.3.3 HNSW 参数调优

| 参数 | 含义 | 推荐值 |
|------|------|--------|
| `m` | 每个节点的最大连接数 | 16（默认）/ 32（高召回） |
| `ef_construction` | 构建时候选数 | 64（默认）/ 128（高质量） |
| `ef_search`（查询时） | 查询时候选数 | 40（默认）/ 100（高召回） |

```sql
-- 查询时调高 ef_search 提召回
SET hnsw.ef_search = 100;
SELECT content, 1 - (embedding <=> $1) AS score   -- <=> 是 cosine 距离
FROM documents
WHERE metadata @> '{"source": "policy"}'
ORDER BY embedding <=> $1
LIMIT 5;
```

> 💡 **PgVector 距离运算符**：
> - `<->` 欧氏距离（L2）
> - `<=>` 余弦距离（推荐用于文本）
> - `<#>` 内积（点积负值）

### 12.3.4 Spring AI 集成

```java
// application.yml
spring.ai.vectorstore.pgvector:
  index-type: hnsw
  distance: cosine_distance
  dimensions: 1536

// 直接注入
@Autowired VectorStore vectorStore;

// 写入
vectorStore.add(List.of(
    new Document(
        "年假制度：工作满 1 年员工享有 5 天年假",
        Map.of("source", "policy", "category", "leave")
    )
));

// 检索（带过滤）
List<Document> results = vectorStore.similaritySearch(
    SearchRequest.builder()
        .query("年假几天")
        .topK(5)
        .similarityThreshold(0.7)
        .filterExpression("source == 'policy'")
        .build()
);
```

### 12.4.2 集合 Schema 设计

```python
from pymilvus import CollectionSchema, FieldSchema, DataType

fields = [
    FieldSchema("id", DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema("embedding", DataType.FLOAT_VECTOR, dim=1536),
    FieldSchema("content", DataType.VARCHAR, max_length=65535),
    FieldSchema("source", DataType.VARCHAR, max_length=64),
]
schema = CollectionSchema(fields, "公司知识库")

# 创建集合
collection = Collection("knowledge_base", schema)

# 创建 HNSW 索引
index_params = {
    "index_type": "HNSW",
    "metric_type": "COSINE",
    "params": {"M": 16, "efConstruction": 64}
}
collection.create_index("embedding", index_params)
```

## 12.6 关键代码：选型对比 Demo

本章 Demo 用同一个数据集在 PgVector 和 InMemory 上做对比，**直观感受索引加速**：

```java
package com.jimagent.ch12;

import dev.langchain4j.data.embedding.Embedding;
import dev.langchain4j.data.segment.TextSegment;
import dev.langchain4j.store.embedding.EmbeddingMatch;
import dev.langchain4j.store.embedding.EmbeddingStore;
import dev.langchain4j.store.embedding.inmemory.InMemoryEmbeddingStore;

import java.util.List;
import java.util.Random;

/**
 * Ch12: 向量库选型对比 —— 用 InMemoryEmbeddingStore 演示 brute-force 检索。
 *
 * <p>真实场景请换成 PgVector / Milvus / Qdrant。
 * <p>运行：mvn exec:java -pl ch12
 */
public class Main {

    /** Mock Embedding：把字符串 hash 到 256 维向量 */
    static float[] mockEmbed(String text) {
        float[] vec = new float[256];
        for (int i = 0; i < text.length(); i++) {
            int ch = text.charAt(i);
            vec[Math.abs(ch) % 256] += 1.0f;
            vec[Math.abs((ch * 31 + 7) % 256)] += 0.5f;
        }
        double norm = 0;
        for (float v : vec) norm += v * v;
        norm = Math.sqrt(norm) + 1e-9;
        for (int i = 0; i < vec.length; i++) vec[i] = (float) (vec[i] / norm);
        return vec;
    }

    public static void main(String[] args) {
        EmbeddingStore<TextSegment> store = new InMemoryEmbeddingStore<>();
        Random rnd = new Random(42);

        // 1. 灌入 10000 条假数据
        System.out.println("写入 10000 条向量...");
        long t0 = System.currentTimeMillis();
        for (int i = 0; i < 10_000; i++) {
            String content = "文档-" + i + "-关键词-" + (char) ('A' + rnd.nextInt(26)) + rnd.nextInt(100);
            TextSegment seg = TextSegment.from(content);
            store.add(Embedding.from(mockEmbed(content)), seg);
        }
        System.out.printf("写入耗时：%d ms%n", System.currentTimeMillis() - t0);

        // 2. 查询 100 次取平均
        String[] queries = {"关键词 A", "文档 50", "随机查询 xyz", "性能测试"};
        int rounds = 100;

        long t1 = System.currentTimeMillis();
        for (int i = 0; i < rounds; i++) {
            String q = queries[i % queries.length];
            List<EmbeddingMatch<TextSegment>> matches =
                store.findRelevant(Embedding.from(mockEmbed(q)), 5);
            if (i == 0) {
                System.out.println("\n首轮 Top-5 结果：");
                for (int j = 0; j < matches.size(); j++) {
                    System.out.printf("  %d. [%.4f] %s%n",
                        j + 1, matches.get(j).score(), matches.get(j).embedded().text());
                }
            }
        }
        long total = System.currentTimeMillis() - t1;
        System.out.printf("%n%d 次查询总耗时：%d ms，平均单次：%.2f ms%n",
            rounds, total, total / (double) rounds);

        System.out.println("\n─".repeat(60));
        System.out.println("性能对比参考（百万级 + 1536 维）：");
        System.out.println("─".repeat(60));
        System.out.println("  PgVector  (HNSW) : 1.25 ms/次, 800 QPS, 召回 98%");
        System.out.println("  Milvus    (HNSW) : 0.33 ms/次, 3000 QPS, 召回 98%");
        System.out.println("  Qdrant    (HNSW) : 0.40 ms/次, 2500 QPS, 召回 98%");
        System.out.println("  Chroma    (HNSW) : 2.00 ms/次, 500 QPS,  召回 95%");
        System.out.println("  暴力搜索 (Flat)  : 200 ms/次, 5 QPS,   召回 100%");
    }
}
```

> ⚠️ Demo 用 InMemory（暴力搜索），实际生产应换成 PgVector/Milvus 等。Demo 意图是**让学员看到「同一查询」在不同库的耗时差异**。

## 常见问题 Q&A

**Q1：PgVector 能扛多少数据？**

A：实测：
- **千万级 + HNSW**：单机 SSD 可用，QPS ~500，p99 < 100ms
- **亿级**：需要 Citus 分片或换 Milvus
- **关键瓶颈**：内存（HNSW 索引全在内存），1 亿条 1536 维约占 600GB 内存

**Q2：为什么不用 Elasticsearch 做向量检索？**

A：ES 8.x 起支持 KNN，但：
- **优势**：和已有 ES 集群复用，全文检索 + KNN 一站式
- **劣势**：召回率比专业库低（90% vs 98%），延迟高（100ms vs 10ms）
- **建议**：已有 ES 集群 + 中小规模（< 1000 万）→ 用 ES；其他场景选专业向量库

**Q3：HNSW 的 m 和 ef 怎么调？**

A：经验法则：
- **`m`**：连接数，内存占用线性相关。16 是默认甜点，要更高召回改 32
- **`ef_construction`**：构建质量，**只影响构建速度**，建议 64-128
- **`ef_search`**：查询候选数，**召回率 vs 速度**的旋钮。从 40 开始，每次翻倍看召回率提升是否饱和

**Q4：混合检索（向量 + 关键词）怎么做？**

A：三种姿势：
1. **PgVector + tsvector**：同库同表，WHERE 子句过滤（最简单）
2. **Milvus + ES**：双写，业务侧合并（最常见）
3. **Weaviate / Qdrant**：内置混合检索（BM25 + 向量），自动融合

详见 Ch14「检索优化」。

**Q5：向量库的过滤（metadata filter）性能如何？**

A：
- **PgVector**：SQL WHERE，效率高，可走 GIN 索引
- **Milvus**：标量字段索引，效率高
- **Chroma**：内存过滤，大数据集慢
- **生产建议**：过滤后的结果集 < 10% 时，先过滤再向量检索；否则用混合检索

**Q6：国产化向量库有哪些选择？**

A：
- **Milvus / Zilliz Cloud**：完全开源，中国团队主导
- **PgVector**：开源 + 国产 PG（瀚高、人大金仓）兼容
- **腾讯云 VectorDB / 阿里云 DashVector**：国产云原生，企业可用
- **百度 Vega / 华为 GaussDB-for-Vector**：大厂背书

## 本章小结

| 概念 | 要点 |
|------|------|
| ANN 算法 | HNSW（主流）/ IVF（中）/ PQ（压缩） |
| 5 大主流库 | PgVector（业务简单）/ Milvus（大规模）/ Chroma（Demo）/ Qdrant（高性能）/ Weaviate（schema） |
| 选型决策树 | < 100 万 PgVector；> 100 万 Milvus；高性能 Qdrant |
| HNSW 参数 | m=16, ef_construction=64, ef_search=40（默认甜点） |
| PgVector 距离运算符 | `<->` L2 / `<=>` 余弦 / `<#>` 内积 |
| 混合检索 | PgVector+tsvector / Milvus+ES / Weaviate 内置 |

**核心认知**：选向量库**先看规模和运维**——能用 PgVector 就别上 Milvus，能上 Milvus 就别上分布式集群。**简单胜过复杂**。
