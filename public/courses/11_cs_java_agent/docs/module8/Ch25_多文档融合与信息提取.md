## 1. 研报项目的特殊性

不同于合同审查（单一文档），研报项目的输入是**多源异构**：

```
输入：
- 5 份行业报告 PDF（机构出品，权威但慢）
- 3 份公司财报（Excel + PDF）
- 10 篇新闻（HTML 爬虫）
- 行业数据库 API（JSON）
- 历史研报（内部积累）

输出：
- 一份 3000-5000 字的综合研报
- 含 5-10 个图表
- 含引用列表
```

**核心挑战**：如何把**几十万字的多源资料**压缩成**几千字的可信研报**。

## 2. 多文档加载策略

### 2.1 统一抽象

```java
interface DocumentLoader {
    List<Document> load(Source source) throws Exception;
}

record Source(String type, String uri, Map<String, String> metadata) {}
record Document(String id, String content, Map<String, String> metadata) {}
```

### 2.2 各类型实现

```java
class PdfLoader implements DocumentLoader {
    public List<Document> load(Source s) {
        String text = new Tika().parseToString(new File(s.uri()));
        return List.of(new Document(s.uri(), text, s.metadata()));
    }
}

class ExcelLoader implements DocumentLoader {
    public List<Document> load(Source s) {
        // 每个表作为一个 Document
        try (Workbook wb = WorkbookFactory.create(new File(s.uri()))) {
            return wb.spliterator().stream()
                .map(sheet -> toDocument(s, sheet))
                .toList();
        }
    }
}

class HtmlLoader implements DocumentLoader {
    public List<Document> load(Source s) {
        Document doc = Jsoup.connect(s.uri()).get();
        // 去广告 / 去导航 / 抽正文
        String main = doc.select("article, .content, .article-body").text();
        return List.of(new Document(s.uri(), main, s.metadata()));
    }
}

class ApiLoader implements DocumentLoader {
    public List<Document> load(Source s) {
        String json = httpClient.send(s.uri());
        Object data = new ObjectMapper().readValue(json, Object.class);
        return List.of(new Document(s.uri(), data.toString(), s.metadata()));
    }
}
```

### 2.3 元数据规范

每个文档必须带元数据：

```java
metadata.put("source_type", "industry_report");   // 来源类型
metadata.put("publish_date", "2024-12-01");       // 发布日期
metadata.put("author", "ABC 研究院");              // 作者
metadata.put("credibility", "high");              // 可信度
metadata.put("category", "industry/tech");        // 分类
```

**关键**：后续的「引用溯源」「时效性判断」全靠元数据。

## 3. 信息抽取

### 3.1 三种抽取模式

| 模式 | 用法 | 示例 |
|------|------|------|
| **规则抽取** | 正则 / 关键词 | "营收 ¥1.2 亿" |


## 4. 三大融合问题

### 4.1 去重

同一事实可能出现在多份文档：

```
doc-001: "苹果 2024 营收 3910 亿美元"
doc-002: "Apple 2024 年营收 3910 亿美金"
doc-003: "苹果公司去年营收 3910 亿美元"
```

**解法**：

```java
class Deduplicator {
    List<Fact> dedupe(List<Fact> facts) {
        // 1. 同一字段名 + 同一周期 + 数值接近 → 视为重复
        Map<String, Fact> unique = new HashMap<>();
        for (Fact f : facts) {
            String key = f.name() + "|" + f.period() + "|" + roundValue(f.value());
            if (!unique.containsKey(key) || higherCredibility(f, unique.get(key))) {
                unique.put(key, f);
            }
        }
        return new ArrayList<>(unique.values());
    }
}
```

**保留高可信度来源**：行业报告 > 公司公告 > 新闻 > 社交媒体。

### 4.2 冲突

```
doc-001: "市场份额 35%"
doc-002: "市场份额 28%"
```

**解法**：

```java
class ConflictResolver {
    Fact resolve(List<Fact> conflicting) {
        // 1. 按 credibility 排序
        conflicting.sort(Comparator.comparing(Fact::credibility).reversed());
        // 2. 取最高可信度的，标注其他冲突源
        Fact primary = conflicting.get(0);
        return new Fact(primary.value(), primary.unit(), primary.period(),
            "conflict:" + conflicting.stream().map(Fact::sourceId).toList());
    }
}
```

**研报里常见做法**：保留主要数字 + 引用其他来源作为「另一说」。

### 4.3 时效性

```
doc-001 (2022): "市场规模 100 亿"
doc-002 (2024): "市场规模 150 亿"
```

**解法**：保留最新，旧数据放在「历史趋势」里。

```java
class FreshnessFilter {
    Fact filter(List<Fact> sameField) {
        return sameField.stream()
            .max(Comparator.comparing(Fact::publishDate))
            .orElseThrow();
    }
}
```

## 5. LangGraph4j 编排抽取流程

### 5.1 图设计

```
START → load → extract → dedupe → resolve_conflict → filter_fresh → END
                                              ↓
                                       (失败 fallback)
                                              ↓
                                            manual_review
```

### 5.2 关键节点

```java
var graph = new StateGraph<>(ExtractState.SCHEMA, ExtractState::new)
    .addNode("load", node_async(this::loadDocs))
    .addNode("extract", node_async(this::extractFacts))
    .addNode("dedupe", node_async(this::dedupeFacts))
    .addNode("resolve", node_async(this::resolveConflicts))
    .addNode("filter", node_async(this::filterFresh))
    .addNode("manual_review", node_async(this::flagForManual))
    .addEdge(START, "load")
    .addEdge("load", "extract")
    .addEdge("extract", "dedupe")
    .addEdge("dedupe", "resolve")
    .addConditionalEdges("resolve",
        edge_async(s -> s.hasHighConflict() ? "review" : "ok"),
        Map.of("review", "manual_review", "ok", "filter"))
    .addEdge("manual_review", "filter")
    .addEdge("filter", END);
```

### 5.3 优势

- **可观测**：每个节点输出可追溯
- **可恢复**：失败节点能重试
- **可干预**：高冲突场景 HITL 人工 review

## 常见问题 Q&A

**Q1：LLM 抽取不准怎么办？**

- **加 Few-shot**：给 LLM 看 5 个标注示例
- **分批抽取**：一次只抽一类字段（先抽财务，再抽市场）
- **二次校验**：抽完后让另一个 LLM 验证

**Q2：怎么避免幻觉？**

- Prompt 里强制「找不到填 null」
- 抽取后做 source_id 反查：如果数字找不到原文，剔除
- 用 RAG 而非 LLM 知识：所有事实必须从给定资料里抽

**Q3：Excel 数据怎么抽取？**

Excel 不是文本，要先**转结构化**（每行一个 record），再把每个 record 视为一个 "fact"。LLM 处理 Excel 数据要先转 Markdown 表格。

**Q4：API 数据怎么算"可信度"？**

按 API 提供方：官方数据（统计局 / 交易所）= 1.0；商业 API（Wind / 同花顺）= 0.9；第三方爬虫 = 0.5。

## 本章小结

| 能力 | 实现 |
|------|------|
| **加载** | 统一 DocumentLoader 抽象 + 元数据 |
| **抽取** | 规则 + NER + LLM 三种模式 |
| **去重** | name + period + value 三元组哈希 |
| **冲突** | credibility 排序，保留高可信度 |
| **时效** | 按 publish_date 取最新 |
| **编排** | LangGraph4j 状态图 |

**核心洞察**：多文档融合的难点在**「数据治理」**而不是算法。把可信度 / 时效性 / 冲突解决机制设计好，研报就有了基础。
