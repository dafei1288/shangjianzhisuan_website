## 1. 从数据到洞察的三层

```
原始数据 → 统计分析 → 洞察文案
  ↓           ↓           ↓
[1.2, 1.5,   环比 +25%   "营收连续 3 个季度增长，
 1.8, 2.2]   同比 +30%    Q3 突破 2 亿，主要受 A
                         业务驱动"
```

研报的核心价值在**第三层**：不是把数据再列一遍，而是给出**「为什么」**和**「接下来呢」**。

## 2. 三种核心分析

### 2.1 趋势分析

判断序列是上升 / 下降 / 波动 / 平稳：

```java
class TrendAnalyzer {
    String analyze(List<Double> series) {
        if (series.size() < 2) return "数据不足";
        
        // 1. 简单线性回归
        double slope = linearRegressionSlope(series);
        
        // 2. 计算波动率（标准差 / 均值）
        double mean = mean(series);
        double std = std(series);
        double cv = std / Math.max(mean, 0.001);
        
        if (cv > 0.3) return "波动剧烈";
        if (slope > 0.05 * mean) return "显著上升";
        if (slope < -0.05 * mean) return "显著下降";
        return "基本平稳";
    }
}
```

### 2.2 对比分析

A vs B 看谁强、强多少：

```java
class ComparisonAnalyzer {
    record Comparison(double a, double b, double diff, double diffPct, String winner) {}
    
    Comparison compare(double a, double b, String aName, String bName) {
        double diff = a - b;
        double pct = b == 0 ? Double.POSITIVE_INFINITY : diff / Math.abs(b);
        String winner = a > b ? aName : bName;
        return new Comparison(a, b, diff, pct, winner);
    }
}
```

### 2.3 结构分析（占比）

整体里各部分占多少、是否集中：

```java
class StructureAnalyzer {
    record Structure(double total, List<Part> parts, double concentration) {
        record Part(String name, double value, double pct) {}
    }
    
    Structure analyze(Map<String, Double> data) {
        double total = data.values().stream().mapToDouble(Double::doubleValue).sum();
        List<Structure.Part> parts = data.entrySet().stream()
            .sorted((a, b) -> Double.compare(b.getValue(), a.getValue()))
            .map(e -> new Structure.Part(e.getKey(), e.getValue(), e.getValue() / total))
            .toList();
        
        // HHI 指数：市场份额平方和（用于衡量集中度）
        double hhi = parts.stream().mapToDouble(p -> Math.pow(p.pct() * 100, 2)).sum();
        return new Structure(total, parts, hhi);
    }
}
```

HHI > 2500 视为高度集中。

### 3.3 ECharts 配置生成

```java
record EChartConfig(
    String title,
    String tooltip,
    Legend legend,
    XAxis xAxis,
    YAxis yAxis,
    List<Series> series
) {
    record Legend(List<String> data) {}
    record XAxis(String type, List<String> data) {}
    record YAxis(String type) {}
    record Series(String name, String type, List<Object> data) {}
}

EChartConfig buildLineChart(String title, List<String> dates, Map<String, List<Double>> seriesMap) {
    return new EChartConfig(
        title, "axis",
        new EChartConfig.Legend(new ArrayList<>(seriesMap.keySet())),
        new EChartConfig.XAxis("category", dates),
        new EChartConfig.YAxis("value"),
        seriesMap.entrySet().stream()
            .map(e -> new EChartConfig.Series(e.getKey(), "line", 
                e.getValue().stream().map(v -> (Object) v).toList()))
            .toList()
    );
}
```

## 4. 数据洞察生成

### 4.1 洞察模板

```java
class InsightGenerator {
    String generate(AnalysisResult result, String context) {
        StringBuilder sb = new StringBuilder();
        
        // 1. 趋势
        if (result.hasTrend()) {
            sb.append(String.format("%s 呈 %s 态势（%s → %s）。",
                result.metric(), result.trendDirection(),
                fmt(result.startValue()), fmt(result.endValue())));
        }
        
        // 2. 增长率
        if (result.hasGrowth()) {
            sb.append(String.format(" 环比 %s %.1f%%", 
                result.growthRate() > 0 ? "增长" : "下降",
                Math.abs(result.growthRate() * 100)));
        }
        
        // 3. 异常
        if (result.hasAnomaly()) {
            sb.append(String.format(" ⚠ %s 出现异常波动", result.anomalyPeriod()));
        }
        
        // 4. 对比（如果有基准）
        if (result.hasBenchmark()) {
            sb.append(String.format("，%s 行业平均 %s", 
                result.beatsBenchmark() ? "高于" : "低于",
                fmt(result.benchmark())));
        }
        
        return sb.toString();
    }
}
```

## 5. 自适应图表

同一份数据，**研报版**和**摘要版**展示不同：

| 版本 | 图表数 | 详情程度 | 用途 |
|------|--------|---------|------|
| 研报版 | 8-12 | 每图带数据 + 注释 | 完整研报 PDF |
| 摘要版 | 1-3 | 每图带洞察 | 邮件 / 微信推送 |
| Dashboard | 5-8 | 交互式 | BI 看板 |

```java
class AdaptiveRenderer {
    List<Chart> render(List<Facts> facts, RenderMode mode) {
        return switch (mode) {
            case FULL -> renderFull(facts);
            case SUMMARY -> renderSummary(facts);
            case DASHBOARD -> renderDashboard(facts);
        };
    }
}
```

## 常见问题 Q&A

**Q1：洞察文案千篇一律怎么办？**

加 **「反向提问」**：让 LLM 在生成洞察前先问 3 个关键问题（"为什么这个数字重要？"），强迫它思考再写。

**Q2：图表数据太少怎么办？**

< 3 个数据点不画图，改用文字描述。**画一个丑陋的图表不如不画**。

**Q3：洞察和实际数据不符？**

LLM 算术能力差。**数字部分用模板严格生成**，LLM 只负责"为什么"和"建议"。

**Q4：怎么评估洞察质量？**

- 人工抽查（每周 20 条）
- 让另一个 LLM 当评委（Pair-wise 比较）
- 用户反馈埋点（有用 / 没用）

## 本章小结

| 能力 | 实现 |
|------|------|
| **趋势分析** | 线性回归斜率 + 变异系数 |
| **对比分析** | diff / diffPct / winner |
| **结构分析** | 占比 + HHI 集中度 |
| **图表选择** | 规则决策树 + LLM 兜底 |
| **洞察生成** | 模板（数字）+ LLM（原因/建议） |
| **自适应** | FULL / SUMMARY / DASHBOARD 三种模式 |

**核心洞察**：图表 + 洞察不是"装饰"，而是 **「让数据变成决策」的关键一跳**。研报读者没时间看 100 个数字，他们要的是 3 句话。
