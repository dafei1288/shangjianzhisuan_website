## 1. 合同解析为什么难？

合同文档看起来"规整"，实际解析坑很多：

| 文档类型 | 解析挑战 |
|---------|---------|
| **PDF（文本型）** | 字符顺序乱、分栏、页眉页脚打断 |
| **PDF（扫描型）** | 需要 OCR，识别率 80-95% |
| **Word (.docx)** | XML 结构复杂，样式继承 |
| **Word (.doc)** | 二进制格式，必须 Tika |
| **表格** | 跨页表格断裂、合并单元格 |
| **图片** | 印章 / 签名 / 二维码 |
| **附件** | 一个合同可能有 N 个附件（清单 / 报价单） |

**核心洞察**：合同解析的目标不是"完美还原"，而是"**抽取条款 + 元数据**"。

## 2. 工具选型

### 2.1 三大主流工具

| 工具 | 适合 | 限制 |
|------|------|------|
| **Apache Tika** | 通用、支持 1000+ 格式 | 输出纯文本，丢结构 |
| **Apache PDFBox** | PDF 精细控制（坐标 / 字体） | 只能 PDF，代码量大 |
| **Tabula** | PDF 表格专用 | 复杂表格失败 |
| **Apache POI** | Word/Excel 精细控制 | 内存占用大 |
| **Aspose** | 商业库，质量最高 | 收费 |

### 2.2 推荐组合

```
PDF（文本型）   → Tika + PDFBox（双管齐下）
PDF（扫描型）   → Tika 失败时降级到 OCR（Tesseract）
Word (.docx)   → Apache POI 直接读 XML
Word (.doc)    → Tika（POI 也支持但慢）
Excel 附件     → Apache POI
通用兜底       → Tika（任何格式都能出文本）
```

## 3. Tika 通用解析

### 3.1 最简调用

```java
import org.apache.tika.Tika;

public class TikaParser {
    public static String parse(File file) throws Exception {
        Tika tika = new Tika();
        return tika.parseToString(file);
    }
}
```

**优点**：3 行代码搞定任意格式。
**缺点**：丢结构（章节 / 表格 / 列表都成纯文本）。

### 3.2 保留结构的解析

```java
import org.apache.tika.parser.AutoDetectParser;
import org.apache.tika.parser.ParseContext;
import org.apache.tika.sax.ToXMLContentHandler;
import org.xml.sax.ContentHandler;

public String parseToHtml(File file) throws Exception {
    AutoDetectParser parser = new AutoDetectParser();
    ContentHandler handler = new ToXMLContentHandler();
    ParseContext context = new ParseContext();
    
    try (InputStream stream = new FileInputStream(file)) {
        parser.parse(stream, handler, new Metadata(), context);
        return handler.toString();
        // 输出 XHTML：<h1>章节</h1> <p>段落</p> <table>表格</table>
    }
}
```

输出 XHTML 后用 Jsoup 解析 DOM，能恢复部分结构。

## 4. 章节识别算法

合同典型结构：

```
第一部分 总则
  第一条 合同主体
    1.1 甲方：...
    1.2 乙方：...
  第二条 合同标的
第二部分 付款条款
  第三条 付款方式
    3.1 ...
```

### 4.1 启发式规则

```java
class ClauseSegmenter {
    // 中国合同的章节模式
    static final Pattern[] PATTERNS = {
        Pattern.compile("^第[一二三四五六七八九十百千]+部分\\s*(.+)$"),  // 第N部分
        Pattern.compile("^第[一二三四五六七八九十百千]+条\\s*(.+)$"),     // 第N条
        Pattern.compile("^[0-9]+\\.[0-9]+\\s*(.+)$"),                  // 1.1 / 1.2
        Pattern.compile("^\\([一二三四五六七八九十]+\\)\\s*(.+)$"),      // （一）（二）
        Pattern.compile("^[0-9]+\\)\\s*(.+)$")                          // 1) 2)
    };
    
    List<Clause> segment(String text) {
        List<Clause> clauses = new ArrayList<>();
        Clause current = null;
        for (String line : text.split("\n")) {
            String stripped = line.strip();
            boolean matched = false;
            for (Pattern p : PATTERNS) {
                Matcher m = p.matcher(stripped);
                if (m.matches()) {
                    if (current != null) clauses.add(current);
                    current = new Clause(stripped, "");
                    matched = true;
                    break;
                }
            }
            if (!matched && current != null) {
                current.appendBody(line);
            }
        }
        if (current != null) clauses.add(current);
        return clauses;
    }
}
```

### 4.2 字体 / 字号辅助

PDF 解析能拿到字号，标题通常字号大 + 加粗。结合 Tika 的 XHTML 输出 `<h1>` `<h2>` 标签更准。

## 5. 表格提取

### 5.1 PDFBox + Tabula

```java
import technology.tabula.ObjectExtractor;
import technology.tabula.Page;
import technology.tabula.Table;
import technology.tabula.extractors.BasicExtractionMode;

public List<Table> extractTables(File pdf) throws Exception {
    List<Table> tables = new ArrayList<>();
    try (PDDocument doc = PDDocument.load(pdf)) {
        ObjectExtractor extractor = new ObjectExtractor(doc);
        for (int p = 1; p <= doc.getNumberOfPages(); p++) {
            Page page = extractor.extract(p);
            tables.addAll(new SpreadsheetExtractionAlgorithm().extract(page));
        }
    }
    return tables;
}
```

### 5.2 表格 → JSON

```java
record ContractTable(
    String title,           // "付款计划"
    List<String> headers,
    List<List<String>> rows
) {}
```

便于后续 LLM 理解和 RAG 检索。

## 6. 中文乱码 / OCR / 扫描件

### 6.1 中文乱码

PDF 里中文乱码通常是 **CMap 缺失** 或 **字体嵌入问题**。PDFBox 3.x 默认带 CMap：

```xml
<dependency>
    <groupId>org.apache.pdfbox</groupId>
    <artifactId>pdfbox</artifactId>
    <version>3.0.1</version>
</dependency>
```

如果还是乱码，降级到 Tika + 配 `EncodingDetector`。

### 6.2 OCR 兜底

扫描件 / 图片 PDF 必须走 OCR：

```java
import net.sourceforge.tess4j.Tesseract;

public String ocr(File image) throws Exception {
    Tesseract t = new Tesseract();
    t.setLanguage("chi_sim+eng");  // 中文简体 + 英文
    return t.doOCR(image);
}
```

### 6.3 判断是否需要 OCR

```java
boolean needsOcr(File pdf) throws Exception {
    try (PDDocument doc = PDDocument.load(pdf)) {
        PDFTextStripper stripper = new PDFTextStripper();
        String text = stripper.getText(doc);
        // 文本提取结果 < 100 字符，基本是扫描件
        return text.trim().length() < 100;
    }
}
```

## 常见问题 Q&A

**Q1：Tika 解析特别慢怎么办？**

Tika 启动慢（10s）是 JVM 类加载，**生产环境用 Tika Server**（独立进程，长驻）。

**Q2：表格跨页断裂怎么办？**

用 Tabula 的 `SpreadsheetExtractionAlgorithm`，它会尝试合并跨页。失败时手工 merge：判断表头是否一致。

**Q3：合同里嵌图片（印章）影响解析吗？**

不影响文本提取，但 OCR 时会把印章识别成乱码。建议**先抠出图片区域再 OCR**。

**Q4：怎么测试解析质量？**

- 准备 50+ 真实合同标注（条款边界 / 表格）
- 自动解析后计算 IoU（Intersection over Union）
- 目标：边界 IoU > 0.85

## 本章小结

| 工具 | 场景 | 关键 API |
|------|------|---------|
| **Tika** | 通用 / 兜底 | `Tika.parseToString()` |
| **PDFBox** | PDF 精细 | `PDDocument.load()` + `PDFTextStripper` |
| **Tabula** | PDF 表格 | `SpreadsheetExtractionAlgorithm` |
| **Tesseract** | OCR | `Tesseract.doOCR()` |

**核心洞察**：合同解析的瓶颈不在工具，而在**结构恢复**。先用 Tika 拿文本，再用启发式规则识别章节，最后用 Tabula 补表格。
