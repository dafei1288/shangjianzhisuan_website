## 1. 风险评分模型

### 1.1 三级 vs 数字分

单纯三级（高 / 中 / 低）粒度太粗，一份合同 50 条款里有 30 条「中风险」是没意义的。

**推荐：三级 + 0-100 分**：

| 等级 | 分数 | 颜色 | 含义 |
|------|------|------|------|
| 🔴 高 | 75-100 | red | 必须修改 |
| 🟡 中 | 40-74 | yellow | 建议修改 |
| 🟢 低 | 0-39 | green | 提示观察 |
| ⚪ 信息 | - | gray | 无风险记录 |

### 1.2 评分维度

```java
record RiskScore(
    int overall,                  // 综合分 0-100
    int severity,                 // 后果严重度 0-100
    int probability,              // 发生概率 0-100
    int detectability             // 可检测性 0-100（越高越难发现）
) {
    // FMEA 风险优先数 RPN = severity × probability × detectability
    int rpn() { return severity * probability * detectability / 10000; }
}
```

### 1.3 LLM 评分 Prompt

```java
String scoringPrompt = """

{
```

## 2. 引用溯源

### 2.1 为什么溯源？

合规场景要求「**每个判断都能追到规则原文**」。LLM 说"违约金过高"不行，必须给出：
- 哪条规则说的（规则 ID + 原文）
- 历史相似案例（判决书号 + 摘要）
- 条款原文位置（页码 + 段落）

### 2.2 数据结构

```java
record Citation(
    String type,           // "rule" / "case" / "statute"
    String id,             // "rule-001" / "case-2023-001"
    String source,         // "公司采购合同管理办法"
    String text,           // 引用的原文片段
    Location location       // 位置
) {
    record Location(int page, int paragraph, int charOffset) {}
}

record AnnotatedRisk(
    String clauseId,
    String clauseText,
    RiskScore score,
    List<String> issues,
    List<Citation> citations   // 溯源
) {}
```

### 2.3 在报告里渲染

```markdown

> 甲方未按期付款，每延期一日按未付金额 0.5% 支付违约金。
```

## 3. 报告生成

### 3.1 Markdown 报告

```java
class MarkdownReportGenerator {
    String generate(Contract contract, List<AnnotatedRisk> risks) {
        StringBuilder sb = new StringBuilder();
        sb.append("# 合同审查报告\n\n");
        sb.append("**合同名称：** ").append(contract.name()).append("\n");
        sb.append("**审查日期：** ").append(LocalDate.now()).append("\n");
        sb.append("**总体风险：** ").append(overallLevel(risks)).append("\n\n");
        
        sb.append("## 概览\n\n");
        sb.append("| 等级 | 数量 | 占比 |\n|------|------|------|\n");
        sb.append(riskStats(risks));
        
        sb.append("\n## 详细审查\n\n");
        for (AnnotatedRisk r : risks) {
            sb.append(renderRisk(r));
        }
        
        sb.append("\n## 修改建议清单\n\n");
        for (AnnotatedRisk r : risks) {
            if (!r.issues().isEmpty()) {
                sb.append("- [ ] ").append(r.clauseId()).append(": ").append(r.issues().get(0)).append("\n");
            }
        }
        
        return sb.toString();
    }
}
```

### 3.2 PDF 导出

Markdown → PDF 有两条路：

#### 方案 A：Pandoc（外部工具）

```bash
pandoc report.md -o report.pdf --pdf-engine=xelatex -V CJKmainfont="SimSun"
```

需要本地装 Pandoc + LaTeX。质量好但部署麻烦。

#### 方案 B：Flying Saucer（纯 Java）

```java
import org.xhtmlrenderer.pdf.ITextRenderer;

public byte[] toPdf(String html) throws Exception {
    ITextRenderer renderer = new ITextRenderer();
    renderer.setDocumentFromString(html);
    renderer.layout();
    try (ByteArrayOutputStream out = new ByteArrayOutputStream()) {
        renderer.createPDF(out);
        return out.toByteArray();
    }
}
```

Markdown → HTML（commonmark-java）→ PDF。中文字体需要嵌入。

#### 方案 C：OpenHTMLtoPDF（推荐）

```xml
<dependency>
    <groupId>com.openhtmltopdf</groupId>
    <artifactId>openhtmltopdf-pdfbox</artifactId>
    <version>1.0.10</version>
</dependency>
<dependency>
    <groupId>com.openhtmltopdf</groupId>
    <artifactId>openhtmltopdf-slf4j</artifactId>
    <version>1.0.10</version>
</dependency>
```

支持 CSS、中文字体、表格样式，是 Java PDF 报告的事实标准。

### 3.3 Word 导出（POI）

很多法务同事只接受 Word 报告：

```java
import org.apache.poi.xwpf.usermodel.*;

public void exportWord(ReviewReport report, OutputStream out) throws Exception {
    try (XWPFDocument doc = new XWPFDocument()) {
        XWPFParagraph title = doc.createParagraph();
        title.setAlignment(ParagraphAlignment.CENTER);
        XWPFRun titleRun = title.createRun();
        titleRun.setText("合同审查报告");
        titleRun.setBold(true);
        titleRun.setFontSize(18);
        
        for (AnnotatedRisk r : report.risks()) {
            XWPFParagraph p = doc.createParagraph();
            XWPFRun run = p.createRun();
            run.setText("【" + r.clauseId() + "】 " + r.score().overall() + "/100");
            run.setBold(true);
            // ... 添加原文、问题、建议
        }
        
        doc.write(out);
    }
}
```

```java
@PostMapping("/review")
public ReviewResponse review(@RequestParam MultipartFile file) throws Exception {
    // 1. 解析
    Contract contract = parser.parse(file.getInputStream(), file.getOriginalFilename());

    return new ReviewResponse(contract, risks, markdown, pdf, word);
}
```

## 常见问题 Q&A

**Q1：报告里的 emoji 会乱码吗？**

Markdown 渲染正常，PDF 导出需要用支持 emoji 的字体（如 NotoColorEmoji）。生产环境建议**用文字替代 emoji**（"高" / "中" / "低" + 颜色样式）。

**Q2：报告太长怎么办？**

- 默认只列高风险
- 提供详细版 / 简版切换
- 加目录跳转（PDF 的 outline）

**Q3：用户能在报告里直接改条款吗？**

加一个「编辑模式」：用户改完条款 → 系统自动重审 → 实时显示新风险分。本质是把审查做成 stream / 反应式。

**Q4：怎么对接公司 OA？**

- 报告导出为 Word + 上传 OA
- OA 里审批流（合规 / 法务 / 业务三方）
- 审批意见回写系统作为反馈数据

## 本章小结

| 能力 | 实现 |
|------|------|
| **风险评分** | severity × probability × detectability（FMEA） |
| **引用溯源** | Citation 数据结构 + 多类型（规则/案例/法规） |
| **报告格式** | Markdown + PDF（OpenHTMLtoPDF）+ Word（POI） |
| **整合** | Spring Boot REST API，一键上传 → 出报告 |

**核心洞察**：审查报告的**价值在「可追溯」**——每个风险点能跳到原文、引用规则、找到案例。这才能让法务信任 LLM 的判断，而不是把它当"参考意见"。
