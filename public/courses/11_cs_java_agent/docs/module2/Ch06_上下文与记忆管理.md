## 6.1 为什么需要 Memory

### 6.1.1 没有 Memory 的悲剧

```java
// 第 1 轮
chatClient.prompt().user("我叫张三").call().content();
// → "你好，张三！有什么可以帮你的？"

// 第 2 轮
chatClient.prompt().user("我叫什么名字？").call().content();
// → "对不起，我不知道你的名字。"  ← 悲剧
```

每次 `.call()` 都是独立请求，**LLM 看不到前一轮**。除非把历史手动拼到 Prompt 里。

### 6.1.2 有 Memory 的优雅写法

```java
String conversationId = "user-001";

// 第 1 轮
chatClient.prompt()
    .user("我叫张三")
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
    .call().content();

// 第 2 轮
chatClient.prompt()
    .user("我叫什么名字？")
    .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
    .call().content();
// → "你叫张三。"  ← 自动带历史
```

底层：Spring AI 在调用前**自动从存储加载历史**，调用后**自动保存新对话**。

## 6.2 ChatMemory 抽象

### 6.2.1 接口定义

```java
public interface ChatMemory {

    // 加载会话历史（用于构造 Prompt）
    List<Message> get(String conversationId);

    // 保存一条新消息
    void add(String conversationId, Message message);

    // 清空会话
    void clear(String conversationId);
}
```

**核心字段**：`conversationId`。同一个 id 的消息组成一段对话，不同 id 完全隔离。

### 6.2.2 内置实现

| 实现 | 存储 | 适用场景 |
|------|------|----------|
| `MessageChatMemoryAdvisor` | 内存（Map） | Demo、单机测试 |
| `JdbcChatMemoryRepository` | 关系型数据库 | 生产环境，跨实例共享 |
| `RedisChatMemoryRepository` | Redis | 高并发、TTL 自动过期 |

> 本课程 Module 4 的 RAG 项目会用 PostgreSQL + PgVector 同时存对话历史和向量。

### 6.2.3 接入 Advisor

ChatMemory 通过 **Advisor 链**接入（Ch07 会深入 Advisor）：

```java
@Configuration
class AiConfig {

    @Bean
    ChatClient chatClient(ChatClient.Builder builder, ChatMemory memory) {
        return builder
            .defaultAdvisors(new MessageChatMemoryAdvisor(memory))
            .build();
    }

    @Bean
    ChatMemory chatMemory() {
        return new InMemoryChatMemory();  // 或 JdbcChatMemoryRepository
    }
}
```

注册后，**所有 `.call()` 自动带历史**，无需手动管理。

## 6.3 窗口溢出策略

### 6.3.1 问题

DeepSeek 上下文窗口 64K，GPT-4o 128K。看起来很大，但多轮对话很快爆：

```
Round 1:  user(20) + assistant(200) = 220
Round 2:  user(20) + assistant(200) = 440
...
Round 50: 11000 tokens 累计
Round 200: 44000 tokens
Round 250: 55000 tokens ← 接近窗口上限
```

### 6.3.2 三种策略

```
策略 A：滑动窗口（保留最近 N 轮）
┌────────────────────┐
│  [丢弃] Round 1-40 │  ← 超出窗口的最早对话被截断
│  Round 41-50        │  ← 保留最近 10 轮
│  Round 51（当前）    │
└────────────────────┘
特点：实现简单，但「忘了早期约定」

策略 B：摘要压缩
┌────────────────────┐
│  [摘要] 用户叫张三... │  ← LLM 把旧对话压缩成 200 字摘要
│  Round 41-50        │
│  Round 51（当前）    │
└────────────────────┘
特点：信息保留好，但每次摘要消耗 Token

策略 C：RAG 检索
┌────────────────────┐
│  [Top-K 相关片段]   │  ← 从全部历史 Embedding 检索最相关 5 段
│  Round 51（当前）    │
└────────────────────┘
特点：信息保留最好，但工程复杂（Module 4 重点）
```

### 6.3.3 实战配置：滑动窗口

Spring AI 的 `MessageChatMemoryAdvisor` 默认保留全部历史，**要手动限制**：

```java
// 自定义 ChatMemory 实现，只保留最近 N 条
public class SlidingWindowChatMemory implements ChatMemory {

    private static final int MAX_MESSAGES = 20;  // 最近 10 轮 = 20 条消息
    private final Map<String, List<Message>> store = new ConcurrentHashMap<>();

    @Override
    public void add(String conversationId, Message message) {
        List<Message> history = store.computeIfAbsent(conversationId, k -> new ArrayList<>());
        history.add(message);
        // 滑动窗口：超出则截断
        if (history.size() > MAX_MESSAGES) {
            history.subList(0, history.size() - MAX_MESSAGES).clear();
        }
    }

    @Override
    public List<Message> get(String conversationId) {
        return new ArrayList<>(store.getOrDefault(conversationId, List.of()));
    }

    @Override
    public void clear(String conversationId) {
        store.remove(conversationId);
    }
}
```

### 6.3.4 进阶：Token 窗口（比条数更准）

条数窗口有缺陷：一句「好」和一段 2000 字的代码差异巨大。生产环境通常按 **Token 数**截断：

```java
public class TokenWindowChatMemory implements ChatMemory {
    private static final int MAX_TOKENS = 4000;  // 给历史留 4K Token
    // ...add 时累计 Token，超过则从最早开始删
}
```

> 💡 Token 估算用 Ch02 的算法即可，精度不需要太高。

## 6.4 多用户会话隔离

### 6.4.1 问题

```java
// 用户 A 说「我叫张三」
chatClient.prompt().user("我叫张三")...
// 用户 B 紧接着问
chatClient.prompt().user("我叫什么？")...
// → "你叫张三"  ← 串号了！B 怎么知道 A 的名字？
```

### 6.4.2 解决：每个用户独立 conversationId

```java
public String chat(String userId, String userMessage) {
    String conversationId = "user-" + userId;  // ← 关键

    return chatClient.prompt()
        .user(userMessage)
        .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
        .call()
        .content();
}
```

**底层**：ChatMemory 用 `conversationId` 做 Map key，天然隔离。

### 6.4.3 多人共享 vs 单人独占

| 场景 | conversationId 设计 |
|------|---------------------|
| 单用户单 Agent | `user-{userId}` |
| 单用户多 Agent | `user-{userId}-agent-{agentType}` |
| 多用户协作（共享会话） | `session-{sessionId}`（多 userId 共享同一 session） |
| 群聊（@机器人的消息） | `group-{groupId}` |

> 💡 conversationId 的设计**直接决定记忆范围**。错的设计会让用户看到别人的隐私。

## 6.5 持久化到数据库

### 6.5.1 为什么不用内存

内存 ChatMemory 有 3 个问题：
1. 重启即丢
2. 多实例不共享（负载均衡场景下用户串号）
3. 内存无限增长

生产环境**必须**用数据库持久化。

### 6.5.2 用 JDBC（PostgreSQL）

**依赖**：

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-model-chat-memory-jdbc</artifactId>
</dependency>
```

**配置**：

```yaml
spring:
  ai:
    chat:
      memory:
        repository:
          jdbc:
            initialize-schema: embedded   # 自动建表
```

**使用**（和内存版完全一样）：

```java
@Bean
ChatMemory chatMemory(JdbcChatMemoryRepository repo) {
    return ChatMemory.builder()
        .chatMemoryRepository(repo)
        .build();
}
```

### 6.5.3 自动建表 SQL

Spring AI 启动时自动执行：

```sql
CREATE TABLE SPRING_AI_CHAT_MEMORY (
    conversation_id VARCHAR(36) NOT NULL,
    content         TEXT        NOT NULL,
    type            VARCHAR(10) NOT NULL,   -- USER / ASSISTANT / SYSTEM
    "timestamp"     TIMESTAMP   NOT NULL
);
CREATE INDEX idx_conv_ts ON SPRING_AI_CHAT_MEMORY(conversation_id, "timestamp");
```

## 关键代码：多轮对话 Demo

本章 Demo 演示一个**会记名字的多轮对话**：

```java
package com.jimagent.ch06;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.memory.InMemoryChatMemory;
import org.springframework.ai.openai.OpenAiChatModel;
import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.ai.openai.api.OpenAiApi;

import java.util.Scanner;

import static org.springframework.ai.chat.client.advisor.AbstractChatMemoryAdvisor.CHAT_MEMORY_CONVERSATION_ID_KEY;

/**
 * Ch06: 多轮对话 + 多用户隔离 Demo。
 *
 * <p>启动后会进入交互式对话：
 * <pre>
 *   你的 ID > user-001
 *   你 > 我叫张三
 *   Agent > 你好张三！
 *   你 > 我叫什么？
 *   Agent > 你叫张三。
 *   你 > /switch user-002    # 切换用户
 *   你 > 我叫什么？
 *   Agent > 抱歉，我不知道你的名字。  ← 用户隔离生效
 * </pre>
 */
public class Main {

    public static void main(String[] args) {
        String apiKey = System.getenv("DEEPSEEK_API_KEY");
        if (apiKey == null) {
            System.out.println("⚠️  未设置 DEEPSEEK_API_KEY，跳过实际调用。");
            return;
        }

        // 1. 共享的 ChatMemory（所有用户共用底层存储，靠 conversationId 隔离）
        ChatMemory memory = new InMemoryChatMemory();

        // 2. 注册 Memory Advisor
        ChatClient client = ChatClient.builder(buildModel(apiKey))
            .defaultSystem("你是有礼貌的助手。简洁回答，不超过 50 字。")
            .defaultAdvisors(MessageChatMemoryAdvisor.builder(memory).build())
            .build();

        Scanner scanner = new Scanner(System.in);
        String currentUserId = "default-user";

        System.out.println("=".repeat(60));
        System.out.println("  Ch06 多轮对话 Demo");
        System.out.println("  命令：/switch <userId>  /clear  /quit");
        System.out.println("=".repeat(60));

        while (true) {
            System.out.print("你 > ");
            String input = scanner.nextLine().trim();
            if (input.isEmpty()) continue;
            if ("/quit".equals(input)) break;
            if (input.startsWith("/switch ")) {
                currentUserId = input.substring(8).trim();
                System.out.println("→ 已切换到用户: " + currentUserId);
                continue;
            }
            if ("/clear".equals(input)) {
                memory.clear(currentUserId);
                System.out.println("→ 已清空当前用户记忆");
                continue;
            }

            String answer = client.prompt()
                .user(input)
                .advisors(a -> a.param(CHAT_MEMORY_CONVERSATION_ID_KEY, currentUserId))
                .call()
                .content();
            System.out.println("Agent > " + answer);
        }
    }

    static OpenAiChatModel buildModel(String apiKey) {
        OpenAiApi api = OpenAiApi.builder()
            .baseUrl("https://api.deepseek.com")
            .apiKey(apiKey)
            .build();
        return OpenAiChatModel.builder()
            .openAiApi(api)
            .defaultOptions(OpenAiChatOptions.builder().model("deepseek-chat").build())
            .build();
    }
}
```

运行 `mvn exec:java -pl ch06`，**测试用户切换时记忆是否真的隔离**。

## 常见问题 Q&A

**Q1：Memory 会无限增长吗？**

A：会，除非配置窗口策略。生产环境**必须**用 `SlidingWindowChatMemory` 或 `TokenWindowChatMemory`。

**Q2：Memory 和 RAG 有什么区别？**

A：
- Memory：**对话历史**，按 conversationId 隔离，时间敏感（最近最重要）
- RAG：**知识库**，全局共享，按相似度检索（无时间序）

简单记：Memory 是「**短期记忆**」，RAG 是「**长期知识**」。

**Q3：用 PostgreSQL 存对话历史慢吗？**

A：单查询 < 5ms（有索引）。瓶颈在 LLM 调用本身（500ms-2s）。**完全够用**。

如果担心，可以加 Redis 缓存最近活跃会话，DB 做持久化兜底。

**Q4：能跨进程共享 Memory 吗？**

A：能，但必须用数据库版（JDBC/Redis）。内存版只在当前 JVM 有效。

**Q5：JSON 格式的对话历史怎么存？**

A：Spring AI 默认用 `Message` 抽象，JDBC 实现自动序列化为 JSON 字符串存 TEXT 列。**不要自己设计表结构**。

**Q6：会话超时怎么处理？**

A：
- JDBC 版：用 Spring `@Scheduled` 定期清理 30 天前的记录
- Redis 版：`spring.ai.chat.memory.repository.redis.ttl=7d`

## 本章小结

| 概念 | 要点 |
|------|------|
| ChatMemory | Spring AI 记忆抽象，按 conversationId 隔离 |
| 内置实现 | InMemory（demo）/ JDBC（生产）/ Redis（高并发） |
| 溢出策略 | 滑动窗口（条数）/ Token 窗口（精确）/ 摘要压缩 |
| 多用户隔离 | conversationId 设计直接决定记忆范围 |
| 持久化 | 必做，避免重启丢失、多实例不共享 |

**核心认知**：Memory 是「**短期记忆**」，让 Agent 记得当前对话；RAG 是「**长期知识**」，让 Agent 拥有跨会话的记忆。
