## 1. SQL 安全：不止是关键词过滤

### 1.1 三层防御

Ch20 的关键词过滤太弱（`SELECT * FROM x WHERE 1=1; DROP TABLE y` 能绕过）。生产系统需要三层：

```
┌─────────────────────────────────────────┐
│  Layer 1: 静态检查（字符串过滤）          │
│  - 黑名单关键词：DROP/ALTER/INSERT...    │
│  - 强制 LIMIT                            │
│  - 禁止分号                              │
└─────────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────┐
│  Layer 2: AST 解析                       │
│  - 用 JSqlParser 解析 AST                │
│  - 验证所有 statement 都是 SELECT        │
│  - 验证没有子查询里藏 DDL                 │
│  - 验证没有 UNION 拼接其他类型           │
└─────────────────────────────────────────┘
                   ↓
┌─────────────────────────────────────────┐
│  Layer 3: 运行时隔离                     │
│  - 只读 DB 用户（DB 权限层）              │
│  - READ_ONLY 事务                        │
│  - query timeout                         │
│  - row limit（JDBC 层）                  │
└─────────────────────────────────────────┘
```

### 1.2 AST 解析（关键）

```java
import net.sf.jsqlparser.parser.CCJSqlParserUtil;
import net.sf.jsqlparser.statement.select.Select;
import net.sf.jsqlparser.statement.Statement;

void validateAst(String sql) throws Exception {
    Statement stmt = CCJSqlParserUtil.parse(sql);
    if (!(stmt instanceof Select)) {
        throw new SecurityException("仅允许 SELECT 语句");
    }
    Select select = (Select) stmt;
    // 进一步检查：WITH 子句、UNION、子查询
    select.getSelectBody().accept(new SecurityValidatorVisitor());
}
```

**好处**：解析 AST 比 regex 可靠得多。即使 LLM 用 `/* DROP TABLE */` 注释藏雷，AST 也能识别。

### 1.3 限流（防 LLM 失控）

```java
class SqlRateLimiter {
    private final Map<String, RateBucket> userBuckets = new ConcurrentHashMap<>();
    
    void check(String userId) {
        RateBucket bucket = userBuckets.computeIfAbsent(userId, k -> new RateBucket(10, 60));
        if (!bucket.tryConsume()) {
            throw new RateLimitException("超过 10 次/分钟");
        }
    }
}
```

防止恶意用户/失控 Agent 把 DB 打爆。

## 2. 图表类型自动选择

### 2.1 图表类型决策树

```
查询结果 = 1 行 1 列？
├─ 是 → 直接显示数字（不需要图表）
└─ 否 → 数据有"time" / "date" 列？
        ├─ 是 → 折线图
        └─ 否 → 数据 ≤ 10 行？
                ├─ 是 → 柱状图
                └─ 否 → 单列分类 + 单列数值？
                        ├─ 是 → 饼图（如果 ≤ 7 类）
                        └─ 否 → 数据表格
```

### 2.2 LLM 辅助决策

```java

    @P("查询的列") List<String> columns,
    @P("数据样例") List<List<Object>> sampleRows,
    @P("用户原始问题") String question

```

LLM 能理解 "对比 A 和 B" → 柱状图，"趋势" → 折线图，"占比" → 饼图。

## 3. 数据洞察生成

### 3.1 什么是洞察？

裸数字：

```
华东销售额：1250 万
华南销售额：980 万
华北销售额：1500 万
```

洞察：

```
华北地区销售额最高（1500 万），比华东高 20%，
比华南高 53%。建议关注华南市场。
```

洞察 = **数字 + 比较 + 启发**。

### 3.2 三种洞察类型

| 类型 | 例子 | 触发条件 |
|------|------|---------|
| **比较型** | "X 比 Y 高 30%" | 多行单指标 |
| **趋势型** | "本月环比下降 15%" | 时间序列 |
| **异常型** | "上海数据异常偏低" | 离群点检测 |

### 3.4 异常检测（算法兜底）

LLM 有时数字感差，用统计学方法兜底：

```java
List<String> detectAnomalies(List<Double> values) {
    double mean = values.stream().mapToDouble(d -> d).average().orElse(0);
    double std = Math.sqrt(values.stream()
        .mapToDouble(d -> Math.pow(d - mean, 2)).average().orElse(0));
    
    List<String> anomalies = new ArrayList<>();
    for (int i = 0; i < values.size(); i++) {
        double z = std > 0 ? Math.abs(values.get(i) - mean) / std : 0;
        if (z > 2) anomalies.add("第 " + (i+1) + " 行数据异常（Z-score=" + z + "）");
    }
    return anomalies;
}
```

Z-score > 2 通常算异常（95% 置信区间外）。

### 4.2 完整请求流

@PostMapping("/query")
public Nl2SqlResponse query(@RequestBody String question) {
    // 1. Agent 决策（自动调工具）
    AgentResult result = agent.ask(question);
    
    // 2. 安全二次校验
    safetyValidator.validate(result.sql());
    
    // 3. 选图表
    ChartConfig chart = chartPicker.pick(result.queryResult(), question);
    
    // 4. 生成洞察
    String insight = insightGenerator.generate(result.queryResult(), question);

        result.sql(),
        result.queryResult(),
        chart,
        insight
    );
}

## 常见问题 Q&A

**Q1：LLM 生成的图表类型不可靠怎么办？**

加规则引擎兜底。LLM 决策 + 规则约束：例如 LLM 选饼图但数据 > 7 类，自动 fallback 到柱状图。

**Q2：洞察文案太啰嗦怎么破？**

Prompt 里加字数限制（"≤ 50 字"），并用 LLM 自评（生成后再让 LLM 打分，< 7 分重写）。

**Q3：用户能修改 SQL 后再执行吗？**

加一个"编辑模式"：返回 SQL 后，前端可编辑，用户确认后再执行。增加 `executeCustomSql` 接口。

**Q4：怎么监控 NL2SQL 系统质量？**

- **准确率**：抽样人工标注（正确 / 错误 / 部分正确）
- **执行成功率**：SQL 能跑通的比例
- **用户满意度**：点赞 / 点踩埋点
- 详见 Ch29（监控与可观测性）
