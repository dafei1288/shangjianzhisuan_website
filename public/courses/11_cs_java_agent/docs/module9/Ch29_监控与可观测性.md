## 1. Agent 系统的可观测三层

```
┌─────────────────────────────────────────────┐
│  Metrics（指标） - 数字时序                   │
│  例：llm.token.input, llm.latency.p99        │
├─────────────────────────────────────────────┤
│  Traces（链路） - 调用关系                    │
│  例：User → Agent → LLM + 3 个 Tool          │
├─────────────────────────────────────────────┤
│  Logs（日志） - 事件细节                      │
│  例：tool=search, query="苹果Q3", cost=0.003  │
└─────────────────────────────────────────────┘
```

这三层互补：
- **Metrics**：告诉你「**有什么问题**」（latency 高）
- **Traces**：告诉你「**问题在哪一段**」（是 LLM 慢还是 Tool 慢）
- **Logs**：告诉你「**为什么出这个问题**」（Tool 调用返回 500）

## 3. Agent 核心指标定义

### 3.1 成本指标

```java
@Service
public class LlmMetrics {
    private final Counter tokenInput;
    private final Counter tokenOutput;
    private final Counter costCounter;
    private final Counter cacheHit;
    private final Counter cacheMiss;

    public LlmMetrics(MeterRegistry reg) {
        this.tokenInput = Counter.builder("llm.token.input")
            .description("LLM input tokens").register(reg);
        // ... 类似声明其他
    }

    public void record(String model, Usage usage, boolean cached) {
        tokenInput.increment(usage.getPromptTokens());
        tokenOutput.increment(usage.getCompletionTokens());
        costCounter.increment(calcCost(model, usage));
        if (cached) cacheHit.increment(); else cacheMiss.increment();
    }
}
```

**关键标签**：
- `model`：哪个模型（deepseek-v3 / gpt-4o）
- `feature`：业务功能（nl2sql / contract-review / report-gen）
- `cache`：是否命中缓存

### 3.2 性能指标

| 指标 | 类型 | 含义 |
|------|------|------|
| `llm.latency` | Timer | 单次 LLM 调用延迟 |
| `agent.total_latency` | Timer | Agent 完整请求延迟 |
| `tool.call_latency` | Timer | 工具调用延迟（含外部 API） |
| `rag.retrieve_latency` | Timer | 向量检索延迟 |
| `agent.turns` | Distribution | Agent 推理轮数（多轮 ReAct） |

### 3.3 质量指标（最重要）

```java
// 用户反馈：thumbs up/down
public void recordFeedback(String agentId, boolean positive) {
    Counter.builder("agent.feedback")
        .tag("agent", agentId)
        .tag("sentiment", positive ? "up" : "down")
        .register(registry).increment();
}

// 工具调用失败率
public void recordToolCall(String tool, boolean success) {
    Counter.builder("tool.call")
        .tag("tool", tool)
        .tag("result", success ? "success" : "fail")
        .register(registry).increment();
}

// LLM 调用失败率（限流 / 超时 / 内容审查）
public void recordLlmError(String model, String errorCode) {
    Counter.builder("llm.error")
        .tag("model", model)
        .tag("code", errorCode)  // rate_limit / timeout / content_filter
        .register(registry).increment();
}
```

**关键指标**：
- **满意度**：`rate(agent.feedback{sentiment="up"}) > 0.8`
- **工具成功率**：`rate(tool.call{result="success"}) > 0.95`
- **LLM 错误率**：`rate(llm.error) < 0.01`

## 4. Grafana 大盘设计

### 4.1 4 个核心面板

#### Panel 1：QPS & 延迟
```promql
# QPS
rate(agent_total_latency_count[5m])

# P50/P95/P99 延迟
histogram_quantile(0.5, rate(agent_total_latency_bucket[5m]))
histogram_quantile(0.95, rate(agent_total_latency_bucket[5m]))
histogram_quantile(0.99, rate(agent_total_latency_bucket[5m]))
```

#### Panel 2：Token 消耗 & 成本
```promql
# 每分钟 Token
rate(llm_token_input_total[5m]) + rate(llm_token_output_total[5m])

# 每日成本（美元）
increase(llm_cost_total[24h])
```

#### Panel 3：缓存命中率
```promql
llm_cache_hit_total / (llm_cache_hit_total + llm_cache_miss_total)
```

#### Panel 4：用户满意度
```promql
sum(rate(agent_feedback{sentiment="up"}[1h]))
  / sum(rate(agent_feedback[1h]))
```

### 4.2 告警规则

```yaml
groups:
- name: agent_alerts
  rules:
  - alert: HighLatency
    expr: histogram_quantile(0.95, rate(agent_total_latency_bucket[5m])) > 10
    for: 5m
    annotations:
      summary: "P95 latency > 10s"

  - alert: HighLLMErrorRate
    expr: rate(llm_error_total[5m]) / rate(llm_call_total[5m]) > 0.05
    for: 2m
    annotations:
      summary: "LLM error rate > 5%"

  - alert: LowCacheHitRate
    expr: llm_cache_hit_total / (llm_cache_hit_total + llm_cache_miss_total) < 0.05
    for: 30m
    annotations:
      summary: "LLM cache hit rate < 5%, cost will spike"

  - alert: BudgetExceeded
    expr: increase(llm_cost_total[24h]) > 100
    annotations:
      summary: "Daily LLM cost > $100"

  - alert: UserSatisfactionDrop
    expr: sum(rate(agent_feedback{sentiment="down"}[1h]))
        / sum(rate(agent_feedback[1h])) > 0.3
    for: 30m
    annotations:
      summary: "Thumbs down rate > 30%, investigate quality"
```

## 5. OpenTelemetry 链路追踪

### 5.1 为什么 Agent 需要 Trace

一次用户请求的内部调用链：

```
User Query "查苹果Q3营收"
└─ Agent Loop (5 turns)
   ├─ Turn 1
   │  ├─ LLM call (decide tool)
   │  ├─ Tool: searchSchema
   │  │  └─ VectorStore query
   │  └─ Tool: generateSql
   ├─ Turn 2
   │  ├─ LLM call (execute tool)
   │  └─ Tool: executeSql
   │     └─ Database query
   └─ Turn 3
      └─ LLM call (final answer)
```

看 `latency.p99 = 8s`，**根本不知道是哪一段慢**。Trace 能定位到具体 Span。

### 5.2 接入

#### 依赖

```xml
<dependency>
    <groupId>io.opentelemetry.instrumentation</groupId>
    <artifactId>opentelemetry-spring-boot-starter</artifactId>
</dependency>
```

#### application.yml

```yaml
otel:
  exporter:
    otlp:
      endpoint: http://otel-collector:4317
  service:
    name: java-ai-agent
  traces:
    sampler:
      probability: 0.1  # 10% 采样，全量太贵
```

### 5.3 自定义 Span

```java
@WithSpan("agent.run")
public AgentResponse run(@SpanAttribute("query") String query) {
    Span span = Span.current();
    span.setAttribute("agent.id", agentId);
    span.setAttribute("query.length", query.length());

    try {
        // ... Agent 逻辑
        span.setAttribute("agent.turns", turns);
        span.setAttribute("agent.tools_used", String.join(",", tools));
        return response;
    } catch (Exception e) {
        span.recordException(e);
        span.setStatus(StatusCode.ERROR);
        throw e;
    }
}

public String callLlm(String prompt) {
    Span span = tracer.spanBuilder("llm.call")
        .setAttribute("llm.model", "deepseek-v3")
        .setAttribute("llm.input_tokens", estimateTokens(prompt))
        .startSpan();
    try (var scope = span.makeCurrent()) {
        String result = delegate.call(prompt);
        span.setAttribute("llm.output_tokens", estimateTokens(result));
        return result;
    } finally {
        span.end();
    }
}
```

### 5.4 看 Trace 输出

在 Jaeger / Tempo UI 上：

```
[agent.run 7.8s]  query="查苹果Q3营收"
├── [llm.call 1.2s]  model=deepseek-v3  in=800 out=120
├── [tool.searchSchema 80ms]
├── [llm.call 1.5s]  in=2000 out=200
├── [tool.executeSql 230ms]  sql="SELECT revenue..."
├── [llm.call 1.8s]  in=2500 out=400
└── [llm.call 1.4s]  in=3000 out=150  (final answer)
```

**一眼看出**：LLM 调用占 6s（4 次），工具调用占 0.3s，优化方向就是减少 LLM 轮数。

### 6.2 MDC 注入 trace ID

```java
@Component
public class TraceIdFilter implements WebFilter {
    @Override
    public Mono<Void> filter(ServerWebExchange ex, WebFilterChain chain) {
        String traceId = UUID.randomUUID().toString();
        MDC.put("trace_id", traceId);
        MDC.put("user_id", getUserId(ex));
        return chain.filter(ex)
            .doFinally(s -> MDC.clear());
    }
}
```

## 常见问题 Q&A

**Q1：Prometheus 采样间隔多少合适？**

A：**15 秒**。10 秒太频繁（存储压力大），30 秒太慢（告警延迟）。Agent 这种长尾场景建议用直方图 + P99 告警，别用平均值。

**Q2：Trace 采样率怎么定？**

A：开发期 100%，上线后 10%。关键路径（错误 / 慢请求）100% 采样。可以配 `parent_based` 采样：父 Span 决定子 Span 是否采样，保证链路完整。

**Q3：日志里能放用户 query 吗？**

A：**敏感字段必须脱敏**（手机号 / 身份证 / 邮箱 / 卡号）。建议加 `LogSanitizer`，在写日志前正则替换。Query 内容可以放，但要走加密存储，PII 数据保留期不超过 90 天。

**Q4：LLM 调用失败怎么区分错误类型？**

A：错误码细分：
- `rate_limit`：限流，指数退避重试
- `timeout`：超时，降级到小模型或返回兜底
- `content_filter`：内容审查，返回「无法处理此类问题」
- `network`：网络，重试 3 次
- `invalid_request`：参数错，告警人工介入

## 本章小结

- **三层观测缺一不可**：Metrics（有什么问题）+ Traces（哪一段）+ Logs（为什么）
- **质量指标比性能指标重要**：用户满意度、工具成功率、LLM 错误率才是 Agent 的命脉
- **OpenTelemetry 是标配**：自定义 Span 看完整 Agent 调用链，定位 LLM 多轮慢
- **告警先于优化**：先配告警发现问题，再做 Ch28 的优化
