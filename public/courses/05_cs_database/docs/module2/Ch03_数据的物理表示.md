## 3. 核心概念

### 3.1 从表到字节：数据库存储的本质

关系型数据库的核心任务之一，是把"逻辑上的表格"映射到"物理上的字节序列"。

```
逻辑层（用户视角）：
┌────┬────────┬───────┐
│ id │  name  │ score │
├────┼────────┼───────┤
│  1 │ Alice  │  95   │
│  2 │ Bob    │  87   │
└────┴────────┴───────┘

物理层（磁盘视角）：
[00 00 00 01] [00 05] [41 6C 69 63 65] [00 00 00 5F]
  id=1          len=5   "Alice"(UTF-8)    score=95
```

这个映射过程就是**序列化（Serialization）**。反过来，从字节恢复成行数据，叫**反序列化（Deserialization）**。

### 3.2 类型系统（Type System）

数据库需要一个类型系统来描述每一列的数据类型。JimSQL 支持三种基础类型：

| 类型      | Java 表示 | 字节宽度         | 说明                         |
|-----------|-----------|------------------|------------------------------|
| `INT`     | `int`     | 4 字节（固定）   | 32位有符号整数               |
| `BOOLEAN` | `boolean` | 1 字节（固定）   | 0=false, 1=true              |
| `VARCHAR` | `String`  | 2+N 字节（变长） | 前2字节存长度，后N字节存内容 |

```java
public enum Type {
    INT,
    BOOLEAN,
    VARCHAR;

    // 定长类型的字节宽度（VARCHAR 返回 -1，表示变长）
    public int getFixedSize() {
        switch (this) {
            case INT:     return 4;
            case BOOLEAN: return 1;
            case VARCHAR: return -1;  // 变长
            default: throw new IllegalStateException();
        }
    }

    public boolean isFixedLength() {
        return this != VARCHAR;
    }
}
```

**关键设计决策**：为什么 VARCHAR 前面要存长度？

因为读取时必须知道"这个字符串到哪里结束"。有两种方案：
- **定界符方案**：用特殊字符（如 `\0`）标记结束——但字符串内容本身可能包含该字符
- **长度前缀方案**：先存长度，再存内容——读取时先读2字节得到长度，再读对应字节数

JimSQL 采用长度前缀方案，更安全、更高效。

### 3.3 字段值（Field）

每个字段值需要一个统一的抽象，无论是 INT 还是 VARCHAR，都能被统一处理：

```java
// 字段值的抽象接口
public interface Field {
    Type getType();
    byte[] serialize();
    String toString();
}

// INT 字段
public class IntField implements Field {
    private final int value;

    public IntField(int value) { this.value = value; }

    @Override
    public Type getType() { return Type.INT; }

    @Override
    public byte[] serialize() {
        // 大端序：高位字节在前
        return new byte[] {
            (byte)(value >> 24),
            (byte)(value >> 16),
            (byte)(value >> 8),
            (byte)(value)
        };
    }
}

// VARCHAR 字段
public class StringField implements Field {
    private final String value;

    public StringField(String value) { this.value = value; }

    @Override
    public Type getType() { return Type.VARCHAR; }

    @Override
    public byte[] serialize() {
        byte[] strBytes = value.getBytes(StandardCharsets.UTF_8);
        int len = strBytes.length;
        // 格式：[2字节长度][N字节内容]
        byte[] result = new byte[2 + len];
        result[0] = (byte)(len >> 8);
        result[1] = (byte)(len);
        System.arraycopy(strBytes, 0, result, 2, len);
        return result;
    }
}
```

### 3.4 Schema（TupleDesc）：表的结构描述

Schema 描述了一张表有哪些列、每列叫什么名字、是什么类型。在 JimSQL 中叫 `TupleDesc`（Tuple Descriptor，元组描述符）。

```
TupleDesc for table "students":
┌─────────┬──────────┬──────────┬──────────────┐
│ 列索引  │  列名    │  类型    │  偏移量      │
├─────────┼──────────┼──────────┼──────────────┤
│    0    │  id      │  INT     │  0           │
│    1    │  name    │ VARCHAR  │  4           │
│    2    │  score   │  INT     │  动态计算    │
└─────────┴──────────┴──────────┴──────────────┘
```

注意：由于 VARCHAR 是变长的，`score` 的偏移量在序列化时是动态的，不能预先固定。这是变长字段带来的核心复杂性。

```java
public class TupleDesc {
    public static class ColumnDesc {
        public final String name;
        public final Type type;

        public ColumnDesc(String name, Type type) {
            this.name = name;
            this.type = type;
        }
    }

    private final ColumnDesc[] columns;

    public TupleDesc(ColumnDesc[] columns) {
        this.columns = columns;
    }

    public int numColumns() { return columns.length; }

    public String getColumnName(int i) { return columns[i].name; }

    public Type getColumnType(int i) { return columns[i].type; }

    // 查找列索引（按名称）
    public int fieldNameToIndex(String name) {
        for (int i = 0; i < columns.length; i++) {
            if (columns[i].name.equals(name)) return i;
        }
        throw new NoSuchElementException("Column not found: " + name);
    }
}
```

### 3.5 Tuple（行）：数据的内存表示

Tuple 是一行数据在内存中的表示，包含一个 `Field` 数组和对应的 `TupleDesc`：

```java
public class Tuple {
    private final TupleDesc schema;
    private final Field[] fields;

    public Tuple(TupleDesc schema, Field[] fields) {
        if (fields.length != schema.numColumns()) {
            throw new IllegalArgumentException("Field count mismatch");
        }
        this.schema = schema;
        this.fields = fields;
    }

    public Field getField(int i) { return fields[i]; }

    public TupleDesc getSchema() { return schema; }

    public int numFields() { return fields.length; }
}
```

### 3.6 序列化：Tuple → byte[]

序列化的目标是把 Tuple 转换成一段连续的字节，可以写入磁盘。

**字节布局设计**：

```
对于 (id=1, name="Alice", score=95)：

偏移  内容
0     [00 00 00 01]        → id = 1 (INT, 4字节)
4     [00 05]              → name 长度 = 5 (2字节)
6     [41 6C 69 63 65]     → "Alice" (5字节 UTF-8)
11    [00 00 00 5F]        → score = 95 (INT, 4字节)

总计：15字节
```

```java
public byte[] serialize() {
    // 第一步：计算总字节数
    int totalSize = 0;
    for (Field f : fields) {
        totalSize += f.serialize().length;
    }

    // 第二步：逐字段写入
    byte[] result = new byte[totalSize];
    int offset = 0;
    for (Field f : fields) {
        byte[] fieldBytes = f.serialize();
        System.arraycopy(fieldBytes, 0, result, offset, fieldBytes.length);
        offset += fieldBytes.length;
    }
    return result;
}
```

### 3.7 反序列化：byte[] → Tuple

反序列化需要 Schema 的配合，因为只有知道每列的类型，才能正确解析字节：

```java
public static Tuple deserialize(byte[] data, TupleDesc schema) {
    Field[] fields = new Field[schema.numColumns()];
    int offset = 0;

    for (int i = 0; i < schema.numColumns(); i++) {
        Type type = schema.getColumnType(i);
        switch (type) {
            case INT: {
                // 读4字节，大端序转 int
                int value = ((data[offset]   & 0xFF) << 24)
                          | ((data[offset+1] & 0xFF) << 16)
                          | ((data[offset+2] & 0xFF) << 8)
                          |  (data[offset+3] & 0xFF);
                fields[i] = new IntField(value);
                offset += 4;
                break;
            }
            case BOOLEAN: {
                fields[i] = new BooleanField(data[offset] != 0);
                offset += 1;
                break;
            }
            case VARCHAR: {
                // 先读2字节长度
                int len = ((data[offset] & 0xFF) << 8) | (data[offset+1] & 0xFF);
                offset += 2;
                // 再读 len 字节内容
                String value = new String(data, offset, len, StandardCharsets.UTF_8);
                fields[i] = new StringField(value);
                offset += len;
                break;
            }
        }
    }
    return new Tuple(schema, fields);
}
```

**关键点**：`& 0xFF` 的作用是将 `byte`（有符号，范围 -128~127）转换为无符号整数（0~255），避免符号扩展导致的错误。

### 3.8 定长 vs 变长：存储差异对比

```
定长字段（INT）：
┌──────────────────────────────────────────────┐
│ 偏移量固定，可以随机访问第 N 个字段          │
│ 例：第3列偏移 = 0 + 4 + 4 = 8（已知）       │
└──────────────────────────────────────────────┘

变长字段（VARCHAR）：
┌──────────────────────────────────────────────┐
│ 偏移量动态，必须顺序扫描才能定位字段         │
│ 例：第3列偏移 = 4 + 2 + len("Alice") = 11   │
│     但 len 只有读完第2列才知道               │
└──────────────────────────────────────────────┘
```

这就是为什么很多数据库（包括 PostgreSQL）会把变长字段放在行的末尾，或者使用额外的"偏移量数组"来支持随机访问。

### 4.2 Field 接口与三种实现

```java
interface Field {
    Type getType();
    byte[] serialize();
}

// INT 字段：4字节大端序
class IntField implements Field {
    final int value;

    IntField(int value) { this.value = value; }

    @Override
    public Type getType() { return Type.INT; }

    @Override
    public byte[] serialize() {
        return new byte[] {
            (byte)(value >> 24),
            (byte)(value >> 16),
            (byte)(value >> 8),
            (byte)(value)
        };
    }

    @Override
    public String toString() { return String.valueOf(value); }
}

// BOOLEAN 字段：1字节，0或1
class BooleanField implements Field {
    final boolean value;

    BooleanField(boolean value) { this.value = value; }

    @Override
    public Type getType() { return Type.BOOLEAN; }

    @Override
    public byte[] serialize() {
        return new byte[] { value ? (byte)1 : (byte)0 };
    }

    @Override
    public String toString() { return String.valueOf(value); }
}

// VARCHAR 字段：2字节长度 + N字节UTF-8内容
class StringField implements Field {
    final String value;

    StringField(String value) { this.value = value; }

    @Override
    public Type getType() { return Type.VARCHAR; }

    @Override
    public byte[] serialize() {
        byte[] strBytes = value.getBytes(StandardCharsets.UTF_8);
        int len = strBytes.length;
        byte[] result = new byte[2 + len];
        result[0] = (byte)(len >> 8);
        result[1] = (byte)(len & 0xFF);
        System.arraycopy(strBytes, 0, result, 2, len);
        return result;
    }

    @Override
    public String toString() { return value; }
}
```

### 4.3 TupleDesc 完整实现

```java
class TupleDesc {
    static class ColumnDesc {
        final String name;
        final Type type;

        ColumnDesc(String name, Type type) {
            this.name = name;
            this.type = type;
        }
    }

    private final ColumnDesc[] columns;

    TupleDesc(ColumnDesc[] columns) {
        this.columns = columns.clone();
    }

    // 工厂方法：快速创建
    static TupleDesc of(String[] names, Type[] types) {
        if (names.length != types.length) {
            throw new IllegalArgumentException("names and types length mismatch");
        }
        ColumnDesc[] cols = new ColumnDesc[names.length];
        for (int i = 0; i < names.length; i++) {
            cols[i] = new ColumnDesc(names[i], types[i]);
        }
        return new TupleDesc(cols);
    }

    int numColumns() { return columns.length; }

    String getColumnName(int i) { return columns[i].name; }

    Type getColumnType(int i) { return columns[i].type; }

    int fieldNameToIndex(String name) {
        for (int i = 0; i < columns.length; i++) {
            if (columns[i].name.equals(name)) return i;
        }
        throw new NoSuchElementException("Column not found: " + name);
    }

    @Override
    public String toString() {
        StringBuilder sb = new StringBuilder("TupleDesc{");
        for (int i = 0; i < columns.length; i++) {
            if (i > 0) sb.append(", ");
            sb.append(columns[i].name).append(":").append(columns[i].type);
        }
        sb.append("}");
        return sb.toString();
    }
}
```

### 4.4 Tuple 完整实现（含序列化/反序列化）

```java
class Tuple {
    private final TupleDesc schema;
    private final Field[] fields;

    Tuple(TupleDesc schema, Field[] fields) {
        if (fields.length != schema.numColumns()) {
            throw new IllegalArgumentException(
                "Expected " + schema.numColumns() + " fields, got " + fields.length);
        }
        this.schema = schema;
        this.fields = fields.clone();
    }

    Field getField(int i) { return fields[i]; }

    TupleDesc getSchema() { return schema; }

    int numFields() { return fields.length; }

    // 序列化：Tuple → byte[]
    byte[] serialize() {
        byte[][] serializedFields = new byte[fields.length][];
        int totalSize = 0;
        for (int i = 0; i < fields.length; i++) {
            serializedFields[i] = fields[i].serialize();
            totalSize += serializedFields[i].length;
        }

        byte[] result = new byte[totalSize];
        int offset = 0;
        for (byte[] fb : serializedFields) {
            System.arraycopy(fb, 0, result, offset, fb.length);
            offset += fb.length;
        }
        return result;
    }

    // 反序列化：byte[] → Tuple（需要 Schema 指导）
    static Tuple deserialize(byte[] data, TupleDesc schema) {
        Field[] fields = new Field[schema.numColumns()];
        int offset = 0;

        for (int i = 0; i < schema.numColumns(); i++) {
            Type type = schema.getColumnType(i);
            switch (type) {
                case INT: {
                    int value = ((data[offset]   & 0xFF) << 24)
                              | ((data[offset+1] & 0xFF) << 16)
                              | ((data[offset+2] & 0xFF) << 8)
                              |  (data[offset+3] & 0xFF);
                    fields[i] = new IntField(value);
                    offset += 4;
                    break;
                }
                case BOOLEAN: {
                    fields[i] = new BooleanField(data[offset] != 0);
                    offset += 1;
                    break;
                }
                case VARCHAR: {
                    int len = ((data[offset] & 0xFF) << 8) | (data[offset+1] & 0xFF);
                    offset += 2;
                    String value = new String(data, offset, len, StandardCharsets.UTF_8);
                    fields[i] = new StringField(value);
                    offset += len;
                    break;
                }
                default:
                    throw new IllegalStateException("Unknown type: " + type);
            }
        }
        return new Tuple(schema, fields);
    }

    @Override
    public String toString() {
        StringBuilder sb = new StringBuilder("(");
        for (int i = 0; i < fields.length; i++) {
            if (i > 0) sb.append(", ");
            sb.append(fields[i].toString());
        }
        sb.append(")");
        return sb.toString();
    }
}
```

## 5. 实践练习

### 练习1（基础）：添加 FLOAT 类型

在现有类型系统中添加 `FLOAT` 类型（对应 Java `float`，4字节）：

1. 在 `Type` 枚举中添加 `FLOAT`，`getFixedSize()` 返回 4
2. 实现 `FloatField` 类，序列化时使用 `Float.floatToIntBits()` 转换为整数再存储
3. 在 `Tuple.deserialize()` 中添加 `FLOAT` 的反序列化逻辑
4. 测试：创建包含 FLOAT 字段的 Tuple，序列化后反序列化，验证值不变

**提示**：`Float.floatToIntBits(3.14f)` 返回 IEEE 754 表示的整数，`Float.intBitsToFloat(bits)` 还原。

### 练习2（进阶）：实现 Tuple 的相等性比较

实现 `Tuple.equals(Object other)` 方法：

1. 两个 Tuple 相等，当且仅当它们的 Schema 相同且所有字段值相等
2. 同时实现 `hashCode()`（基于所有字段的哈希值）
3. 为 `IntField`、`StringField`、`BooleanField` 分别实现 `equals()` 和 `hashCode()`
4. 测试：创建两个内容相同的 Tuple，验证 `equals()` 返回 true；修改一个字段，验证返回 false

### 练习3（挑战）：支持 NULL 值

真实数据库中，字段可以为 NULL。设计并实现 NULL 值的序列化方案：

1. 在 Tuple 的序列化格式中，在所有字段数据之前添加一个"NULL 位图"（每个字段占1位）
2. 如果某字段为 NULL，位图对应位置为1，且该字段不占用任何字节
3. 反序列化时，先读取 NULL 位图，再按位图决定是否读取字段数据
4. 实现 `NullField` 类表示 NULL 值
5. 测试：创建含 NULL 字段的 Tuple，序列化后反序列化，验证 NULL 字段正确还原

**提示**：N 个字段需要 `(N + 7) / 8` 字节的位图。

## 6. 常见问题

**Q1：为什么用大端序而不是小端序？**

A：大端序（高位字节在前）是网络字节序的标准，也是 Java 的默认字节序（`ByteBuffer` 默认大端）。数据库文件通常需要跨平台读取，使用大端序可以避免在不同 CPU 架构（x86 小端 vs ARM 大端）之间的兼容问题。JimSQL 统一使用大端序，与 Java 的 `DataOutputStream` 行为一致。

**Q2：VARCHAR 最大长度为什么用2字节存储？**

A：2字节可以表示 0~65535，即最大 64KB 的字符串。这是一个工程权衡：1字节只能存255字节（太小），4字节可以存4GB（太浪费）。MySQL 的 VARCHAR 也使用1或2字节存储长度（根据最大长度自动选择）。JimSQL 简化为固定2字节。

**Q3：`& 0xFF` 为什么必须写？**

A：Java 的 `byte` 是有符号类型，范围 -128~127。当字节值为 `0xFF`（十进制255）时，Java 会把它解释为 -1。在做位运算时，-1 会被符号扩展为 `0xFFFFFFFF`，导致计算错误。`& 0xFF` 把它截断为 `0x000000FF`（255），确保按无符号字节处理。

**Q4：Schema 和 Tuple 为什么要分开设计？**

A：这是"元数据与数据分离"的设计原则。一张表有百万行数据，但 Schema 只有一份。如果每个 Tuple 都存一份 Schema，内存浪费极大。分离后，所有 Tuple 共享同一个 TupleDesc 对象，只需存一个引用（8字节指针）。这也是面向对象设计中"享元模式（Flyweight）"的体现。

- **Field 层次**：`IntField`、`BooleanField`、`StringField` 封装了各类型的序列化逻辑
- **TupleDesc**：描述表结构（列名+列类型），是 Schema 的内存表示
- **Tuple**：一行数据的内存表示，持有 Field 数组和 TupleDesc 引用
- **序列化协议**：INT=4字节大端，BOOLEAN=1字节，VARCHAR=2字节长度+N字节内容

下一章（Ch04）将把 Tuple 组织进**页（Page）**，实现磁盘级别的数据组织。

```
本章知识图谱：

Type ──────────────────────────────────────────────────┐
  ├── INT (4B)                                          │
  ├── BOOLEAN (1B)                                      │
  └── VARCHAR (2+NB)                                    │
                                                        ▼
Field ──────────────────────────────────────────── serialize()
  ├── IntField                                          │
  ├── BooleanField                                      │
  └── StringField                                       │
                                                        ▼
TupleDesc ──────────────────────────────────────── 列名+类型
  └── ColumnDesc[]                                      │
                                                        ▼
Tuple ──────────────────────────────── serialize() / deserialize()
  ├── TupleDesc (引用)
  └── Field[]
```
