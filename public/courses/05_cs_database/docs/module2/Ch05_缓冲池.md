## 核心概念

### 1. 内存与磁盘的速度鸿沟

现代计算机的存储层次结构中，不同层级的访问速度差异巨大：

| 存储层级 | 典型访问延迟 | 容量（典型） |
|----------|-------------|-------------|
| CPU 寄存器 | < 1 ns     | 几百字节    |
| L1/L2 缓存 | 1-10 ns    | 几 MB       |
| 内存（DRAM）| 50-100 ns  | 几十 GB     |
| SSD        | 0.1-1 ms   | 几百 GB     |
| HDD        | 5-10 ms    | 几 TB       |

内存比 SSD 快约 1000 倍，比 HDD 快约 100000 倍。如果每次读写一行数据都触发磁盘 I/O，数据库性能将极其低下。

**缓冲池（Buffer Pool）** 就是数据库在内存中维护的一块区域，用来缓存最近访问过的页。当需要读取某一页时，先检查缓冲池：

- **缓存命中（Cache Hit）**：页已在内存中，直接返回，无需磁盘 I/O
- **缓存未命中（Cache Miss）**：页不在内存中，从磁盘读取，放入缓冲池

### 2. BufferPool 的核心操作

```
getPage(pageId)
  ├── 命中：直接返回内存中的页
  └── 未命中：从磁盘读取 → 放入缓冲池 → 如果缓冲池满了，先淘汰一页

markDirty(pageId)
  └── 标记该页已被修改（脏页），淘汰时必须写回磁盘

flushPage(pageId)
  └── 将脏页写回磁盘，清除脏页标记

flushAll()
  └── 将所有脏页写回磁盘（通常在事务提交或数据库关闭时调用）
```

### 3. LRU 置换策略

当缓冲池满了，需要淘汰一页为新页腾出空间。常见的置换策略有：

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| FIFO | 淘汰最早进入的页 | 实现简单 | 不考虑访问频率 |
| LRU  | 淘汰最近最少使用的页 | 符合局部性原理 | 需要维护访问顺序 |
| Clock | LRU 的近似实现 | 开销小 | 精度略低 |

**LRU（Least Recently Used）** 的核心思想：如果一个页最近被访问过，它在近期被再次访问的概率更高；反之，长时间未被访问的页可以优先淘汰。

Java 的 `LinkedHashMap` 支持按访问顺序排序（`accessOrder=true`），天然适合实现 LRU：

```java
// accessOrder=true：每次 get/put 都会把该条目移到链表尾部
// 链表头部 = 最久未访问（LRU 候选）
// 链表尾部 = 最近访问
LinkedHashMap<PageId, HeapPage> cache = new LinkedHashMap<>(capacity, 0.75f, true);
```

### 4. 脏页管理

**脏页（Dirty Page）** 是指在内存中被修改过、但尚未写回磁盘的页。

脏页管理的关键规则：**脏页在被淘汰出缓冲池之前，必须先写回磁盘**。否则修改会丢失。

```
淘汰流程：
1. 找到 LRU 候选页
2. 检查该页是否是脏页
3. 如果是脏页 → 先写回磁盘（flush）→ 再从缓冲池移除
4. 如果不是脏页 → 直接从缓冲池移除
```

### 5. Pin/Unpin 语义

**Pin（固定）** 表示某个事务或操作正在使用这个页，缓冲池不能淘汰它。**Unpin（解除固定）** 表示使用完毕，缓冲池可以在需要时淘汰它。

```
pin 计数器（pinCount）：
- getPage() 时：pinCount++
- 使用完毕后：pinCount--（unpin）
- 淘汰时：只能淘汰 pinCount == 0 的页
```

如果所有页都被 pin 住，缓冲池无法淘汰任何页，此时 getPage() 应该抛出异常（缓冲池耗尽）。

## 代码讲解

### 5.1 LRU 缓存的核心实现

```java
public class LRUCache<K, V> {
    private final int capacity;
    // accessOrder=true：每次访问都把条目移到链表尾部
    private final LinkedHashMap<K, V> map;

    public LRUCache(int capacity) {
        this.capacity = capacity;
        this.map = new LinkedHashMap<>(capacity, 0.75f, true) {
            @Override
            protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
                // 当容量超限时，自动移除最久未访问的条目
                return size() > capacity;
            }
        };
    }

    public V get(K key) {
        return map.getOrDefault(key, null);
    }

    public void put(K key, V value) {
        map.put(key, value);
    }

    // 返回最久未访问的 key（LRU 候选）
    public K getLRUKey() {
        return map.keySet().iterator().next();
    }
}
```

### 5.2 BufferPool 的完整实现

```java
public class BufferPool {
    private final int capacity;           // 最大缓存页数
    private final Map<PageId, HeapPage> pages;    // pageId -> 页
    private final Set<PageId> dirtyPages;         // 脏页集合
    private final Map<PageId, Integer> pinCounts; // pin 计数

    public BufferPool(int capacity) {
        this.capacity = capacity;
        // accessOrder=true 实现 LRU
        this.pages = new LinkedHashMap<>(capacity, 0.75f, true);
        this.dirtyPages = new HashSet<>();
        this.pinCounts = new HashMap<>();
    }

    public HeapPage getPage(PageId pageId, HeapFile file) throws IOException {
        if (pages.containsKey(pageId)) {
            // 缓存命中：更新访问顺序（LinkedHashMap 自动处理）
            pinCounts.merge(pageId, 1, Integer::sum);
            return pages.get(pageId);
        }
        // 缓存未命中：从磁盘读取
        if (pages.size() >= capacity) {
            evict(); // 淘汰一页
        }
        HeapPage page = file.readPage(pageId.getPageNo());
        pages.put(pageId, page);
        pinCounts.put(pageId, 1);
        return page;
    }

    public void markDirty(PageId pageId) {
        dirtyPages.add(pageId);
    }

    public void unpin(PageId pageId) {
        pinCounts.computeIfPresent(pageId, (k, v) -> v > 0 ? v - 1 : 0);
    }

    public void flushPage(PageId pageId, HeapFile file) throws IOException {
        if (dirtyPages.contains(pageId)) {
            file.writePage(pages.get(pageId));
            dirtyPages.remove(pageId);
        }
    }

    // 淘汰最久未访问且未被 pin 的页
    private void evict() throws IOException {
        for (PageId candidate : pages.keySet()) {
            if (pinCounts.getOrDefault(candidate, 0) == 0) {
                // 脏页先写回磁盘（此处简化：直接移除，完整实现需要 file 引用）
                dirtyPages.remove(candidate);
                pages.remove(candidate);
                pinCounts.remove(candidate);
                return;
            }
        }
        throw new RuntimeException("缓冲池耗尽：所有页都被 pin 住");
    }
}
```

### 5.3 缓存命中率的意义

```java
// 统计缓存命中率
int hits = 0, misses = 0;

HeapPage getPage(PageId pageId) {
    if (cache.containsKey(pageId)) {
        hits++;
        return cache.get(pageId);
    }
    misses++;
    // 从磁盘读取...
}

double hitRate() {
    return (double) hits / (hits + misses);
}
// 命中率 90% 意味着 90% 的请求不需要磁盘 I/O
```

## 常见问题

### Q1: 缓冲池容量应该设多大？

通常设为可用内存的 70-80%。太小会导致频繁淘汰（缓存抖动），太大会挤占操作系统和其他进程的内存。MySQL InnoDB 的 `innodb_buffer_pool_size` 默认是 128MB，生产环境通常设为物理内存的 50-70%。

### Q2: 为什么 LRU 对顺序扫描效果差？

顺序扫描会依次访问每一页，每页只访问一次。LRU 缓存对这种模式没有帮助——每次都是缓存未命中，还会把热点页挤出缓存。这个问题叫做"缓存污染"。PostgreSQL 和 MySQL 对顺序扫描使用特殊策略（如 MRU 或 Ring Buffer）来避免污染缓冲池。

### Q3: 脏页写回时机有哪些选择？

- **淘汰时写回**：只在页被淘汰时写回，I/O 次数少，但崩溃时可能丢失数据
- **定期检查点**：每隔一段时间把所有脏页写回（Checkpoint），平衡性能与安全性
- **事务提交时写回**：每次事务提交都写回相关脏页，安全但 I/O 开销大

JimSQL 采用最简单的"淘汰时写回"策略。

### Q4: pin/unpin 忘记调用会怎样？

忘记 unpin 会导致页永远无法被淘汰，缓冲池最终耗尽，所有新的 getPage 请求都会失败。这类似于内存泄漏。生产数据库通常用 RAII 或 try-finally 确保 unpin 一定被调用。

## 本章小结

本章实现了数据库存储层的关键优化组件：

- **BufferPool**：在内存中缓存磁盘页，避免重复 I/O
- **LRU 置换**：基于 `LinkedHashMap(accessOrder=true)` 实现，淘汰最久未访问的页
- **脏页管理**：修改过的页在淘汰前必须写回磁盘，保证数据不丢失
- **Pin/Unpin**：防止正在使用的页被淘汰，避免数据竞争

缓冲池是数据库性能的核心。一个设计良好的缓冲池可以让 90% 以上的页访问在内存中完成，将磁盘 I/O 降低一个数量级。下一章的 SeqScan 将通过缓冲池访问 HeapFile，完成存储层的最后一块拼图。
