## 核心概念

### 1. 迭代器模型（Volcano/Iterator Model）

1990 年，Goetz Graefe 在论文《Volcano — An Extensible and Parallel Query Evaluation System》中提出了**迭代器模型**，也叫 Volcano 模型或 Pipeline 模型。这是现代关系型数据库查询执行引擎的基础架构。

迭代器模型的核心思想：**每个查询算子都实现同一个接口，上层算子通过调用下层算子的 `next()` 来驱动数据流动**。

```
DbIterator 接口：
  open()    → 初始化，准备开始迭代
  hasNext() → 是否还有下一条 Tuple
  next()    → 返回下一条 Tuple
  close()   → 释放资源，结束迭代
```

一个典型的查询执行树：

```
Project（投影）
  └── Filter（过滤：age > 18）
        └── SeqScan（顺序扫描 students 表）
```

执行时，Project 调用 Filter 的 `next()`，Filter 调用 SeqScan 的 `next()`，SeqScan 从磁盘读取 Tuple。数据像流水线一样从底层流向顶层，**不需要把中间结果全部存入内存**。

### 2. 为什么用迭代器而不是物化

**物化（Materialization）** 是指把中间结果全部计算出来存入内存，再传给上层算子。

| 方式 | 内存占用 | 延迟 | 适用场景 |
|------|----------|------|----------|
| 物化 | 高（需存全部中间结果） | 高（等全部计算完才返回） | 小数据集 |
| 迭代器 | 低（每次只处理一行） | 低（第一行很快返回） | 大数据集 |

对于一张有 1 亿行的表，物化需要把所有行加载到内存；迭代器只需要在内存中保留"当前正在处理的那一行"，内存占用极低。

### 3. RecordId：定位一条记录

`RecordId` 是一个二元组 `(pageId, slotNo)`，唯一标识表中的一条记录：

```
RecordId = (PageId(tableId=1, pageNo=3), slotNo=7)
→ 第 1 张表的第 3 页的第 7 个槽位
```

RecordId 的用途：
- **更新/删除**：通过 RecordId 直接定位到要修改的行，不需要全表扫描
- **索引**：B+ 树索引的叶节点存储的就是 `(key, RecordId)` 对
- **游标**：SeqScan 可以记录当前扫描到的 RecordId，支持暂停和恢复

### 4. SeqScan 的工作原理

SeqScan 是最基础的查询算子，它遍历 HeapFile 的所有页，对每一页遍历所有有效槽位，逐行返回 Tuple。

```
SeqScan.open()
  → 初始化：pageNo = 0, slotNo = -1
  → 从 BufferPool 获取第 0 页

SeqScan.next()
  → 在当前页找下一个有效槽位
  → 如果当前页扫描完，移到下一页
  → 返回当前槽位的 Tuple

SeqScan.close()
  → 释放对当前页的 pin
  → 重置状态
```

### 5. 迭代器的组合

迭代器的强大之处在于**可以任意组合**。每个算子只需要知道如何调用下层算子的 `next()`，不需要知道下层是什么：

```java
// Filter 算子：包装任意 DbIterator，过滤不满足条件的行
class Filter implements DbIterator {
    private final DbIterator child;    // 下层迭代器
    private final Predicate pred;      // 过滤条件

    public Tuple next() {
        while (child.hasNext()) {
            Tuple t = child.next();
            if (pred.test(t)) return t; // 满足条件才返回
        }
        return null;
    }
}

// 使用：Filter 包装 SeqScan
DbIterator scan = new SeqScan(schema, heapFile);
DbIterator filter = new Filter(scan, t -> ((IntField)t.getField(1)).value > 18);
filter.open();
while (filter.hasNext()) {
    System.out.println(filter.next());
}
filter.close();
```

### 6.2 DbIterator 接口

```java
public interface DbIterator {
    // 初始化迭代器，准备开始扫描
    void open() throws IOException;

    // 是否还有下一条 Tuple
    boolean hasNext();

    // 返回下一条 Tuple（调用前必须先调用 open()）
    Tuple next();

    // 重置迭代器到初始状态（不需要重新 open）
    void rewind() throws IOException;

    // 释放资源
    void close();

    // 返回该迭代器输出的 Schema
    TupleDesc getTupleDesc();
}
```

### 6.3 SeqScan 的完整实现

```java
public class SeqScan implements DbIterator {
    private final TupleDesc schema;
    private final HeapFile file;
    private int currentPageNo;      // 当前扫描到第几页
    private HeapPage currentPage;   // 当前页的引用
    private int currentSlot;        // 当前页内的槽位号
    private boolean opened;

    public SeqScan(TupleDesc schema, HeapFile file) {
        this.schema = schema;
        this.file = file;
    }

    @Override
    public void open() throws IOException {
        currentPageNo = 0;
        currentSlot = -1;
        currentPage = null;
        opened = true;
        // 加载第一页（如果文件非空）
        if (file.numPages() > 0) {
            currentPage = file.readPage(0);
        }
    }

    @Override
    public boolean hasNext() {
        if (!opened || currentPage == null) return false;
        // 在当前页找下一个有效槽位
        for (int s = currentSlot + 1; s < currentPage.getSlotCount(); s++) {
            if (currentPage.isSlotUsed(s)) return true;
        }
        // 当前页扫描完，检查后续页
        for (int p = currentPageNo + 1; p < file.numPages(); p++) {
            try {
                HeapPage page = file.readPage(p);
                for (int s = 0; s < page.getSlotCount(); s++) {
                    if (page.isSlotUsed(s)) return true;
                }
            } catch (IOException e) { break; }
        }
        return false;
    }

    @Override
    public Tuple next() {
        // 在当前页找下一个有效槽位
        for (int s = currentSlot + 1; s < currentPage.getSlotCount(); s++) {
            if (currentPage.isSlotUsed(s)) {
                currentSlot = s;
                try { return currentPage.getTuple(s); }
                catch (IOException e) { throw new RuntimeException(e); }
            }
        }
        // 当前页扫描完，移到下一页
        while (++currentPageNo < file.numPages()) {
            try {
                currentPage = file.readPage(currentPageNo);
                currentSlot = -1;
                for (int s = 0; s < currentPage.getSlotCount(); s++) {
                    if (currentPage.isSlotUsed(s)) {
                        currentSlot = s;
                        return currentPage.getTuple(s);
                    }
                }
            } catch (IOException e) { throw new RuntimeException(e); }
        }
        throw new NoSuchElementException("没有更多 Tuple");
    }

    @Override
    public void rewind() throws IOException {
        close();
        open();
    }

    @Override
    public void close() {
        opened = false;
        currentPage = null;
        currentPageNo = 0;
        currentSlot = -1;
    }

    @Override
    public TupleDesc getTupleDesc() { return schema; }
}
```

### 6.4 Filter 算子（演示迭代器组合）

```java
public class Filter implements DbIterator {
    private final DbIterator child;
    private final java.util.function.Predicate<Tuple> predicate;
    private Tuple next;

    public Filter(DbIterator child, java.util.function.Predicate<Tuple> predicate) {
        this.child = child;
        this.predicate = predicate;
    }

    @Override
    public void open() throws IOException {
        child.open();
        advance(); // 预取第一条满足条件的 Tuple
    }

    private void advance() {
        next = null;
        while (child.hasNext()) {
            Tuple t = child.next();
            if (predicate.test(t)) { next = t; break; }
        }
    }

    @Override
    public boolean hasNext() { return next != null; }

    @Override
    public Tuple next() {
        Tuple result = next;
        advance();
        return result;
    }

    @Override
    public void rewind() throws IOException { child.rewind(); advance(); }

    @Override
    public void close() { child.close(); next = null; }

    @Override
    public TupleDesc getTupleDesc() { return child.getTupleDesc(); }
}
```

## 常见问题

### Q1: open() 和 rewind() 有什么区别？

`open()` 是第一次初始化，分配资源（如从 BufferPool 获取页）。`rewind()` 是重置到初始状态，通常实现为 `close()` + `open()`，用于需要多次扫描同一张表的场景（如嵌套循环 Join 的内层表）。

### Q2: SeqScan 为什么不直接用 Java 的 Iterator 接口？

Java 的 `Iterator` 没有 `open()`、`close()` 和 `rewind()` 方法。数据库迭代器需要显式的生命周期管理：`open()` 时分配资源（pin 页），`close()` 时释放资源（unpin 页）。如果用 Java 原生 `Iterator`，资源管理会变得困难。

### Q3: SeqScan 扫描时，BufferPool 的作用是什么？

SeqScan 每次读取一页时，应该通过 BufferPool 的 `getPage()` 而不是直接调用 `HeapFile.readPage()`。这样如果同一页被多次访问（如嵌套循环 Join），BufferPool 可以直接从内存返回，避免重复磁盘 I/O。本章 Demo 为简化实现，直接调用 HeapFile，完整实现应接入 BufferPool。

### Q4: 如果表在扫描过程中被修改（插入/删除），SeqScan 会怎样？

这涉及并发控制（MVCC 或锁）。简单实现（如 JimSQL）不支持扫描中修改，完整数据库通过快照隔离或行锁来保证扫描结果的一致性。这是 Module 4（事务与并发）的内容。

## 本章小结

本章完成了存储层的最后一块拼图：

- **RecordId**：`(pageId, slotNo)` 二元组，唯一定位一条记录
- **DbIterator 接口**：`open/hasNext/next/rewind/close` 五个方法，定义查询算子的统一接口
- **SeqScan**：遍历 HeapFile 所有页的所有有效槽位，逐行返回 Tuple
- **迭代器组合**：Filter、Limit 等算子包装下层迭代器，形成查询执行树

迭代器模型是现代数据库查询引擎的基础。从 Ch03 到 Ch06，我们建立了完整的存储层栈：

```
SQL 查询
  ↓
DbIterator（SeqScan / Filter / Join）   ← 本章
  ↓
BufferPool（内存缓存）                   ← Ch05
  ↓
HeapFile（多页文件）                     ← Ch04
  ↓
HeapPage（固定大小页）                   ← Ch04
  ↓
Tuple / Field / TupleDesc               ← Ch03
  ↓
磁盘字节
```
