## 1. 一条 SQL 的完整旅程（回顾）

```
SELECT s.name, AVG(sc.grade)
FROM students s JOIN scores sc ON s.id = sc.student_id
WHERE s.dept = 'CS'
GROUP BY s.name
HAVING AVG(sc.grade) > 85
ORDER BY AVG(sc.grade) DESC
LIMIT 10;
```

```
1. Lexer (Ch07)
   → [SELECT][s.name][,][AVG][...][LIMIT][10]

2. Parser (Ch08)
   → SelectStatement AST

3. Binder (Ch09)
   → 验证 students, scores 表存在
   → 验证 name, dept, grade 列存在
   → 推导类型

4. Optimizer (Ch26-27)
   → 谓词下推: Filter(dept='CS') 下推到 SeqScan
   → 选择 HashJoin（students 较小，作为 Build 侧）
   → 估算代价，选择执行计划

5. Executor (Ch10-14)
   → Limit(10)
     └─ OrderBy(AVG DESC)
          └─ Filter(AVG > 85)
               └─ Aggregate(GROUP BY name, AVG(grade))
                    └─ HashJoin(s.id = sc.student_id)
                         ├─ Filter(dept='CS')
                         │    └─ SeqScan(students)
                         └─ SeqScan(scores)

6. Storage (Ch03-06)
   → BufferPool 管理页缓存
   → HeapFile 读取数据页
   → 磁盘 I/O

7. Index (Ch15-19)
   → 若 dept 列有索引，用 IndexScan 替代 SeqScan

8. Transaction (Ch20-22)
   → 读操作获取 S 锁 / 创建 Read View
   → MVCC 保证快照隔离

9. WAL (Ch23-25)
   → 写操作先写日志
   → 崩溃后 ARIES 三阶段恢复
```

## 6. 结语

从第一章的"数据库是什么"到第三十章的"扩展方向"，我们亲手实现了：

- **存储层**：Tuple 序列化、HeapPage 槽位图、BufferPool LRU
- **SQL 解析**：手写 Lexer、递归下降 Parser、Binder
- **执行引擎**：Volcano 模型、6 种算子
- **索引**：完整 B+ 树（插入/删除/范围查询）
- **事务**：2PL 死锁检测、MVCC 版本链
- **日志恢复**：WAL、ARIES 三阶段
- **查询优化**：谓词下推、直方图、代价估算

这 30 章覆盖了工业级数据库的所有核心模块。真实数据库（MySQL、PostgreSQL）在每个模块上都有数十年的工程积累，但原理是相通的。

**理解原理，才能驾驭工具。**

## 常见问题 Q&A

**Q1: 30 章学完了，真的理解数据库了吗？**
A: 理解了核心原理。存储引擎、查询处理、事务、恢复这四大模块都有了动手实现的经验。但生产数据库有大量工程细节（并发控制、分布式、高可用），需要继续学习。

**Q2: 课程中最重要的是哪些章节？**
A: Ch03（数据存储）、Ch08（Parser）、Ch16（B+ 树）、Ch22（MVCC）、Ch23（WAL）。这 5 章覆盖了数据库最核心的机制。

**Q3: 下一步推荐什么？**
A: 推荐阅读 SQLite 源码（代码质量极高），然后尝试参与开源数据库项目。JimSQL 是起点，不是终点。

## 10. JimSQL 已知局限与改进方向

| 局限 | 影响 | 改进方案 |
|------|------|---------|
| 单线程执行 | 无法利用多核 | 增加工作线程池 |
| 表级锁 | 并发度低 | 行级锁 + MVCC |
| 无查询缓存 | 重复查询每次执行 | LRU 查询缓存 |
| 无子查询 | SQL 表达力受限 | 改造 Parser + 子查询展开 |
| 无网络协议 | 只能嵌入式使用 | 实现 MySQL/PostgreSQL 协议 |
| 无统计信息自动收集 | 优化器决策可能过时 | 后台 ANALYZE 线程 |
| B+ 树无并发控制 | 多线程访问不安全 | 蟹行协议或 B-link 树 |
| 无复制 | 无高可用 | 主从复制 + Raft |
