## 核心概念

### 1. 全表扫描的代价

假设 students 表有 100 万行，每页存 100 行，共 10000 页。

执行 `SELECT * FROM students WHERE id = 999999`：

```
SeqScan 需要读取所有 10000 页
每页 4KB，共 40MB 磁盘 I/O
时间复杂度：O(N)，N = 总行数
```

如果有索引：

```
B+树高度 ≈ log_100(1000000) ≈ 3 层
只需读取 3 个页（根节点 + 中间节点 + 叶子节点）
时间复杂度：O(log N)
```

**差距**：10000 次 I/O → 3 次 I/O，提升 3000 倍。

### 2. 索引的本质

索引是一种**辅助数据结构**，它：
1. 存储键值（被索引的列）和对应的行位置（PageId + SlotId）
2. 以某种有序或可快速查找的方式组织
3. 独立于原始数据文件存储（`.idx` 文件）

```
原始数据（students.db）：
  Page 0: [(1,张三,90), (2,李四,75), (3,王五,88), ...]
  Page 1: [(101,赵六,62), ...]

索引（students_id.idx）：
  1 → (Page 0, Slot 0)
  2 → (Page 0, Slot 1)
  3 → (Page 0, Slot 2)
  101 → (Page 1, Slot 0)
  ...（有序排列）
```

### 3. 三种主流索引结构对比

#### 哈希索引（Hash Index）

```
原理：key → hash(key) → bucket → 行位置
查找：O(1) 平均
范围查询：不支持（哈希后无序）
适用：等值查询（WHERE id = 5）
```

#### B+ 树（B+ Tree）

```
原理：多路平衡搜索树，叶子节点用链表连接
查找：O(log N)
范围查询：支持（叶子链表顺序遍历）
适用：等值查询 + 范围查询（WHERE score BETWEEN 80 AND 90）
```

#### LSM Tree（Log-Structured Merge Tree）

```
原理：写入先到内存（MemTable），定期刷盘合并
写入：O(1) 内存写，极快
读取：需要查多层，较慢
适用：写多读少（如日志系统、时序数据库）
代表：RocksDB、LevelDB、Cassandra
```

#### 对比表

| 特性 | 哈希索引 | B+ 树 | LSM Tree |
|------|---------|-------|---------|
| 等值查询 | O(1) | O(log N) | O(log N) |
| 范围查询 | 不支持 | O(log N + K) | O(log N + K) |
| 写入 | O(1) | O(log N) | O(1) 内存 |
| 磁盘空间 | 中 | 中 | 高（多层） |
| 适用场景 | 等值查询为主 | 通用 OLTP | 写多读少 |

**JimSQL 选择 B+ 树**：因为它同时支持等值查询和范围查询，是 OLTP 数据库的标准选择（MySQL InnoDB、PostgreSQL 都用 B+ 树）。

### 4. 索引的代价

索引不是免费的：

| 代价 | 说明 |
|------|------|
| 空间 | 索引文件额外占用磁盘空间 |
| 写入变慢 | INSERT/UPDATE/DELETE 需要同步维护索引 |
| 维护成本 | 索引越多，写入越慢 |

**原则**：不是所有列都需要索引。只对高选择性（cardinality 高）、频繁查询的列建索引。

### 5. 索引的分类

```
按结构：哈希索引 / B+树索引 / 全文索引 / 空间索引
按列数：单列索引 / 复合索引（多列）
按唯一性：唯一索引（UNIQUE）/ 普通索引
按存储：聚簇索引（数据按索引顺序存储）/ 非聚簇索引（索引与数据分离）
```

**聚簇索引 vs 非聚簇索引**：

```
聚簇索引（InnoDB 主键）：
  叶子节点直接存储完整行数据
  查主键：一次 B+树查找即可
  查非主键：需要"回表"（先查二级索引，再查主键索引）

非聚簇索引（MyISAM / JimSQL）：
  叶子节点存储 (key, PageId, SlotId)
  查询时需要根据 PageId+SlotId 再读一次数据页
```

## 代码讲解

### 15.1 RecordId：行的物理地址

索引的叶子节点存储的是行的物理地址，用 `RecordId` 表示：

```java
/**
 * 行的物理地址：(pageId, slotId)
 * pageId: 数据在哪一页
 * slotId: 在该页的哪个槽位
 */
public class RecordId {
    private final int pageId;
    private final int slotId;

    public RecordId(int pageId, int slotId) {
        this.pageId = pageId;
        this.slotId = slotId;
    }

    public int getPageId() { return pageId; }
    public int getSlotId() { return slotId; }

    @Override
    public String toString() {
        return "(" + pageId + "," + slotId + ")";
    }

    @Override
    public boolean equals(Object o) {
        if (!(o instanceof RecordId)) return false;
        RecordId r = (RecordId) o;
        return pageId == r.pageId && slotId == r.slotId;
    }

    @Override
    public int hashCode() {
        return 31 * pageId + slotId;
    }
}
```

### 15.2 Index 接口

所有索引结构都实现统一的接口：

```java
/**
 * 索引接口：所有索引结构的统一抽象
 */
public interface Index<K extends Comparable<K>> {

    /** 插入一个键值对 */
    void insert(K key, RecordId rid);

    /** 删除一个键 */
    void delete(K key);

    /** 等值查找：返回 key 对应的 RecordId */
    RecordId search(K key);

    /** 范围查找：返回 [low, high] 范围内的所有 RecordId */
    List<RecordId> rangeSearch(K low, K high);

    /** 返回索引中的键数量 */
    int size();
}
```

### 15.3 哈希索引实现（对比用）

```java
/**
 * 简单哈希索引（内存版，仅支持等值查询）
 */
public class HashIndex<K extends Comparable<K>> implements Index<K> {

    private final Map<K, RecordId> map = new HashMap<>();

    @Override
    public void insert(K key, RecordId rid) {
        map.put(key, rid);
    }

    @Override
    public void delete(K key) {
        map.remove(key);
    }

    @Override
    public RecordId search(K key) {
        return map.get(key);
    }

    @Override
    public List<RecordId> rangeSearch(K low, K high) {
        // 哈希索引不支持范围查询！
        throw new UnsupportedOperationException(
            "哈希索引不支持范围查询，请使用 B+树索引"
        );
    }

    @Override
    public int size() {
        return map.size();
    }
}
```

### 15.4 全表扫描 vs 索引查找的性能对比

```java
import java.util.*;

public class IndexBenchmark {

    static final int N = 1_000_000; // 100 万行

    // 模拟全表扫描
    static RecordId seqScan(List<int[]> table, int targetId) {
        for (int i = 0; i < table.size(); i++) {
            if (table.get(i)[0] == targetId) {
                return new RecordId(i / 100, i % 100);
            }
        }
        return null;
    }

    public static void main(String[] args) {
        // 构建模拟数据
        List<int[]> table = new ArrayList<>(N);
        HashIndex<Integer> hashIdx = new HashIndex<>();

        for (int i = 0; i < N; i++) {
            table.add(new int[]{i, i * 2}); // [id, score]
            hashIdx.insert(i, new RecordId(i / 100, i % 100));
        }

        int target = 999_999;

        // 全表扫描
        long start = System.nanoTime();
        RecordId r1 = seqScan(table, target);
        long seqTime = System.nanoTime() - start;

        // 哈希索引
        start = System.nanoTime();
        RecordId r2 = hashIdx.search(target);
        long hashTime = System.nanoTime() - start;

        System.out.printf("全表扫描: %,d ns，结果: %s%n", seqTime, r1);
        System.out.printf("哈希索引: %,d ns，结果: %s%n", hashTime, r2);
        System.out.printf("加速比: %.0fx%n", (double) seqTime / hashTime);
    }
}
```

## 常见问题

### Q1：为什么 MySQL 的主键推荐用自增整数？

B+树的插入需要保持有序。如果主键是随机 UUID，每次插入都可能触发页分裂（将一个满页分成两个半满页），导致大量随机 I/O 和空间浪费。自增整数总是插入到最右边的叶子节点，不会触发中间节点的分裂，性能更好。

### Q2：索引越多越好吗？

不是。每个索引都需要在 INSERT/UPDATE/DELETE 时同步维护。如果一张表有 10 个索引，每次写入需要更新 10 个索引文件，写入性能会显著下降。一般原则：只对 WHERE 子句中频繁出现的高选择性列建索引。

### Q3：什么是覆盖索引（Covering Index）？

如果查询所需的所有列都在索引中，就不需要回表读取数据页，这种索引叫覆盖索引。例如：索引建在 `(id, name, score)` 上，查询 `SELECT name, score WHERE id = 5` 可以直接从索引返回结果，无需读数据页。

### Q4：JimSQL 支持复合索引吗？

基础版 JimSQL 只支持单列索引。复合索引（多列）的实现需要将多列值拼接为一个复合键，并定义复合键的比较规则。这是进阶内容，在 Ch19 索引集成章节会简要介绍。

## 本章小结

1. **全表扫描的代价**：O(N)，100 万行需要读 10000 页
2. **索引的本质**：辅助数据结构，存储键值到行地址的映射
3. **三种结构**：哈希索引（等值快）、B+树（通用）、LSM Tree（写多读少）
4. **JimSQL 选 B+树**：同时支持等值和范围查询，是 OLTP 标准
5. **索引的代价**：空间 + 写入变慢，不是越多越好
