## 3. 核心概念

### 3.1 语法分析 vs 语义分析

经过 Ch08 的 Parser，我们已经能把 SQL 字符串转换成 AST。但 Parser 只检查**结构**是否合法，不检查**含义**是否正确。

| 错误类型 | 示例 | 由谁检测 |
|---------|------|---------|
| 词法错误 | `SELEC name FROM t` | Lexer |
| 语法错误 | `SELECT FROM WHERE` | Parser |
| 语义错误（表不存在） | `SELECT * FROM xyz` | Binder |
| 语义错误（列不存在） | `SELECT abc FROM students` | Binder |
| 语义错误（类型不匹配） | `WHERE score > 'hello'` | Binder |

**语义分析（Semantic Analysis）** 的任务是在结构合法的 AST 上，进一步验证其"意义"是否正确。

**绑定（Binding）** 是语义分析的核心操作：把 AST 中的字符串名称（如 `"students"`、`"score"`）替换为 Catalog 中的实际对象引用（如 `TableSchema` 对象、`ColumnSchema` 对象）。

### 3.2 Catalog：元数据的注册表

**Catalog** 是数据库的"字典"，存储所有表的结构信息（元数据）。在真实数据库中，Catalog 通常持久化在系统表中；在 JimSQL 中，我们用内存中的 HashMap 模拟。

Catalog 的核心数据结构：

```
Catalog
└── tables: Map<String, TableSchema>
    └── TableSchema
        ├── name: String          // 表名，如 "students"
        └── columns: List<ColumnSchema>
            └── ColumnSchema
                ├── name: String  // 列名，如 "score"
                └── type: DataType // 列类型：INT 或 VARCHAR
```

Catalog 提供的核心操作：

```java
// 注册一张表（CREATE TABLE 时调用）
void registerTable(TableSchema table);

// 查找表（SELECT/INSERT 时调用）
TableSchema getTable(String tableName);  // 不存在时返回 null

// 检查表是否存在
boolean hasTable(String tableName);
```

### 3.3 Binder 的四项职责

**职责 1：验证表名存在**

```
SELECT * FROM students
              ^^^^^^^^
              Binder 在 Catalog 中查找 "students"
              → 找到：继续
              → 找不到：抛出 BindException("表 'students' 不存在")
```

**职责 2：验证列名存在**

```
SELECT name, score FROM students
       ^^^^  ^^^^^
       Binder 在 students 表的列列表中查找 "name" 和 "score"
       → 找到：继续
       → 找不到：抛出 BindException("列 'xyz' 在表 'students' 中不存在")
```

**职责 3：类型推导与类型检查**

```
WHERE score > 80
      ^^^^^   ^^
      score 是 INT 类型（来自 Catalog）
      80 是整数字面量（来自 AST）
      → INT > INTEGER：类型兼容，通过

WHERE score > 'hello'
      ^^^^^   ^^^^^^^
      score 是 INT 类型
      'hello' 是字符串字面量
      → INT > STRING：类型不匹配，抛出 BindException
```

**职责 4：将字符串引用替换为对象引用**

绑定前的 AST（Parser 输出）：
```
SelectStatement {
  columns: ["name", "score"]   ← 字符串
  tableName: "students"        ← 字符串
  whereClause: Condition("score", ">", "80", false)
}
```

绑定后的 AST（Binder 输出）：
```
BoundSelectStatement {
  columns: [ColumnSchema{name="name", type=VARCHAR},
            ColumnSchema{name="score", type=INT}]  ← 对象引用
  table: TableSchema{name="students", columns=[...]}  ← 对象引用
  whereClause: BoundCondition {
    column: ColumnSchema{name="score", type=INT}   ← 对象引用
    operator: ">"
    value: "80"
    valueType: INT
  }
}
```

绑定后的 AST 不再需要查 Catalog，执行引擎可以直接使用对象引用，效率更高。

### 3.4 绑定的完整流程

```
                    ┌─────────────────────────────────┐
                    │           Catalog                │
                    │  students: {id:INT, name:VARCHAR,│
                    │             score:INT}           │
                    └──────────────┬──────────────────┘
                                   │ 查询元数据
                                   ▼
Parser 输出的 AST ──► [Binder] ──► 绑定后的 AST
                         │
                         └── 发现错误 ──► BindException
```

Binder 的处理步骤（以 SELECT 为例）：

```
1. 从 AST 取出 tableName = "students"
2. 在 Catalog 中查找 "students" → 找到 TableSchema
3. 对每个查询列（"name", "score"）：
   a. 在 TableSchema 中查找该列 → 找到 ColumnSchema
   b. 记录列的类型
4. 如果有 WHERE 子句：
   a. 在 TableSchema 中查找条件列（"score"）→ 找到，类型为 INT
   b. 检查右侧字面量类型：整数字面量 → 类型为 INT
   c. 比较：INT vs INT → 兼容，通过
5. 构建 BoundSelectStatement，所有字符串引用替换为对象引用
```

### 3.5 类型系统设计

JimSQL 的简化类型系统只有两种类型：

```java
public enum DataType {
    INT,     // 整数，对应 Java int
    VARCHAR  // 可变长字符串，对应 Java String
}
```

类型兼容规则：

| 列类型 | 字面量类型 | 是否兼容 |
|--------|-----------|---------|
| INT | INTEGER（整数字面量） | 兼容 |
| INT | STRING（字符串字面量） | 不兼容 |
| VARCHAR | STRING（字符串字面量） | 兼容 |
| VARCHAR | INTEGER（整数字面量） | 不兼容（严格模式） |

注意：真实数据库（如 MySQL）对 `VARCHAR = 123` 会做隐式类型转换。JimSQL 采用严格模式，不做隐式转换，类型不匹配直接报错。

## 4. 代码讲解

### 4.1 DataType 枚举和 ColumnSchema

```java
public enum DataType {
    INT, VARCHAR;

    /** 检查字面量类型是否与列类型兼容 */
    public boolean isCompatibleWith(boolean isStringLiteral) {
        if (this == INT)     return !isStringLiteral;  // INT 只接受整数字面量
        if (this == VARCHAR) return isStringLiteral;   // VARCHAR 只接受字符串字面量
        return false;
    }
}

public class ColumnSchema {
    public final String name;
    public final DataType type;

    public ColumnSchema(String name, DataType type) {
        this.name = name;
        this.type = type;
    }

    @Override
    public String toString() {
        return name + ":" + type;
    }
}
```

### 4.2 TableSchema

```java
public class TableSchema {
    public final String name;
    private final List<ColumnSchema> columns;
    // 用 Map 加速列名查找，避免每次 O(n) 遍历
    private final Map<String, ColumnSchema> columnMap;

    public TableSchema(String name, List<ColumnSchema> columns) {
        this.name = name;
        this.columns = new ArrayList<>(columns);
        this.columnMap = new HashMap<>();
        for (ColumnSchema col : columns) {
            columnMap.put(col.name.toLowerCase(), col);
        }
    }

    /** 按名称查找列，大小写不敏感，找不到返回 null */
    public ColumnSchema getColumn(String colName) {
        return columnMap.get(colName.toLowerCase());
    }

    public List<ColumnSchema> getColumns() {
        return Collections.unmodifiableList(columns);
    }

    @Override
    public String toString() {
        return "TableSchema{" + name + ": " + columns + "}";
    }
}
```

### 4.3 Catalog

```java
public class Catalog {
    private final Map<String, TableSchema> tables = new HashMap<>();

    /** 注册一张表（CREATE TABLE 时调用） */
    public void registerTable(TableSchema table) {
        tables.put(table.name.toLowerCase(), table);
    }

    /** 查找表，找不到返回 null */
    public TableSchema getTable(String tableName) {
        return tables.get(tableName.toLowerCase());
    }

    /** 检查表是否存在 */
    public boolean hasTable(String tableName) {
        return tables.containsKey(tableName.toLowerCase());
    }

    /** 列出所有已注册的表名 */
    public List<String> listTables() {
        return new ArrayList<>(tables.keySet());
    }
}
```

### 4.4 绑定后的 AST 节点

绑定后的节点与 Parser 输出的节点分开定义，体现"绑定前"和"绑定后"的明确边界：

```java
/** 绑定后的 SELECT 语句 */
public class BoundSelectStatement {
    public final List<ColumnSchema> columns;  // 对象引用，而非字符串
    public final TableSchema table;           // 对象引用
    public final BoundCondition whereClause;  // 可为 null

    public BoundSelectStatement(List<ColumnSchema> columns,
                                 TableSchema table,

        this.columns = columns;
        this.table = table;
        this.whereClause = whereClause;

}

/** 绑定后的 WHERE 条件 */
public class BoundCondition {
    public final ColumnSchema column;  // 对象引用
    public final String operator;
    public final String value;
    public final DataType valueType;   // 推导出的字面量类型

    public BoundCondition(ColumnSchema column, String operator,
                           String value, DataType valueType) {
        this.column = column;
        this.operator = operator;
        this.value = value;
        this.valueType = valueType;
    }
}
```

### 4.6 Binder 类：绑定 SELECT 语句

```java
public class Binder {
    private final Catalog catalog;

    public Binder(Catalog catalog) {
        this.catalog = catalog;
    }

    public BoundSelectStatement bindSelect(SelectStatement stmt) {
        // 步骤 1：验证表名
        TableSchema table = catalog.getTable(stmt.tableName);
        if (table == null) {
            throw new BindException("表 '" + stmt.tableName + "' 不存在");
        }

        // 步骤 2：验证并绑定列名
        List<ColumnSchema> boundColumns = new ArrayList<>();
        if (stmt.columns.size() == 1 && stmt.columns.get(0).equals("*")) {
            // SELECT * → 绑定为所有列
            boundColumns.addAll(table.getColumns());
        } else {
            for (String colName : stmt.columns) {
                ColumnSchema col = table.getColumn(colName);
                if (col == null) {
                    throw new BindException(
                        "列 '" + colName + "' 在表 '" + stmt.tableName + "' 中不存在");
                }
                boundColumns.add(col);
            }
        }

        // 步骤 3：验证并绑定 WHERE 条件
        BoundCondition boundWhere = null;
        if (stmt.whereClause != null) {
            boundWhere = bindCondition(stmt.whereClause, table);
        }

        return new BoundSelectStatement(boundColumns, table, boundWhere);
    }

    private BoundCondition bindCondition(Condition cond, TableSchema table) {
        // 验证条件列存在
        ColumnSchema col = table.getColumn(cond.column);
        if (col == null) {
            throw new BindException(
                "WHERE 子句中的列 '" + cond.column + "' 在表 '" + table.name + "' 中不存在");
        }

        // 类型推导：字面量类型
        DataType literalType = cond.isString ? DataType.VARCHAR : DataType.INT;

        // 类型检查：列类型 vs 字面量类型
        if (!col.type.isCompatibleWith(cond.isString)) {
            throw new BindException(
                "类型不匹配：列 '" + cond.column + "' 是 " + col.type
                + " 类型，但比较值 '"
                + (cond.isString ? "'" + cond.value + "'" : cond.value)
                + "' 是 " + literalType + " 类型");
        }

        return new BoundCondition(col, cond.operator, cond.value, literalType);
    }
}
```

### 4.7 Binder：绑定 INSERT 语句

INSERT 的绑定需要验证：
1. 表存在
2. 值的数量与列数量匹配
3. 每个值的类型与对应列类型匹配

```java
public BoundInsertStatement bindInsert(InsertStatement stmt) {
    // 验证表名
    TableSchema table = catalog.getTable(stmt.tableName);
    if (table == null) {
        throw new BindException("表 '" + stmt.tableName + "' 不存在");
    }

    List<ColumnSchema> cols = table.getColumns();

    // 验证值数量
    if (stmt.values.size() != cols.size()) {
        throw new BindException(
            "INSERT 值数量不匹配：表 '" + stmt.tableName
            + "' 有 " + cols.size() + " 列，但提供了 " + stmt.values.size() + " 个值");
    }

    // 逐列验证类型（简化：通过 isNumeric 判断字面量类型）
    List<TypedValue> typedValues = new ArrayList<>();
    for (int i = 0; i < cols.size(); i++) {
        ColumnSchema col = cols.get(i);
        String rawValue = stmt.values.get(i);
        boolean isNumeric = rawValue.matches("-?\\d+");
        DataType literalType = isNumeric ? DataType.INT : DataType.VARCHAR;

        if (col.type != literalType) {
            throw new BindException(
                "INSERT 第 " + (i + 1) + " 列 '" + col.name
                + "' 类型为 " + col.type
                + "，但提供的值 '" + rawValue + "' 是 " + literalType + " 类型");
        }
        typedValues.add(new TypedValue(rawValue, literalType));
    }

    return new BoundInsertStatement(table, typedValues);
}
```

### 4.8 Binder：处理 CREATE TABLE

CREATE TABLE 的绑定相对简单：主要验证表名不重复，并将列定义注册到 Catalog。

```java
public void bindAndRegisterCreateTable(CreateTableStatement stmt) {
    // 验证表名不重复
    if (catalog.hasTable(stmt.tableName)) {
        throw new BindException("表 '" + stmt.tableName + "' 已存在");
    }

    // 构建 TableSchema 并注册
    List<ColumnSchema> cols = new ArrayList<>();
    for (ColumnDef def : stmt.columns) {
        DataType type = def.type.equals("INT") ? DataType.INT : DataType.VARCHAR;
        cols.add(new ColumnSchema(def.name, type));
    }

    TableSchema schema = new TableSchema(stmt.tableName, cols);
    catalog.registerTable(schema);
}
```

### 4.9 绑定前后的对比

以 `SELECT name, score FROM students WHERE score > 80` 为例：

**绑定前（Parser 输出）**：
```
SelectStatement {
  columns:     ["name", "score"]          ← 字符串列表
  tableName:   "students"                 ← 字符串
  whereClause: Condition {
    column:   "score"                     ← 字符串
    operator: ">"
    value:    "80"
    isString: false
  }
}
```

**绑定后（Binder 输出）**：
```
BoundSelectStatement {
  columns: [ColumnSchema{name=name, type=VARCHAR},
            ColumnSchema{name=score, type=INT}]   ← 对象引用，含类型信息
  table:   TableSchema{name=students, columns=[
             ColumnSchema{id, INT},
             ColumnSchema{name, VARCHAR},
             ColumnSchema{score, INT}]}            ← 对象引用，含完整结构
  whereClause: BoundCondition {
    column:    ColumnSchema{name=score, type=INT}  ← 对象引用
    operator:  ">"
    value:     "80"
    valueType: INT                                 ← 推导出的类型
  }
}
```

执行引擎拿到绑定后的 AST，不需要再查 Catalog，直接通过对象引用访问列类型和表结构，效率更高，逻辑更清晰。

## 5. 实践练习

### 练习 1（基础）：扩展类型系统支持 BOOLEAN

当前 JimSQL 只有 INT 和 VARCHAR 两种类型。请添加 BOOLEAN 类型支持。

要求：
1. 在 `DataType` 枚举中添加 `BOOLEAN`
2. 在 `TokenType` 中添加 `BOOLEAN` 关键字，并在 Lexer 中识别
3. 在 `ColumnDef` 解析中支持 `BOOLEAN` 类型（无长度参数）
4. 在 `DataType.isCompatibleWith()` 中定义 BOOLEAN 的兼容规则：
   - 只接受字符串字面量 `'true'` 或 `'false'`（简化处理）
5. 测试：`CREATE TABLE flags (id INT, active BOOLEAN)`

### 练习 2（进阶）：实现列别名的绑定

SQL 支持列别名：`SELECT score AS grade FROM students`。请实现别名的绑定。

要求：
1. 在 `TokenType` 中添加 `AS` 关键字
2. 修改 Parser 的列解析：支持 `IDENTIFIER [AS IDENTIFIER]` 语法
3. 创建 `AliasedColumn` 类，包含 `ColumnSchema column` 和 `String alias`
4. 在 Binder 中：绑定原始列名，记录别名
5. 测试：`SELECT score AS grade, name AS student_name FROM students`
   - 验证绑定后 `grade` 对应 `score` 列（INT 类型）

### 练习 3（挑战）：实现跨表引用检测（多表 JOIN 的前置）

当 SQL 中出现 `WHERE t1.score > 80` 这样的带表名前缀的列引用时，Binder 需要解析 `t1.score` 为"表 t1 的 score 列"。

要求：
1. 修改 Lexer：识别 `.` 符号（添加 `DOT` TokenType）
2. 修改 Parser：在列名解析时支持 `IDENTIFIER.IDENTIFIER` 格式，构建 `QualifiedColumn` 节点（含 tableName 和 columnName）
3. 修改 Binder：
   - 支持 FROM 子句中的多表（`FROM t1, t2`）
   - 对 `QualifiedColumn` 先查表名，再查列名
   - 对无前缀的列名，在所有 FROM 表中查找，若有歧义（多个表都有同名列）则报错
4. 测试：
   ```sql
   SELECT s.name, s.score FROM students s WHERE s.score > 60
   ```

## 6. 常见问题

**Q1：Binder 一定要产生新的"绑定后 AST"吗？能不能直接修改原 AST？**

A：两种方式都可行，各有取舍：

- **产生新 AST（本章采用）**：原 AST 保持不变，绑定后的 AST 是新对象。优点：原 AST 可复用（如用于错误恢复、重新绑定），符合不可变设计原则；缺点：需要定义两套节点类。
- **原地修改 AST**：在原 AST 节点上添加字段（如 `resolvedTable`、`resolvedColumn`），绑定时填充这些字段。优点：节省内存，代码量少；缺点：AST 节点变得复杂，绑定前后状态混在一起。

生产级数据库（如 PostgreSQL）通常采用产生新 AST 的方式，因为查询优化阶段也会产生多个变换后的 AST 版本。

---

**Q2：类型检查应该在 Binder 还是执行引擎中做？**

A：类型检查应该在 Binder 中做，原因：

1. **尽早失败**：在执行前发现类型错误，避免浪费 I/O 资源（执行可能涉及磁盘读写）
2. **职责分离**：执行引擎假设输入的 AST 已经过语义验证，不需要再做类型检查，逻辑更简单
3. **错误信息更好**：Binder 知道列名和类型，能给出 `"列 'score' 是 INT 类型，但比较值 'hello' 是 VARCHAR 类型"` 这样的精确错误；执行引擎只知道运行时值，错误信息不够友好

---

**Q3：Catalog 在真实数据库中是如何持久化的？**

A：真实数据库的 Catalog 存储在**系统表（System Tables）**中，这些表和用户数据表一样存储在磁盘上，但由数据库引擎保留和管理。

- **MySQL**：`information_schema` 数据库，包含 `TABLES`、`COLUMNS` 等系统表
- **PostgreSQL**：`pg_catalog` schema，包含 `pg_class`（表）、`pg_attribute`（列）等
- **SQLite**：`sqlite_master` 表，存储所有表的 CREATE TABLE 语句

JimSQL 的 Catalog 是纯内存实现，重启后丢失。后续章节（存储引擎部分）会实现 Catalog 的持久化。

---

**Q4：如果 SQL 中有子查询（如 `WHERE id IN (SELECT id FROM t2)`），Binder 如何处理？**

A：子查询的绑定是递归的：

1. 外层查询的 Binder 遇到子查询节点
2. 递归调用 `bindSelect()` 处理子查询
3. 子查询绑定完成后，其结果类型（返回的列类型）作为外层查询的输入类型

例如 `WHERE id IN (SELECT id FROM t2)`：
- 先绑定子查询 `SELECT id FROM t2`，得到结果类型为 `[INT]`（假设 t2.id 是 INT）
- 再检查外层 `id` 列的类型是否与子查询结果类型兼容（都是 INT，兼容）

JimSQL 当前版本不支持子查询，这是后续扩展的方向。

## 7. 本章小结

本章实现了 JimSQL SQL 解析管道的最后一环：语义分析与绑定（Binder）。

核心收获：

1. **语义分析是语法分析的延伸**：语法分析检查结构，语义分析检查含义。两者职责清晰，不应混淆
2. **Catalog 是 Binder 的数据源**：没有 Catalog，Binder 无法验证表名和列名是否存在
3. **绑定的本质是"名称解析"**：把字符串名称替换为对象引用，让后续处理不再依赖字符串比较
4. **类型推导在绑定阶段完成**：执行引擎拿到的 AST 已经包含完整的类型信息，无需再推导
5. **错误信息要有意义**：`BindException` 应包含表名、列名、期望类型、实际类型等上下文，帮助用户快速定位问题

至此，Module 3（SQL 解析）全部完成。完整的解析管道如下：

```
SQL 字符串
    │
    ▼
[Lexer]   ──► Token 流                    Ch07
    │
    ▼
[Parser]  ──► AST（字符串引用）            Ch08
    │
    ▼
[Binder]  ──► 绑定后的 AST（对象引用）    Ch09
    │
    ▼
[执行引擎] ──► 查询结果                   Module 4（待实现）
```

下一个 Module 将基于绑定后的 AST，实现查询执行引擎：从磁盘读取数据、应用过滤条件、返回结果集。

## 课堂练习

### ⭐ 基础
1. 对 `SELECT a FROM t WHERE b > 5` 追踪语义分析过程（验证表和列是否存在）
2. 测试引用不存在的列时报错信息
3. 解释语义分析与语法分析的区别

### ⭐⭐ 进阶
1. 实现列引用解析（`SELECT t.a FROM t` → 绑定到表 t 的列 a）
2. 实现类型检查（`WHERE name > 5` → 字符串与数字比较应报错）
3. 实现别名解析（`SELECT score AS s ORDER BY s`）

### ⭐⭐⭐ 挑战
1. 实现聚合函数的语义校验（`SELECT dept, COUNT(*) FROM t` 中非聚合列必须在 GROUP BY 中）
2. 实现子查询的语义绑定
3. 设计语义分析的错误收集机制（一次报告多个错误而非遇错即停）
