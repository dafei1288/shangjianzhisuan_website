## 3. 核心概念

### 3.1 关系代数基础

关系代数是关系数据库的理论基础，它定义了对"关系"（表）进行操作的一组运算符。每个运算符接受一个或两个关系作为输入，输出一个新的关系。

#### 五种基本运算

**选择（Selection，σ）**

从关系中筛选满足条件的行，类似 SQL 的 WHERE 子句。

```
σ_{score > 80}(students)
```

等价 SQL：
```sql
SELECT * FROM students WHERE score > 80
```

**投影（Projection，π）**

从关系中选取指定的列，类似 SQL 的 SELECT 列表（不含聚合）。

```
π_{name, score}(students)
```

等价 SQL：
```sql
SELECT name, score FROM students
```

**连接（Join，⋈）**

将两个关系按照连接条件合并，是关系代数中最复杂的运算。

```
students ⋈_{students.id = scores.student_id} scores
```

等价 SQL：
```sql
SELECT * FROM students JOIN scores ON students.id = scores.student_id
```

**并（Union，∪）**

合并两个结构相同的关系，去除重复行。

```
result_2023 ∪ result_2024
```

等价 SQL：
```sql
SELECT * FROM result_2023 UNION SELECT * FROM result_2024
```

**差（Difference，-）**

从第一个关系中去除在第二个关系中出现的行。

```
all_students - graduated_students
```

等价 SQL：
```sql
SELECT * FROM all_students EXCEPT SELECT * FROM graduated_students
```

#### 派生运算

基于五种基本运算，可以派生出更多运算：

| 派生运算 | 定义 | SQL 对应 |
|---------|------|---------|
| 交（∩） | R ∩ S = R - (R - S) | INTERSECT |
| 自然连接 | 按同名列连接后投影去重 | NATURAL JOIN |
| 除（÷） | 复杂，用于"对所有...都满足"的查询 | 无直接对应 |

### 3.2 SQL 到关系代数的翻译

一条 SQL 语句可以被机械地翻译成关系代数表达式：

```sql
SELECT name, AVG(score) as avg_score
FROM students
WHERE grade = '大三'
GROUP BY name
HAVING AVG(score) > 85
ORDER BY avg_score DESC
```

翻译步骤（从内到外）：

```
1. FROM students                    → 关系 students
2. WHERE grade = '大三'             → σ_{grade='大三'}(students)
3. GROUP BY name + AVG(score)       → γ_{name; AVG(score)}(...)
4. HAVING AVG(score) > 85           → σ_{avg_score > 85}(...)
5. SELECT name, avg_score           → π_{name, avg_score}(...)
6. ORDER BY avg_score DESC          → τ_{avg_score DESC}(...)
```

完整表达式：
```
τ_{avg_score DESC}(
  π_{name, avg_score}(
    σ_{avg_score > 85}(
      γ_{name; AVG(score) → avg_score}(
        σ_{grade='大三'}(students)
      )
    )
  )
)
```

### 3.3 算子树（Operator Tree）

算子树是关系代数表达式的树形表示，也是数据库执行引擎的核心数据结构。

#### 算子树的结构

```
        π_{name}
            |
        σ_{score > 80}
            |
        SeqScan(students)
```

对应 SQL：
```sql
SELECT name FROM students WHERE score > 80
```

每个节点是一个"算子"（Operator），叶子节点通常是表扫描（SeqScan 或 IndexScan），内部节点是各种处理算子。

#### 更复杂的例子

```sql
SELECT s.name, sc.score
FROM students s
JOIN scores sc ON s.id = sc.student_id
WHERE sc.score > 90
ORDER BY sc.score DESC
```

对应算子树：
```
            τ_{score DESC}
                  |
            π_{name, score}
                  |
            σ_{score > 90}
                  |
            HashJoin(s.id = sc.student_id)
           /                    \
    SeqScan(students)      SeqScan(scores)
```

数据从叶子节点向上流动，每个算子对数据进行处理后传给父节点。

### 3.4 Volcano/Iterator 模型

Volcano 模型（也叫 Iterator 模型）是最经典的数据库执行模型，由 Goetz Graefe 在 1994 年提出。

#### 核心接口

每个算子都实现相同的三个接口：

```java
interface Operator {
    void open();           // 初始化，分配资源
    Row next();            // 返回下一行，无数据时返回 null
    void close();          // 释放资源
    Schema getSchema();    // 返回输出的列定义
}
```

#### 执行流程

以 `Filter(SeqScan)` 为例：

```
调用者调用 filter.next()
  → filter 内部调用 child.next() 获取一行
  → 如果满足条件，返回该行
  → 如果不满足，继续调用 child.next()
  → 直到找到满足条件的行或 child 返回 null
```

时序图：
```
Client          Filter          SeqScan
  |               |                |
  |-- next() ---> |                |
  |               |-- next() ----> |
  |               | <-- row1 ----- |  (不满足条件，继续)
  |               |-- next() ----> |
  |               | <-- row2 ----- |  (满足条件)
  | <-- row2 ---- |                |
  |               |                |
  |-- next() ---> |                |
  |               |-- next() ----> |
  |               | <-- null ----- |  (数据耗尽)
  | <-- null ---- |                |
```

#### 拉取式 vs 推送式

**拉取式（Pull-based / Volcano）**
- 上层算子主动向下层"拉取"数据
- 优点：实现简单，天然支持 LIMIT（不需要处理所有数据）
- 缺点：函数调用开销大，不利于 CPU 流水线优化

**推送式（Push-based）**
- 下层算子主动向上层"推送"数据
- 优点：更好的 CPU 缓存利用率，便于向量化执行
- 缺点：实现复杂，LIMIT 需要特殊处理
- 代表：Apache Flink、DuckDB（向量化执行）

JimSQL 采用 Volcano 模型，因为它更易于理解和实现。

### 3.5 从 AST 到算子树

查询优化器负责将 AST（抽象语法树）转换为算子树，这个过程分两步：

**第一步：生成逻辑计划（Logical Plan）**

逻辑计划直接对应关系代数，不考虑具体实现方式：
- `LogicalScan` → 扫描某张表
- `LogicalFilter` → 过滤
- `LogicalProject` → 投影
- `LogicalJoin` → 连接

**第二步：生成物理计划（Physical Plan）**

物理计划选择具体的实现算法：
- `LogicalScan` → `SeqScan` 或 `IndexScan`
- `LogicalJoin` → `NestedLoopJoin` 或 `HashJoin` 或 `SortMergeJoin`

```
AST
 ↓ (语义分析 + 逻辑规划)
逻辑计划树
 ↓ (查询优化 + 物理规划)
物理计划树（算子树）
 ↓ (执行引擎)
结果集
```

## 4. 代码讲解

### 4.1 核心数据结构

首先定义行（Row）和模式（Schema）：

```java
// 一行数据，用 Object[] 存储各列的值
public class Row {
    private final Object[] values;
    private final Schema schema;

    public Row(Object[] values, Schema schema) {
        this.values = values.clone();
        this.schema = schema;
    }

    public Object get(int index) {
        return values[index];
    }

    public Object get(String columnName) {
        int idx = schema.getColumnIndex(columnName);
        if (idx < 0) throw new IllegalArgumentException("Column not found: " + columnName);
        return values[idx];
    }

    public int size() { return values.length; }
}
```

```java
// 列定义
public class Column {
    public final String name;
    public final Class<?> type;  // Integer.class, String.class, Double.class 等

    public Column(String name, Class<?> type) {
        this.name = name;
        this.type = type;
    }
}

// 模式：一组列定义
public class Schema {
    private final List<Column> columns;

    public Schema(List<Column> columns) {
        this.columns = new ArrayList<>(columns);
    }

    public int getColumnIndex(String name) {
        for (int i = 0; i < columns.size(); i++) {
            if (columns.get(i).name.equals(name)) return i;
        }
        return -1;
    }

    public List<Column> getColumns() { return Collections.unmodifiableList(columns); }
    public int size() { return columns.size(); }
}
```

### 4.2 Operator 接口

```java
public interface Operator {
    /**
     * 初始化算子，分配资源，递归初始化子算子
     */
    void open();

    /**
     * 返回下一行数据
     * @return 下一行，如果没有更多数据则返回 null
     */
    Row next();

    /**
     * 关闭算子，释放资源，递归关闭子算子
     */
    void close();

    /**
     * 返回该算子输出的列定义
     */
    Schema getSchema();

    /**
     * 返回算子树的字符串表示（用于调试）
     */
    default String explain(int indent) {
        return " ".repeat(indent) + getClass().getSimpleName();
    }
}
```

### 4.3 MockScan：内存数据源

```java
/**
 * 模拟顺序扫描算子（SeqScan）
 * 从内存中的数据列表逐行返回数据
 */
public class MockScan implements Operator {
    private final String tableName;
    private final Schema schema;
    private final List<Row> data;
    private int cursor;

    public MockScan(String tableName, Schema schema, List<Row> data) {
        this.tableName = tableName;
        this.schema = schema;
        this.data = new ArrayList<>(data);
    }

    @Override
    public void open() {
        cursor = 0;  // 重置游标
        System.out.println("[MockScan] open: " + tableName);
    }

    @Override
    public Row next() {
        if (cursor >= data.size()) return null;
        return data.get(cursor++);
    }

    @Override
    public void close() {
        System.out.println("[MockScan] close: " + tableName + ", scanned " + cursor + " rows");
    }

    @Override
    public Schema getSchema() { return schema; }

    @Override
    public String explain(int indent) {
        return " ".repeat(indent) + "SeqScan(" + tableName + ")";
    }
}
```

### 4.4 算子树的构建与执行

```java
/**
 * 执行一个算子树，收集所有结果
 */
public static List<Row> execute(Operator root) {
    List<Row> results = new ArrayList<>();
    root.open();
    Row row;
    while ((row = root.next()) != null) {
        results.add(row);
    }
    root.close();
    return results;
}

/**
 * 打印算子树结构
 */
public static void printPlan(Operator op) {
    printPlanHelper(op, 0);
}

private static void printPlanHelper(Operator op, int indent) {
    System.out.println(op.explain(indent));
    if (op instanceof UnaryOperator) {
        printPlanHelper(((UnaryOperator) op).getChild(), indent + 2);
    } else if (op instanceof BinaryOperator) {
        printPlanHelper(((BinaryOperator) op).getLeft(), indent + 2);
        printPlanHelper(((BinaryOperator) op).getRight(), indent + 2);
    }
}
```

### 4.5 完整示例：SELECT name FROM students WHERE score > 80

```java
// 1. 构建数据
Schema studentSchema = new Schema(Arrays.asList(
    new Column("id", Integer.class),
    new Column("name", String.class),
    new Column("score", Integer.class)
));

List<Row> studentData = Arrays.asList(
    new Row(new Object[]{1, "Alice", 92}, studentSchema),
    new Row(new Object[]{2, "Bob", 75}, studentSchema),
    new Row(new Object[]{3, "Charlie", 88}, studentSchema),
    new Row(new Object[]{4, "Diana", 65}, studentSchema)
);

// 2. 构建算子树
Operator scan = new MockScan("students", studentSchema, studentData);
Operator filter = new FilterOperator(scan, row -> (Integer) row.get("score") > 80);
Operator project = new ProjectOperator(filter, Arrays.asList("name"));

// 3. 打印执行计划
System.out.println("=== 执行计划 ===");
printPlan(project);
// 输出：
// Projection[name]
//   Filter[score > 80]
//     SeqScan(students)

// 4. 执行
System.out.println("\n=== 执行结果 ===");
List<Row> results = execute(project);
for (Row r : results) {
    System.out.println(r.get("name"));
}
// 输出：
// Alice
// Charlie
```

### 练习 1（基础）：手写关系代数表达式

将以下 SQL 翻译成关系代数表达式，并画出算子树：

```sql
SELECT student_id, COUNT(*) as cnt
FROM scores
WHERE subject = 'Math'
GROUP BY student_id
HAVING COUNT(*) >= 2
```

**提示**：按照 FROM → WHERE → GROUP BY → HAVING → SELECT 的顺序逐步翻译。

**参考答案**：
```
π_{student_id, cnt}(
  σ_{cnt >= 2}(
    γ_{student_id; COUNT(*) → cnt}(
      σ_{subject='Math'}(scores)
    )
  )
)
```

### 练习 2（进阶）：实现 UnionOperator

基于 Volcano 模型，实现一个 `UnionAllOperator`，它接受两个子算子，先返回第一个子算子的所有行，再返回第二个子算子的所有行（不去重）。

```java
public class UnionAllOperator implements Operator {
    private final Operator left;
    private final Operator right;
    private boolean leftDone;

    public UnionAllOperator(Operator left, Operator right) {
        // 要求两个子算子的 schema 相同
        this.left = left;
        this.right = right;
    }

    @Override
    public void open() {
        leftDone = false;
        left.open();
        // right 暂不 open，等 left 耗尽后再 open
    }

    @Override
    public Row next() {
        if (!leftDone) {
            Row row = left.next();
            if (row != null) return row;
            // left 耗尽，切换到 right
            left.close();
            right.open();
            leftDone = true;
        }
        return right.next();
    }

    @Override
    public void close() {
        if (!leftDone) left.close();
        right.close();
    }

    @Override
    public Schema getSchema() { return left.getSchema(); }
}
```

测试：用两个 MockScan 构建 UnionAll，验证结果行数等于两个数据集行数之和。

## 6. 常见问题

**Q1：为什么 next() 返回 null 而不是抛出 NoSuchElementException？**

A：数据库执行引擎对性能极其敏感，`next()` 会被调用数百万次。抛出异常的开销远大于返回 null 的检查。此外，null 作为"无更多数据"的信号语义清晰，不会与正常的空值混淆（行本身不会是 null，行中的某列值才可能是 null）。

**Q2：open() 和 close() 是必须的吗？直接在构造函数里初始化不行吗？**

A：open()/close() 是必须的，原因有三：
1. 同一个算子可能被多次执行（如嵌套循环连接中，内层算子每次外层迭代都要重新 open）
2. 资源（文件句柄、网络连接）应该在真正需要时才分配，而不是在构造时
3. 支持"重置"语义：close() 后再 open() 可以重新扫描

**Q3：算子树和 AST 有什么区别？**

A：AST（抽象语法树）是对 SQL 文本结构的忠实表示，反映的是语法结构，不关心执行。算子树是执行计划，每个节点都是一个可执行的算子，反映的是数据流向和处理逻辑。同一个 SQL 可以有多种不同的算子树（对应不同的执行策略），查询优化器的工作就是找到最优的那棵。

**Q4：Volcano 模型的性能瓶颈在哪里？**

A：Volcano 模型的主要性能瓶颈是虚函数调用开销。每处理一行数据，都需要通过接口调用 `next()`，这会导致 CPU 分支预测失败和指令缓存未命中。现代数据库（如 DuckDB、Hyper）采用向量化执行（Vectorized Execution）或代码生成（Code Generation）来解决这个问题：向量化执行每次处理一批（如 1024 行）数据，大幅减少函数调用次数；代码生成则直接生成针对特定查询的机器码，消除虚函数调用。

## 7. 本章小结

本章建立了执行引擎的理论基础：

1. **关系代数**是 SQL 的数学基础，五种基本运算（σ、π、⋈、∪、-）可以表达所有 SQL 查询
2. **算子树**是关系代数的可执行表示，每个节点是一个算子，数据从叶子节点向根节点流动
3. **Volcano/Iterator 模型**通过统一的 `open()/next()/close()` 接口，将算子解耦，使得算子可以任意组合
4. **拉取式执行**天然支持 LIMIT 优化，是最简单也最经典的执行模型

下一章（Ch11）将实现两个最基础的算子：Filter 和 Projection，并建立表达式求值框架。
