## 核心概念

### 1. 文件系统 vs 数据库

假设你要存储一批学生成绩，最简单的方案是写一个 CSV 文件：

```
id,name,score
1,张三,90
2,李四,85
```

这能工作，但当你面对以下场景时，文件系统就力不从心了：

| 场景 | 文件系统的问题 |
|------|--------------|
| 两个程序同时写文件 | 数据损坏，没有并发保护 |
| 程序写到一半崩溃 | 文件残缺，无法恢复 |
| 查询 score > 80 的学生 | 必须全文件扫描，无法加速 |
| 修改表结构（加一列） | 需要重写整个文件 |
| 多个表关联查询 | 需要自己写 Join 逻辑 |

数据库就是为了系统性地解决这些问题而生的。

### 2. ACID：数据库的四个承诺

```
A — Atomicity    原子性：一个事务要么全做，要么全不做
C — Consistency  一致性：事务前后数据满足所有约束
I — Isolation    隔离性：并发事务互不干扰
D — Durability   持久性：提交后的数据永久保存
```

**原子性示例**：银行转账，A 扣 100 元，B 加 100 元。如果扣款成功但加款失败，必须回滚扣款。

**持久性示例**：`COMMIT` 之后，即使服务器断电，数据也不能丢失。这就是为什么需要 WAL（Write-Ahead Log）。

### 3. 一条 SQL 的完整旅程

```
用户输入: SELECT name FROM students WHERE score > 80

         │
         ▼
┌─────────────────┐
│   词法分析 Lexer │  "SELECT" "name" "FROM" "students" "WHERE" "score" ">" "80"
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  语法分析 Parser │  构建 AST（抽象语法树）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  语义分析 Binder │  验证表名/列名存在，推导类型
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  查询优化器      │  选择最优执行计划（走索引还是全表扫描？）
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  执行引擎        │  Filter(score>80) → SeqScan(students)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  存储引擎        │  从磁盘读取 Page，返回 Tuple
└─────────────────┘
         │
         ▼
      结果集: [张三, 王五, ...]
```

这条路径就是本课程 30 章的主线。每个方框对应一个模块。

### 4. JimSQL 架构导览

JimSQL（Jim Isn't MySQL）是一个用 Java 实现的文件系统数据库，代码结构清晰，适合学习：

```
jimsql/
  src/main/java/
    com/jimsql/
      storage/     存储层：Page、HeapFile、BufferPool
      sql/         SQL 解析：Lexer、Parser、AST
      executor/    执行引擎：算子树、各类 Operator
      index/       索引：B+ 树实现
      transaction/ 事务：LockManager、MVCC
      recovery/    恢复：WAL、LogManager
      catalog/     元数据：TableInfo、ColumnInfo
```

## 代码讲解

### 1.1 文件系统的脆弱性演示

```java
// 演示：没有数据库时，并发写文件会发生什么
import java.io.*;
import java.util.concurrent.*;

public class FileConcurrencyDemo {

    static final String FILE = "scores.csv";

    // 模拟两个线程同时追加记录
    public static void main(String[] args) throws Exception {
        // 清空文件
        new FileWriter(FILE, false).close();

        ExecutorService pool = Executors.newFixedThreadPool(2);
        CountDownLatch latch = new CountDownLatch(2);

        // 线程1：写入 100 条记录
        pool.submit(() -> {
            try (FileWriter fw = new FileWriter(FILE, true)) {
                for (int i = 1; i <= 100; i++) {
                    fw.write(i + ",student_A_" + i + ",90\n");
                    Thread.sleep(1); // 模拟处理延迟
                }
            } catch (Exception e) { e.printStackTrace(); }
            finally { latch.countDown(); }
        });

        // 线程2：同时写入 100 条记录
        pool.submit(() -> {
            try (FileWriter fw = new FileWriter(FILE, true)) {
                for (int i = 101; i <= 200; i++) {
                    fw.write(i + ",student_B_" + i + ",85\n");
                    Thread.sleep(1);
                }
            } catch (Exception e) { e.printStackTrace(); }
            finally { latch.countDown(); }
        });

        latch.await();
        pool.shutdown();

        // 统计实际写入行数（可能不是 200）
        long lines = new BufferedReader(new FileReader(FILE))
            .lines().count();
        System.out.println("期望 200 行，实际: " + lines);
        // 结果往往 < 200，且部分行可能损坏
    }
}
```

这个演示说明：没有并发控制，文件写入是不安全的。数据库的锁机制就是为了解决这个问题。

### 1.2 ACID 的直观演示

```java
// 演示：原子性 — 转账操作
public class AtomicityDemo {

    static int accountA = 1000;
    static int accountB = 500;

    // 不安全的转账（没有原子性）
    static void unsafeTransfer(int amount) {
        accountA -= amount;          // 步骤1：扣款
        if (true) throw new RuntimeException("系统崩溃！");
        accountB += amount;          // 步骤2：加款（永远不会执行）
    }

    // 安全的转账（模拟原子性）
    static void safeTransfer(int amount) {
        int savedA = accountA;
        int savedB = accountB;
        try {
            accountA -= amount;
            if (true) throw new RuntimeException("系统崩溃！");
            accountB += amount;
        } catch (Exception e) {
            // 回滚：恢复原始值
            accountA = savedA;
            accountB = savedB;
            System.out.println("事务回滚，账户余额恢复");
        }
    }

    public static void main(String[] args) {
        System.out.println("=== 不安全转账 ===");
        System.out.println("转账前: A=" + accountA + ", B=" + accountB);
        try { unsafeTransfer(100); } catch (Exception e) { /* 忽略 */ }
        System.out.println("崩溃后: A=" + accountA + ", B=" + accountB);
        // A=900, B=500 — 钱凭空消失了！

        accountA = 1000; accountB = 500; // 重置

        System.out.println("\n=== 安全转账（有原子性）===");
        System.out.println("转账前: A=" + accountA + ", B=" + accountB);
        safeTransfer(100);
        System.out.println("回滚后: A=" + accountA + ", B=" + accountB);
        // A=1000, B=500 — 正确回滚
    }
}
```

### 1.3 JimSQL 第一次运行

```java
// 演示：克隆 JimSQL 后，运行第一个查询
// 这段代码展示 JimSQL 的顶层入口

import com.jimsql.JimSQL;

public class FirstQuery {
    public static void main(String[] args) throws Exception {
        // 初始化数据库（在当前目录创建数据文件）
        JimSQL db = new JimSQL("./mydb");

        // 建表
        db.execute("CREATE TABLE students (id INT, name VARCHAR(50), score INT)");

        // 插入数据
        db.execute("INSERT INTO students VALUES (1, '张三', 90)");
        db.execute("INSERT INTO students VALUES (2, '李四', 75)");
        db.execute("INSERT INTO students VALUES (3, '王五', 88)");

        // 查询
        var result = db.query("SELECT name, score FROM students WHERE score > 80");

        System.out.println("score > 80 的学生：");
        while (result.next()) {
            System.out.println("  " + result.getString("name")
                + " -> " + result.getInt("score"));
        }

        db.close();
    }
}
```

预期输出：
```
score > 80 的学生：
  张三 -> 90
  王五 -> 88
```

## 常见问题

### Q1：NoSQL 数据库不需要 ACID 吗？

不完全对。早期 NoSQL（如 MongoDB 3.x 之前）确实牺牲了部分 ACID 来换取性能和扩展性。但现代 NoSQL 数据库大多已支持事务（MongoDB 4.0+、Cassandra LWT）。ACID 是需求，不是技术选型——取决于业务是否需要强一致性。

### Q2：JimSQL 和 MySQL 的差距在哪里？

JimSQL 是教学用的简化实现，主要差距：
- **性能**：没有生产级的查询优化器和缓存策略
- **SQL 支持**：只支持基础 DML/DDL，不支持子查询、视图、存储过程
- **并发**：锁粒度较粗，吞吐量有限
- **可靠性**：WAL 实现简化，不支持 Point-in-Time Recovery

但核心原理完全一致，学完 JimSQL 再看 MySQL 源码会豁然开朗。

### Q3：为什么用 Java 而不是 C/C++？

大多数教学数据库（CMU BusTub、MIT SimpleDB）用 C++ 或 Java。Java 的优势：
- 内存安全，不会因指针错误掩盖逻辑 bug
- 代码可读性高，适合教学
- JimSQL 本身就是 Java 实现，课程与项目保持一致

## 本章小结

本章建立了学习数据库的认知框架：

1. **文件系统的局限**：并发、崩溃恢复、查询性能是文件系统无法解决的三大问题
2. **ACID 是数据库的核心承诺**：原子性、一致性、隔离性、持久性
3. **SQL 的执行路径**：Lexer → Parser → Binder → Optimizer → Executor → Storage，这是本课程的主线
4. **JimSQL 的定位**：教学级 Java 数据库，代码清晰，覆盖所有核心模块
