# D5: 连线——让任务从进来到完成顺畅流转

> 🔗 Module 3 · 打通通路 · 第 5 天 | 认知课 30 分钟 + 实战 60–90 分钟

## 学习目标

- 理解单点提效的天花板：**断点在"衔接"**，不在工具
- 掌握工作流五站模型：**任务进来 → 资料调取 → AI 处理 → 人工验收 → 产出归档**
- 会画自己的任务流转图（纸笔或白板工具均可）
- 用工作台全链路跑通 1 个真实任务
- 明确人工环节的位置：验收与决策不外包

## 认知课：为什么每个工具都快了，任务还是慢

### 断点诊断

```text
一个典型任务的完整旅程：

任务进来        资料调取         AI 处理         人工验收        产出归档
（微信/邮件）   （翻找 10 分钟）  （AI 3 分钟）   （你 5 分钟）   （又散落了）
    ✅            ❌ 卡住           ✅              ✅             ❌ 丢失

单点都快，衔接全断：
- 资料在哪？→ 靠记忆翻找
- 用哪个助手？→ 每次现想
- 产出存哪？→ 完成就忘
```

**工作流思维**：给任务的每一站指定**归属**——资料从库里取、处理用哪个助手固定下来、产出必须回库里存。这就是"打通通路"。

### 五站模型

```text
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ ① 任务进 │ → │ ② 资料调 │ → │ ③ AI 处 │ → │ ④ 人工验 │ → │ ⑤ 产出归 │
│   站      │   │   取     │   │   理     │   │   收     │   │   档     │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
  收件箱        知识库搜索     助手 SOP      验收清单      回到知识库
  （D1）        （D1+D2）     （D4）        （D3）        （D1）
```

每一站都来自你前 5 天建好的能力——D5 只是把它们**连线**。

### 人工环节留在哪

```text
交给 AI ✅                 留给人 ⚠️
────────────────       ────────────────
找资料、组织语言          判断：这个结论对不对
套模板出初稿              决策：选哪个方案、发不发
格式转换、摘要            负责：对外发出的东西你签字
重复追问与迭代            口径：涉及承诺、价格、立场
```

> 原则：**AI 出力，你拍板**。凡是"错了要你负责"的环节，就在验收站由你完成。

### 流转图怎么画

用纸笔或任何画图工具（甚至用 Markdown 缩进）画出：

```markdown
# 工作流：一期 Newsletter

① 任务进站
   触发：每周四 10:00（固定触发，不靠想起）
② 资料调取
   来源：[[03-素材/选题库]] + [[00-收件箱]] 本周新素材
③ AI 处理
   助手：Newsletter 起草官（SOP：结构=开场1句+3条精选+1个观点）
   路径：贴素材 + SOP → 初稿
④ 人工验收
   验收：事实核对 / 口吻（D3 清单）/ 三条精选是否真值得读
⑤ 产出归档
   存放：[[04-档案/Newsletter/第N期]] + 发布
   沉淀：读者反馈记回 [[03-素材/选题库]]
```

## 实战任务

### 任务 1：选定练手任务（10 分钟）

选**一个你每周都会做的完整任务**（不是碎片动作）：

```text
好的练手任务：          不好的练手任务：
一期 Newsletter         "回复一条消息"（太小）
一份周报/月报           "学一个新工具"（不是任务）
一次客户方案交付        "整理一下资料"（没有终点产出）
一次复盘、一期视频脚本
```

### 任务 2：画流转图（20 分钟）

按五站模型画出你的流转图（模板见 `demos/templates/d5_工作流画布.md`）。**每一站必须写明**：

- 具体动作是什么
- 用知识库里的哪个资料/哪个助手（写出名字）
- 触发条件是什么（什么时候、什么事件触发这个流程）

### 任务 3：全链路真实跑通一遍（40 分钟）

不是想象，是**现在就跑**。按流转图一站一站执行：

```text
跑通检查点：
□ 任务已定义清楚（终点产出是什么）
□ 资料从知识库调出（30 秒内找到）
□ 助手 SOP 被使用（不是现编提示词）
□ 验收清单过一遍（人工环节真实执行）
□ 产出已归档进知识库（不是散落桌面）
□ 有没有哪一站卡住 → 记下来，调整流转图后重跑该站
```

### 任务 4：母版化（15 分钟）

跑通后，把流转图精简为一页"操作卡"存入 `02-项目/工作流/`。下次同类任务，照卡执行，不再思考流程本身。

## 实战场景

- **小李**："周报工作流"：收件箱本周事实 → 数据快读官 → 周报代笔官 → 验收 → 归档 + 发出。周四 30 分钟收工
- **王姐**："客户咨询工作流"：进线记录 → 初复咨询师 → 她只看"待确认点" → 回复 → 会话归档进客户档案
- **老张**："报价工作流"：需求单 → 报价助理出区间 → 他核价 → 报价单归档 + 跟进提醒

## 常见卡点 FAQ

**Q1：跑一半发现某站没有现成助手？**
A：临时用 D3 的提问公式手动做该站（不中断任务），完成后把这一站补成助手 SOP——工作流会"长"出新的助手需求，这正是它比清单强的地方。

**Q2：流程比直接干还慢？**
A：第一次跑慢是正常的（流程冷启动）。判断标准看第三次：如果第三次仍比手动慢，说明该任务不值得流程化，砍掉或简化——工作流也要有淘汰机制。

**Q3：触发总靠"想起来"，经常忘？**
A：给高频工作流上闹钟（每周四 10:00 = Newsletter 时间）。触发机制越"物理"越可靠：闹钟 > 待办清单 > 靠记忆。

**Q4：AI 处理这一站要贴好几次上下文，麻烦？**
A：这一站切换到 D2 的"长期挂载"路径（NotebookLM/Projects），资料包常驻后，流程里只剩"贴输入"一个动作。

## 小结

| 要点 | 说明 |
|---|---|
| 断点在衔接 | 单点提效有天花板，五站连线才有流水线 |
| 五站模型 | 任务进 → 资料取 → AI 处理 → 人工验 → 产出存 |
| 人工环节 | AI 出力，你拍板；错了要你负责的事不外包 |
| 母版化 | 跑通一次 → 操作卡 → 照卡执行不再思考 |
| 淘汰机制 | 第三次仍慢于手动的流程，砍掉 |
