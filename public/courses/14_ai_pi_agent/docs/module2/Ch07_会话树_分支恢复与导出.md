## 1. 会话的树结构

pi 的每个会话是一个 **JSONL 文件**（每行一条 JSON），默认存在 `~/.pi/agent/sessions/`，按工作目录组织。

每条记录有两个关键字段：`id` 和 `parentId`——这就是"树"的由来：

```
会话文件（一棵树）
├── ① 用户: "修复登录 bug"         ← 根节点
│   ├── ② 助手: 调用 grep …        ← parentId = ①
│   │   ├── ③ 助手: 调用 edit …    ← parentId = ②
│   │   │   └── ④ 用户: "换个方案"  ← 当前叶子（active path）
│   │   └── ⑤ 分支点：从这里 /tree 回到 ② 再走另一条路
│   │       └── ⑥ 助手: 用另一种方式修复   ← 新分支
│   └── ⑦ 另一条早期分支
```

**关键特性**：分支不产生新文件，全部保存在**同一个 JSONL** 里，通过 parentId 串联。这意味着：
- 历史永不丢失
- 可以随时回到任意节点"重来"
- 多个探索方向并存

```bash
# 查看当前会话文件
/session
# 输出示例: Session file: ~/.pi/agent/sessions/xxx.jsonl
```

## 2. 会话管理 CLI

| 命令 | 说明 |
|------|------|
| `pi -c` | 继续最近的会话 |
| `pi -r` | 浏览选择历史会话 |
| `pi --no-session` | 临时会话（不保存） |
| `pi --name "任务名"` | 启动时设置会话显示名 |
| `pi --session <路径\|id>` | 打开指定会话文件或 ID |
| `pi --fork <路径\|id>` | 从指定会话分支出新会话 |
| `pi --session-dir <目录>` | 自定义会话存储目录 |

```bash
# 继续昨天的会话
pi -c

# 用指定名字开启一次性任务（便于后续检索）
pi --name "release audit" -p "Audit this repository"

# 从另一个项目 fork 一个会话过来干活
pi --fork ~/.pi/agent/sessions/other-project/xxx.jsonl
```

## 3. `/tree`：可视化导航

按 `Escape` 两次或输入 `/tree`，进入会话树视图：

```
┌─ Session Tree ────────────────────────────────┐
│ ● 用户: 修复登录 bug                            │
│ ├─ 助手: 调用了 grep …                         │
│ │ ├─ 助手: 调用了 edit …                       │
│ │ │ └─ ◉ 用户: "换个方案"   ← 当前叶子          │
│ │ └─ 助手: 用另一种方式修复   ← 可切换的分支      │
│ └─ 助手: 直接重写文件                          │
└────────────────────────────────────────────────┘
```

### 3.1 操作

| 按键 | 功能 |
|------|------|
| `↑` `↓` | 移动选择 |
| `Enter` | 从该节点继续（后续成为新分支） |
| `Ctrl+←` `Ctrl+→`（或 Alt） | 折叠/展开、分支间跳转 |
| `←` `→` | 分页 |
| `Ctrl+O` | 切换过滤模式：默认 / no-tools / user-only / labeled-only / all |
| `Ctrl+X` | 复制选中消息 |
| `Shift+L` | 给条目打标签（书签） |
| `Shift+T` | 标签附带时间戳 |

### 3.2 过滤模式

| 模式 | 显示 |
|------|------|
| 默认 | 全部门类 |
| no-tools | 隐藏工具调用，只看对话 |
| user-only | 只看用户消息 |
| labeled-only | 只看打过标签的节点 |
| all | 全部 |

> 💡 打标签技巧：对关键节点按 `Shift+L` 打标签（如"方案A验证通过"），之后用 labeled-only 过滤，几十轮的会话也能秒定位。

## 4. `/fork` 与 `/clone`

两者都创建**新会话文件**，但语义不同：

| 操作 | 行为 | 场景 |
|------|------|------|
| `/fork` | 从某条**用户消息**分支出新会话，选中消息回到编辑器待修改 | 探索"另一种问法/方案" |
| `/clone` | **复制当前活动分支**到新会话，编辑器为空 | 想要一个干净的副本继续干 |
| `--fork`（CLI） | 从会话文件/ID 复制到当前项目新会话 | 跨项目复用 |

```
/fork 流程:
原会话: A → B → C → D(选中)
           ▼ /fork
新会话: A → B → C → [编辑器中可修改 D] → 提交新方案

/clone 流程:
原会话: A → B → C → D(当前分支)
           ▼ /clone
新会话: A → B → C → D (完整复制，编辑器为空)
```

> 💡 何时用哪个：想"换条路试试"用 `/fork`（编辑出发点）；想要"同样上下文换个新任务"用 `/clone`。

## 5. 导出、导入与分享

| 命令 | 说明 |
|------|------|
| `/export [文件]` | 导出为 HTML（可读）或 JSONL（可恢复） |
| `/import <文件>` | 从 JSONL 导入并恢复会话 |
| `/share` | 上传为私有 GitHub gist，得到可分享 HTML 链接 |

```bash
# 导出可读 HTML
/export session.html

# 导出可恢复 JSONL
/export session.jsonl

# 分享（需要 GitHub 认证）
/share
# → https://gist.github.com/xxx (私有链接)
```

**典型工作流**：
1. 长任务干了一半，导出 HTML 存档给同事看
2. 换个机器，`/export` JSONL → 新机器 `/import` 无缝续跑
3. 遇到有意思的调试过程，`/share` 发到群里讨论

## 6. 实战场景：调试回溯工作流

### 6.1 场景一：试错探索

```
你："修复登录 bug"
→ agent 方案 A 失败
→ /tree 回到方案 A 之前的节点，问"换一种思路，检查 token 过期"
→ 产生方案 B 分支
→ 再回 /tree 对比两条分支的结论
```

一次会话里并行探索多个方案，最终选定最优解——试错零成本。

### 6.2 场景二：跨机器无缝续跑

```bash
# 机器 A：导出可恢复会话
/export login-fix.jsonl

# 机器 B：恢复
/import login-fix.jsonl
# 或 CLI
pi --session login-fix.jsonl
```

适合在家/公司/服务器之间搬运未完成的任务。

### 6.3 场景三：分享调试过程

```bash
/share
# 得到私有 gist 链接，发给同事
```

配合 `Ctrl+X`（复制最后一条助手消息）快速粘贴关键结论到群里。

## 7. 常见问题 Q&A

**Q1：分支会不会把会话文件搞得很臃肿？**
A：所有分支都在同一个 JSONL，文件确实会变大，但每个节点只是追加，不重复存储历史；可定期 `pi --fork` 把活跃分支提取成新文件瘦身。

**Q2：`/tree` 里选中历史节点继续，原来的分支还在吗？**
A：在。继续只会产生新分支，原分支完整保留，随时可切回。

**Q3：`/fork` 和 `/clone` 都能从命令行用吗？**
A：可以。CLI 对应 `pi --fork <path|id>`；`/clone` 的等价 CLI 是 `pi --session <path> --name "new-name"`（复制后另存）。

**Q4：导出 HTML 和 JSONL 有什么区别？**
A：HTML 给人看（渲染完整对话）；JSONL 给机器恢复（可 `/import` 或 `--session` 续跑）。分享用 HTML，备份/迁移用 JSONL。

## 8. 动手试试

1. 连续问三个问题，按两次 `Escape` 打开 `/tree`，观察树形结构
2. 回到第 2 条消息继续，问一个不同的问题——产生一条新分支
3. 再用 `/tree` 切回原分支，确认两条分支都在
4. 给一个关键节点按 `Shift+L` 打标签，用 `Ctrl+O` 切到 labeled-only 过滤
5. 对第 1 条用户消息执行 `/fork`，改个问法提交
6. 执行 `/export session.html` 并打开看效果

## 9. 小结

| 要点 | 说明 |
|------|------|
| 会话格式 | JSONL 树，id/parentId 链，分支不产生新文件 |
| CLI | `-c` 继续 / `-r` 恢复 / `--session` 指定 / `--fork` 分支 |
| `/tree` | 可视化导航、分支切换、过滤、标签 |
| `/fork` | 从用户消息分叉，编辑器带可改的出发点 |
| `/clone` | 复制当前分支到新会话 |
| 导出分享 | HTML 给人看 / JSONL 恢复 / gist 分享 |
