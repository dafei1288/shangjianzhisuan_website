# Ch09：设置、上下文文件与项目信任

> 配置是智能体的"性格"。这一章讲透三件事：settings.json 的分层配置体系、AGENTS.md / CLAUDE.md 上下文文件如何让模型"懂你的项目"、以及项目信任机制如何在安全与便利之间取得平衡。

## 学习目标

学完本章后，你将能够：

1. 区分全局与项目设置，理解合并规则
2. 用 settings.json 配置常用选项（compaction / retry / transport 等）
3. 编写 AGENTS.md / CLAUDE.md 上下文文件，让模型遵循项目约定
4. 使用 SYSTEM.md 自定义系统提示
5. 说清项目信任流程（trust）并正确使用 `/trust`

## 1. settings.json：分层配置

### 1.1 两个层级

| 位置 | 作用域 | 优先级 |
|------|--------|--------|
| `~/.pi/agent/settings.json` | 全局（所有项目） | 低 |
| `.pi/settings.json` | 项目级（覆盖全局） | **高** |

**合并规则**：项目设置覆盖全局设置，**嵌套对象按 key 合并**（不是整体替换）：

```jsonc
// ~/.pi/agent/settings.json（全局）
{
  "thinkingLevel": "medium",
  "compaction": { "enabled": true, "threshold": 0.85 },
  "transport": "auto"
}

// .pi/settings.json（项目）
{
  "compaction": { "threshold": 0.7 }   // 只覆盖 threshold，enabled 沿用全局
}
```

### 1.2 常用设置项

```jsonc
{
  "thinkingLevel": "medium",          // 默认 thinking 等级
  "theme": "dark",                    // 主题
  "steeringMode": "one-at-a-time",    // 消息队列投递（ch06）
  "followUpMode": "one-at-a-time",
  "transport": "auto",                // sse / websocket / auto
  "compaction": {                     // 压缩（ch08）
    "enabled": true,
    "threshold": 0.85
  },
  "retry": { "enabled": true, "maxRetries": 3 },   // 自动重试
  "enableSkillCommands": true,        // /skill:name 命令
  "defaultProjectTrust": "ask",       // 未决时的信任回退（见 §4）
  "enableInstallTelemetry": false,    // 安装遥测开关
  "skills": ["~/.claude/skills"],     // 额外技能目录（复用其他工具）
  "extensions": ["/path/to/ext.ts"]   // 额外扩展路径
}
```

> 💡 交互式修改：多数常用项也可以直接用 `/settings` 菜单修改，改完写入对应 JSON。

## 2. 上下文文件：AGENTS.md / CLAUDE.md

### 2.1 加载机制

pi 启动时从以下位置加载上下文文件并**拼接**进系统提示：

```
~/.pi/agent/AGENTS.md      ← 全局（所有项目生效）
父目录 AGENTS.md（向上走）  ← 仓库级约定
当前目录 AGENTS.md         ← 本项目约定
```

**重要**：`CLAUDE.md` 同样被识别（很多项目已有 Claude Code 的 CLAUDE.md，pi 直接复用）。

### 2.2 写什么

AGENTS.md 是给模型的"项目说明书"：

```markdown
# 项目约定

## 技术栈
- TypeScript + Node 20，使用 pnpm

## 命令
- 构建: pnpm build
- 测试: pnpm test        # 改动后必须跑
- Lint: pnpm lint

## 代码规范
- 函数命名用 camelCase
- 错误处理：不要吞异常，用 Result 模式
- 修改公共 API 必须更新 docs/API.md

## 禁止
- 不要修改 node_modules/
- 不要删除 .env
```

### 2.3 效果

- 模型每次启动都读到这些约定 → 行为自动对齐团队规范
- 减少口头交代：AGENTS.md 写清楚，提问时模型自动遵守
- 团队共享：AGENTS.md 提交进仓库，所有人（包括 CI 里的 pi）行为一致

> 💡 这是「团队智能体工作流」的地基，ch29 会把它升级成完整体系。

### 2.4 关闭加载

```bash
pi --no-context-files    # 或 -nc，禁用上下文文件发现
```

## 3. SYSTEM.md：替换系统提示

默认系统提示定义了 pi 的角色（编码助手 + 工具使用规范）。你可以：

| 文件 | 行为 |
|------|------|
| `.pi/SYSTEM.md`（项目） | **替换**默认系统提示 |
| `~/.pi/agent/SYSTEM.md`（全局） | 全局替换 |
| `APPEND_SYSTEM.md` | **追加**（不替换） |

```markdown
<!-- .pi/SYSTEM.md -->
你是一个严格的代码审查助手。输出必须包含：
1. 问题清单（按严重度排序）
2. 修复建议（带代码）
3. 无问题时明确说"通过"
```

> ⚠️ 替换默认提示会丢掉工具使用规范，通常优先用 AGENTS.md 或 APPEND_SYSTEM.md 追加，而非整体替换。

## 4. 项目信任机制

### 4.1 为什么需要信任

项目目录可能包含**本地配置与可执行代码**（`.pi/settings.json`、`.pi/extensions/`、`.agents/skills/`）。pi 在加载这些**项目级资源前**会先确认信任——防止克隆一个恶意仓库就自动执行里面的代码。

### 4.2 信任流程

```
启动 pi 于某项目
   │
   ├─ 项目含 .pi 资源 / .agents/skills 且无已存决定？
   │     │ 是
   │     ▼
   │  询问: 信任此项目？  [Yes / No / 记住]
   │     │
   │     ▼
   │  保存到 ~/.pi/agent/trust.json（记住时）
   │
   ▼
信任后: 才加载 .pi/settings.json、项目扩展、项目技能
未信任: 只加载上下文文件 + 全局/CLI 扩展
```

**相关命令**：

| 方式 | 说明 |
|------|------|
| `/trust` | 保存信任决定（写 trust.json），重启生效 |
| `--approve` / `-a` | 单次运行信任项目本地配置 |
| `--no-approve` / `-na` | 单次运行忽略项目本地配置 |
| `defaultProjectTrust` | 非交互模式的回退：`ask`（默认）/ `always` / `never` |

> ⚠️ 非交互模式（-p / json / rpc）不弹确认框，靠 `defaultProjectTrust` 决定；脚本里跑 pi 前记得评估是否加 `-a`。

## 常见问题 Q&A

**Q1：AGENTS.md、CLAUDE.md、SYSTEM.md 到底应该选哪个？**
A：优先用 AGENTS.md / CLAUDE.md 写项目约定，因为它们是追加上下文，不会破坏默认工具规范。只有你明确要重写 agent 角色和行为边界时，才使用 SYSTEM.md；多数团队更适合用 APPEND_SYSTEM.md 做补充。

**Q2：项目级 `.pi/settings.json` 要不要提交到仓库？**
A：如果它代表团队共识，例如包管理器、默认模型范围、技能目录，可以提交。如果里面包含个人路径、私有扩展或敏感信息，就放在全局配置或 `.gitignore` 里。

**Q3：为什么项目本地扩展和技能需要 trust？**
A：因为扩展是可执行代码，技能也可能引导模型运行脚本。trust 机制的意义是避免你刚 clone 一个陌生仓库时，就自动加载其中的可执行资源。

**Q4：非交互模式下 trust 怎么处理？**
A：`pi -p`、json、rpc 不适合弹确认框，所以要提前设置 `defaultProjectTrust`，或在明确可信的脚本中使用 `-a`。CI 里建议默认不信任项目级扩展，只加载审查过的全局资源。

## 6. 小结

| 要点 | 说明 |
|------|------|
| 设置分层 | 全局 `~/.pi/agent/` + 项目 `.pi/`，项目优先，嵌套合并 |
| 常用项 | thinking / theme / compaction / retry / transport / skills 目录 |
| 上下文文件 | AGENTS.md / CLAUDE.md 从全局+父目录+当前目录拼接加载 |
| SYSTEM.md | 项目/全局替换默认系统提示；APPEND_SYSTEM.md 追加 |
| 项目信任 | 防恶意仓库；`/trust`、`-a`/`-na`、`defaultProjectTrust` |
