## 1. 界面四区总览

pi 的交互界面从上到下分四个区域：

```
┌─────────────────────────────────────────────┐
│ ① 启动头部：快捷键提示 / AGENTS.md / 技能 / 扩展 │
├─────────────────────────────────────────────┤
│ ② 消息区：你的消息、回复、工具调用与结果        │
│   （thinking 块可折叠、工具输出可折叠）          │
├─────────────────────────────────────────────┤
│ ③ 编辑器：输入框（边框颜色 = thinking 等级）    │
├─────────────────────────────────────────────┤
│ ④ 页脚：目录 / 会话名 / token / 费用 / 模型     │
└─────────────────────────────────────────────┘
```

| 区域 | 关键信息 |
|------|---------|
| ① 启动头部 | 输入 `/hotkeys` 看全部快捷键；显示已加载的 AGENTS.md、模板、技能、扩展 |
| ② 消息区 | 流式输出；`Ctrl+O` 折叠/展开工具输出，`Ctrl+T` 折叠/展开 thinking |
| ③ 编辑器 | 主战场，本章重点 |
| ④ 页脚 | `↑`输入 `↓`输出 `R`缓存读 `W`缓存写 `CH`缓存命中率，+ 费用/上下文/模型 |

## 2. 编辑器核心技巧

### 2.1 `@` 文件引用 — 让模型"看到"文件

在输入框输入 `@`，会弹出模糊搜索，选择项目文件后把文件内容附带给 LLM：

```
@config.ts 帮我看下这个文件的配置逻辑
```

**适用场景**：需要模型精确读取某个文件，而不是让它自己去翻。

### 2.2 Tab 路径补全

输入路径时按 `Tab` 自动补全：

```
请修改 src/uti[Tab] → src/utils/
```

> 💡 配合 `@` 使用：先 `@` 选文件，再补充指令，是最高频的提效组合。

### 2.3 多行输入

- **Shift+Enter**（Windows Terminal 用 Ctrl+Enter）输入多行
- 写完多行指令后按 Enter 发送

```
写一段脚本：
1. 读取 data.csv
2. 过滤空行
3. 输出统计
[Shift+Enter]
就按这个步骤来[Enter 发送]
```

### 2.4 外部编辑器（Ctrl+G）

按 `Ctrl+G` 用外部编辑器打开输入内容（`$VISUAL` / `$EDITOR`，Windows 默认记事本，其他平台 nano）。适合编辑长指令、复杂提示词。

### 2.5 粘贴图片

- **Ctrl+V**（Windows Terminal 用 Alt+V）粘贴剪贴板中的图片
- 或直接把图片文件拖进终端
- pi 会把图片作为多模态输入附带给模型

```
[粘贴一张报错截图] 帮我分析这个报错
```

## 3. bash 快捷命令：在对话中执行命令

| 输入 | 行为 | 适用场景 |
|------|------|---------|
| `!命令` | 执行命令，**结果发送给 LLM** | 让模型基于命令输出继续推理 |
| `!!命令` | 执行命令，**结果不发送** | 只想自己看结果，不污染对话 |

```bash
!git status                      # 执行并把结果给模型
!!npm run build                  # 执行但不打扰模型
```

> 💡 典型用法：`!git diff` 后紧跟着提问"帮我 review 这些改动"——命令输出直接成为模型上下文，省掉一次工具调用。

## 4. 常用快捷键速查

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+C` | 清空编辑器 |
| `Ctrl+C` ×2 | 退出 pi |
| `Escape` | 取消/中止当前任务 |
| `Escape` ×2 | 打开 `/tree` 会话树 |
| `Ctrl+L` | 打开模型选择器 |
| `Ctrl+P` / `Shift+Ctrl+P` | 循环切换模型（前/后） |
| `Shift+Tab` | 循环 thinking 等级 |
| `Ctrl+O` | 折叠/展开工具输出 |
| `Ctrl+T` | 折叠/展开 thinking 块 |
| `Ctrl+X` | 复制最后一条助手消息 |
| `Ctrl+G` | 外部编辑器 |
| `Ctrl+V` / `Alt+V` | 粘贴图片（Windows） |

自定义快捷键：编辑 `~/.pi/agent/keybindings.json`（详见 ch09 与 `/hotkeys`）。

## 5. 实战场景：三个高频组合

### 5.1 场景一：让模型“先看后改”

```
@src/utils/format.ts 这个函数有 bug，帮我看一下并修复
```

流程：`@` 把文件内容附带给模型 → 模型直接分析 → 用 `edit` 工具改文件。省去“请先找到文件再读”的两轮往返。

### 5.2 场景二：用 `!` 把命令输出变成上下文

```
!git diff
以上是我的改动，帮我 review 一下有没有 bug
```

`git diff` 的输出直接进入对话，模型立刻基于真实改动 review，而不是自己猜。

### 5.3 场景三：图片反馈 UI 修改

```
[拖入设计稿截图] 把页面改成这个样式，重点是对齐和间距
```

多模态输入让“设计还原”类任务从口头描述变成看图说话。

### 5.4 场景四：外置编辑器写长提示

复杂任务（如代码评审要求、重构方案）用 `Ctrl+G` 打开外置编辑器写完整，再发送——避免终端里长文本误触快捷键。

## 6. 常见问题 Q&A

**Q1：`@` 选中的文件内容会一直留在上下文里吗？**
A：会作为一条消息内容进入上下文（除非被压缩）。频繁 `@` 大文件会快速消耗 token，建议只对必要文件使用；大文件优先让模型自己 `read` 关键片段。

**Q2：`!` 和直接让模型跑 `bash` 有什么区别？**
A：`!` 是你主动执行并把结果发送给 LLM；模型跑 `bash` 是它自己决定执行。`!` 适合“我知道要跑什么、只要结果进对话”，模型跑工具适合探索式任务。

**Q3：粘贴图片在哪些平台可用？**
A：终端支持图片粘贴即可（Windows Terminal / iTerm2 / Kitty 等）。Windows 上 `Ctrl+V` 若被占用，改用 `Alt+V`。

**Q4：Ctrl+C 会不会把正在执行的任务杀掉？**
A：按一次是清空编辑器；如果 agent 正在跑，需要按 `Escape` 中止任务，再按 `Ctrl+C` 两次退出 pi。
