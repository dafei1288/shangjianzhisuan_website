## 1. 提供商全景

### 1.1 两类接入方式

```
pi 的提供商体系
├── 订阅（/login OAuth）
│   ├── Claude Pro / Max
│   ├── ChatGPT Plus / Pro（Codex）
│   └── GitHub Copilot
│
└── API Key（export 环境变量 或 /login 选择）
    ├── 海外：Anthropic / OpenAI / Google Gemini / Mistral / Groq / OpenRouter / xAI …
    ├── 国内：DeepSeek / Kimi（月之暗面）/ MiniMax / 智谱 …
    └── 网关：Cloudflare AI Gateway / Vercel AI Gateway / OpenCode Zen …
```

### 1.2 模型目录自动刷新

```bash
pi update --models        # 强制刷新模型目录（平时自动更新）
pi --list-models          # 列出可用模型
pi --list-models claude   # 按关键字搜索
```

> 💡 pi 为每个内置提供商维护"支持工具调用"的模型清单——不是所有模型都能当 agent 用（需要 tool calling 能力）。

## 2. 模型切换技巧

| 操作 | 方法 |
|------|------|
| 选择模型 | `/model` 或 `Ctrl+L`（搜索式选择器） |
| 循环切换 | `Ctrl+P` / `Shift+Ctrl+P`（前/后） |
| 限定循环范围 | `/scoped-models` 或启动 `--models` |
| CLI 指定 | `pi --model anthropic/claude-sonnet-4-6:high` |
| 默认模型 | settings.json 的 `model` 字段 |

```bash
# 限定循环范围（日常只在这几个里切）
pi --models "claude-*,gpt-4o"

# 会话内管理
/scoped-models
```

### 2.1 模型选择策略

| 任务类型 | 建议 |
|---------|------|
| 简单问答/格式化 | 小模型（快、便宜） |
| 日常编码 | 中档主力模型 |
| 架构/疑难调试 | 旗舰模型 + 高 thinking |
| 长文档/大批量 | 高上下文模型 |

## 3. Thinking 七档

### 3.1 等级体系

| 等级 | 用途 | 速度/成本 |
|------|------|----------|
| `off` | 简单问答、格式化 | 最快最省 |
| `minimal` | 轻量推理 | 快 |
| `low` | 日常编码 | 均衡 |
| `medium` | 默认，标准任务 | 均衡 |
| `high` | 复杂任务、重构 | 较慢较贵 |
| `xhigh` | 架构设计、疑难 bug | 慢 |
| `max` | 最复杂推理 | 最慢最贵 |

### 3.2 切换方式

```bash
# 交互
Shift+Tab                    # 循环切换
/settings                    # 菜单设置默认等级

# CLI
pi --thinking high "解决这个难题"
pi --model sonnet:high "…"   # 模型+等级一起指定

# 会话内
/model                       # 选择器里可带等级
```

> 💡 实战经验：**先 low/off 快跑验证思路，再 high 解决卡点**，比全程 max 又慢又贵，效果往往更好。编辑器边框颜色实时显示当前等级。

## 4. 本地模型：llama.cpp

不想用云 API（隐私/离线/省钱）可以本地跑模型：

```bash
pi
/login llama.cpp        # 配置本地路由
/llama                  # 下载/加载/卸载模型
/model                  # 选择已加载的模型
```

```
pi ──► llama.cpp router（本地）──► 本地模型（GGUF）
        └ 兼容 OpenAI API，pi 直接对话
```

**适用场景**：
- 代码在本地，隐私敏感
- 无网络环境开发
- 调优 prompt 阶段低成本试错

> 注意：本地模型的 tool calling 能力取决于模型本身（Qwen、Llama 系支持较好）。

## 5. 实战：模型调优清单

一套从“慢而贵”到“快而省”的调优流程，适合日常开发：

```
① 确认需求复杂度
   ├─ 简单（格式化/问答/命名）→ 小模型 + off
   ├─ 中等（日常编码/修 bug）→ 主力模型 + low/medium
   └─ 复杂（架构/疑难调试）→ 旗舰模型 + high/max

② 先快后慢：先用低等级跑通思路，再用高等级解决卡点
③ 监控成本：页脚费用 + HUD 配额（ch22）
④ 沉淀经验：哪些任务用哪个模型，写进团队 settings.json
```

**示例会话流程**：

```bash
# 第一步：快速验证思路（便宜模型 + off）
pi --model gpt-4o-mini --thinking off "分析这个报错的可能原因"

# 第二步：确认方案后，用强模型 + 高思考深入实现
pi --model sonnet:high "按上面的分析重构这段代码"
```

> 💡 核心心法：**等级匹配复杂度，而不是永远 max**。多数任务 medium 足够，旗舰+高思考留给真正的难题。

## 7. 常见问题 Q&A

**Q1：为什么 `--list-models` 里有些模型选不了？**
A：pi 只列"支持工具调用"的模型；另外模型目录按提供商配置动态生成，未认证的提供商不显示其模型。

**Q2：thinking 等级会不会改变答案正确性？**
A：对复杂推理任务，高 thinking 通常显著提升正确率；对简单任务几乎无差别。核心原则：按任务难度匹配，而不是永远最高。

**Q3：订阅和 API Key 能同时配置吗？**
A：能。凭证互不干扰，`/model` 里两个体系的模型都在，切到哪个用哪个。注意按量付费的模型别在订阅会话里误用。

**Q4：怎么给团队统一默认模型？**
A：项目 `.pi/settings.json` 里设 `model` 和 `thinkingLevel`，提交进仓库即可统一团队行为。
