## 1. 什么时候需要自定义

| 场景 | 方案 |
|------|------|
| 已有兼容 API，但模型没在内置清单 | models.json 加模型 |
| 自建网关/内网代理（OpenAI 兼容） | models.json 加提供商 |

## 2. models.json：给兼容 API 加模型

配置文件：`~/.pi/agent/models.json`。

### 2.1 给已有提供商补模型

```jsonc
{
  "providers": {
    "openai": {
      "models": [
        {
          "id": "my-internal-gpt",
          "name": "Internal GPT (网关)",
          "reasoning": false,
          "input": ["text"],
          "cost": { "input": 0.5, "output": 1.5, "cacheRead": 0.1, "cacheWrite": 0.5 },
          "contextWindow": 128000,
          "maxTokens": 4096
        }
      ]
    }
  }
}
```

### 2.2 声明全新提供商（OpenAI 兼容）

```jsonc
{
  "providers": {
    "my-vendor": {
      "baseUrl": "https://api.my-vendor.com/v1",
      "apiKey": "$MY_VENDOR_KEY",        // 读环境变量
      "api": "openai-completions",       // 协议：openai / anthropic / google
      "models": [
        {
          "id": "my-model-1",
          "name": "My Model 1",
          "reasoning": true,
          "input": ["text", "image"],
          "cost": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0 },
          "contextWindow": 100000,
          "maxTokens": 8192
        }
      ]
    }
  }
}
```

### 2.3 字段速查

| 字段 | 说明 |
|------|------|
| `baseUrl` | API 基础地址 |
| `apiKey` | 密钥（`$ENV_VAR` 引用环境变量，或用 auth.json） |
| `api` | 兼容协议：`openai-completions` / `anthropic-messages` / `google` |
| `models[].id` | 模型 ID（发请求用） |
| `reasoning` | 是否支持推理（thinking） |
| `input` | 输入模态：text / image |
| `cost` | 每百万 token 单价（input/output/cacheRead/cacheWrite） |
| `contextWindow` / `maxTokens` | 上下文窗口与最大输出 |

> ⚠️ 成本字段必须填对——它驱动页脚的费用显示与缓存策略计算，填 0 会看不到真实费用。

## 3. 用扩展实现自定义提供商

需要 OAuth、私有协议或动态模型发现时，用扩展的 `pi.registerProvider()`（ch16 会讲扩展基础，这里先看机制）：

```typescript
// ~/.pi/agent/extensions/my-provider.ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default async function (pi: ExtensionAPI) {
  // 启动时拉取远程模型列表
  const res = await fetch("http://localhost:1234/v1/models");
  const payload = await res.json();

  // 动态注册提供商
  pi.registerProvider("local-openai", {
    baseUrl: "http://localhost:1234/v1",
    apiKey: "$LOCAL_OPENAI_API_KEY",
    api: "openai-completions",
    models: payload.data.map((m: any) => ({
      id: m.id,
      name: m.name ?? m.id,
      reasoning: false,
      input: ["text"],
      cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
      contextWindow: m.context_window ?? 128000,
      maxTokens: m.max_tokens ?? 4096,
    })),
  });
}
```

**异步工厂 + 动态模型**的典型场景：
- 本地推理服务器（LM Studio / Ollama 等）的模型列表
- 企业内部门户的动态模型目录
- 需要先获取 token 才能列模型的 API

> 扩展注册的提供商在启动前完成 flush，`pi --list-models` 也能看到它们（ch16 详述扩展加载时机）。

## 4. 实战案例：接入内网模型网关

很多公司有内网 OpenAI 兼容网关（统一计费/审计/路由）。接入只需一个 provider 定义：

```jsonc
// ~/.pi/agent/models.json
{
  "providers": {
    "corp-gateway": {
      "baseUrl": "https://llm.corp.internal/v1",
      "apiKey": "$CORP_GATEWAY_KEY",       // 从环境变量读，或 /login 存 auth.json
      "api": "openai-completions",
      "models": [
        {
          "id": "corp-gpt-4o",
          "name": "Corp GPT-4o (内网)",
          "reasoning": false,
          "input": ["text"],
          "cost": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0 },
          "contextWindow": 128000,
          "maxTokens": 4096
        }
      ]
    }
  }
}
```

验证：

```bash
pi --list-models | grep corp
# → corp-gateway/corp-gpt-4o
pi --model corp-gateway/corp-gpt-4o -p "测试连接"
```

> 💡 内网网关通常内部计费（cost 填 0 不影响实际扣费，但页脚费用显示会失真；有计费接口的话用扩展实现真实费用，参考 ch22 quota 模式）。

## 6. 常见问题 Q&A

**Q1：models.json 和扩展注册 provider 哪个优先？**
A：models.json 是静态配置（简单场景）；扩展注册是动态的（需要代码逻辑）。两者可以共存，ID 冲突时以扩展为准。

**Q2：自定义模型为什么工具调用失败？**
A：多半是模型本身不支持 tool calling，或 `reasoning`/`input` 字段声明与实际能力不符。检查：模型是否真兼容所选协议、`baseUrl` 路径是否正确。

**Q3：`apiKey` 用 `$ENV` 还是 auth.json？**
A：环境变量适合 CI/脚本；auth.json 适合个人交互使用（`/login` 写凭证）。扩展场景两者都能用，`ModelRuntime` 的解析优先级：运行时覆盖 → auth.json → 环境变量。

**Q4：可以完全不用 pi 内置的模型目录吗？**
A：可以。`pi --no-...` 相关开关 + 只保留自己的 models.json 提供商，配合 `--no-extensions` 等参数，能做到"只用自己的配置"（CLI 资源选项详见 README）。

## 7. 小结

| 要点 | 说明 |
|------|------|
| 兼容层 | OpenAI / Anthropic / Google 三协议可接入 |
| models.json | 补模型、声明新提供商、字段控制上下文/成本/能力 |
| 扩展注册 | `pi.registerProvider()` 动态模型 + OAuth + 私有协议 |
| 成本字段 | 务必填对，驱动费用显示与缓存计算 |
| 适用边界 | 静态配置用 models.json，动态逻辑用扩展 |
