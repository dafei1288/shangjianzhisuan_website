## 1. 什么是 pi？

### 1.1 核心概念

**pi**（官网 pi.dev，npm 包 `@earendil-works/pi-coding-agent`）是一个 **minimal terminal coding harness**——一个极简的终端编码智能体框架。

拆开这三个词：

| 词 | 含义 |
|----|------|
| **terminal** | 跑在终端里，不是网页不是 IDE 插件 |
| **coding** | 专为编程任务设计：读代码、改文件、跑命令 |
| **harness** | 不直接提供智能，而是给 LLM 装上"手和脚"的执行框架 |

官方 slogan 一句话点透它的性格：

> *"There are many agent harnesses, but this one is yours."*
> 有很多智能体框架，但**这一个**是你的。

#### 极简内核是什么

pi 的内核小到只有几件事：

1. 一个 **Agent Loop**（LLM ↔ 工具 ↔ 用户的循环）
2. 四个内置工具：`read`、`write`、`edit`、`bash`
3. 会话管理（JSONL 树）、上下文压缩、设置加载

它**不做**其他工具内置的功能（子代理、MCP、权限弹窗、计划模式、待办清单），而是把定制能力全部交给外部扩展。这就是「内核极简、能力外置」。

### 1.2 pi 与 LLM 的关系

```
┌─────────────────────────────────────────────┐
│                 pi (Harness)                │
│                                             │
│  ┌───────────────┐      ┌────────────────┐  │
│  │   Agent Loop  │ ───► │    LLM (大脑)   │  │
│  │   (循环调度)   │ ◄─── │  推理/规划/决策  │  │
│  └───────┬───────┘      └────────────────┘  │
│          │ 请求                                │
│          ▼                                   │
│  ┌───────────────┐     ┌─────────────────┐   │
│  │   内置工具     │     │  扩展工具/技能   │   │
│  │ read/edit/    │     │  (后续章节主角)  │   │
│  │ write/bash    │     └─────────────────┘   │
│  └───────────────┘                           │
└─────────────────────────────────────────────┘

职责边界：
  LLM 负责「想」——读指令、决定下一步调哪个工具
  pi  负责「做」——执行工具、管理会话、喂回结果
```

**类比**：
- **LLM** = 大脑：会思考、会规划，但没有"手"
- **pi** = 身体 + 神经系统：大脑说要读文件，它就真的去读；读完把结果传回大脑

这就是所有编码智能体的本质：**一个大脑 + 一套能碰代码的手脚**。

### 1.3 与 Claude Code / Codex 的对比

| 维度 | pi | Claude Code | Codex CLI |
|------|----|-------------|-----------|
| 内核哲学 | 极简，能力全部外置 | 功能完整内置 | 功能完整内置 |
| 子代理 | ❌ 不做（可扩展实现） | ✅ 内置 | ✅ 内置 |
| MCP | ❌ 不做（可扩展实现） | ✅ 内置 | ✅ 内置 |
| 权限弹窗 | ❌ 不做（容器/扩展实现） | ✅ 内置 | ✅ 审批模式 |
| 计划模式 | ❌ 不做（写文件/扩展实现） | ✅ 内置 | ✅ 内置 |
| 扩展机制 | TypeScript 扩展 + 技能 + 模板 | Hooks + 技能 + MCP | Agent SDK |
| 定制深度 | 极高（可替换 UI/内核行为） | 中（受内置限制） | 中 |

> 💡 关键洞察：pi 的"少"不是缺陷，而是设计选择——把决策权交给你。别人内置的每个功能，在 pi 里都是一道"你可以自己实现"的练习题，这也是本课程的核心主线。

## 2. 极简内核哲学

### 2.1 pi 刻意不做的事

pi 的官方文档（README Philosophy 章节）明确列出了几个"刻意不做"：

| 不做 | 理由 | pi 的替代方案 |
|------|------|--------------|
| **MCP** | 构建带 README 的 CLI 工具（技能）更简单 | Skills / 扩展实现 MCP |
| **子代理** | 实现方式太多，不替你决定 | tmux 起多个 pi / 扩展实现 |
| **权限弹窗** | 安全模型应贴合你的环境 | 容器运行 / 扩展实现确认流程 |
| **计划模式** | 计划应写进文件，而不是 UI | TODO.md / 扩展实现 |
| **内置待办** | 会混淆模型 | TODO.md 文件 |
| **后台 bash** | tmux 有完整可观测性 | tmux |

**核心思想**：pi 宁可把内核做小，也不把你锁死在它设计的某种工作流里。你想怎么干活，就怎么扩展它。

### 2.2 为什么这对学习者是好消息

- **入门者**：内核小 → 整个智能体工作机制一目了然，学完能真正"看懂"一个 agent 是怎么跑起来的，而不是被海量功能淹没
- **定制者**：每个"缺失功能"都是一个接口，pi 用最直接的方式告诉你：这里可以插你自己的实现

## 3. 四个扩展维度

pi 的定制能力由四种"资源"构成，它们也是后面 M3-M6 的主角：

```
┌────────────────────────────────────────────────┐
│                   Pi 资源体系                    │
│                                                │
│  ┌─────────────┐ ┌─────────────┐              │
│  │ Extensions  │ │    Skills   │              │
│  │ TypeScript  │ │ SKILL.md    │              │
│  │ 扩展模块     │ │ 按需技能包    │              │
│  │ 工具/事件/UI │ │ 渐进式披露    │              │
│  └─────────────┘ └─────────────┘              │
│  ┌─────────────┐ ┌─────────────┐              │
│  │  Prompt     │ │   Themes    │              │
│  │ Templates   │ │  主题/外观   │              │
│  │ /名称 模板   │ │  热重载      │              │
│  └─────────────┘ └─────────────┘              │
│                                                │
│  ┌──────────────────────────────────────────┐  │
│  │  Pi Packages：把上面四种打包分享到 npm/git │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

| 维度 | 是什么 | 放哪里 | 课程章节 |
|------|--------|--------|---------|
| **Extensions** | TypeScript 模块：自定义工具、命令、事件拦截、UI | `~/.pi/agent/extensions/`、`.pi/extensions/` | M5（ch16-22） |
| **Skills** | 按需加载的能力包（Agent Skills 标准） | `~/.pi/agent/skills/`、`.agents/skills/` | M4（ch13-15） |
| **Prompt Templates** | 可复用的提示模板，`/名称` 展开 | `~/.pi/agent/prompts/`、`.pi/prompts/` | M3（ch10） |
| **Themes** | 终端主题，热重载 | `~/.pi/agent/themes/`、`.pi/themes/` | M3 附带 |
| **Pi Packages** | 打包以上四种，npm/git 分发 | `pi install npm:xxx` | M6（ch23） |

## 4. 一个会话的完整旅程（预览）

先看一张全貌图，把「极简内核」四个字具象化——这就是 pi 内部一次对话的全部流程：

```
你输入: "把 README.md 里的表格转成 markdown 列表"
          │
          ▼
  ┌────────────────────────────────────┐
  │            pi 内核                 │
  │                                    │
  │  ① 组装上下文 (AGENTS.md + 历史)    │
  │  ② 发给 LLM (系统提示 + 工具清单)    │
  │  ③ LLM 回复: 调用 read 读文件       │
  │  ④ 执行 read → 结果回传 LLM         │
  │  ⑤ LLM 回复: 调用 edit 改文件       │
  │  ⑥ 执行 edit → 结果回传             │
  │  ⑦ LLM 总结完成，输出给用户          │
  │                                    │
  └────────────────────────────────────┘
          │
          ▼
 会话存为 JSONL (可 /tree 分支回溯)
```

第 ③④⑤⑥ 步就是一个 **Agent Loop（工具循环）**——它是 pi 和所有编码智能体的心脏，下一章（ch02）我们会把它彻底拆开。

## 5. 动手试试：安装并跑起你的第一个 pi

### 5.1 安装

**方式一：npm 全局安装（推荐）**

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

`--ignore-scripts` 跳过依赖的生命周期脚本，pi 正常安装不需要它们。

**方式二：官方安装脚本（Linux / macOS）**

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

### 5.2 认证

**方式 A：API Key**

```bash
export ANTHROPIC_API_KEY=sk-ant-...
pi
```

**方式 B：订阅登录（Claude Pro/Max、ChatGPT Plus、GitHub Copilot）**

```bash
pi
/login    # 然后选择提供商
```

### 5.3 第一次对话

```bash
pi "列出当前目录下所有 .ts 文件"
```

你会看到 pi 的模型：先思考，再调用 `ls` / `find` 之类的工具，最后给你答案——**一个"大脑"第一次长出"手"的瞬间**。

### 5.4 验证你的认知

```bash
pi --version                          # 版本
pi --help                             # 完整 CLI 参考
pi --list-models | head               # 可用模型（需已认证）
```

## 常见问题 Q&A

**Q1：我已经会用 Claude Code / Codex，还有必要学 pi 吗？**
A：有必要，前提是你想理解和定制智能体内核。Claude Code / Codex 更像完整产品，pi 更像可拆开的工作台；学 pi 的收益不是“又会一个工具”，而是能看懂 Agent Loop、扩展点和工具契约。

**Q2：pi 刻意不做 MCP、子代理、权限弹窗，会不会不够用？**
A：日常编码够用，复杂能力通过扩展、技能、tmux 或容器补齐。课程后半段正是围绕这些“缺失功能”展开，让你学会按自己的安全模型和工作流来装配能力。

**Q3：这门课需要先读 pi 源码吗？**
A：不需要。前半段先从使用和心智模型入手，后半段再进入扩展和 SDK；如果你能读懂 TypeScript 函数签名，就可以跟着代码示例逐步深入。

**Q4：我应该按顺序学完 30 章，还是只看扩展部分？**
A：第一次建议至少按 M1-M2 建立基础，再进入你关心的模块。已经熟悉终端智能体的同学可以快速扫过 Ch01-Ch09，重点投入 Ch16-Ch22 和 Ch30。
