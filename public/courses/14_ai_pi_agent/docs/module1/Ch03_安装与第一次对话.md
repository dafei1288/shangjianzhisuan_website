> 环境搭建全流程：安装 pi、认证提供商、完成第一次对话。从一个"Hello World"开始，亲眼看到 Agent Loop 第一次跑起来。

## 学习目标

学完本章后，你将能够：

1. 用两种方式安装 pi（npm / 官方脚本）

5. 用 CLI 参数验证安装

## 1. 安装 pi

### 1.1 方式一：npm 全局安装（推荐）

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

`--ignore-scripts` 跳过依赖生命周期脚本——pi 正常安装不需要它们（省时间、更安全）。

验证：

```bash
pi --version
```

### 1.2 方式二：官方安装脚本（Linux / macOS）

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

### 1.3 平台注意

| 平台 | 说明 |
|------|------|
| Windows | 参考官方 docs/windows.md（终端推荐 Windows Terminal） |
| Android（Termux） | 参考 docs/termux.md |
| tmux 用户 | 参考 docs/tmux.md（配合后台会话使用） |

### 1.4 常见问题排查

```bash
pi --version          # 版本
which pi              # 安装位置
npm ls -g @earendil-works/pi-coding-agent   # npm 确认
```

> ⚠️ 如果 `pi` 命令找不到：npm 全局 bin 目录可能不在 PATH。Windows 下通常为 `%APPDATA%\npm`，Linux/macOS 为 `/usr/local/bin` 或 nvm 对应目录。

## 2. 认证提供商

pi 支持两种认证方式，覆盖主流模型提供商。

### 2.1 方式 A：API Key（按量付费）

```bash
export ANTHROPIC_API_KEY=sk-ant-...
pi
```

支持的 API Key 提供商（ch11 详解）：Anthropic、OpenAI、DeepSeek、Gemini、Mistral、Groq、OpenRouter、Kimi、MiniMax 等 20+ 家。

### 2.2 方式 B：订阅登录（包月）

```bash
pi
/login        # 选择提供商后走 OAuth 登录
```

支持的订阅：**Claude Pro/Max**、**ChatGPT Plus/Pro（Codex）**、**GitHub Copilot**。

### 2.3 订阅 vs API Key 怎么选

| 维度 | 订阅（/login） | API Key |
|------|---------------|---------|
| 计费 | 包月固定 | 按 token 计费 |
| 门槛 | 有对应产品订阅即可 | 需要开通 API 账号 |
| 适合 | 日常高频使用、想省心 | 开发集成、自动化脚本、控成本 |
| 典型 | Claude Pro、ChatGPT Plus | Anthropic/DeepSeek/OpenRouter Key |

> 💡 推荐：日常对话用订阅；跑自动化（ch27 RPC/JSON 模式）用 API Key，便于环境变量注入。

## 3. 第一次对话

### 3.1 启动并观察

```bash
pi
```

启动后观察界面（对照 ch05 的四区布局）：

```
pi 0.x.x · AGENTS.md: 0 · skills: 0 · extensions: 0
[模型名]                      ← 页脚显示当前模型
> _                          ← 编辑器
```

### 3.2 第一个任务

输入：

```
列出当前目录下所有文件，并告诉我最大的那个
```

**预期过程**（亲眼验证 ch02 的 Agent Loop）：

```
1. 模型 thinking: 我需要先看看目录里有什么
2. 调用工具: ls / find
3. 工具结果返回
4. 模型分析大小
5. 输出最终答案
```

### 3.3 切换模型

```bash
/model            # 打开模型选择器
# 或 Ctrl+L
```

选一个便宜的模型试试，感受不同模型的风格差异。

## 4. CLI 快速验证

```bash
# 一次性提问（print 模式，ch04 详解）
pi -p "用一句话介绍你自己"

# 指定模型提问
pi --model sonnet:high "解释什么是 Agent Loop"

# 只读模式（不给写工具，安全起见试试）
pi --tools read,grep,find,ls -p "审查当前目录代码风格"

# 版本与帮助
pi --version
pi --help
```

## 5. 动手试试：验证安装

1. 安装 pi，运行 `pi --version` 确认成功
2. 配置认证（API Key 或 /login）
3. 完成第一次对话：问"这个目录里有什么？"
4. 用 `pi -p` 做一次无界面提问
5. 尝试 `--model` 指定一个模型提问
6. 查看 `~/.pi/agent/` 目录结构（auth.json / sessions/ 等），了解配置落点

## 6. 常见问题 Q&A

**Q1：`/login` 登录后还要设置 API Key 吗？**
A：不用。订阅登录走 OAuth，凭证存在 `~/.pi/agent/auth.json`；API Key 是另一条路径，二者互不干扰。

**Q2：没有 Claude 订阅也没有 API Key 能玩吗？**
A：可以。免费/低价途径：Gemini、Groq、DeepSeek 等开放注册即有 API Key；或用 llama.cpp 跑本地模型（docs/llama-cpp.md，ch11 也会讲）。

**Q3：为什么 `pi -p` 有时没输出？**
A：print 模式需要认证与可用模型；检查 `pi --list-models` 能否列出模型、API Key 是否生效。

**Q4：安装脚本和 npm 装的有什么区别？**
A：本质相同（都安装同一 npm 包）。安装脚本适合不想手动配 npm 全局路径的场景，会自动处理 PATH。

## 7. 小结

| 要点 | 说明 |
|------|------|
| 安装 | `npm i -g --ignore-scripts @earendil-works/pi-coding-agent` 或官方脚本 |
| 认证 | API Key（按量）或 /login 订阅（包月），凭证存 auth.json |
| 第一次对话 | 观察"thinking → 工具调用 → 结果 → 答案"完整链路 |
| CLI 验证 | `-p` 一次性提问、`--model` 指定模型、`--tools` 限制工具 |
| 配置落点 | `~/.pi/agent/`（auth.json / sessions/ / settings.json） |
