## 1. 主流技能仓库

| 仓库 | 内容 | 获取 |
|------|------|------|
| [Anthropic Skills](https://github.com/anthropics/skills) | 文档处理（docx/pdf/pptx/xlsx）、Web 开发 | git clone |
| [Pi Skills](https://github.com/badlogic/pi-skills) | Web 搜索、浏览器自动化、Google API、转录 | git clone / 包 |
| 社区技能（GitHub 搜索 `agent-skills` / `SKILL.md`） | 各类专用技能 | 按需挑选 |

安装示例：

```bash
# 克隆 Anthropic 官方技能集
git clone https://github.com/anthropics/skills ~/.pi/agent/skills/anthropic-skills

# 或只放需要的子目录
mkdir -p ~/.pi/agent/skills && cp -r skills/pdf ~/.pi/agent/skills/pdf-tools
```

> ⚠️ 安全审查：技能是可被模型执行的指令 + 可能包含脚本。安装第三方技能前**通读 SKILL.md 与脚本**，只装信任来源。

## 2. 复用 Claude Code / Codex 技能

Agent Skills 是开放标准，同一个技能文件能在 pi、Claude Code、Codex 间流转。

### 2.1 直接引用目录（settings.json）

```json
{
  "skills": [
    "~/.claude/skills",
    "~/.codex/skills"
  ]
}
```

### 2.2 项目级复用

```jsonc
// .pi/settings.json
{
  "skills": ["../.claude/skills"]
}
```

### 2.3 为什么可行

| 工具 | 技能目录 | 标准 |
|------|---------|------|
| pi | `~/.pi/agent/skills/`、`~/.agents/skills/` | Agent Skills |
| Claude Code | `~/.claude/skills/` | Agent Skills |
| Codex | `~/.codex/skills/` | Agent Skills |

三者的 SKILL.md 都是同一套 frontmatter + 指令格式——**一套技能，多工具通用**，这就是标准化的红利。

> 💡 团队场景：技能目录进 git 仓库（`.agents/skills/`），所有用支持 Agent Skills 标准的工具的人自动获得同一套能力。

## 3. 技能的分发方式

| 方式 | 适用 | 命令 |
|------|------|------|
| git clone 目录 | 个人/团队 | 手动 |
| settings.json 引用 | 已有路径 | 配置 |
| **Pi 包** | 对外分发 | `pi install`（ch23） |

### 3.1 打包进 Pi 包

```jsonc
// package.json
{
  "name": "my-skills-pack",
  "keywords": ["pi-package"],
  "pi": {
    "skills": ["./skills"]
  }
}
```

```bash
pi install npm:my-skills-pack
```

### 3.2 通过包分发技能

```
my-skills-pack/
├── package.json
├── skills/
│   ├── pdf-tools/SKILL.md
│   ├── web-search/SKILL.md
│   └── git-commit/SKILL.md
└── README.md
```

安装后技能自动被发现，无需手动复制——这是 ch23 的预告，也是"技能生态"的最后一环。

## 4. 技能库管理建议

### 4.1 目录规划

```
~/.pi/agent/skills/
├── core/                # 自用核心技能（手写）
├── anthropic/           # 官方技能集（只留用到的）
└── community/           # 社区技能（审查后放）
```

### 4.2 定期清理

技能太多 → 描述列表变长 → 模型选择负担增加。原则：**只留常被调用的**，其余移到归档目录。

### 4.3 命名与冲突

- 不同来源的同名技能：pi 保留先发现的，并告警
- 命名建议：`工具-用途`（`pdf-tools`、`web-search`）

## 5. 实战：搭建团队技能库

把技能目录变成团队的“能力资产”：

```
.agents/skills/                     ← 提交进 git 仓库
├── README.md                       # 索引：每个技能的用途一句话
├── component-gen/SKILL.md          # 生成组件
├── pr-review/SKILL.md              # PR 审查流程
├── release/SKILL.md                # 发布流程
└── data-export/SKILL.md            # 数据导出
```

**命名约定**：`领域-动作`（`component-gen`、`pr-review`）——避免和全局技能冲突，也利于模型理解。

**README 索引模板**：

```markdown
# 团队技能库

| 技能 | 用途 | 维护人 |
|------|------|--------|
| component-gen | 按团队规范生成组件 | 张三 |
| pr-review | 拉取请求审查流程 | 李四 |

## 约定
- 新增技能需经 review
- description 必须写触发场景
- 脚本依赖在 Setup 里注明
```

> 💡 团队技能库的价值：新成员 clone 仓库即获得全套能力；技能与工具解耦（开放标准），团队换工具也不丢资产。

## 7. 常见问题 Q&A

**Q1：技能名冲突会怎样？**
A：pi 告警并保留先发现的那个。冲突时改名或调整目录顺序（settings.json 中靠前的优先）。

**Q2：引用了 Claude 的技能目录，Claude 会受影响吗？**
A：不会。pi 只是**读取**目录，不改动文件。两边共享同一套技能文件，互不干扰。

**Q3：技能里的脚本依赖 npm 包怎么处理？**
A：SKILL.md 的 `## Setup` 里写明 `npm install`，模型首次使用时按步骤执行（或你自己提前装好）。

**Q4：技能仓库一般怎么搜？**
A：GitHub 搜 `agent-skills`、`SKILL.md`、`skills` + 关键词；关注 Anthropic 官方与 pi 生态（Discord、npm `pi-package` 关键词）。
