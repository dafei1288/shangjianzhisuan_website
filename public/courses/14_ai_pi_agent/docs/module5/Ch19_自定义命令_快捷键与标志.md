## 1. registerCommand：斜杠命令

### 1.1 基本用法

```typescript
pi.registerCommand("stats", {
  description: "Show session stats",
  handler: async (args, ctx) => {
    ctx.ui.notify(`Session: ${ctx.sessionManager.getSessionFile() ?? "ephemeral"}`, "info");
  },
});
```

```bash
/stats                    # 调用
/stats 详细               # args = "详细"
```

### 1.2 命令参数

```typescript
pi.registerCommand("review", {
  description: "Review current changes",
  handler: async (args, ctx) => {
    const scope = args || "staged";
    ctx.ui.notify(`Reviewing ${scope} changes…`, "info");
  },
});
```

### 1.3 命令里调用 LLM

命令是"可以主动发起对话"的地方（事件里通常不行）：

```typescript
pi.registerCommand("kickoff", {
  description: "Start a task",
  handler: async (args, ctx) => {
    await ctx.sendUserMessage(args || "请开始工作");   // 作为用户消息发出
  },
});
```

> 💡 命令 + LLM 是高级玩法的基础：`/review` 先收集状态，再让模型干活；`/handoff` 把当前会话交给新会话（§3.3）。

## 2. registerShortcut / registerFlag

### 2.1 快捷键

```typescript
pi.registerShortcut("ctrl+shift+j", {
  description: "Open plan overlay",
  handler: async (_ctx) => {
    // 打开自定义浮层（ch20）
  },
});
```

> 快捷键与内置冲突时以后注册者为准；可查 `/hotkeys` 确认。

### 2.2 CLI 标志

```typescript
pi.registerFlag("my-flag", {
  description: "Enable my feature",
  handler: async (value, ctx) => {
    ctx.ui.notify(`my-flag=${value ?? true}`, "info");
  },
});
```

```bash
pi --my-flag           # value = true
pi --my-flag=off       # value = "off"
```

## 3. ExtensionCommandContext：命令专属能力

命令 handler 收到的是 `ExtensionCommandContext`——比事件 ctx 多了**会话控制方法**（事件里调用会死锁，所以只在命令里提供）。

### 3.1 waitForIdle：等 agent 停下来

```typescript
pi.registerCommand("check", {
  handler: async (_args, ctx) => {
    await ctx.waitForIdle();          // 等所有自动重试/压缩/后续消息跑完
    ctx.ui.notify("Agent is fully idle", "info");
  },
});
```

### 3.2 newSession：开新会话干活

```typescript
pi.registerCommand("handoff", {
  handler: async (_args, ctx) => {
    await ctx.newSession({
      parentSession: ctx.sessionManager.getSessionFile(),
      withSession: async (newCtx) => {
        // ⚠️ 只准用 newCtx，别用旧 ctx / 旧 pi（已失效）
        await newCtx.sendUserMessage("Continue from the previous session");
      },
    });
  },
});
```

### 3.3 switchSession / fork / navigateTree

```typescript
pi.registerCommand("goto", {
  handler: async (args, ctx) => {
    // 切到另一个会话文件
    await ctx.switchSession(args, {
      withSession: async (newCtx) => {
        await newCtx.sendUserMessage("Resume here");
      },
    });
  },
});

// fork / clone
await ctx.fork("entry-id", { position: "before" });   // fork
await ctx.fork("entry-id", { position: "at" });       // clone

// 树内导航
await ctx.navigateTree("entry-id", { summarize: true });
```

### 3.4 reload：热重载一切

```typescript
pi.registerCommand("reload-runtime", {
  handler: async (_args, ctx) => {
    await ctx.reload();     // 触发完整 reload 流程
    return;                 // reload 后旧代码栈不再可靠，直接返回
  },
});
```

## 4. 会话替换的生命周期与坑

`newSession / switchSession / fork` 都会触发**会话替换**：

```
old session ──session_shutdown──► 新 runtime 重建 ──session_start──► withSession 回调
```

**三坑**：
1. `withSession` 里只能用传入的新 ctx（旧 pi/ctx 已失效会抛错）
2. 之前提取的裸对象（如 `const sm = ctx.sessionManager`）在替换后失效
3. reload 后旧代码栈仍在运行当前 handler——`await ctx.reload(); return;` 是最安全姿势

## 5. 实战：一个完整的命令

```typescript
// checkpoint.ts —— 会话内 git 检查点（ch21 会升级为完整安全扩展）
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("checkpoint", {
    description: "Commit current state as a checkpoint",
    handler: async (_args, ctx) => {
      const { execSync } = await import("node:child_process");
      try {
        execSync("git add -A && git commit -m 'checkpoint'", { stdio: "pipe" });
        ctx.ui.notify("Checkpoint saved", "success");
      } catch {
        ctx.ui.notify("Nothing to commit or not a git repo", "warning");
      }
    },
  });

  pi.registerShortcut("ctrl+shift+c", {
    description: "Quick checkpoint",
    handler: async (_ctx) => {
      pi.sendUserMessage("/checkpoint", { deliverAs: "followUp" });
    },
  });
}
```

> 注意：`pi.sendUserMessage("/checkpoint", {deliverAs:"followUp"})` 是把命令排进队列的惯用法——快捷键里无法直接调用命令 handler，通过消息队列转发。

## 7. 常见问题 Q&A

**Q1：命令名会和内置命令冲突吗？**
A：会。建议加前缀命名（`/hud_stats`、`/myco_deploy`），避免覆盖内置行为。

**Q2：快捷键 handler 里能调用命令吗？**
A：不能直接调 handler，用 `pi.sendUserMessage("/cmd", {deliverAs:"followUp"})` 转发（见实战示例）。

**Q3：命令里能等待 agent 空闲再做修改吗？**
A：能——`await ctx.waitForIdle()` 就是为此设计。之后修改 sessionManager 是安全的。

**Q4：`ctx.reload()` 后还能继续用 ctx 吗？**
A：不能可靠使用。模式固定为 `await ctx.reload(); return;`。

## 8. 小结

| 要点 | 说明 |
|------|------|
| registerCommand | `/xxx` 命令 + args 参数 + 可发消息调 LLM |
| registerShortcut / registerFlag | 快捷键、CLI 标志 |
| 命令专属能力 | waitForIdle / newSession / switchSession / fork / navigateTree / reload |
| 会话替换 | withSession 用新 ctx；旧对象失效 |
| 转发模式 | 快捷键 → sendUserMessage 排队命令 |
