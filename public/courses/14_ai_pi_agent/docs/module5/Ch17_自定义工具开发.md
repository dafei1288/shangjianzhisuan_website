## 1. 工具定义解剖

回顾 ch02：工具是模型与世界的接口。pi 中一个工具就是注册时传入的定义对象：

```typescript
pi.registerTool({
  // ① 身份
  name: "deploy",
  label: "Deploy",
  description: "Deploy the app to the target environment",

  // ② 参数契约（typebox schema）
  parameters: Type.Object({
    env: Type.String({ description: "Target: staging | production" }),
    tag: Type.Optional(Type.String({ description: "Git tag to deploy" })),
  }),

  // ③ 执行逻辑
  async execute(toolCallId, params, signal, onUpdate, ctx) {
    return { content: [...], details: {} };
  },
});
```

### 1.1 三要素

| 要素 | 说明 |
|------|------|
| **name / description** | 模型的"使用说明书"——描述决定模型何时调用 |
| **parameters** | 参数 schema，模型据此生成合法参数 |
| **execute** | 真正的执行函数，返回结果回传模型 |

> 💡 **description 决定使用率**：`"Run deploy"` 和 `"Deploy the app to staging/production with optional git tag. Use when user asks to deploy or release"` 的调用频率天差地别——和技能 description（ch14）同理。

## 2. typebox 参数 schema

### 2.1 常用类型

```typescript
import { Type } from "typebox";

const schema = Type.Object({
  path: Type.String({ description: "File path" }),          // 字符串
  count: Type.Number({ minimum: 1, maximum: 100 }),          // 数字+范围
  verbose: Type.Optional(Type.Boolean()),                    // 可选布尔
  tags: Type.Array(Type.String()),                           // 字符串数组
  mode: Type.Union([                                         // 枚举
    Type.Literal("fast"),
    Type.Literal("safe"),
  ]),
});
```

### 2.2 导出类型（跨文件复用）

```typescript
import { Static } from "typebox";

export type DeployInput = Static<typeof schema>;
// → { path: string; count?: number; verbose?: boolean; ... }
```

> 💡 良好 schema 的回报：模型生成的参数几乎一次正确，少一次"参数错误重试"。**每个字段都写 description** 是最低成本的高收益习惯。

## 3. execute 契约

### 3.1 返回值

```typescript
async execute(toolCallId, params, signal, onUpdate, ctx) {
  // 成功：
  return {
    content: [{ type: "text", text: "Deployed v1.2.3 to production" }],
    details: { deployId: "abc123", duration: 42 },  // 结构化详情（TUI 可显示）
  };

  // 失败：标记 isError，模型会看到并尝试纠错
  return {
    content: [{ type: "text", text: "Deploy failed: build error" }],
    details: { error: "build error" },
    isError: true,
  };
}
```

| 字段 | 作用 |
|------|------|
| `content` | 回传给模型的结果文本（必填） |
| `details` | 结构化信息，TUI 渲染用（建议带） |
| `isError` | 标记失败，模型据此重试或换方案 |

### 3.2 execute 参数

| 参数 | 说明 |
|------|------|
| `toolCallId` | 本次调用 ID |
| `params` | 模型生成的参数（已按 schema 校验） |
| `signal` | 中止信号：**长任务必须监听**，用户 Esc 时优雅退出 |
| `onUpdate` | 流式更新进度 |
| `ctx` | 扩展上下文（sessionManager、ui 等） |

```typescript
// 长任务正确姿势：响应中止
async execute(_id, params, signal) {
  const proc = spawn("npm", ["run", "build"], { signal });
  proc.on("close", (code) => {
    return { content: [{ type: "text", text: `exit ${code}` }], details: {} };
  });
}
```

## 4. 动态工具与运行时开关

### 4.1 运行时注册

`pi.registerTool()` 不仅能在加载时调用，也能在事件/命令里调用：

```typescript
pi.on("session_start", (_e, ctx) => {
  // 根据环境动态注册
  if (fs.existsSync("deploy.sh")) {
    pi.registerTool({ name: "deploy", /* … */ });
  }
});
```

注册后工具**立即刷新**，模型下一轮就能调用，无需 `/reload`。

### 4.2 setActiveTools：开关工具

```typescript
pi.registerCommand("readonly", {
  handler: async (_args, ctx) => {
    // 只保留只读工具
    pi.setActiveTools(["read", "grep", "find", "ls"]);
    ctx.ui.notify("Read-only mode", "info");
  },
});
```

> 💡 场景：安全模式开关、按项目切换工具集、临时禁用有风险的工具。

### 4.3 CLI 侧控制

```bash
# 白名单：只用这些工具
pi --tools read,deploy

# 排除
pi --exclude-tools ask_question

# 全部关闭
pi --no-tools

# 只保留扩展/自定义工具（去掉内置）
pi --no-builtin-tools
```

## 5. 实战：一个完整工具

```typescript
// weather.ts —— 查询天气（示意）
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "weather",
    label: "Weather",
    description: "Get current weather for a city. Use when user asks about weather.",
    parameters: Type.Object({
      city: Type.String({ description: "City name, e.g. Beijing" }),
      unit: Type.Optional(Type.Union([Type.Literal("c"), Type.Literal("f")])),
    }),
    async execute(_id, params) {
      const unit = params.unit ?? "c";
      // 真实实现：调天气 API
      return {
        content: [{ type: "text", text: `Beijing: 22°${unit.toUpperCase()}, sunny` }],
        details: { city: params.city, unit },
      };
    },
  });
}
```

## 7. 常见问题 Q&A

**Q1：工具参数被模型生成错了怎么办？**
A：先检查 schema 的 description 是否明确；再用 `tool_call` 事件（ch18）拦截改写参数，或返回 isError 让模型自纠。

**Q2：execute 里能用 ctx 做什么？**
A：ctx 提供 sessionManager（读写会话）、ui（交互）、signal 等。注意工具 ctx 没有 waitForIdle 等命令级能力（那是 ch19 的 ExtensionCommandContext）。

**Q3：多个扩展注册同名工具会怎样？**
A：后注册覆盖先注册（或冲突告警），取决于具体行为。命名时加前缀避免冲突：`hud_status`、`myco_deploy`。

**Q4：工具结果很大（比如读整个文件）怎么办？**
A：模型上下文有限，工具应"返回摘要 + 按需分页"。可参考内置 read 的 offset/limit 设计。

## 8. 小结

| 要点 | 说明 |
|------|------|
| 三要素 | name/description（模型视角）+ parameters（schema）+ execute（执行） |
| schema | typebox：String/Number/Array/Union/Literal，字段都写 description |
| 返回值 | content 给模型 + details 给 UI + isError 标记失败 |
| 长任务 | 监听 signal 响应中止 |
| 动态 | registerTool 可运行时调用；setActiveTools 开关工具；CLI --tools 白名单 |
