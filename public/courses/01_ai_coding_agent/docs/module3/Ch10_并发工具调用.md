# 第 10 章 并发工具调用 -- 让 Agent 同时做多件事

> 当 LLM 一次返回多个 `tool_call` 时，如果工具之间相互独立，就可以并行执行，显著降低延迟。

3. 保证并行执行后结果按 `tool_call_id` 顺序聚合返回给 LLM
4. 实现 `ConcurrentAgent` 类，继承 `AgentLoop` 并添加并发能力
5. 使用 Mock 测试验证并发执行的正确性和顺序保证

## 核心概念

### LLM 并行工具调用的场景

当用户提出需要多个独立信息源的任务时，LLM 会在一次响应中返回多个 `tool_call`：

```python
# 用户: "同时读取 config.py 和 main.py，比较它们"
# LLM 返回:
response.choices[0].message.tool_calls = [
    tool_call(id="call_1", function=Function(name="read_file", arguments='{"path":"config.py"}')),
    tool_call(id="call_2", function=Function(name="read_file", arguments='{"path":"main.py"}')),
]
```

这两个读取操作互相独立，完全可以并行执行。

### 串行 vs 并发的时间对比

```
串行执行（第 9 章的做法）:
  read_file("config.py") ----耗时 0.5s----> 结果1
  read_file("main.py")                      ----耗时 0.3s----> 结果2
  总耗时：0.8s

并发执行（本章的做法）:
  read_file("config.py") ----耗时 0.5s----> 结果1
  read_file("main.py")   ----耗时 0.3s---> 结果2
  总耗时：0.5s（取最长的一个）
```

### ThreadPoolExecutor 核心机制

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=5) as executor:
    # 提交任务，返回 Future 对象
    futures = {
        executor.submit(handler, **args): tool_call_id
        for tool_call_id, handler, args in tasks
    }
    # 按完成顺序获取结果
    for future in as_completed(futures):
        result = future.result()
        call_id = futures[future]
```

关键特性：
- `submit` 返回 `Future` 对象，任务在后台线程执行
- `as_completed` 按完成顺序迭代，不按提交顺序
- `executor.map` 按提交顺序返回结果，但不绑定 `tool_call_id`

### 结果顺序保证

LLM 要求 `tool` 消息的顺序与 `tool_calls` 列表中的 `tool_call_id` 一一对应。因此需要用字典保存 `tool_call_id -> result` 的映射，然后按原始顺序追加：

```python
# 收集结果到字典
results_map = {}
for future in as_completed(futures):
    call_id = futures[future]
    results_map[call_id] = future.result()

# 按原始 tool_calls 顺序追加
for tc in msg.tool_calls:
    messages.append({
        "role": "tool",
        "tool_call_id": tc.id,
        "content": results_map[tc.id],
    })
```

### 并发安全约束

- 并发数不能无限大，使用 `max_workers` 限制线程池大小
- 共享资源（如文件写入）需要加锁
- 工具之间如果有依赖关系，不应该并发执行

## 代码讲解

### 10.1 串行执行的问题

回顾第 9 章的执行方式 -- 串行 `for` 循环：

```python
# 第 9 章的做法：串行执行每个 tool_call
for tool_call in msg.tool_calls:
    result = self._execute_tool(tool_call)
    self.messages.append({
        "role": "tool",
        "tool_call_id": tool_call.id,
        "content": str(result),
    })
```

当 `msg.tool_calls` 包含 3 个文件读取时，总耗时 = 耗时1 + 耗时2 + 耗时3。

### 10.2 使用 ThreadPoolExecutor 并行执行

将串行执行改为并行：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def _execute_tools_parallel(self, tool_calls):
    """并行执行多个工具调用，返回 {tool_call_id: result} 映射"""
    results_map = {}

    with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
        # 构建 {Future: tool_call_id} 的映射
        futures = {}
        for tc in tool_calls:
            name = tc.function.name
            try:
                args = json.loads(tc.function.arguments)
            except json.JSONDecodeError:
                results_map[tc.id] = f"Error: 参数 JSON 解析失败"
                continue

            handler = self.tool_handlers.get(name)
            if not handler:
                results_map[tc.id] = f"Error: 未知工具 '{name}'"
                continue

            future = executor.submit(self._safe_execute, handler, args)
            futures[future] = tc.id

        # 收集结果
        for future in as_completed(futures):
            call_id = futures[future]
            try:
                result = future.result(timeout=self.tool_timeout)
                results_map[call_id] = str(result)
            except Exception as e:
                results_map[call_id] = f"Error: {type(e).__name__}: {e}"

    return results_map

def _safe_execute(self, handler, args):
    """线程安全的工具执行包装器"""
    try:
        return handler(**args)
    except Exception as e:
        return f"Error: {type(e).__name__}: {e}"
```

### 10.3 ConcurrentAgent 类

继承 `AgentLoop`，添加并发执行能力：

```python
import json
from concurrent.futures import ThreadPoolExecutor, as_completed
from openai import OpenAI


class ConcurrentAgent:
    """支持并发工具调用的 Agent"""

    def __init__(self, model="gpt-4o-mini", system_prompt="",
                 max_iterations=20, max_workers=5, tool_timeout=30):
        self.client = OpenAI()
        self.model = model
        self.max_iterations = max_iterations
        self.max_workers = max_workers        # 线程池大小
        self.tool_timeout = tool_timeout      # 单个工具超时（秒）
        self.messages = []
        self.tool_schemas = []
        self.tool_handlers = {}
        self.iteration_count = 0
        self.tool_call_history = []

        if system_prompt:
            self.messages.append({"role": "system", "content": system_prompt})

    def register_tool(self, schema, handler):
        """注册工具"""
        name = schema["function"]["name"]
        self.tool_schemas.append(schema)
        self.tool_handlers[name] = handler
        return self

    def run(self, user_message: str) -> str:
        """运行并发 Agent Loop"""
        self.messages.append({"role": "user", "content": user_message})
        self.iteration_count = 0

        for i in range(self.max_iterations):
            self.iteration_count = i + 1

            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.messages,
                tools=self.tool_schemas or None,
            )
            choice = response.choices[0]
            msg = choice.message

            if choice.finish_reason == "tool_calls":
                self.messages.append(msg)

                # 判断并发还是串行
                if len(msg.tool_calls) > 1:
                    results_map = self._execute_tools_parallel(msg.tool_calls)
                    for tc in msg.tool_calls:
                        self.messages.append({
                            "role": "tool",
                            "tool_call_id": tc.id,
                            "content": results_map.get(tc.id, "Error: 无结果"),
                        })
                    tool_names = [tc.function.name for tc in msg.tool_calls]
                    print(f"  [循环 {i+1}] 并发调用 {len(msg.tool_calls)} 个工具: {tool_names}")
                else:
                    # 单个工具调用，直接执行（避免线程池开销）
                    tc = msg.tool_calls[0]
                    result = self._execute_single_tool(tc)
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": tc.id,
                        "content": str(result),
                    })
                    print(f"  [循环 {i+1}] 调用工具: {tc.function.name}")
            else:
                self.messages.append(msg)
                return msg.content

        return "[Agent] 已达最大循环次数。"

    def _execute_tools_parallel(self, tool_calls):
        """并行执行多个工具"""
        results_map = {}

        with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
            futures = {}
            for tc in tool_calls:
                future = executor.submit(self._execute_single_tool, tc)
                futures[future] = tc.id

            for future in as_completed(futures):
                call_id = futures[future]
                try:
                    results_map[call_id] = str(future.result(timeout=self.tool_timeout))
                except Exception as e:
                    results_map[call_id] = f"Error: {type(e).__name__}: {e}"

        return results_map

    def _execute_single_tool(self, tool_call):
        """执行单个工具调用"""
        name = tool_call.function.name
        try:
            args = json.loads(tool_call.function.arguments)
        except json.JSONDecodeError:
            return f"Error: 参数 JSON 解析失败"

        handler = self.tool_handlers.get(name)
        if not handler:
            return f"Error: 未知工具 '{name}'"

        try:
            return handler(**args)
        except Exception as e:
            return f"Error: {type(e).__name__}: {e}"
```

import unittest
from unittest.mock import Mock, patch
import json
import time


class TestConcurrentAgent(unittest.TestCase):

    def _make_tool_call(self, call_id, name, arguments):
        tc = Mock()
        tc.id = call_id
        tc.function = Mock()
        tc.function.name = name
        tc.function.arguments = json.dumps(arguments)
        return tc

    def _make_response(self, finish_reason, content=None, tool_calls=None):
        msg = Mock()
        msg.content = content
        msg.tool_calls = tool_calls
        msg.model_dump = Mock(return_value={})

        choice = Mock()
        choice.finish_reason = finish_reason
        choice.message = msg

        response = Mock()
        response.choices = [choice]
        return response

    @patch("openai.OpenAI")
    def test_parallel_tool_execution(self, MockClient):
        """测试并发执行多个 tool_call，结果顺序正确"""
        mock_client = MockClient.return_value

        # 第一轮：LLM 返回两个 tool_call
        tc1 = self._make_tool_call("call_001", "read_file", {"path": "a.py"})
        tc2 = self._make_tool_call("call_002", "read_file", {"path": "b.py"})
        response_round1 = self._make_response("tool_calls", tool_calls=[tc1, tc2])

        # 第二轮：LLM 给出总结
        response_round2 = self._make_response("stop", content="两个文件比较结果...")

        mock_client.chat.completions.create.side_effect = [
            response_round1,
            response_round2,
        ]

        # 记录调用顺序，验证并发
        call_log = []

        def mock_read_file(path):
            call_log.append(path)
            time.sleep(0.1)  # 模拟 IO 延迟
            return f"content of {path}"

        agent = ConcurrentAgent(system_prompt="test", max_workers=5)
        agent.register_tool(
            {"type": "function", "function": {"name": "read_file", "parameters": {}}},
            mock_read_file,
        )

        result = agent.run("比较 a.py 和 b.py")

        # 验证最终结果
        self.assertEqual(result, "两个文件比较结果...")
        self.assertEqual(agent.iteration_count, 2)

        # 验证两个文件都被读取
        self.assertIn("a.py", call_log)
        self.assertIn("b.py", call_log)

        # 验证 messages 结构
        # [system, user, assistant(tool_calls), tool, tool, assistant(text)]
        self.assertEqual(len(agent.messages), 6)

        # 验证 tool_call_id 顺序正确
        tool_msgs = [m for m in agent.messages if m.get("role") == "tool"]
        self.assertEqual(len(tool_msgs), 2)
        self.assertEqual(tool_msgs[0]["tool_call_id"], "call_001")
        self.assertEqual(tool_msgs[1]["tool_call_id"], "call_002")

    @patch("openai.OpenAI")
    def test_single_tool_uses_serial_path(self, MockClient):
        """测试单个 tool_call 走串行路径"""
        mock_client = MockClient.return_value

        tc = self._make_tool_call("call_001", "read_file", {"path": "a.py"})
        response1 = self._make_response("tool_calls", tool_calls=[tc])
        response2 = self._make_response("stop", content="完成")

        mock_client.chat.completions.create.side_effect = [response1, response2]

        agent = ConcurrentAgent(system_prompt="test")
        agent.register_tool(
            {"type": "function", "function": {"name": "read_file", "parameters": {}}},
            lambda path: f"content of {path}",
        )

        result = agent.run("读取 a.py")
        self.assertEqual(result, "完成")


if __name__ == "__main__":
    unittest.main()

## 常见问题

### Q1：工具之间有依赖怎么办？

LLM 在一次响应中发出有依赖关系的 `tool_call` 是设计问题。解决方案：
- 在 System Prompt 中明确说明"不要在一次响应中发出有依赖关系的工具调用"
- 依赖型的工具调用应该在两轮循环中分别发出
- 如果确实需要在执行层处理，可以将依赖图排序后串行执行（复杂度高，不推荐）

### Q2：并发写入同一个文件怎么办？

两个 `tool_call` 同时写入同一个文件会导致冲突。解决方案：
- 对文件操作加锁（`threading.Lock`）
- 在 System Prompt 中告知"不要同时写入同一个文件"
- 实际场景中 LLM 很少这样做

### Q3：并发数过多导致性能下降？

LLM 一次返回 10+ 个 `tool_call`。解决方案：
- `max_workers` 控制线程池大小（推荐 3-5）
- 使用 `Semaphore` 限制并发数
- 对超大量调用分批执行

### Q4：为什么用线程池而不是 asyncio？

工具函数大多是同步的（文件操作、子进程调用等）。`ThreadPoolExecutor` 直接包装同步函数，无需改造工具为 `async`。如果要统一异步，可以使用 `asyncio` + `loop.run_in_executor`，但增加了复杂度。

### Q5：`as_completed` 的顺序问题

`as_completed` 按完成顺序迭代，不是提交顺序。必须用字典保存 `future -> tool_call_id` 映射，收集完所有结果后再按原始 `tool_calls` 列表的顺序追加 `tool` 消息。

## 本章小结

| 概念 | 要点 |
|---|---|
| 并行 `tool_call` | LLM 一次返回多个独立工具调用，可并行执行 |
| `ThreadPoolExecutor` | 线程池并行执行同步工具函数，避免改造为 async |
| 结果顺序保证 | 用字典保存 `tool_call_id -> result` 映射，按原始顺序追加 `tool` 消息 |
| `ConcurrentAgent` | 继承 `AgentLoop` 思路，单个调用走串行路径，多个调用走并行路径 |
| 错误隔离 | 一个工具失败不影响其他工具，错误信息作为 `tool` 消息返回 |
| 超时控制 | `tool_timeout` 防止单个工具卡住整个循环 |
| 并发限制 | `max_workers` 控制线程池大小，避免资源耗尽 |

本章的并发能力是 Agent 性能优化的第一步。在后续章节中，并发执行会与错误重试（Ch12）结合使用，进一步提升 Agent 的健壮性。
