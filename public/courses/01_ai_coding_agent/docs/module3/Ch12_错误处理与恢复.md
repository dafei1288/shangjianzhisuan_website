## 核心概念

### Agent 系统中的三类错误

```
错误类型 1: LLM API 调用错误
  - RateLimitError (429): 限流，服务端要求降低请求频率
  - APIConnectionError: 网络中断、DNS 解析失败
  - APITimeoutError: 请求超时
  - BadRequestError (400): token 超限、参数错误
  - InternalServerError (500): 服务端内部错误

  处理策略：指数退避重试（仅对 429/500/网络错误重试）
             400 错误不重试，需要修改请求

错误类型 2: 工具执行错误
  - FileNotFoundError: 文件路径不存在
  - PermissionError: 权限不足
  - subprocess.TimeoutExpired: 命令执行超时
  - json.JSONDecodeError: 工具参数解析失败

  处理策略：将错误信息格式化后反馈给 LLM，让 LLM 自我修正

错误类型 3: LLM 输出错误
  - 幻觉：调用不存在的工具
  - 参数格式错误：生成无效 JSON
  - 重复循环：反复调用同一个工具

  处理策略：参数校验 + 错误反馈 + 循环检测
```

### 核心原则：错误不是终点

传统编程中，错误意味着"出问题了，停下来"。但在 Agent 中，错误是**信息** -- LLM 可以根据错误信息调整策略：

```
循环 1: Agent 调用 read_file("main.py")
         -> Error: File not found: main.py
循环 2: Agent 看到错误，决定先搜索文件
         -> 调用 search_files("*.py")
         -> 找到 main.py 在 src/ 目录下
循环 3: Agent 调用 read_file("src/main.py")
         -> 成功读取文件内容
```

### ErrorType 错误分类

```python
from enum import Enum

class ErrorType(Enum):
    """Agent 错误分类"""
    # API 错误 -- 可重试
    RATE_LIMIT = "rate_limit"           # 429 限流

    CONNECTION_ERROR = "connection_error"  # 网络错误
    TIMEOUT = "timeout"                 # 超时

    # API 错误 -- 不可重试
    BAD_REQUEST = "bad_request"         # 400 参数错误
    AUTH_ERROR = "auth_error"           # 401/403 认证错误

    # 工具执行错误
    FILE_NOT_FOUND = "file_not_found"
    PERMISSION_DENIED = "permission_denied"
    COMMAND_FAILED = "command_failed"
    TOOL_TIMEOUT = "tool_timeout"

    # LLM 输出错误
    UNKNOWN_TOOL = "unknown_tool"
    INVALID_ARGS = "invalid_args"
```

### API 重试 vs 工具重试

两种完全不同的重试策略：

```
API 重试（指数退避）:
  调用 LLM API -> 429 Rate Limit -> 等待 1s -> 重试
  -> 429 Rate Limit -> 等待 2s -> 重试
  -> 成功

  特点：对同一请求重复发送，LLM 不感知重试过程
  适用：网络波动、限流、服务端临时故障

工具重试（错误反馈给 LLM）:
  LLM 调用 read_file("main.py") -> Error: 文件不存在
  -> 将错误作为 tool_result 返回给 LLM
  -> LLM 看到 "文件不存在"，决定搜索文件
  -> LLM 调用 search_files("*.py") -> 找到正确路径

  特点：LLM 主动参与修正过程，每次尝试可能不同
  适用：工具参数错误、文件路径错误、命令失败
```

### 指数退避公式

```
delay = min(base_delay * (2 ** attempt), max_delay) + random_jitter

示例（base_delay=1s, max_delay=30s）:
  第 1 次重试: 1 * 2^0 = 1s  + jitter -> ~1.05s
  第 2 次重试: 1 * 2^1 = 2s  + jitter -> ~2.12s
  第 3 次重试: 1 * 2^2 = 4s  + jitter -> ~4.08s
  第 4 次重试: 1 * 2^3 = 8s  + jitter -> ~8.15s
  第 5 次重试: 1 * 2^4 = 16s + jitter -> ~16.03s
```

## 代码讲解

### 12.1 retry_with_backoff 指数退避装饰器

```python
import time
import random
import json
from functools import wraps
from typing import Type, Tuple

def retry_with_backoff(
    max_retries: int = 3,
    base_delay: float = 1.0,
    max_delay: float = 30.0,
    jitter: bool = True,
    retryable_errors: Tuple[Type[Exception], ...] = (Exception,),
):
    """带指数退避和抖动的重试装饰器

    Args:
        max_retries: 最大重试次数（不含首次调用）
        base_delay: 基础等待时间（秒）
        max_delay: 最大等待时间（秒）
        jitter: 是否添加随机抖动（避免惊群效应）
        retryable_errors: 可重试的异常类型元组
    """
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(max_retries + 1):
                try:
                    return func(*args, **kwargs)
                except retryable_errors as e:
                    last_error = e
                    if attempt >= max_retries:
                        print(f"  [重试耗尽] {type(e).__name__}: {e}")
                        raise

                    # 指数退避 + 抖动
                    delay = min(base_delay * (2 ** attempt), max_delay)
                    if jitter:
                        delay += random.uniform(0, delay * 0.1)

                    print(f"  [重试 {attempt+1}/{max_retries}] "
                          f"{type(e).__name__}, 等待 {delay:.1f}s...")
                    time.sleep(delay)

            raise last_error  # 不应到达这里
        return wrapper
    return decorator
```

### 12.2 错误分类和格式化

将错误分类为 `ErrorType`，并为 LLM 生成结构化的错误信息：

```python
import os
import subprocess

class ErrorClassifier:
    """错误分类器：将异常映射为 ErrorType 和 LLM 友好的消息"""

    @staticmethod
    def classify(error: Exception) -> ErrorType:
        """将 Python 异常分类为 ErrorType"""
        if isinstance(error, FileNotFoundError):
            return ErrorType.FILE_NOT_FOUND
        elif isinstance(error, PermissionError):
            return ErrorType.PERMISSION_DENIED
        elif isinstance(error, subprocess.TimeoutExpired):
            return ErrorType.COMMAND_FAILED
        elif isinstance(error, TimeoutError):
            return ErrorType.TOOL_TIMEOUT
        elif isinstance(error, json.JSONDecodeError):
            return ErrorType.INVALID_ARGS
        else:
            return ErrorType.COMMAND_FAILED

    @staticmethod
    def format_for_llm(error_type: ErrorType, tool_name: str,
                       error: Exception, args: dict) -> str:
        """格式化错误信息，让 LLM 能理解并自我修正"""
        suggestions = {
            ErrorType.FILE_NOT_FOUND:
                f"文件路径 '{args.get('path', '')}' 不存在。建议：先使用 search_files 查找正确的文件路径。",
            ErrorType.PERMISSION_DENIED:
                f"没有权限访问该文件。建议：检查文件权限或使用其他路径。",
            ErrorType.COMMAND_FAILED:
                f"命令执行失败。建议：检查命令语法，或尝试更简单的命令。",
            ErrorType.TOOL_TIMEOUT:
                f"操作超时。建议：缩小操作范围或增加超时时间。",
            ErrorType.INVALID_ARGS:
                f"工具参数格式无效。建议：检查参数是否为有效的 JSON。",
            ErrorType.UNKNOWN_TOOL:
                f"该工具不存在。建议：使用可用的工具列表中的工具。",
        }

        suggestion = suggestions.get(error_type, f"执行失败: {error}")
        return f"[{tool_name}] 错误: {type(error).__name__}: {error}\n建议: {suggestion}"
```

### 12.3 ResilientAgent 类

整合 API 重试、工具错误反馈、死循环检测：

```python
from openai import OpenAI, RateLimitError, APIConnectionError, APITimeoutError


class ResilientAgent:
    """具备错误恢复能力的健壮 Agent"""

    def __init__(self, model="gpt-4o-mini", system_prompt="",
                 max_iterations=20, max_api_retries=3, max_tool_retries=1):
        self.client = OpenAI()
        self.model = model
        self.max_iterations = max_iterations
        self.max_api_retries = max_api_retries   # API 重试次数
        self.max_tool_retries = max_tool_retries  # 工具级别重试（通常为 0 或 1）
        self.messages = []
        self.tool_schemas = []
        self.tool_handlers = {}
        self.iteration_count = 0
        self.error_history = []    # 错误历史记录
        self.call_history = []     # 工具调用历史（用于死循环检测）

        if system_prompt:
            self.messages.append({"role": "system", "content": system_prompt})

    def register_tool(self, schema, handler):
        name = schema["function"]["name"]
        self.tool_schemas.append(schema)
        self.tool_handlers[name] = handler
        return self

    @retry_with_backoff(
        max_retries=3,
        base_delay=1.0,
        max_delay=30.0,
        retryable_errors=(RateLimitError, APIConnectionError, APITimeoutError),
    )
    def _call_llm(self):
        """带指数退避重试的 LLM API 调用"""
        return self.client.chat.completions.create(
            model=self.model,
            messages=self.messages,
            tools=self.tool_schemas or None,
        )

    def _execute_tool_safely(self, tool_call) -> str:
        """安全执行工具，错误格式化后返回给 LLM"""
        name = tool_call.function.name

        # 1. 参数解析
        try:
            args = json.loads(tool_call.function.arguments)
        except json.JSONDecodeError as e:
            self._record_error(ErrorType.INVALID_ARGS, name, e, {})
            return ErrorClassifier.format_for_llm(
                ErrorType.INVALID_ARGS, name, e,
                {"raw": tool_call.function.arguments}
            )

        # 2. 工具查找
        handler = self.tool_handlers.get(name)
        if not handler:
            error = ValueError(f"未知工具: {name}")
            available = list(self.tool_handlers.keys())
            self._record_error(ErrorType.UNKNOWN_TOOL, name, error, args)
            return f"[{name}] 错误: 工具不存在。可用工具: {available}"

        # 3. 工具执行
        try:
            result = handler(**args)
            return str(result)
        except Exception as e:
            error_type = ErrorClassifier.classify(e)
            self._record_error(error_type, name, e, args)
            return ErrorClassifier.format_for_llm(error_type, name, e, args)

    def _record_error(self, error_type: ErrorType, tool_name: str,
                      error: Exception, args: dict):
        """记录错误到历史"""
        self.error_history.append({
            "iteration": self.iteration_count,
            "type": error_type.value,
            "tool": tool_name,
            "error": str(error),
            "args_preview": str(args)[:200],
        })

    def _detect_stuck_loop(self, window=3) -> bool:
        """检测是否陷入死循环（连续相同的工具调用）"""
        if len(self.call_history) < window:
            return False
        last_n = [
            (h["name"], h.get("args_hash", ""))
            for h in self.call_history[-window:]
        ]
        return len(set(str(t) for t in last_n)) == 1

    def run(self, user_message: str) -> str:
        """运行具备错误恢复能力的 Agent"""
        self.messages.append({"role": "user", "content": user_message})
        self.iteration_count = 0

        for i in range(self.max_iterations):
            self.iteration_count = i + 1

            # API 调用（带重试）
            try:
                response = self._call_llm()
            except (RateLimitError, APIConnectionError, APITimeoutError) as e:
                return f"[Agent] API 调用失败（重试耗尽）: {type(e).__name__}: {e}"

            choice = response.choices[0]
            msg = choice.message

            if choice.finish_reason == "tool_calls":
                self.messages.append(msg)

                for tool_call in msg.tool_calls:
                    name = tool_call.function.name
                    args_str = tool_call.function.arguments

                    # 记录调用历史
                    self.call_history.append({
                        "name": name,
                        "args_hash": hash(args_str),
                    })

                    # 检测死循环
                    if self._detect_stuck_loop():
                        return (f"[Agent] 检测到死循环：连续重复调用工具 '{name}'。"
                                f"请调整指令或检查工具是否正常工作。")

                    # 安全执行工具
                    result = self._execute_tool_safely(tool_call)
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": tool_call.id,
                        "content": result,
                    })

                tool_names = [tc.function.name for tc in msg.tool_calls]
                error_count = sum(1 for e in self.error_history
                                  if e["iteration"] == i + 1)
                status = f" ({error_count} 个错误)" if error_count > 0 else ""
                print(f"  [循环 {i+1}] 工具: {tool_names}{status}")
            else:
                self.messages.append(msg)
                return msg.content

        return "[Agent] 已达最大循环次数。"

    def get_error_report(self) -> str:
        """获取错误报告"""
        if not self.error_history:
            return "本次运行无错误。"

        lines = [f"共 {len(self.error_history)} 个错误:"]
        for e in self.error_history:
            lines.append(f"  循环{e['iteration']}: [{e['type']}] {e['tool']} - {e['error']}")
        return "\n".join(lines)
```

## 常见问题

### Q1：重试风暴怎么避免？

API 限流后疯狂重试会加剧问题。解决方案：
- 重试次数不超过 3-5 次
- 每次重试指数退避（1s, 2s, 4s, 8s...）
- 设置最大延迟上限（如 30 秒）
- 添加随机抖动避免多个客户端同时重试（惊群效应）

### Q2：错误信息泄露敏感数据怎么办？

错误信息中可能包含绝对路径、系统用户名等。解决方案：
- 发送给 LLM 前进行脱敏（替换绝对路径为相对路径）
- 不把完整 stack trace 返回给 LLM，只保留关键信息
- 对生产环境使用专门的 `sanitize_error` 函数

```python
import re

def sanitize_error(msg: str) -> str:
    """脱敏错误信息"""
    msg = re.sub(r'/home/\w+/', '~/', msg)
    msg = re.sub(r'C:\\Users\\\w+\\', '~\\', msg)
    msg = re.sub(r'api[_-]?key["\s:=]+\S+', 'api_key=***', msg, flags=re.IGNORECASE)
    return msg
```

### Q3：死循环检测的窗口大小怎么设？

窗口太小容易误判，太大检测不及时。推荐：
- 窗口大小 3：连续 3 次相同调用判定为死循环
- 同时检查工具名称和参数的哈希值
- 可以根据任务复杂度调整窗口大小

### Q4：API 重试和工具重试的区别？

API 重试：对同一请求重复发送，LLM 不感知。适用于网络波动、限流。
工具重试：将错误反馈给 LLM，LLM 调整策略后再次尝试。适用于参数错误、路径错误。
两者互不冲突，API 重试在 `_call_llm` 层面，工具重试在 `_execute_tool_safely` 层面。

### Q5：所有错误都要反馈给 LLM 吗？

是的。即使工具执行失败，也应该将错误信息作为 `tool_result` 返回，而不是抛出异常中断循环。LLM 可以根据错误信息决定下一步（换路径、换工具、向用户说明情况）。只有在 API 调用层面才需要抛出异常触发重试。
