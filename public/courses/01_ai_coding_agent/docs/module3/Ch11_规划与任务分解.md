# 第 11 章 规划与任务分解 -- Plan-Then-Execute 模式

> 复杂任务不能靠一轮工具调用完成。Plan-Then-Execute 模式让 Agent 先制定计划，再逐步执行，并支持动态调整。

## 核心概念

### ReAct vs Plan-Then-Execute

两种主要的 Agent 推理模式：

```
ReAct 模式（第 9 章的隐式规划）:
  每一步都是临场决策，没有全局规划
  LLM -> tool_call -> 观察 -> LLM -> tool_call -> ...
  优点：灵活，适合简单任务
  缺点：复杂任务容易迷失方向

Plan-Then-Execute 模式（本章）:
  先制定完整计划，再按计划逐步执行
  LLM -> 生成 Plan(步骤列表) -> 逐步执行每个 PlanStep -> 动态调整
  优点：全局视野，适合复杂多步任务
  缺点：额外 token 开销，计划可能需要调整
```

### Plan 和 PlanStep 数据结构

```python
from dataclasses import dataclass, field
from enum import Enum
from typing import Optional

class StepStatus(Enum):
    PENDING = "pending"
    RUNNING = "running"
    DONE = "done"
    FAILED = "failed"
    SKIPPED = "skipped"

@dataclass
class PlanStep:
    """计划中的单个步骤"""
    id: int
    description: str
    tool_name: Optional[str] = None       # 预计使用的工具
    tool_args: Optional[dict] = None      # 预计的参数
    status: StepStatus = StepStatus.PENDING
    result: Optional[str] = None          # 执行结果
    depends_on: list[int] = field(default_factory=list)  # 依赖的步骤 ID

@dataclass
class Plan:
    """完整的执行计划"""
    goal: str                    # 总目标
    steps: list[PlanStep]        # 步骤列表
    created_at: str = ""         # 创建时间
    current_step_id: int = 0     # 当前执行的步骤 ID

    def get_pending_steps(self) -> list[PlanStep]:
        """获取所有未执行的步骤"""
        return [s for s in self.steps if s.status == StepStatus.PENDING]

    def get_next_step(self) -> Optional[PlanStep]:
        """获取下一个可执行的步骤（状态为 pending 且依赖已满足）"""
        completed_ids = {s.id for s in self.steps if s.status == StepStatus.DONE}
        for step in self.steps:
            if step.status == StepStatus.PENDING:
                if all(dep in completed_ids for dep in step.depends_on):
                    return step
        return None

    def get_progress(self) -> str:
        """获取进度摘要"""
        total = len(self.steps)
        done = sum(1 for s in self.steps if s.status == StepStatus.DONE)
        failed = sum(1 for s in self.steps if s.status == StepStatus.FAILED)
        return f"进度: {done}/{total} 完成, {failed} 失败"
```

### JSON 计划解析

LLM 输出一个结构化的 JSON 计划，Agent 将其解析为 `Plan` 对象：

```json
{
  "goal": "为项目添加类型注解",
  "steps": [
    {"id": 1, "description": "读取 utils.py 文件内容", "tool_name": "read_file", "depends_on": []},
    {"id": 2, "description": "识别所有无类型注解的函数", "tool_name": null, "depends_on": [1]},
    {"id": 3, "description": "为每个函数添加类型注解", "tool_name": "edit_file", "depends_on": [2]},
    {"id": 4, "description": "运行类型检查验证", "tool_name": "run_command", "depends_on": [3]}
  ]
}
```

### 动态调整

计划不是一成不变的。执行过程中可能出现：
- 某个步骤失败，需要调整后续步骤
- 发现新的信息，需要插入新步骤
- 某些步骤不再必要，可以跳过

Agent 需要在每步执行后重新评估计划。

### 11.2 JSON 计划解析器

将 LLM 输出解析为 `Plan` 对象：

```python
import json
import re
from datetime import datetime

class PlanParser:
    """从 LLM 输出中解析执行计划"""

    @staticmethod
    def parse(llm_output: str) -> Plan:
        """从 LLM 文本中提取并解析 JSON 计划"""
        # 尝试提取 JSON 块
        json_match = re.search(r'```json\s*(.*?)\s*```', llm_output, re.DOTALL)
        if json_match:
            json_str = json_match.group(1)
        else:
            # 尝试直接解析整个文本
            json_str = llm_output

        data = json.loads(json_str)

        steps = []
        for s in data.get("steps", []):
            step = PlanStep(
                id=s["id"],
                description=s["description"],
                tool_name=s.get("tool_name"),
                tool_args=s.get("tool_args"),
                depends_on=s.get("depends_on", []),
            )
            steps.append(step)

        return Plan(
            goal=data.get("goal", ""),
            steps=steps,
            created_at=datetime.now().isoformat(),
        )

    @staticmethod
    def format_plan(plan: Plan) -> str:
        """将 Plan 格式化为可读文本"""
        lines = [f"目标: {plan.goal}", ""]
        for step in plan.steps:
            deps = f" (依赖: {step.depends_on})" if step.depends_on else ""
            lines.append(f"  [{step.status.value}] 步骤 {step.id}: {step.description}{deps}")
        lines.append(f"\n{plan.get_progress()}")
        return "\n".join(lines)
```

### 11.3 PlanningAgent 类

结合 `AgentLoop` 和 `Plan` 实现带规划能力的 Agent：

```python
from openai import OpenAI


class PlanningAgent:
    """带 Plan-Then-Execute 能力的 Agent"""

    def __init__(self, model="gpt-4o-mini", system_prompt="",
                 max_iterations=30, max_plan_retries=2):
        self.client = OpenAI()
        self.model = model
        self.max_iterations = max_iterations
        self.max_plan_retries = max_plan_retries
        self.messages = []
        self.tool_schemas = []
        self.tool_handlers = {}
        self.current_plan: Optional[Plan] = None
        self.iteration_count = 0

        if system_prompt:
            self.messages.append({"role": "system", "content": system_prompt})

    def register_tool(self, schema, handler):
        """注册工具"""
        name = schema["function"]["name"]
        self.tool_schemas.append(schema)
        self.tool_handlers[name] = handler
        return self

    def run(self, user_message: str) -> str:
        """运行规划 Agent"""
        self.messages.append({"role": "user", "content": user_message})
        self.iteration_count = 0

        for i in range(self.max_iterations):
            self.iteration_count = i + 1

            response = self.client.chat.completions.create(
                model=self.model,
                messages=self.messages,
                tools=self.tool_schemas or None,
            )
            choice = response.choices[0]
            msg = choice.message

            # 尝试从 LLM 输出中解析计划
            if msg.content:
                self._try_parse_plan(msg.content)

            if choice.finish_reason == "tool_calls":
                self.messages.append(msg)

                for tool_call in msg.tool_calls:
                    result = self._execute_tool(tool_call)
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": tool_call.id,
                        "content": str(result),
                    })

                    # 更新当前步骤的状态
                    self._update_step_status(tool_call.function.name, result)

                self._print_progress()
            else:
                self.messages.append(msg)
                return msg.content

        return "[PlanningAgent] 已达最大循环次数。"

    def _try_parse_plan(self, text: str):
        """尝试从 LLM 文本中解析计划"""
        try:
            plan = PlanParser.parse(text)
            if plan.steps:
                self.current_plan = plan
                print(f"\n[计划] 目标: {plan.goal}")
                for step in plan.steps:
                    print(f"  步骤 {step.id}: {step.description}")
                print()
        except (json.JSONDecodeError, KeyError):
            # LLM 没有输出计划格式，这是正常的
            pass

    def _execute_tool(self, tool_call):
        """执行单个工具调用"""
        name = tool_call.function.name
        try:
            args = json.loads(tool_call.function.arguments)
        except json.JSONDecodeError:
            return "Error: 参数 JSON 解析失败"

        handler = self.tool_handlers.get(name)
        if not handler:
            return f"Error: 未知工具 '{name}'"

        try:
            return handler(**args)
        except Exception as e:
            return f"Error: {type(e).__name__}: {e}"

    def _update_step_status(self, tool_name: str, result: str):
        """更新计划中匹配步骤的状态"""
        if not self.current_plan:
            return

        is_error = result.startswith("Error:")
        for step in self.current_plan.steps:
            if step.tool_name == tool_name and step.status == StepStatus.PENDING:
                step.status = StepStatus.FAILED if is_error else StepStatus.DONE
                step.result = result
                break

    def _print_progress(self):
        """打印当前进度"""
        if self.current_plan:
            print(f"  {self.current_plan.get_progress()}")

    def replan(self, reason: str):
        """请求 LLM 重新制定计划"""
        self.messages.append({
            "role": "user",
            "content": f"当前计划执行遇到问题: {reason}。请重新制定计划。",
        })
        if self.current_plan:
            for step in self.current_plan.steps:
                if step.status == StepStatus.FAILED:
                    step.status = StepStatus.PENDING  # 重置失败步骤
```

## 常见问题

### Q1：规划过于复杂怎么办？

LLM 把简单任务拆成 20 个步骤，执行时间很长。解决方案：
- 在 System Prompt 中限制步骤数："将任务控制在 3-5 个步骤内"
- 对简单任务不启用规划，直接走 ReAct 模式
- 先判断任务复杂度，只对复杂任务启用 `PlanningAgent`

### Q2：子任务之间有依赖如何处理？

`PlanStep` 的 `depends_on` 字段记录依赖关系。`get_next_step` 方法会检查依赖是否满足。但对于 Agent Loop 中由 LLM 自主决策的场景，依赖通常通过 messages 的上下文自然保证 -- LLM 看到之前步骤的结果后才决定下一步。

### Q3：计划执行失败后如何回滚？

文件操作的回滚比较复杂。基础策略：
- 执行前创建备份（复制文件到 `.bak`）
- System Prompt 中引导 LLM："如果步骤失败，尝试修复而不是跳过"
- 记录所有操作日志，支持手动回滚

### Q4：规划的额外 token 开销

让 LLM 先规划再执行，token 消耗会明显增加。优化策略：
- 只对复杂任务启用规划
- 规划完成后可以压缩规划文本，只保留关键信息
- 使用更便宜的模型（如 `gpt-4o-mini`）做规划，用更强的模型做执行

### Q5：JSON 解析失败怎么办？

LLM 输出的 JSON 可能格式不规范。防御策略：
- 使用 `try/except` 包裹解析逻辑
- 支持多种 JSON 提取模式（` ```json``` ` 包裹、纯 JSON、混合文本）
- 解析失败时回退到 ReAct 模式，不影响执行

## 本章小结

| 概念 | 要点 |
|---|---|
| Plan-Then-Execute | 先规划后执行，适合复杂多步任务 |
| `Plan` / `PlanStep` | 数据结构管理步骤、状态、依赖关系 |
| `StepStatus` | `PENDING` / `RUNNING` / `DONE` / `FAILED` / `SKIPPED` |
| JSON 计划解析 | 从 LLM 输出中提取 JSON 并构造 `Plan` 对象 |
| `PlanningAgent` | 结合 AgentLoop 和 Plan 的规划 Agent |
| 动态调整 | 执行中发现问题后调用 `replan` 重新制定计划 |
| 依赖管理 | `depends_on` 字段记录步骤间依赖，`get_next_step` 自动检查 |
| Mock 测试 | 验证计划解析、状态更新、依赖判断的正确性 |

Plan-Then-Execute 是 Agent 处理复杂任务的关键能力。下一章将讨论错误处理与恢复 -- 当计划中的步骤失败时，Agent 如何自动重试和降级。
