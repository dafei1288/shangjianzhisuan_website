## 核心概念

### 上下文膨胀问题

在多轮对话中，消息历史持续增长。每轮对话至少增加 user + assistant 两条消息，如果涉及工具调用还会增加 tool_calls + tool_result 消息。一个读取了大文件内容的工具调用可能单条就消耗数千 token。如果不主动管理，对话进行到 10-20 轮时就会逼近 context window 上限。

### 三种压缩策略对比

| 策略 | 原理 | Token 节省 | 信息损失 | 计算成本 | 适用场景 |
|------|------|-----------|---------|---------|---------|
| truncate | 截断长消息 | 中 | 高 | 零 | 工具返回值过长 |
| sliding_window | 只保留最近 N 轮 | 高 | 中 | 零 | 日常对话 |
| LLM 摘要 | 用 LLM 总结历史 | 最高 | 低 | 高 | 长期任务 |
| 混合策略 | 组合以上策略 | 高 | 低 | 中 | 生产环境 |

### 保留策略

无论使用哪种压缩策略，以下消息必须始终保留：

- **System prompt**：绝对不可丢弃，是 Agent 身份的基础
- **最近 2-3 轮对话**：保证当前任务上下文的连贯性
- **未完成的工具调用链**：tool_call 必须有对应的 tool_result，否则 API 报错
- **关键决策点**：用户明确确认过的重要决策

### 压缩后恢复

压缩后原始消息不能丢弃。将完整消息历史保存在 `original_messages` 中，当后续对话需要回溯早期上下文时，可以通过关键词搜索从原始消息中恢复。

## 代码讲解

### 15.1 压缩策略基类与枚举

```python
from abc import ABC, abstractmethod
from enum import Enum
from typing import Optional
import logging

logger = logging.getLogger(__name__)


class CompressionStrategy(Enum):
    """压缩策略类型"""
    TRUNCATE = "truncate"
    SLIDING_WINDOW = "sliding_window"
    LLM_SUMMARY = "llm_summary"


class CompressionResult:
    """压缩结果"""
    def __init__(self, messages: list, original_count: int,
                 compressed_count: int, strategy: str):
        self.messages = messages
        self.original_count = original_count
        self.compressed_count = compressed_count
        self.saved_tokens = original_count - compressed_count
        self.strategy = strategy
        self.compression_ratio = (
            self.saved_tokens / original_count if original_count > 0 else 0
        )

    def summary(self) -> str:
        return (
            f"[{self.strategy}] {self.original_count} -> "
            f"{self.compressed_count} tokens "
            f"(节省 {self.compression_ratio:.1%})"
        )


class BaseCompressor(ABC):
    """压缩策略基类"""

    @abstractmethod
    async def compress(
        self, messages: list, target_tokens: int, token_counter
    ) -> CompressionResult:
        """将消息压缩到目标 token 数以内"""
        ...
```

### 15.2 截断策略（TruncateCompressor）

```python
class TruncateCompressor(BaseCompressor):
    """
    截断策略：将过长的消息内容截断到指定长度。
    主要用于处理工具返回值过长的情况。
    """

    def __init__(self, max_content_length: int = 3000):
        self.max_content_length = max_content_length

    async def compress(
        self, messages: list, target_tokens: int, token_counter
    ) -> CompressionResult:
        original_tokens = token_counter.count_messages(messages)
        compressed = []

        for msg in messages:
            content = msg.get("content", "")
            if not isinstance(content, str):
                compressed.append(msg)
                continue

            if len(content) > self.max_content_length:
                truncated = content[:self.max_content_length]
                truncated += f"\n\n... [已截断，原文 {len(content)} 字符，"
                truncated += f"仅保留前 {self.max_content_length} 字符]"
                new_msg = {**msg, "content": truncated}
                compressed.append(new_msg)
                logger.debug(
                    f"截断消息: role={msg['role']}, "
                    f"{len(content)} -> {len(truncated)} 字符"
                )
            else:
                compressed.append(msg)

        compressed_tokens = token_counter.count_messages(compressed)
        return CompressionResult(
            messages=compressed,
            original_count=original_tokens,
            compressed_count=compressed_tokens,
            strategy="truncate",
        )
```

### 15.3 滑动窗口策略（SlidingWindowCompressor）

```python
class SlidingWindowCompressor(BaseCompressor):
    """
    滑动窗口策略：只保留 system 消息 + 最近 N 轮对话。
    "一轮" 定义为从 user 消息到下一个 user 消息之间的所有消息。
    """

    def __init__(self, keep_rounds: int = 5):
        self.keep_rounds = keep_rounds

    def _split_rounds(self, messages: list) -> list[list]:
        """将消息按轮次分割"""
        rounds = []
        current_round = []

        for msg in messages:
            if msg["role"] == "system":
                continue  # system 消息单独处理
            if msg["role"] == "user" and current_round:
                rounds.append(current_round)
                current_round = []
            current_round.append(msg)

        if current_round:
            rounds.append(current_round)

        return rounds

    async def compress(
        self, messages: list, target_tokens: int, token_counter
    ) -> CompressionResult:
        original_tokens = token_counter.count_messages(messages)

        # 分离 system 消息和非 system 消息
        system_msgs = [m for m in messages if m["role"] == "system"]
        other_msgs = [m for m in messages if m["role"] != "system"]

        # 按轮次分割
        rounds = self._split_rounds(other_msgs)

        # 只保留最近 N 轮
        kept_rounds = rounds[-self.keep_rounds:]
        kept_messages = []
        for r in kept_rounds:
            kept_messages.extend(r)

        compressed = system_msgs + kept_messages
        compressed_tokens = token_counter.count_messages(compressed)

        logger.info(
            f"滑动窗口: 保留 {len(kept_rounds)}/{len(rounds)} 轮, "
            f"丢弃了 {len(rounds) - len(kept_rounds)} 轮历史"
        )

        return CompressionResult(
            messages=compressed,
            original_count=original_tokens,
            compressed_count=compressed_tokens,
            strategy="sliding_window",
        )
```

### 15.4 LLM 摘要策略（LLMSummaryCompressor）

```python
SUMMARY_SYSTEM_PROMPT = """你是一个对话摘要助手。你的任务是将对话历史压缩为简洁的摘要。

要求：
1. 保留关键决策和结论
2. 保留重要的代码变更描述（文件名 + 变更内容）
3. 保留未解决的问题和待办事项
4. 丢弃日常问候、重复讨论和无关细节
5. 摘要不超过 500 字
6. 使用条目式格式，每条一行"""


class LLMSummaryCompressor(BaseCompressor):
    """
    LLM 摘要策略：用 LLM 对历史对话生成摘要，
    将摘要作为 system 消息插入，替代原始历史。
    """

    def __init__(self, llm_client, summary_model: str = "gpt-4o-mini"):
        self.llm_client = llm_client
        self.summary_model = summary_model

    def _format_messages_as_text(self, messages: list) -> str:
        """将消息列表格式化为纯文本供 LLM 摘要"""
        lines = []
        for msg in messages:
            role = msg.get("role", "unknown")
            content = msg.get("content", "")
            if isinstance(content, str):
                # 截断过长的单条消息，避免摘要请求本身太长
                if len(content) > 500:
                    content = content[:500] + "..."
                lines.append(f"[{role}]: {content}")
        return "\n".join(lines)

    async def compress(
        self, messages: list, target_tokens: int, token_counter
    ) -> CompressionResult:
        original_tokens = token_counter.count_messages(messages)

        system_msgs = [m for m in messages if m["role"] == "system"]
        other_msgs = [m for m in messages if m["role"] != "system"]

        # 保留最近 3 轮不压缩
        rounds = self._split_rounds(other_msgs)
        if len(rounds) <= 3:
            return CompressionResult(
                messages=messages,
                original_count=original_tokens,
                compressed_count=original_tokens,
                strategy="llm_summary (skip: too few rounds)",
            )

        history_to_summarize = rounds[:-3]
        recent_to_keep = rounds[-3:]

        # 将历史消息格式化为文本
        history_flat = []
        for r in history_to_summarize:
            history_flat.extend(r)
        history_text = self._format_messages_as_text(history_flat)

        # 调用 LLM 生成摘要
        summary = await self._generate_summary(history_text)

        # 构建压缩后的消息列表
        summary_msg = {
            "role": "system",
            "content": f"[之前的对话历史摘要]\n{summary}",
        }

        recent_flat = []
        for r in recent_to_keep:
            recent_flat.extend(r)

        compressed = system_msgs + [summary_msg] + recent_flat
        compressed_tokens = token_counter.count_messages(compressed)

        return CompressionResult(
            messages=compressed,
            original_count=original_tokens,
            compressed_count=compressed_tokens,
            strategy="llm_summary",
        )

    async def _generate_summary(self, conversation_text: str) -> str:
        """调用 LLM 生成摘要"""
        response = await self.llm_client.chat.completions.create(
            model=self.summary_model,
            messages=[
                {"role": "system", "content": SUMMARY_SYSTEM_PROMPT},
                {"role": "user", "content": f"请摘要以下对话：\n\n{conversation_text}"},
            ],
            max_tokens=800,
            temperature=0,
        )
        return response.choices[0].message.content

    def _split_rounds(self, messages: list) -> list[list]:
        """复用滑动窗口的轮次分割逻辑"""
        rounds = []
        current_round = []
        for msg in messages:
            if msg["role"] == "user" and current_round:
                rounds.append(current_round)
                current_round = []
            current_round.append(msg)
        if current_round:
            rounds.append(current_round)
        return rounds
```

### 15.5 统一的 ContextCompressor

```python
class ContextCompressor:
    """
    统一上下文压缩器。
    自动选择压缩策略，保留原始消息用于恢复。
    """

    def __init__(self, token_counter, token_budget, llm_client=None):
        self.token_counter = token_counter
        self.token_budget = token_budget
        self.original_messages: list = []  # 完整原始消息备份

        # 初始化各策略
        self._strategies = {
            CompressionStrategy.TRUNCATE: TruncateCompressor(),
            CompressionStrategy.SLIDING_WINDOW: SlidingWindowCompressor(keep_rounds=5),
        }
        if llm_client:
            self._strategies[CompressionStrategy.LLM_SUMMARY] = \
                LLMSummaryCompressor(llm_client)

    async def compress_if_needed(self, messages: list) -> tuple[list, Optional[CompressionResult]]:
        """检查预算，必要时压缩"""
        msg_tokens = self.token_counter.count_messages(messages)
        report = self.token_budget.check(msg_tokens)

        if not report.should_compress:
            return messages, None

        # 保存原始消息
        self.original_messages = list(messages)

        # 选择策略
        if report.level.value in ("critical", "exceeded") and \
           CompressionStrategy.LLM_SUMMARY in self._strategies:
            strategy = CompressionStrategy.LLM_SUMMARY
        else:
            strategy = CompressionStrategy.SLIDING_WINDOW

        # 先尝试截断（零成本）
        if msg_tokens > self.token_budget.available_for_messages * 0.8:
            truncate_result = await self._strategies[
                CompressionStrategy.TRUNCATE
            ].compress(messages, self.token_budget.available_for_messages,
                       self.token_counter)
            messages = truncate_result.messages

        # 如果截断不够，再用选定策略
        current_tokens = self.token_counter.count_messages(messages)
        if current_tokens > self.token_budget.available_for_messages:
            result = await self._strategies[strategy].compress(
                messages, self.token_budget.available_for_messages,
                self.token_counter
            )
            logger.info(f"上下文压缩完成: {result.summary()}")
            return result.messages, result

        return messages, None

    def search_original(self, keyword: str) -> list:
        """在原始消息中搜索关键词，用于恢复上下文"""
        results = []
        for msg in self.original_messages:
            content = str(msg.get("content", ""))
            if keyword.lower() in content.lower():
                results.append(msg)
        return results
```

## 常见问题

### Q1: LLM 摘要本身消耗 token 怎么办？

摘要需要额外调用一次 LLM，有 token 成本。但这个成本是值得的：一次摘要消耗约 500-1000 token，但可以释放数千甚至上万 token 的空间。使用更便宜的模型（如 gpt-4o-mini）做摘要可以进一步降低成本。摘要结果可以缓存，避免对同一段历史重复摘要。

### Q2: 压缩后 Agent "忘记" 了之前讨论的内容怎么办？

这正是 `original_messages` 备份的作用。当 Agent 需要回溯早期内容时，可以通过 `search_original()` 搜索原始消息，将相关片段作为新的 user 消息注入回去。另一种方案是在 system prompt 中加入"如果不确定历史内容，主动询问用户"的指令。

### Q3: 滑动窗口的轮数怎么定？

取决于对话内容的密度。简单的问答对话每轮消耗少，可以保留更多轮（如 8-10 轮）。涉及大量代码和工具调用的对话每轮消耗多，保留较少轮（如 3-5 轮）。可以根据 token 预算动态调整：预算紧张时减少保留轮数，预算充裕时增加。

### Q4: 工具调用链被截断导致 API 报错怎么办？

这是滑动窗口策略的常见坑。必须保证 tool_call 消息和对应的 tool_result 消息在同一轮内不被拆分。`_split_rounds()` 方法通过按 user 消息边界分割来避免这个问题。如果某轮包含未完成的工具调用（有 tool_call 但没有 tool_result），必须将整轮保留。

## 本章小结

本章实现了完整的多策略上下文压缩系统。`TruncateCompressor` 负责处理工具返回值过长的场景（零成本）；`SlidingWindowCompressor` 通过丢弃早期对话来释放空间（零计算成本但信息有损）；`LLMSummaryCompressor` 用 LLM 对历史生成摘要（有计算成本但信息保留最好）。统一的 `ContextCompressor` 根据预算紧张程度自动选择策略，同时保留原始消息用于后续恢复。这套系统确保 Agent 在长对话中始终运行在 token 预算范围内。
