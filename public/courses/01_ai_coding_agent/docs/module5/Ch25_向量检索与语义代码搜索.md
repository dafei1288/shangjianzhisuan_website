## 核心概念

### 1. 从文本搜索到语义搜索

传统的 `grep`/`ripgrep` 基于精确文本匹配或正则表达式，只能找到字面上包含关键词的代码。但开发者经常用自然语言描述意图，与代码中的命名存在语义鸿沟。

```
用户搜索: "用户登录验证"
grep 能找到: 包含 "用户登录验证" 字面量的注释
语义搜索能找到: verify_token(), authenticate(), check_credentials() 等
```

语义搜索的核心思路：将代码和查询都映射到同一向量空间，通过向量距离衡量语义相似度。即使字面完全不同，只要语义接近就能匹配。

### 2. CodeChunker：代码分块策略

代码文件通常很长，不能将整个文件作为一个检索单元。`CodeChunker` 利用 Python `ast` 模块将源代码解析为语法树，按函数（`FunctionDef`/`AsyncFunctionDef`）和类（`ClassDef`）粒度切分为 chunk。

关键设计：
- **AST 驱动切分**：不是按固定行数粗暴切割，而是尊重代码的逻辑结构
- **容错处理**：遇到 `SyntaxError` 时，将整个文件作为一个 "module" chunk
- **稳定 ID**：每个 chunk 基于 `file_path:start_line:name` 生成 MD5 哈希 ID，确保多次索引结果一致
- **目录级扫描**：`chunk_directory()` 递归扫描 `.py` 文件，自动跳过隐藏目录和 `__pycache__`

### 3. EmbeddingProvider：向量化接口

Embedding（嵌入）是将文本转换为固定维度浮点向量的过程。本演示定义了 `EmbeddingProvider` Protocol 接口，并提供了两种实现：

| 实现 | 原理 | 用途 |
|------|------|------|
| `MockEmbeddingProvider` | SHA-256 哈希映射为向量，确定性、归一化 | 单元测试 |
| `SimpleEmbeddingProvider` | 词袋模型（Bag-of-Words），分词后哈希到固定维度 | 无 API 的 fallback |

生产环境中可将此接口替换为 OpenAI Embedding、sentence-transformers 等真实模型。

### 4. VectorStore：向量索引与检索

`VectorStore` 维护 chunk 与向量的平行列表，通过余弦相似度进行检索：

```
cosine_similarity(a, b) = (a . b) / (|a| * |b|)
```

核心设计：
- **纯 Python 实现**：不依赖 numpy，使用 `sum()` 和列表推导完成向量运算
- **暴力搜索**：遍历所有向量计算相似度，按分数降序排列取 top-k
- **简洁接口**：`add()` / `add_batch()` 入索引，`search()` 检索，`clear()` 重置

暴力搜索在数千 chunk 内性能足够。大规模场景可替换为 FAISS、Annoy 等近似最近邻索引。

### 5. SemanticSearchTool：Agent 集成

`SemanticSearchTool` 将 Chunker + Embedding + Store 三者整合，提供面向 Agent 的简洁接口：

- `index_file(source, file_path)`：索引单个文件
- `index_directory(dir_path)`：递归索引整个目录
- `search(query, top_k)`：语义搜索，返回 `SearchResult` 列表
- `search_and_format(query, top_k)`：搜索并格式化为可读文本，适合直接注入 Agent 上下文

## 代码实现

### 25.1 数据结构

```python
@dataclass
class CodeChunk:
    content: str          # chunk 的源代码内容
    file_path: str        # 所属文件路径
    start_line: int       # 起始行号
    end_line: int         # 结束行号
    name: str             # 函数名/类名
    kind: str             # "function", "class", "module"
    chunk_id: str = ""    # 基于内容的稳定哈希 ID

    def __post_init__(self):
        if not self.chunk_id:
            raw = f"{self.file_path}:{self.start_line}:{self.name}"
            self.chunk_id = hashlib.md5(raw.encode()).hexdigest()[:12]

@dataclass
class SearchResult:
    chunk: CodeChunk
    score: float          # 余弦相似度分数
    query: str = ""
```

### 25.2 CodeChunker 核心

```python
class CodeChunker:
    def __init__(self, max_chunk_lines: int = 80):
        self.max_chunk_lines = max_chunk_lines

    def chunk_file(self, source: str, file_path: str = "") -> list[CodeChunk]:
        try:
            tree = ast.parse(source)
        except SyntaxError:
            # 语法错误时整个文件作为一个 chunk
            return [CodeChunk(
                content=source, file_path=file_path,
                start_line=1, end_line=len(source.splitlines()),
                name=file_path, kind="module",
            )]

        chunks = []
        lines = source.splitlines()
        for node in ast.walk(tree):
            if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef)):
                start, end = node.lineno, node.end_lineno or node.lineno
                content = "\n".join(lines[start - 1:end])
                chunks.append(CodeChunk(
                    content=content, file_path=file_path,
                    start_line=start, end_line=end,
                    name=node.name,
                    kind="class" if isinstance(node, ast.ClassDef) else "function",
                ))
        # 无任何函数/类时，整个文件作为一个 module chunk
        if not chunks:
            chunks.append(CodeChunk(
                content=source, file_path=file_path,
                start_line=1, end_line=len(lines),
                name=file_path, kind="module",
            ))
        return chunks
```

### 25.3 EmbeddingProvider 与实现

```python
@runtime_checkable
class EmbeddingProvider(Protocol):
    def embed(self, text: str) -> list[float]: ...
    def embed_batch(self, texts: list[str]) -> list[list[float]]: ...

class MockEmbeddingProvider:
    """基于 SHA-256 哈希的确定性 embedding（测试用）"""
    def __init__(self, dim: int = 64):
        self.dim = dim
        self._cache: dict[str, list[float]] = {}

    def embed(self, text: str) -> list[float]:
        if text in self._cache:
            return self._cache[text]
        h = hashlib.sha256(text.encode()).digest()
        vec = [h[i % len(h)] / 255.0 - 0.5 for i in range(self.dim)]
        norm = math.sqrt(sum(v * v for v in vec)) or 1.0
        vec = [v / norm for v in vec]
        self._cache[text] = vec
        return vec

class SimpleEmbeddingProvider:
    """基于词袋的 embedding（无需外部依赖的 fallback）"""
    def __init__(self, dim: int = 64):
        self.dim = dim

    def embed(self, text: str) -> list[float]:
        words = text.lower().split()
        vec = [0.0] * self.dim
        for word in words:
            idx = hash(word) % self.dim
            vec[idx] += 1.0
        norm = math.sqrt(sum(v * v for v in vec)) or 1.0
        return [v / norm for v in vec]
```

### 25.4 VectorStore 余弦检索

```python
class VectorStore:
    def __init__(self, dim: int = 64):
        self.dim = dim
        self._vectors: list[list[float]] = []
        self._chunks: list[CodeChunk] = []

    @staticmethod
    def cosine_similarity(a: list[float], b: list[float]) -> float:
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = math.sqrt(sum(x * x for x in a)) or 1e-10
        norm_b = math.sqrt(sum(x * x for x in b)) or 1e-10
        return dot / (norm_a * norm_b)

    def search(self, query_vector: list[float], top_k: int = 5) -> list[SearchResult]:
        if not self._vectors:
            return []
        scores = [self.cosine_similarity(query_vector, v) for v in self._vectors]
        indexed = sorted(enumerate(scores), key=lambda x: x[1], reverse=True)
        return [SearchResult(chunk=self._chunks[i], score=s) for i, s in indexed[:top_k]]
```

### 25.5 SemanticSearchTool 集成

```python
class SemanticSearchTool:
    def __init__(self, embedding_provider: EmbeddingProvider, dim: int = 64):
        self.provider = embedding_provider
        self.store = VectorStore(dim=dim)
        self.chunker = CodeChunker()

    def index_file(self, source: str, file_path: str = ""):
        chunks = self.chunker.chunk_file(source, file_path)
        vectors = self.provider.embed_batch([c.content for c in chunks])
        self.store.add_batch(chunks, vectors)

    def index_directory(self, dir_path: str):
        chunks = self.chunker.chunk_directory(dir_path)
        vectors = self.provider.embed_batch([c.content for c in chunks])
        self.store.add_batch(chunks, vectors)

    def search_and_format(self, query: str, top_k: int = 5) -> str:
        results = self.search(query, top_k)
        if not results:
            return "No results found."
        lines = []
        for i, r in enumerate(results, 1):
            lines.append(
                f"{i}. {r.chunk.name} ({r.chunk.kind}) "
                f"@ {r.chunk.file_path}:{r.chunk.start_line} "
                f"[score: {r.score:.3f}]"
            )
            for pl in r.chunk.content.splitlines()[:3]:
                lines.append(f"   {pl}")
        return "\n".join(lines)
```

## 关键要点

| 概念 | 说明 |
|------|------|
| AST 切分 | 利用 `ast.parse()` 按函数/类边界切分代码，保留语义完整性 |
| Protocol 模式 | `EmbeddingProvider` 使用 `typing.Protocol`，实现结构化子类型，方便替换不同实现 |
| Mock Embedding | SHA-256 哈希生成确定性向量，缓存确保相同文本返回相同向量，适合单元测试 |
| 词袋 Embedding | 分词后哈希映射到固定维度，归一化后可作为零依赖的 baseline |
| 余弦相似度 | 衡量两个向量方向的接近程度，归一化后范围为 [-1, 1]，值越大越相似 |
| 纯 Python 实现 | 所有向量运算使用 `sum()` + 列表推导，不依赖 numpy，降低部署复杂度 |
| top-k 检索 | 暴力搜索在数千 chunk 规模内足够高效，大规模可替换为 FAISS 等近似索引 |
| Agent 集成 | `SemanticSearchTool` 封装分块/向量化/检索流程，`search_and_format()` 输出可直接注入上下文 |

## 常见问题 Q&A

**Q1：为什么要按函数/类切 chunk，而不是整文件建索引？**

A：因为整文件粒度太粗。一个大文件里往往混着多个职责，整文件 embedding 会把语义搅在一起，导致召回结果“相关但不准”。按函数/类切分更接近开发者真实想找的单元。

**Q2：MockEmbeddingProvider 明明不真实，为什么课程里还要先讲它？**

A：因为它解决了教学中的两个实际问题：一是完全零依赖，二是结果稳定可复现。你可以先把“分块 -> 向量化 -> 检索”链路跑通，再替换成真实模型，而不是一开始就被 API、网络和成本问题绊住。

**Q3：语义搜索是不是就能完全替代 `grep`？**

A：不能。语义搜索擅长“意思相近”的召回，`grep` 擅长“字面精确”的定位。真实 Agent 往往两者都要：先用语义搜索找候选区域，再用关键词或 AST 做精确落点。

**Q4：为什么这里先用暴力搜索，不直接上 FAISS？**

A：因为教学目标是先理解检索原理，而不是一开始就引入复杂依赖。对几百到几千个 chunk 的课程 demo 来说，暴力 top-k 足够了；等你确认链路成立，再替换为更高性能的索引库更合理。

## 本章小结

向量检索与语义代码搜索赋予 Agent"理解代码含义"的能力：
- **嵌入模型**：将代码片段映射到高维向量空间，语义相似的代码在空间中相近

- **搜索应用**：自然语言描述→语义向量→匹配相关代码，比关键词搜索更智能
