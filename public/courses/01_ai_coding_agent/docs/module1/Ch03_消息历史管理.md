## 核心概念

### 1. 消息生命周期

在 Agent Loop 的每一次迭代中，消息经历以下阶段：

```
创建 system prompt
    ↓
追加用户消息 (user)
    ↓
传递给 LLM → 获得响应
    ↓
追加 assistant 消息
    ↓
[如果包含 tool_calls]
    ↓
执行工具 → 追加 tool 消息
    ↓
再次传递给 LLM（循环）
    ↓
...
    ↓
历史过长 → 截断（truncate）
    ↓
继续循环
```

关键洞察：消息历史是 Agent 唯一的"记忆"。如果管理不当，要么丢失重要上下文，要么超出 token 限制导致 API 报错。

### 2. 不可变性保护

消息历史是一个有状态的组件。Agent Loop 会频繁读写消息，同时其他组件（如日志、UI）可能也需要读取。如果读取者意外修改了内部列表，将导致难以追踪的 bug。

```python
# 危险：直接暴露内部列表
class BadHistory:
    def __init__(self):
        self.messages = []  # 外部可以直接 self.messages.append(...)

# 安全：通过方法控制访问，返回拷贝
class GoodHistory:
    def __init__(self):
        self._messages = []  # 私有属性

    def get_messages(self) -> list[Message]:
        return list(self._messages)  # 浅拷贝，外部修改不影响内部
```

### 3. 截断策略的必要性

LLM 都有上下文窗口限制：

| 模型 | 上下文窗口 |
|------|-----------|
| GPT-4o | 128K tokens |
| GPT-4o-mini | 128K tokens |
| Claude Sonnet | 200K tokens |
| DeepSeek V3 | 128K tokens |

一个 Coding Agent 在复杂任务中可能产生大量消息（读取多个文件、执行多个命令），很容易接近限制。截断不是"可选项"，而是"必须项"。

### 4. 截断的核心原则

1. **永远保留 system 消息**：system prompt 包含 Agent 的行为指令，丢失会导致行为异常
2. **优先保留最近的消息**：最近的对话最相关，早期消息的参考价值递减
3. **成对保留 tool_calls 和 tool_result**：tool_calls 消息如果没有对应的 tool_result，API 会报错

## 代码讲解

### history.py —— 完整实现

```python
from __future__ import annotations
from dataclasses import dataclass
import logging

logger = logging.getLogger(__name__)


class MessageHistory:
    """消息历史管理器
    
    职责:
    1. 安全地存储和检索消息
    2. 提供增删改查接口
    3. 实现 token 预算管理
    4. 保护内部状态不被外部意外修改
    """

    def __init__(self, system_prompt: str | None = None, max_tokens: int = 100000):
        self._messages: list[Message] = []
        self._max_tokens = max_tokens

        if system_prompt:
            self._messages.append(Message.system(system_prompt))

    @property
    def count(self) -> int:
        """当前消息数量"""
        return len(self._messages)

    @property
    def max_tokens(self) -> int:
        """token 预算上限"""
        return self._max_tokens

    def get_messages(self) -> list[Message]:
        """获取消息列表的浅拷贝

        返回新的 list 对象，但内部的 Message 对象是共享引用。
        这意味着:
        - 调用者 append/remove 不会影响内部列表  ✓
        - 调用者修改某个 Message 的属性会影响内部  ⚠

        设计理由: 完整深拷贝的代价太高（每次 API 调用都要复制），
        而我们信任内部模块不会恶意修改 Message 对象。
        """
        return list(self._messages)

    def get_api_messages(self) -> list[dict]:
        """获取 API 所需格式的消息列表

        等价于: [m.to_dict() for m in self.get_messages()]
        但内部直接遍历 _messages，避免不必要的拷贝。
        """
        return [m.to_dict() for m in self._messages]

    def add(self, message: Message) -> None:
        """添加一条消息"""
        if not isinstance(message, Message):
            raise TypeError(f"期望 Message 类型，收到 {type(message).__name__}")
        self._messages.append(message)
        logger.debug(f"消息已添加: role={message.role}, 总数={len(self._messages)}")

    def add_user(self, content: str) -> None:
        """快捷方法：添加用户消息"""
        self.add(Message.user(content))

    def add_assistant(self, content: str | None = None,
                      tool_calls: list[ToolCall] | None = None) -> None:
        """快捷方法：添加助手消息"""
        self.add(Message(role="assistant", content=content, tool_calls=tool_calls))

    def add_tool_result(self, tool_call_id: str, content: str, name: str | None = None) -> None:
        """快捷方法：添加工具执行结果"""
        self.add(Message(
            role="tool",
            content=content,
            tool_call_id=tool_call_id,
            name=name,
        ))

    def remove_last(self) -> Message | None:
        """移除并返回最后一条消息"""
        if self._messages:
            msg = self._messages.pop()
            logger.debug(f"消息已移除: role={msg.role}, 剩余={len(self._messages)}")
            return msg
        return None

    def clear(self, keep_system: bool = True) -> None:
        """清空消息历史

        Args:
            keep_system: 是否保留 system 消息。默认 True，
                         因为 system prompt 通常在 Agent 整个生命周期内有效。
        """
        if keep_system:
            self._messages = [m for m in self._messages if m.role == "system"]
        else:
            self._messages.clear()
        logger.debug(f"历史已清空, 保留 {len(self._messages)} 条消息")

    def truncate(self, max_tokens: int | None = None, keep_recent: int = 4) -> None:
        """截断消息历史以控制 token 预算

        策略:
        1. 保留所有 system 消息
        2. 保留最近 keep_recent 条非 system 消息
        3. 如果仍然超限，从最早的非 system 消息开始删除
        4. 确保 tool_calls 和 tool_result 成对保留

        Args:
            max_tokens: token 预算上限，默认使用 self._max_tokens
            keep_recent: 至少保留最近 N 条非 system 消息
        """
        budget = max_tokens or self._max_tokens

        # 估算当前 token 使用量
        current_tokens = self.estimate_tokens()

        if current_tokens <= budget:
            return  # 无需截断

        logger.info(f"开始截断: 当前 {current_tokens} tokens, 预算 {budget}")

        # 分离 system 消息和非 system 消息
        system_msgs = [m for m in self._messages if m.role == "system"]
        non_system = [m for m in self._messages if m.role != "system"]

        # 从最早的非 system 消息开始删除
        removed = 0
        while non_system and keep_recent > 0 and len(non_system) > keep_recent:
            # 估算是否已经满足预算
            test_messages = system_msgs + non_system
            if self._estimate_tokens_for(test_messages) <= budget:
                break

            # 删除最早的一条
            removed_msg = non_system.pop(0)
            removed += 1

            # 如果删除的是包含 tool_calls 的 assistant 消息，
            # 也需要删除对应的 tool result 消息
            if removed_msg.role == "assistant" and removed_msg.tool_calls:
                call_ids = {tc.id for tc in removed_msg.tool_calls}
                non_system = [
                    m for m in non_system
                    if not (m.role == "tool" and m.tool_call_id in call_ids)
                ]

            # 如果删除的是 tool result，检查是否需要删除对应的 assistant tool_calls
            # （这种情况较少，因为 tool result 在 assistant 之后）

        self._messages = system_msgs + non_system
        new_tokens = self.estimate_tokens()
        logger.info(f"截断完成: 移除 {removed} 条消息, {current_tokens} → {new_tokens} tokens")

    def estimate_tokens(self) -> int:
        """估算当前消息历史的 token 数量

        使用启发式方法：
        - 英文: ~0.75 words/token → ~4 chars/token
        - 中文: ~1.5 chars/token
        - 取保守估计: ~3 chars/token
        - 加上消息结构的开销（role、tool_call_id 等字段）

        注意: 这是粗略估算，实际值可能有 20-30% 的误差。
        精确计算需要使用 tiktoken（OpenAI）或对应模型的 tokenizer。
        """
        return self._estimate_tokens_for(self._messages)

    @staticmethod
    def _estimate_tokens_for(messages: list[Message]) -> int:
        """为一组消息估算 token 数量"""
        total = 0
        for msg in messages:
            # 消息结构开销: role 字段、分隔符等，每条约 4 tokens
            total += 4

            if msg.content:
                # 文本内容: 约 3 个字符 = 1 token（保守估计）
                total += len(msg.content) // 3 + 1

            if msg.tool_calls:
                for tc in msg.tool_calls:
                    # tool_call 结构开销
                    total += 8
                    if tc.arguments:
                        total += len(tc.arguments) // 3 + 1

            # tool_call_id 和 name 的开销
            if msg.tool_call_id:
                total += 2
            if msg.name:
                total += 2

        return total

    def get_summary(self) -> dict:
        """获取历史摘要（用于日志和调试）"""
        role_counts = {}
        for m in self._messages:
            role_counts[m.role] = role_counts.get(m.role, 0) + 1

        return {
            "total_messages": len(self._messages),
            "role_counts": role_counts,
            "estimated_tokens": self.estimate_tokens(),
            "max_tokens": self._max_tokens,
            "token_usage_percent": round(
                self.estimate_tokens() / self._max_tokens * 100, 1
            ),
        }

    def __repr__(self) -> str:
        return (
            f"MessageHistory(messages={len(self._messages)}, "
            f"tokens={self.estimate_tokens()}/{self._max_tokens})"
        )
```

### 集成到 Agent Loop

```python
def agent_loop(user_input: str, history: MessageHistory, provider: LLMProvider) -> str:
    """单轮 Agent Loop"""
    history.add_user(user_input)

    for _ in range(10):  # 最大迭代次数
        # 截断检查
        history.truncate()

        # 调用 LLM
        response = provider.chat(history.get_messages())

        # 如果 LLM 返回文本，完成
        if response.content and not response.tool_calls:
            history.add_assistant(response.content)
            return response.content

        # 如果 LLM 请求调用工具
        if response.tool_calls:
            history.add_assistant(tool_calls=response.tool_calls)

            for tc in response.tool_calls:
                result = execute_tool(tc.name, tc.parse_arguments())
                history.add_tool_result(tc.id, result, name=tc.name)

    return "达到最大迭代次数，任务未完成。"
```

## 实践练习

### 练习 1：添加消息去重（基础）

LLM 有时会重复发送相同的内容（尤其是 temperature 较低时）。实现去重逻辑：

```python
def deduplicate(self) -> int:
    """去除连续的重复消息，返回移除数量

    规则:
    - 如果连续两条相同 role 的消息 content 完全相同，保留第一条
    - 不比较 tool_calls（太复杂，且重复概率低）
    """
    removed = 0
    i = 1
    while i < len(self._messages):
        prev, curr = self._messages[i-1], self._messages[i]
        if (prev.role == curr.role
            and prev.content == curr.content
            and prev.role != "tool"):  # tool 消息不去重（tool_call_id 必须保留）
            self._messages.pop(i)
            removed += 1
        else:
            i += 1
    return removed
```

测试用例：

```python
def test_deduplicate():
    h = MessageHistory()
    h.add_user("hello")
    h.add_assistant("hi")
    h.add_assistant("hi")      # 重复
    h.add_user("how are you")
    h.add_assistant("fine")
    h.add_assistant("fine")    # 重复

    removed = h.deduplicate()
    assert removed == 2
    assert h.count == 4
```

## 常见问题

### Q1: 为什么用浅拷贝而不是深拷贝？

考虑两个方案的性能差异：

```python
import copy
import time

# 假设有 100 条消息
messages = [Message(role="user", content=f"消息 {i}" * 50) for i in range(100)]

# 浅拷贝
start = time.perf_counter()
for _ in range(1000):
    _ = list(messages)
shallow_time = time.perf_counter() - start

# 深拷贝
start = time.perf_counter()
for _ in range(1000):
    _ = copy.deepcopy(messages)
deep_time = time.perf_counter() - start

print(f"浅拷贝: {shallow_time:.3f}s, 深拷贝: {deep_time:.3f}s")
# 典型结果: 浅拷贝 ~0.01s, 深拷贝 ~0.5s (50倍差距)
```

在 Agent Loop 中，每次调用 LLM 都会执行 `get_messages()`，如果使用深拷贝，一个 10 轮的对话会浪费大量时间在复制上。

浅拷贝的风险（调用者修改 Message 对象影响内部状态）在实践中几乎不会发生，因为所有内部代码都是我们自己控制的。如果确实需要更严格的保护，可以在 Message 上使用 `frozen=True`。

### Q2: 截断时如何确保 tool_calls 和 tool_result 成对？

这是截断中最容易出 bug 的地方。如果 API 收到一个 tool_result 消息但没有对应的 tool_calls（或反过来），会返回 400 错误。

我们的策略是：

1. **删除 assistant tool_calls 时**：查找并删除所有 `tool_call_id` 匹配的 tool 消息
2. **删除 tool result 时**：检查对应的 assistant 消息是否还在，如果只有部分 tool result 被删除，也需要删除整个 assistant tool_calls 消息

实际代码中的处理逻辑（在 truncate 方法中）：

```python
if removed_msg.role == "assistant" and removed_msg.tool_calls:
    # 收集被删除 assistant 消息中所有 tool_call 的 ID
    call_ids = {tc.id for tc in removed_msg.tool_calls}
    # 从剩余消息中删除对应的 tool result
    non_system = [
        m for m in non_system
        if not (m.role == "tool" and m.tool_call_id in call_ids)
    ]
```

### Q3: token 估算不准确会有什么后果？

估算偏低（乐观）的后果更严重：可能导致 API 返回 `context_length_exceeded` 错误，Agent 崩溃。

所以我们的启发式方法故意偏保守（3 chars/token，实际可能是 3.5-4 chars/token），并在 `max_tokens` 配置时留出 10-20% 的余量。

```python
# 实际使用时
history = MessageHistory(
    system_prompt="...",
    max_tokens=100000,  # 实际上下文窗口 128K，留出 22K 余量
)
```

### Q4: 多轮对话中，是否需要删除旧的 tool 调用？

取决于场景。在一个长会话中，早期的 tool 调用（如读取某个文件）的信息可能已经被后续的对话覆盖。但删除 tool 调用需要成对删除，而且有些 tool 结果（如文件内容）可能一直有用。

推荐的策略是：不主动删除单个 tool 调用，而是通过 truncate 方法在 token 预算紧张时从最早的开始删除。这样既简单又安全。

## 本章小结

本章建立了消息历史管理的完整体系：

1. **MessageHistory 类**是 Agent 的"记忆管理器"，负责安全存储和检索所有对话消息
2. **浅拷贝保护**在性能和安全之间取得了合理平衡，通过 `list()` 返回新列表防止外部修改内部引用
3. **截断策略**是必不可少的：先保留 system 消息，再保留最近消息，确保 tool_calls/tool_result 成对
4. **token 估算**使用启发式方法（约 3 chars/token），故意偏保守以防止超限
5. **便捷方法**（add_user/add_assistant/add_tool_result）提供了类型安全的快捷操作
