# 第 17 课：毕业项目——搭建你的一人公司

## 学习目标

1. 明确毕业项目的要求、评分标准和交付物清单
2. 从 5 个推荐方向中选择适合自己的项目主题
3. 掌握 7 天运行计划的设计方法
4. 了解项目答辩的流程和展示要点

---

## 一、项目要求与评分标准

### 项目核心要求

你需要从零搭建一个由 AI agent 团队驱动的一人公司，并实际运行至少 7 天。这不是一个纸上谈兵的作业——你需要：

1. 选择一个真实的业务场景
2. 使用 OpenClaw 或 Paperclip（二选一）搭建完整的 agent 系统
3. 完成至少一次真实的业务交付（可以有真实客户或模拟客户）
4. 运行 7 天，收集数据并迭代优化
5. 产出完整的项目报告并进行答辩

### 评分标准

| 维度 | 权重 | 评分细则 |
|------|------|---------|
| **系统设计** | 25% | Agent 架构的合理性、职责划分的清晰度、协作流程的完整性 |
| **实际运行** | 25% | 7 天运行的稳定性、任务完成率、异常处理能力 |
| **业务价值** | 20% | 解决的痛点是否真实、交付物的质量、客户反馈（如果有真实客户） |
| **数据驱动优化** | 15% | 基于运行数据的分析、优化的方向和效果、成本效益分析 |
| **文档与展示** | 15% | 文档的完整性和可读性、答辩的逻辑性和说服力 |

**及格线**：总分 60 分以上，且「实际运行」和「系统设计」两个维度均不低于 50 分。

**优秀线**：总分 85 分以上，且有至少 1 个真实客户完成了真实交付。

## 二、选题建议（5 个方向）

### 方向 1：AI 内容工厂

**场景描述**：为一个特定领域（如技术教程、行业分析、产品评测）搭建自动化内容生产流水线。

**最小交付**：7 天内持续产出并发布 10+ 篇高质量内容到至少 2 个平台。

**推荐 Agent 配置**：
- 选题研究员 → 内容撰写员 → 编辑审核员 → 分发调度员

**适合人群**：有内容创作经验、对某个领域有深度认知的开发者。

**难度**：中等

---

### 方向 2：智能客服系统

**场景描述**：为一个真实或模拟的产品搭建多渠道 AI 客服系统，包含知识库检索、问题分类和升级机制。

**最小交付**：搭建可运行的客服系统，处理 50+ 条模拟或真实客户咨询，准确率 > 85%。

**推荐 Agent 配置**：
- 前线客服 → 知识库检索员 → 升级协调员 → 质检员

**适合人群**：有产品运营经验、对用户体验敏感的开发者。

**难度**：中高

---

### 方向 3：数据分析服务

**场景描述**：为特定行业（如电商、SaaS、自媒体）提供自动化数据分析报告服务。

**最小交付**：搭建数据采集 → 分析 → 报告生成的全流程，完成 3+ 份分析报告。

**推荐 Agent 配置**：
- 数据采集员 → 分析师 → 报告撰写员 → 可视化设计员

**适合人群**：有数据分析背景、擅长从数据中提取洞察的开发者。

**难度**：中等

---

### 方向 4：AI 辅助开发工作室

**场景描述**：搭建一个由 Agent 驱动的微型开发团队，能够自主完成小型功能开发（需求 → 开发 → 测试 → 部署）。

**最小交付**：Agent 团队自主完成 2-3 个小型功能需求的完整开发流程。

**推荐 Agent 配置**：
- 产品经理 → 开发工程师 → 测试工程师 → 运维工程师

**适合人群**：全栈开发者、对 DevOps 流程熟悉的开发者。

**难度**：高

---

### 方向 5：电商运营 Agent 团队

**场景描述**：为一个模拟或真实的电商店铺搭建自动化运营系统（选品分析、Listing 优化、客服）。

**最小交付**：完成完整的运营分析报告 + 自动化客服系统 + 至少 1 次 Listing 优化。

**推荐 Agent 配置**：
- 选品分析师 → Listing 优化员 → 客服 agent → 运营数据员

**适合人群**：有电商经验或对电商行业感兴趣的开发者。

**难度**：中高

## 三、交付物清单

### 必须交付（缺一不可）

1. **项目概述文档**（project-overview.md）
   - 商业模式描述（价值主张、目标客户、收入模型）
   - 选择的工具（OpenClaw 或 Paperclip）及理由
   - Agent 团队架构图（含角色、职责、协作关系）

2. **Agent 配置文件**
   - 所有 Agent 的完整配置文件（system prompt、skill 配置、权限声明）
   - 审批流配置（如适用）
   - 记忆和知识库配置

3. **7 天运行日志**（run-log.md）
   - 每日运行数据：任务数、成功率、token 消耗、异常次数
   - 每日发现的问题和优化措施
   - 成本追踪：7 天的总 AI 运行成本

4. **优化分析报告**（optimization-report.md）
   - 基于运行数据的问题分析
   - 实施的优化措施及效果
   - 成本效益分析（AI 成本 vs 人工成本对比）
   - 如果继续运行的改进计划

5. **答辩演示材料**
   - 10-15 页 PPT 或等效演示文档
   - 包含系统演示截图或录屏

### 可选交付（加分项）

- 真实客户的反馈记录或评价截图
- 收入证明（如果已获得真实收入）
- 开源的项目代码仓库
- 对其他同学的 peer review

## 四、7 天运行计划模板

### 模板结构

```markdown
# 7 天运行计划

## 基本信息
- 项目名称：
- 选择的工具：
- 主题方向：
- 开始日期：

## 每日计划

### Day 0（准备日）：系统搭建
- [ ] 完成 Agent 配置并测试基本功能
- [ ] 准备测试数据/模拟客户
- [ ] 设定运行监控指标
- 成功标准：所有 Agent 可以正常启动并响应

### Day 1：首次完整流程测试
- [ ] 运行一次完整的业务流程
- [ ] 记录每个环节的耗时和输出质量
- [ ] 标记需要人工介入的节点
- 数据记录：任务完成数、成功率、token 消耗

### Day 2：批量运行测试
- [ ] 投入 5-10 个任务进行批量测试
- [ ] 观察并发处理能力和冲突情况
- [ ] 记录异常和失败案例
- 数据记录：并发任务数、失败率、平均耗时

### Day 3：优化第一轮
- [ ] 分析 Day 1-2 的数据，识别瓶颈
- [ ] 调整 Agent prompt、skill 或流程
- [ ] 重新运行并对比优化效果
- 数据记录：优化前后的关键指标对比

### Day 4：压力测试
- [ ] 将任务量提升到预期的 2 倍
- [ ] 测试系统在高负载下的表现
- [ ] 记录降级和失败的触发条件
- 数据记录：最大承载量、降级阈值

### Day 5：真实场景测试
- [ ] 尝试引入 1-2 个真实客户或真实场景
- [ ] 记录与模拟测试的差异
- [ ] 收集客户反馈
- 数据记录：客户满意度、问题清单

### Day 6：优化第二轮
- [ ] 基于真实场景反馈进行第二轮优化
- [ ] 完善审批流和异常处理
- [ ] 编写运营文档
- 数据记录：第二轮优化效果

### Day 7：总结与收尾
- [ ] 汇总 7 天运行数据
- [ ] 撰写优化分析报告
- [ ] 准备答辩材料
- 产出：完整的项目报告
```

## 五、项目答辩指南

### 答辩流程

1. **系统演示（8 分钟）**：展示你的 Agent 系统实际运行，完成一个完整的业务流程
2. **项目讲解（5 分钟）**：商业模式选择、架构设计思路、关键技术决策
3. **数据展示（4 分钟）**：7 天运行数据、优化效果、成本分析
4. **问答环节（8 分钟）**：回答评审和其他同学的提问

### 答辩评分要点

评审关注的不是你的系统有多复杂，而是：

- **你解决了一个真实的问题吗？** 痛点是否真实、方案是否有效
- **你理解你自己的系统吗？** 能否清楚解释每个设计决策背后的原因
- **数据支撑你的结论吗？** 优化是否有数据佐证、而非凭感觉
- **你能从这个项目中学到什么？** 对失败和局限性的诚实反思

### 常见答辩失分点

- 只讲技术不讲业务（这是一个商业项目，不是技术 demo）
- 没有运行数据只有设计文档（空谈）
- 把 Agent 的输出当作自己的成果而不加审核（质量失控）
- 对失败的部分避而不谈（失败经验往往比成功经验更有价值）

### 练习：项目启动检查清单

在正式开始毕业项目之前，完成以下检查清单：

- [ ] 选定了方向（5 选 1 或自定义）

- [ ] 写出了 50 字以内的价值主张

完成所有打勾后，你就正式开始毕业项目了。祝你好运。

## 常见问题 FAQ

**Q：如果没有真实客户，模拟客户可以吗？**
A：可以。模拟客户需要有真实性：真实的需求场景、真实的输入数据、真实的评判标准。不要构造一个「完美的」模拟场景来回避困难。最好的模拟方式是找朋友或同学扮演客户，让他们给出真实的反馈。

**Q：7 天运行期间能不能中途修改配置？**
A：不仅允许，而且鼓励。7 天运行的目的就是发现问题并优化。每次修改都记录到运行日志中，说明改了什么、为什么改、效果如何。这些修改记录本身就是有价值的交付物。

**Q：毕业项目可以选择自定义方向吗？**
A：可以，但需要满足以下条件：1) 有真实的业务场景；2) 需要至少 3 个 Agent 协作；3) 有可量化的成功指标。建议在开始前跟导师或同学讨论你的自定义方向，确保可行性。

**Q：答辩时系统出了 Bug 怎么办？**
A：准备一份备用的录屏视频。答辩现场如果系统正常运行就用现场演示，如果出了问题就播放录屏。更重要的是能够解释 Bug 的原因和修复方案——这恰恰展示了你对自己系统的深度理解。
