## 一、最小可行一人公司（MV-OPC）

### 什么是 MV-OPC？

你可能熟悉 MVP（最小可行产品）的概念。MV-OPC 是这个概念在一人公司层面的延伸：用最少的 agent、最简的流程、最低的成本，快速验证你的商业模式是否有人买单。

MV-OPC 的核心原则：**不要等到完美再出发。先让一个人付钱给你，再考虑优化。**

### MV-OPC 的三个组成部分

```
MV-OPC = 最小价值主张 + 最小交付系统 + 最小获客渠道
```

**最小价值主张**：你能为谁解决什么具体问题？一句话说清楚。不是「我用 AI 帮你做营销」，而是「我帮独立开发者每月多获取 200 个注册用户」。

**最小交付系统**：用最少的 agent 完成从接单到交付的闭环。初始阶段 2-3 个 agent 足够，不需要搭建完整的组织架构。

**最小获客渠道**：只选一个渠道深耕。不要同时做 Twitter、小红书、知乎、邮件营销。选一个你的目标客户聚集的平台，全力以赴。

### MV-OPC 的 OpenClaw 最小配置

```yaml
# mv-opc-openclaw.yaml
# 最小可行配置：3 个 Agent 启动你的公司

gateway:
  platform: telegram  # 先只接一个平台，降低复杂度
  model: claude-sonnet  # 性价比最高的通用模型

agents:
  # Agent 1: 业务接单员
  sales-agent:
    system_prompt: |
      你是公司的业务接待员。你的任务是：
      1. 了解客户需求
      2. 判断是否能提供服务
      3. 给出初步报价和交付时间
      4. 收集必要信息以启动项目
    skills:
      - name: "intake"
        description: "客户需求收集和分类"
      - name: "quote"
        description: "根据需求类型生成报价"
    memory:
      short_term: "对话上下文"
      long_term: "客户偏好、历史订单"

  # Agent 2: 交付执行员
  delivery-agent:
    system_prompt: |
      你是公司的核心交付员。根据客户需求执行具体工作。
      所有交付物必须经过质量检查后才能发送给客户。
    skills:
      - name: "core_service"  # 替换为你的核心服务能力
        description: "执行主要业务交付"
      - name: "quality_check"
        description: "检查交付物质量"
    approval_required:
      - "发送最终交付物给客户"  # 第一次由你亲自审批

  # Agent 3: 运营助手
  ops-agent:
    system_prompt: |
      你是公司的运营助手，负责日常行政和跟踪。
      每日生成运营摘要，追踪收入和成本。
    skills:
      - name: "daily_report"
        description: "每日运营数据汇总"
      - name: "expense_track"
        description: "追踪 AI 运行成本和收入"
    schedule:
      - task: "daily_summary"
        cron: "0 22 * * *"  # 每天 22:00 生成摘要
```

## 二、快速验证方法论

### 三步验证法

验证的核心目标只有一个：**有人愿意付钱**。点赞、收藏、好评都不是真正的验证，只有「付费」是。

**第一步：问题验证（3 天）**

找到 5-10 个潜在客户，跟他们聊天（不是推销），确认：
- 他们是否真的有这个痛点？
- 他们现在怎么解决这个问题？
- 他们愿意为解决方案付多少钱？

Agent 辅助方式：用调研 agent 在相关社区（论坛、Reddit、知识星球）收集用户吐槽和需求帖，整理出痛点清单。

**第二步：方案验证（5 天）**

做出一个「手工版」的解决方案（不需要 AI agent 参与），交付给 1-3 个客户，收集反馈。关键问题：
- 方案是否真的解决了他们的痛点？
- 交付过程有哪些卡点？
- 他们对结果满意吗？

这一步的目的是验证价值，不是验证技术。

**第三步：自动化验证（7 天）**

将验证过的流程用 AI agent 部分自动化，观察：
- 自动化后的交付质量是否仍然达标？
- 你每天节省了多少时间？
- 客户是否注意到差异（不应该注意到）？

### 验证中的 Agent 角色

```yaml
# 验证阶段的 Agent 配置
validation_agent:
  system_prompt: |
    你是市场验证助手。你的任务是帮助创始人快速验证商业想法。
    你需要：
    1. 在指定平台上搜索相关讨论
    2. 提取用户痛点和需求关键词
    3. 分析竞品的用户评价（尤其是差评）
    4. 生成验证报告，包含数据支撑的结论

  skills:
    - name: "market_research"
      input: "目标关键词、目标平台"
      output: "痛点清单、需求频率统计"

    - name: "competitor_analysis"
      input: "竞品名称或 URL"
      output: "定价、用户评价摘要、差异化机会"

    - name: "validation_report"
      input: "调研数据"
      output: "结构化的验证报告（含推荐/不推荐的结论）"
```

## 三、第一笔收入策略

### 获取第一笔收入的 5 条路径

**路径 1：从身边人开始**

- 向你现有的社交网络（同事、朋友、前客户）介绍你的服务
- 给一个「创始客户价」（正常价的 50-70%）
- 用真诚换取口碑，而不是用低价换取订单
- 预期时间：1-7 天

**路径 2：社区贡献 → 付费转化**

- 在目标客户聚集的社区（论坛、Slack 群、Discord）持续提供免费帮助
- 当有人提出与你业务相关的问题时，先给出有价值的回答，再轻描淡写地提到你可以提供更深入的服务
- Agent 辅助：用内容 agent 定期生成有价值的分享帖
- 预期时间：2-4 周

**路径 3：免费试用 → 付费转化**

- 提供有限免费服务（比如免费分析报告、免费诊断），让客户体验价值
- 在交付免费服务的同时，附上付费升级选项
- Agent 辅助：用交付 agent 自动生成免费版和付费版的对比
- 预期时间：1-3 周

**路径 4：平台接单**

- 在 Upwork、Fiverr、闲鱼等平台挂出你的服务
- 前期可以适当降低价格积累评价和案例
- Agent 辅助：用 agent 快速响应询价和生成方案
- 预期时间：1-14 天

**路径 5：内容引流**

- 发布一篇与你的业务高度相关的深度内容
- 在内容中自然地引导读者了解你的服务
- Agent 辅助：用内容创作 agent 快速生产高质量引流内容
- 预期时间：2-6 周

### 第一笔收入的关键心态

- **不要纠结价格**：第一笔收入的核心是验证「有人愿意付钱」，不是赚多少钱。$1 和 $1,000 在验证意义上是等价的
- **不要追求完美交付**：用手工 + AI 的方式快速交付，宁可多花点时间也要让客户满意，但不必追求系统化
- **一定要收集反馈**：交付后主动询问客户满意度、改进建议和是否愿意推荐给朋友

## 四、迭代扩展路线图

### 四阶段扩展模型

```
阶段 0（第 1-2 周）：验证
  └─ 目标：第一笔收入
  └─ Agent：2-3 个
  └─ 月收入：$0 → $500
  └─ 你的时间：80% 执行 + 20% 管理

阶段 1（第 3-8 周）：稳定
  └─ 目标：稳定的月度收入 $1,000-3,000
  └─ Agent：5-8 个
  └─ 关键动作：优化交付流程、增加审批自动化比例
  └─ 你的时间：50% 执行 + 30% 管理 + 20% 销售

阶段 2（第 2-4 个月）：增长
  └─ 目标：月度收入 $3,000-10,000
  └─ Agent：8-15 个
  └─ 关键动作：搭建获客漏斗、内容营销自动化
  └─ 你的时间：20% 执行 + 40% 管理 + 30% 战略 + 10% 销售

阶段 3（第 4-12 个月）：规模化
  └─ 目标：月度收入 $10,000+
  └─ Agent：15-30 个（多部门协作）
  └─ 关键动作：考虑是否雇人、产品化服务、建立品牌
  └─ 你的时间：10% 执行 + 30% 管理 + 40% 战略 + 20% 客户关系
```

### 每个 Agent 的增加时机

不要一开始就搭建完整的 agent 团队。按照「瓶颈驱动」原则增加 agent：

1. 当你发现自己每天花超过 30 分钟在重复性沟通上 → 增加客服/沟通 agent
2. 当内容生产成为获客瓶颈 → 增加内容创作 agent
3. 当数据追踪成为管理负担 → 增加运营分析 agent
4. 当客户量增长导致交付排队 → 增加交付 agent（并行处理）
5. 当质量控制开始下滑 → 增加质检 agent（或增强审批流）

## 实战练习

### 练习 1：设计你的 MV-OPC

完成以下清单：

1. 写出你的「最小价值主张」（一句话）
2. 列出你的 2-3 个最小 agent 配置（角色 + 职责）
3. 选择你的「最小获客渠道」（只选一个）及理由
4. 设定你的「第一笔收入目标」和截止日期

### 练习 2：14 天启动计划

制定一份 14 天启动日程表：

- 第 1-3 天：问题验证（用 agent 辅助调研）
- 第 4-7 天：方案验证（手工交付给 1-2 个客户）
- 第 8-10 天：搭建最小 agent 系统
- 第 11-14 天：启动获客，争取第一笔收入

每一天写下具体要完成的一件事（不是「学习」，而是「交付一个具体的产出」）。

### 产出要求

提交一份 MV-OPC 启动文档，包含：
- 价值主张（50 字以内）
- Agent 配置文件（OpenClaw 或 Paperclip 格式）
- 14 天日程表
- 成功标准（怎么算「验证成功」）

## 常见问题 FAQ

**Q：如果 14 天内没有获得第一笔收入怎么办？**
A：首先不要慌。分析原因：是问题不存在（没人有这个痛点）、方案不对（痛点存在但你的解决方式不对）、还是渠道不对（目标客户没看到你）。针对不同的失败原因调整：换痛点、换方案、换渠道。失败本身就是有价值的验证数据。

**Q：MV-OPC 阶段需要注册公司吗？**
A：不一定。在很多地区，你可以先以个人身份接单（freelancer），等收入稳定到一定程度再注册。但如果你做 SaaS 或涉及用户数据，建议尽早注册以获得法律保护。咨询当地法规或找专业代理记账公司了解。

**Q：AI agent 在验证阶段会不会过度工程化？**
A：如果核心流程还不清晰，先用手工完成前几次交付，确认客户买账后再用 agent 自动化。agent 是放大器，不是救世主。先有可复制的流程，再用 agent 扩大规模。

**Q：如何平衡现有工作和一人公司的启动？**
A：推荐「5+2」模式：工作日每天投入 2 小时（早起或晚上），周末每天投入 4-6 小时。第一周的目标不是赚钱，而是完成问题验证。当你确认需求存在后再加大投入。

**Q：获客渠道太多不知道选哪个？**
A：选你的目标客户最活跃的那一个。如果目标客户是开发者，选 GitHub / Twitter / V2EX。如果目标客户是中小企业主，选微信生态 / 知乎 / 行业论坛。判断标准：你能否在那个平台上找到 10 个潜在客户并进行对话？如果能，就是对的渠道。

## 关键术语速查表

| 术语 | 含义 |
|------|------|
| **MV-OPC** | 最小可行一人公司，用最少资源验证商业模式 |

## 本课小结

从 0 到 1 的启动路径不是一次性发布，而是一连串低成本验证。你要先证明有人有这个问题，再证明你的交付能解决问题，最后才证明 Agent 系统能稳定复制交付。

本课的关键节奏是：先用人工加 Agent 完成少量高质量交付，再把重复环节沉淀成 SOP 和自动化。不要在没有客户反馈前过度搭系统，也不要在没有质量标准前扩大交付规模。

完成本课后，你应该拥有一个 7 天或 14 天的启动计划：每天验证一个关键假设，记录客户反馈、交付耗时、Agent 成本和返工原因。下一课会讨论规模化边界，帮助你判断什么时候继续自动化，什么时候需要真人团队。
