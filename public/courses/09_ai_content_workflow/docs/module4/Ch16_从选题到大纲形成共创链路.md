# Ch16:从选题到大纲,形成共创链路

## 学习目标

- 把选题推进成明确角度和内容结构
- 学会与 AI 共创提纲而不是直接求成稿
- 形成一条稳定的大纲生成流程

---

## 1. 为什么很多题看起来能写,真正下笔却写不动?

因为"题目"不等于"可写状态"。

很多人会卡在这个阶段:

- 有题目
- 也觉得有价值
- 但一打开文档,还是不知道先写什么

这通常说明题目还没被推进到足够清楚。

真正可写的状态,至少应该包括:

- 对象清楚
- 角度清楚
- 目的清楚
- 结构清楚

而这正是共创链路要解决的问题。

---

## 2. 什么叫"从选题到大纲"的共创链路?

你可以把这条链路先理解成四个动作:

```text
题目 -> 角度 -> 结构 -> 提纲
```

很多内容写不下去,不是表达能力不够,而是还没有把题目推进到可写状态。

本章会把共创链路拆成几个动作:

- 从题目澄清写作目的
- 从目的生成角度
- 从角度搭出结构
- 从结构补上关键论点和例子位置

```text
提纲写清楚以后,初稿效率会大幅提升。
```

```mermaid
flowchart LR
    A[题目] --> B[澄清目的]
    B --> C[生成角度]
    C --> D[选择结构]
    D --> E[补关键论点]
    E --> F[形成提纲]
```

---

## 3. 第一步:从题目澄清写作目的

一个题可以有很多种写法。
先要明确这篇内容到底想干什么。

例如同样是"为什么很多人用了 AI 还是写不出来",它可以写成:

- 一个误区拆解
- 一个流程教学
- 一个经验复盘
- 一个观点型内容

所以在进入提纲前,先要问:

- 这篇内容最核心想解决什么问题?
- 它是帮人理解、帮人判断,还是帮人行动?
- 它最适合谁看?

如果这一步不清楚,后面结构很容易漂。

---

## 4. 第二步:从目的生成角度

题目相同,角度可以完全不同。

例如:

题目:很多人用了 AI 还是写不出来

可选角度可能包括:

- 不是工具问题,而是流程问题
- 不是不会写提示词,而是没有选题链路
- 不是没有内容,而是素材没有沉淀成资产

角度的作用,是帮你决定"这篇内容最值得讲哪一刀"。

没有角度,题目就会太泛;
有了角度,内容才开始变得具体。

---

## 5. 第三步:从角度搭出结构

当角度明确后,就可以开始搭结构。

常见的结构方式有:

### 5.1 误区型

适合讲纠偏内容。

```text
常见误区 -> 为什么会这样 -> 正确做法
```

### 5.2 流程型

适合讲操作和方法。

```text
问题 -> 步骤 1 -> 步骤 2 -> 步骤 3 -> 注意事项
```

### 5.3 对比型

适合讲差异和判断。

```text
做法 A -> 做法 B -> 差异 -> 推荐场景
```

### 5.4 复盘型

适合讲经验和个人路径。

```text
起点问题 -> 过程变化 -> 关键转折 -> 结果总结
```

AI 在这一层很适合帮你快速试不同结构方案。

---

## 6. 第四步:从结构补齐提纲

结构只是骨架,提纲还要进一步补具体内容。

一个实用提纲,至少应该包含:

- 每一段要讲什么
- 每一段为什么要放在这里
- 哪一段需要例子
- 哪一段需要数据或案例支撑

你可以要求 AI 继续补这些问题:

- 这一段最关键的一句话是什么?
- 这篇内容最需要哪个例子?
- 哪一部分最可能讲空?

这样提纲会更接近真正能写的状态。

---

## 7. 用阿宁的案例走一遍

下面我们把课程里的贯穿案例直接推进一次。

### 7.1 原始题目

```text
为什么很多上班族明明用了 AI,工作还是没变顺?
```

### 7.2 先澄清写作目的

这篇内容到底想干什么?

- 不是评测工具
- 不是教复杂提示词
- 而是帮读者意识到:问题常常不在工具,而在流程没有接起来

### 7.3 生成 3 个角度

```text
角度 A:不是你不会用 AI,而是你没有工作流
角度 B:AI 没帮你提效,是因为你只在空白页才想起它
角度 C:真正拉开差距的不是模型,而是收集、整理、复用的链路
```

### 7.4 选择结构

这篇更适合走"误区纠偏 + 流程示范"的结构:

```text
问题现象 -> 常见误区 -> 正确流程 -> 一个最小可用做法
```

### 7.5 补成可写提纲

```text
标题:
为什么很多人用了 AI,工作还是没变顺

提纲:
1. 先写常见现象:工具很多,但每天还是乱
2. 点出误区:把 AI 当一次性问答,而不是工作流的一环
3. 拆出正确链路:收集 -> 整理 -> 追问 -> 成稿 -> 复盘
4. 给一个最小做法:一个主力助手 + 一个知识库 + 一个主平台
5. 结尾强调:先跑通,再升级
```

你会发现,一旦走到这里,真正写初稿已经不难了。

---

## 8. 为什么先共创提纲,比直接求成稿更稳?

因为提纲阶段的成本更低、可调空间更大。

如果你直接让 AI 出成稿,常见问题是:

- 看起来很完整,但偏题
- 很顺,但不是你想讲的重点
- 字很多,但结构不对

而提纲阶段改起来更轻:

- 角度不对,可以换
- 结构不顺,可以调
- 重点不够,可以补

这一步做扎实了,后面的初稿会顺很多。

---

## 9. 一条简单可复用的共创模板

你可以先用下面这个模板:

```text
这是我的题目:

请不要直接帮我写成稿,而是按下面顺序帮我共创:
1. 先澄清这篇内容最想解决什么问题
2. 给我 3 个可能的表达角度
3. 帮我选出最适合当前受众的角度
4. 按这个角度生成一个结构清晰的提纲
5. 标出每一部分最适合补什么例子或材料
```

这个流程已经足够帮助你从"有题"推进到"能写"。

## 10. 本章的最小行动

请从你的选题池里挑 3 个题目,分别做一次提纲共创,并记录:

```text
题目:
最适合的角度:
最终采用的结构:
最需要补的例子:
```

做完后,你会明显感觉哪些题已经接近可写状态,哪些还需要继续追问。

## 动手试试 / 实战场景

- 从选题池里挑 3 个题目做提纲练习
- 用 AI 帮你对比不同结构方案
- 沉淀一版"大纲共创模板"

## 常见问题 Q&A

**Q1：我照着模板做了，但生成的大纲还是感觉不对，怎么办？**
A：通常是因为题目还没有被追问清楚。如果题目本身太泛，再好的模板也出不了好大纲。退回 Ch14，先做一轮追问，把题目压缩到一个具体角度，再来做大纲。题目越具体，大纲越容易出。

**Q2：误区和流程两种结构，我怎么判断该用哪个？**
A：如果你这篇想"纠正一个常见误解"，用误区型；如果你想"带人走一遍具体操作"，用流程型；如果你想"比较两个做法的优劣"，用对比型。一个快速判断：你写这篇最主要想让读者知道"那不对"还是"这么做"——前者用误区型，后者用流程型。

**Q3：AI 给我出了 3 个角度，每个角度都像有道理，怎么选？**
A：选"你最想表达的那个"，而不是"最全面"或"看起来最专业"的那个。一个实用的判断：把 AI 给你的 3 个角度各用一句话讲给你朋友听，看哪个你讲得最快、最顺——那个就是你应该先写的。

**Q4：提纲写到什么程度才算"可以开始写了"？**
A：当你能回答这三个问题时就算：每一段要讲什么（不超过一句话）、哪一段需要例子支撑、读者读完后应该记住的一个核心判断是什么。如果能回答，就可以开始写初稿了。不要追求提纲完美——提纲的作用是指路，不是替代写作。

## 小结

- 真正高效的写作,不是从空白页开始,而是从一个已经共创过的大纲开始
- 一条稳定的大纲链路,至少要经过题目、角度、结构、提纲四步
- 用真实案例走完一遍,你会更容易感受到"提纲先行"到底帮你省了什么
- 提纲阶段越清楚,后面的初稿阶段越轻松
